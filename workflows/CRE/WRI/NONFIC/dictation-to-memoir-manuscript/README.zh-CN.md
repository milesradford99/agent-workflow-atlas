# 从口述到回忆录书稿

**工具变体：** `claude-markdown-git-epub` · `notebooklm-claude`

## 背景

回忆录写的是作者自己的人生，所以原始素材早已存在：记忆、旧邮件、日记和博客文章。难处在于把零散的片段变成前后连贯、读起来仍是作者本人口吻的章节。许多作者说比打字更容易，于是对着录音设备讲述片段，往往相隔数周，最后面对一堆既重复又互相矛盾的素材。智能体负责整合这些片段，找出作者早先关于某件事的原话，并把后面的章节与前面的对照。书是什么样、每一段由智能体起草的内容如何重写、每条批评是否采纳，仍由作者决定，因为故事和文风都是作者的，读者读回忆录，是当作作者本人在说话。出版前仍要由人工编辑通读，因为智能体倾向于夸奖。

**术语：**
- **口述片段**：简短的语音录音，转成文字，每段讲一个场景或一件事。
- **文风规则**：书面写下的要求，说明这本书该是什么口吻、是什么和不是什么。
- **一致性检查**：把一章与其他各章对照，找出事实、名字或日期上的矛盾。
- **反面意见（negative case）**：问“哪里不对”，而不是要“更好的版本”，因为要求改进会磨平作者的文风，而问“你怎么看”又容易换来夸奖。
- **Markdown、git、EPUB**：带少量格式标记的纯文本文件；一个保存一组文件每个版本的工具；通用的电子书文件格式。
- **试读者（beta readers）**：在出版前通读书稿并说出哪里有效的志愿读者。

## 用智能体搭建

**形态：** `skill`。一位作者在对话中写一本书，所以一个保存文风规则和章节流程的 skill 就够了。

**需要：** 文本形式的口述转写；作者自己的档案（邮件、日记、博客文章），保存为智能体可检索的文件；书稿放在 git 仓库里，每章一个 Markdown 文件；一个生成 EPUB 的小脚本；一个 skill，里面有作者的文风规则，以及一致性检查和批评轮要问的问题。档案里有他人的私人信件，哪些部分允许智能体检索由作者决定，也不要上传到别处。不要接入任何发布工具。

| 步骤 | 搭建方式 |
|---|---|
| 作者口述片段 + 收集自己的档案 | 由作者完成。转写稿和档案是 skill 的输入。 |
| 智能体梳理素材：提纲、缺口、重复 | skill 通读全部素材，返回提纲、留给作者的问题、缺口，以及在各章之间重复的段落。 |
| 🛑 plan | 见检查点。 |
| 每章：把片段 + 作者档案中的原话整合成章节文件 | skill 根据片段写出章节文件，在档案中检索作者当时关于该事件的原话，凡是无法佐证的细节都标成问题。 |
| 🛑 review (作者重写) | 见检查点。 |
| 跨章一致性检查 ⟲ 作者修正 | skill 把一章与作者指定的其他章对照，列出矛盾。由作者修正。 |
| 编辑式批评轮（找反面意见） | 一个没有见过起草过程的内置子智能体通读书稿，按章节结构返回薄弱之处。 |
| 🛑 review (作者逐条采纳或驳回) | 见检查点。 |
| 每个编辑状态一次 git 提交 → 生成 EPUB | 作者决定之后执行 git 命令；脚本生成 EPUB。 |
| 🛑 handoff | 见检查点。 |

**检查点：** `plan`：skill 在展示提纲和文风规则后停下，作者批准之前不向章节文件写入任何内容。`review`（章节）：skill 在每个章节文件之后停下，由作者重写；智能体从零起草的段落都做了标记，确保没有哪一段不经重写就留下。`review`（批注）：skill 把批评意见编号列出，只应用作者选中的那几条。一条在 `git commit` 前询问的权限规则，使任何改动在作者说“可以”之前进不了历史记录。`handoff`：skill 在结尾说明哪些它无法判断，书稿由智能体之外的人工编辑、校对和试读者接手；智能体没有发布工具。

**与来源相比：** 来源的时间从 2026-04 到 2026-05。两篇都是个人博客，各记述一位作者的做法，都用了 Claude，其中 Whitt 提到它在上下文里装下了整部 80,000 词的书稿。本搭建方式保留了它们报告的内容：每章一个文件、每个状态用 git 保存、一条命令生成 EPUB、要求反面意见、以及作者的重写。它新增了对智能体起草段落的标记，两个来源都没有把这当作一种机制来描述。两个来源都没有提到 skill，所以文风规则怎么存放是本搭建方式的选择。模型能否同时看到整部书稿，取决于模型和书的长度，本搭建方式不依赖这一点。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 作者提供原始素材：在通勤路上口述的片段、语音录下的场景，以及自己过去的文字（20 多年的邮件、通讯、博客文章、日记） [[1]](#sources)[[2]](#sources)。
2. 智能体通读全部素材，返回提纲、作者没问过的问题、缺口，以及在各章之间重复的段落。🛑 **计划**：作者定下文风规则，以及这本书是什么、不是什么 [[2]](#sources)。
3. 作者像管理代码一样管理书稿：每章一个 Markdown 文件，每个编辑状态都用 git 保存，一条命令生成 EPUB [[1]](#sources)。
4. 每一章：智能体把相隔数周录下的口述片段整合成连贯的章节，在邮件档案中检索作者当时关于该事件的原话，并还原记得不全的细节（步道名称、地标、距离）。🛑 **审阅**：作者重写；凡是智能体从零起草的内容，全部被重写 [[1]](#sources)[[2]](#sources)。
5. 智能体做跨章一致性检查（“给定第 1、4、9 章，这一章哪里对不上？”）；在报告的实例中，它找出了六处左右的真实错误 [[1]](#sources)。
6. 智能体做编辑式批评轮，作者明确要求找反面意见，而不是“更好的版本”。🛑 **审阅**：作者采纳了约 60% 的意见，驳回了 40% [[1]](#sources)。
7. 由脚本生成 EPUB。🛑 **接手**：书稿在出版前交给人工编辑、校对和试读者 [[1]](#sources)[[2]](#sources)。

**产出：** 一份完成编辑的回忆录书稿（Markdown + EPUB），交给人工编辑或直接出版。
**失败模式 → 防护：** 要求“更好的版本”会磨掉文风 → 改问现有文字哪里薄弱；智能体倾向于夸奖 → 要求给出反面意见，并让人工编辑始终在环；智能体起草的文字不是作者的文风 → 作者重写每一段生成的内容。
**与相近工作流的区别：** 最接近的是 AWF-0073 资料卷宗到章节的书。0073 由智能体的网络调研卷宗生成章节，带引用、BibTeX 和无依据论断审计。本工作流唯一的素材是作者自己的口述和档案，没有调研或引用步骤，智能体的主要工作是整合、一致性检查和批评，最后一道关是交给人工编辑。素材、检查点和交付物都不同。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Fourth collection pass](../../../../../research/2026-11-fourth-pass.md)。

- [Matt Whitt, Writing a Memoir with Claude](https://mattwhitt.com/blog/writing-a-novel-with-claude/) (2026-04-12)。通勤口述被整合成章节；一致性检查；作者采纳了约 60% 的意见。"28 chapters, 80,000+ words, fully edited". *第一手：是；可信度：高。*
- [Steve Bremner, I Wrote a Book With AI](https://stevebremner.com/2026/05/i-wrote-a-book-with-ai-heres-what-actually-happened/) (2026-05-21)。邮件档案检索 + 语音转写被整理成回忆录；交给人工编辑。"twenty plus years’ worth of emails". *第一手：是；可信度：中。*
