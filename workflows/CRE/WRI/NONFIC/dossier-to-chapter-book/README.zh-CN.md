# 资料卷宗成书

**工具变体：** `claude-code-quarto` · `gemini-cli-research`

## 背景

一本陈述事实的非虚构书，每个论断都要能追溯到读者可以核对的来源。一本十几章的书，作者要为每一章做调研，阅读并筛选来源，写作，还要把参考文献整理好。这很慢，而且让模型去找来源时，它可能编造出看上去很像样、实际并不存在的来源。在这里，智能体做第一轮：每章一份简报，一份带注释来源的网络调研卷宗，一章带引注的草稿，最后审计没有来源支撑的论断。每个阶段仍由作者批准，因为书的论证和准确性由作者负责，印出来的假引注会损害作者。每个被标记的论断，最后也由作者拍板。

**术语：**
- **研究简报**：一章的简短计划：论证脉络、要找的来源类型、图示设想和待解决的问题。
- **卷宗（dossier）**：一章的调研成果：带注释的来源清单、论证主线、章节提纲和图示草图。
- **Quarto**：一个出版系统，用 Markdown 章节文件生成一本书。
- **BibTeX**：参考文献的纯文本格式，这里保存在一个 `.bib` 文件里。
- **DOI**：已发表论文的永久标识符；编造的 DOI 看起来像真的，实际上查不到任何东西。
- **Tier 1 和 Tier 2 来源**：本条目自己的引注规则：Tier 1 是智能体在会话中能打开的文件，如官方出版物，需要有效的 URL；Tier 2 是期刊论文，除非打开过出版方页面，否则只给占位符。
- **无依据的论断、未链接的实体**：没有来源支撑的事实陈述；提到了人、机构或文件却没有给出引用。

## 用智能体搭建

**形态：** `project`。一位作者写一本书，但这本书横跨许多次会话和章节，需要每次都必须成立的规则（引注纪律）、长期存在的项目文件，以及一个没有见过正在写的章节的评审者。[AWF-0011](../../FICTION/bible-driven-novel-draft/) 出于同样的理由采用了同样的形态。

**需要：** 一个 git 仓库，里面有 Quarto 书稿、存放主提示词、简报和卷宗的 `_research/` 文件夹，以及 `references.bib`；一份 `CLAUDE.md`，写明目录结构和引注规则；用于简报、卷宗和章节的 skill；一个网络搜索工具；如果所在领域有文献数据库，则需要能访问它，以便智能体逐篇确认论文。发布不需要任何连接器。

| 步骤 | 搭建方式 |
|---|---|
| 搭建书稿仓库 | 由作者完成，包括 Quarto 结构和任何早期草稿。 |
| 缺口分析 + 研究计划 → 🛑 plan | 一个 skill 读取仓库，列出缺口，并写出涵盖结构、文风、引注标准和图示的主提示词。 |
| 每个章节：研究简报 → 🛑 review (简报) | 一个 skill 为每章写一份简报，存入 `_research/briefs/`。 |
| 每个章节：网络调研卷宗 → 🛑 review (卷宗) | 一个带网络搜索的调研子智能体按 `CLAUDE.md` 里的两级引注规则，为每章写一份卷宗。各章可以并行运行，搜索工具有速率限制时则依次运行。 |
| 每个章节：起草正文 + 引注 + BibTeX → 🛑 review (章节) | 主对话依据卷宗写出章节，在每个 Tier 2 占位符进入 `references.bib` 之前通过查询逐一核实，并运行 Quarto 构建。 |
| 审计无依据的论断 → 🛑 sign-off | 一个没有见过起草过程的自定义只读子智能体读取每个完成的章节，把无依据的论断和未链接的实体列在一个批注文件里。主对话为作者对这些标记做分诊。 |

**检查点：** `plan`：skill 在展示缺口和主提示词后停下。`review`：各 skill 在每份简报、卷宗和章节之后停下，作者接受、改向或重新运行，之后才进入下一阶段。一条在编辑 `references.bib` 前询问的权限规则，使作者看到参考文献的每一处改动。`sign-off`：审计子智能体没有编辑工具，只产出清单，由作者对每个被标记的问题做决定。

**与来源相比：** 唯一的来源没有注明日期；它提到 Claude Opus 4.7 和 Sonnet 4.6，由此可判断出自 2026 年。它用了三个模型：一个负责规划，一个负责起草，一个负责调研和审计。本搭建方式改用同一个智能体工具的子智能体，不再单独选用调研模型，而那是来源出于广度和成本考虑做的选择。它保留了两级引注规则和占位符机制，这是来源在早期卷宗里发现编造的 DOI 之后采用的。来源给出了抽查所得的准确率估计，并承认并非每条引注都经过独立核验，所以出版前仍需人工抽查参考文献。来源还提到，它的调研工具在自主模式下创建了未被要求的文件；本搭建方式把调研子智能体限定为只能写入 `_research/` 之下。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 作者搭好书稿骨架（Quarto 书籍结构、各章初稿、框架）。由一个模型审查仓库、找出缺口，并起草研究计划和主提示词。🛑 **计划**：作者引导分析并调整范围，然后才接受主提示词 [[1]](#sources)。
2. 起草模型为每一章写一份研究简报（共 17 份）。🛑 **审阅**：作者审阅每份简报，必要时重新调整范围 [[1]](#sources)。
3. 第二个带网络搜索的模型（通过 CLI 调用 Gemini）为每一章生成一份资料卷宗：带注释的来源清单、论证主线、章节提纲和图示草图。为避免触发速率限制，各次运行依次进行。这一步适用引注规则：Tier 1 来源需要在会话中确认过的有效 URL，Tier 2 论文除非检索过出版方页面，否则只给占位符。🛑 **审阅**：作者检查每份卷宗的范围缺口和来源质量，然后接受、拒绝或重新运行 [[1]](#sources)。
4. 起草模型依据卷宗撰写章节正文，核验引注，制作图表，并添加 BibTeX 条目。🛑 **审阅**：作者审阅每一章并指示修改 [[1]](#sources)。
5. 跨模型评审：第二个模型 Gemini 审计已完成的章节，找出无依据的论断和未链接的实体，Claude 对这些标记做分诊。🛑 **签发**：作者对每个被标记的问题做最终决定 [[1]](#sources)。

**产出：** 一本 Quarto 书稿（各章文件加一个 .bib 文件），可直接出版或进入下一轮编辑。
**失败模式 → 防护：** 幻觉出来或无法核验的引注 → Tier 1 的有效 URL 规则、未检索到的一律用 DOI 占位符，以及第二个模型的审计。来源自己承认并非每条引注都经过独立核验，因此出版前仍需人工抽查引注。范围漂移 → 作者把关每份简报和卷宗。
**与相近工作流的区别：** AWF-0030 议题树研究产出的是战略答案，不是带引注的书。AWF-0011 设定集驱动的小说起草是虚构创作，没有来源和引注关卡。AWF-0009 筛选漏斗筛选文献，但不撰写长篇章节。
