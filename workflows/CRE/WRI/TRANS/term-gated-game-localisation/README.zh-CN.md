# 术语把关的游戏本地化

**与相近工作流的区别：** AWF-0076 术语表支撑的机翻后编辑连载中，由人工校对（译后编辑者）逐章对每个网文章节做后编辑，并根据读者评论更新术语表。本工作流中，语言专家预先批准术语表，自动规则检查负责捕获问题，最后由 LQA 专家检查，文本按类型分流并覆盖多种语言。检查点的位置和产出（游戏文本，而非章节）都不同。
**工具变体：** `rag-llm` · `rule-qa`

## 步骤

1. 每个游戏版本的源文本按文本类型拆分（系统界面、技能描述、剧情对话、公告、SNS），每种类型有各自的风格规则 [[1]](#sources)。
2. 术语挖掘：用少样本 LLM 从过往译文中抽取术语对（例如「風ノ剣士」→「风之剑士」），并在只有源文的新文本中发现候选术语 [[1]](#sources)。
3. 🛑 **审阅**：候选术语对交给语言专家，只有获批的才进入该版本的术语库（glossary）[[1]](#sources)。
4. RAG 翻译：混合术语检索（IP 名和角色名精确匹配），外加按语义、说话人、风格和情绪相似度重排序的翻译记忆片段 [[1]](#sources)。
5. 规则后检查在生产中运行：混合语言检测、HTML 标签和格式完整性、术语表合规。不合格的条目退回返工 [[1]](#sources)。
6. 🛑 **审阅**：交付前由专业的 LQA（本地化质检）专家检查 [[1]](#sources)。

**产出：** 每个版本最多 10 种语言的本地化文本，上线到游戏构建中。
**失败模式 → 防护：** 增译或漏译、违反术语表、输出语言混杂、标签损坏 → 规则层（覆盖 70%+ 的格式和术语问题）加 LQA 专家。术语表在版本之间过时 → 每个版本都做经专家批准的术语挖掘。
