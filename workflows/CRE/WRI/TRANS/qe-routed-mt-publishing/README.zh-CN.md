# 按质量评估分流的机翻发布

**工具变体：** `microsoft-qe-quest-plus-plus` · `taus-epic-qe` · `modelfront`

## 背景

一家软件公司把产品发布成几十种语言，每个按钮标签和提示信息（界面字符串）每次发版都需要翻译。人工翻译是又慢又贵的一步。机器翻译（MT）往往已经好到人看了也不会改，但不逐条读，谁也不知道是哪些。质量评估（QE）是一种模型，不需要参考译文，就能为每个机翻片段打分，于是流水线可以让高分片段不经审阅直接发布，只把低分片段送给人工译后编辑。智能体这一侧接手分流和记账。人仍然负责三件事：必须经过审阅的字符串（法务文本、营销、“What's New”）、对未通过片段的译后编辑，以及每月核查不经审阅发布是否抬高了错误率、是否影响了客户，因为公司是明知地发布了一部分不完美的文字。

**术语：**
- **界面字符串**：软件界面中的一段文字，例如按钮标签或错误提示。
- **片段（segment）**：翻译的单位，通常是一条字符串或一个句子。
- **翻译记忆库（TM）**：保存以往人工译文的数据库；100% 匹配（完全匹配）指已经有一模一样的译文，可以零成本复用。
- **机器翻译（MT）**：由模型自动翻译。
- **质量评估（QE）**：在看不到人工参考译文的情况下，预测一条机器译文好坏的模型。
- **TER（译文编辑率）**：人工需要修改的译文比例，越低越好。这里预测 TER 高于 0.3 的片段算低质量。
- **译后编辑（PE）**：由人工译者修改机器输出。
- **LQA（语言质量保证）**：审阅人对照错误类型清单检查译文。
- **吞吐量与精确率**：这里分别指阈值放行的片段占比，以及这些放行片段里真正没问题的占比。

## 用智能体搭建

**形态：** `service`。字符串随每次构建到来，没有人守在键盘前；人只看到未通过的片段、抽检样本和每月报告。

**需要：** 带开发者注释和资源名的字符串；对翻译记忆库的读权限；写成文件的排除规则（功能清单、资源清单、最短长度）；每种语言一个 QE 打分器和一个阈值；保存每个片段的去向和分数的存储；译后编辑队列；以往各月的人工审阅结果，用来校准。智能体只对通过的片段有写入本地化字符串的权限，对未通过和被排除的片段没有。

| 步骤 | 搭建方式 |
|---|---|
| 新字符串 → 复用翻译记忆库的完全匹配 → 排除规则 | 一个由你的构建流水线在每批新字符串到来时运行的 Agent SDK 程序或 `claude -p` 任务。它通过翻译记忆库连接器查询完全匹配，并应用排除文件，规则写在代码里，不交给模型自行判断。 |
| 人工翻译 \| 机翻 | 被排除的字符串进入人工翻译队列。其余的由翻译引擎，或由一个保存文风和术语规则的 skill 来机翻。 |
| 为每个片段打 QE 分(按语言设阈值) | 每种语言一个 QE 模型（托管的 QE 服务或自己训练的），每种语言的阈值放在配置文件里。阈值不由智能体选定。 |
| 通过：不经审阅直接发布 \| 未通过：🛑 handoff (人工译后编辑) → 发布 | 通过的片段写入本地化字符串。未通过的进入译后编辑队列，译后编辑批准后再发布。 |
| 🛑 sample (每月核查错误率和客户满意度，重新校准阈值) | 见“检查点”。 |

**检查点：** `handoff`：每个未通过的片段连同原文、机器输出和分数进入译后编辑人员的队列，在译后编辑批准之前，不会往字符串里写任何东西。`sample`：每月，服务从已发布的通过片段中，按产品和语言抽取固定比例交给审阅人，并把错误率与客户满意度数据放在一起报告；是否调整阈值由人决定。漏掉一次接手就会发布未经审阅的文字，所以未通过和被排除的路径没有写入工具，阈值和排除文件只能由人修改。

**与来源相比：** 来源出自 2020-10 到 2024-11；其中一个（TAUS 案例）没有日期。来源 1 是一份幻灯片，撰写本节时无法读出其中的文字，所以它的数字依据的是条目本身的文字。截至 2026-11 搜索更新的记述，找到两篇 2026 年 EAMT 会议论文，一篇讲用模型当评审来判断原始 AI 译文能否不经译后编辑直接发布，一篇讲用小型开放权重模型做 QE（[论文 1](https://aclanthology.org/2026.eamt-1.7.pdf)、[论文 2](https://aclanthology.org/2026.eamt-1.9.pdf)）；这两份 PDF 在此无法读出，所以搭建方式没有依赖它们。来源用的是训练好的 QE 模型；通用智能体打分能否可靠到足以取代它，这里没有任何来源给出答案，所以在让片段不经审阅通过之前，要用你自己内容上的人工审阅结果校准任何打分器。2024 年 BLEND 试点报告说，质量影响没有被测量。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 流水线从翻译记忆库（TM）中复用未改动的字符串和完全匹配（100% 匹配）的字符串 [[1]](#sources)。
2. 排除：对客户影响大的字符串（“What's New”、营销、法务）以及不适合机翻的功能，交给人工翻译。排除依据是资源（词数、资源名、开发者注释）或功能。少于 8 个词的字符串同样排除 [[1]](#sources)。
3. 流水线对其余新字符串做机器翻译。每种语言一个 QE 模型（基于特征，每种语言用 100k+ 个片段训练）预测 TER（译文编辑率）。质量低指预测 TER >0.3 [[1]](#sources)。
4. 团队按目标错误率为每种语言校准 QE 阈值（每个产品、每种语言、每月新增词数的 10%；历史上人工 LQA（语言质量保证）的不合格率为 5%）。在文中的算例里，QE 阈值 0.42 对应 58% 的吞吐量和 62% 的精确率 [[1]](#sources)。
5. 通过 QE 的片段不经人工审阅直接发布，等同于 100% 的翻译记忆库匹配 [[1]](#sources)[[2]](#sources)。
6. 🛑 **接手**：未通过 QE 的片段交给人工译后编辑（PE），与以前一样 [[1]](#sources)[[2]](#sources)。
7. 🛑 **抽检**：团队监控每种语言的客户满意度和错误率，听取客户反馈，并重新调整阈值 [[1]](#sources)。

**产出：** 随构建发布的本地化软件界面字符串。只有未通过 QE 和被排除的字符串经过了人工处理。
**失败模式 → 防护：** QE 模型并不完美，有些低质量机翻是被有意发布的 → 用明确的错误率预算设上限，并关注客户满意度 [1]。短字符串得分差或有歧义 → 设长度阈值 [1]。QE 过度标记（Yamagata 估计 30% 被标为“差”的其实没问题）→ 按领域微调阈值 [3]。对于用户生成内容，字符串被污染且模型没见过 → 未通过的仍保留译后编辑 [3]。
**与相近工作流的区别：** 最接近的是 AWF-0076（术语表支撑的机翻译后编辑连载）和 AWF-0136（术语把关的游戏本地化）。这两个工作流里，每一章或每段文本在发布前都要经过人工译后编辑或 LQA。这里由质量评估（QE）路由器让大部分机翻不经人手直接发布，人只处理未通过的片段并做汇总抽检。自主程度从分段变为抽检，检查点也变成一次接手和一次审计。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [Microsoft (Schmidtke), Scaling up automatic translation for software](https://aclanthology.org/attachments/2020.amta-user.5.Presentation.pdf) (2020-10)。两年来对软件界面做 QE 把关的机翻发布，覆盖 37 种语言，客户满意度保持稳定。"MT now used for 9% of published software translation volumes across 37 languages"; "0.4M VOLUME OF WORDS 'QE PASSED' EACH MONTH"。*第一手：是；可信度：高。*
- [TAUS, Yamagata Europe case study](https://www.taus.net/case-studies/yamagata-saves-up-to-76-in-lead-time-and-costs-with-taus/) (undated)。为保修索赔机翻定制的 QE 模型；“良好”的字符串跳过译后编辑。"65% for the FR-EN language pair and 76% for the DE-EN language pair"。*第一手：厂商；可信度：中。*
- [Custom.MT (Dranch), Automated QE Reduces Cost of Translation](https://custom.mt/quality-estimation-draws-nearer-to-adoption/) (2024-11-06)。BLEND 的客户不再审阅置信度高于阈值的字符串。"The resulting cost saving was 35%, economizing $47k in the pilot project"; "The impact on quality was not measured."。*第一手：访谈；可信度：中。*
