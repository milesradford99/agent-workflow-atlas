# 抽样核验的 LLM 文件分析

**工具变体：** `gpt-4o` · `python-sqlite-r`

## 背景

有些新闻报道靠计数立论：某一类诉讼共有多少起，这一比例多年来如何变化。当事实散落在数百份冗长的法院文件里时，手工通读太慢，关键词搜索又会漏掉措辞不同的案件。语言模型可以对每份文件回答同样的固定问题，产出一张可以计数的表。但模型会出错，而报道里印出的数字必须准确。因此，由智能体批量回答问题；工作能否开始由人决定，任何数字投入使用之前，也由人自己对照事先定好的准确率阈值，核对随机抽样的答案。对所发表内容负责的是新闻机构，不是模型。

**术语：**
- **起诉状（complaint）**：诉讼的第一份文件，写明起诉方的主张。
- **PACER**：美国联邦法院获取案件文件的在线系统。
- **二元问题（binary question）**：针对每份文件向模型提出的是/否问题，区别于开放式问题。
- **结构化输出（structured outputs）**：一种模型设置，强制每个答案采用固定格式，以便脚本读取。
- **双重编码（double coding）**：两个人对同一份文件独立回答同一个问题，再讨论其分歧。
- **准确率阈值**：在核对之前设定的、抽样答案必须达到的最低正确比例，达不到就不能使用结果。
- **redistricting 案件**：来源报道中的一种案件类型；团队必须写清楚什么算这一类，因为措辞稍有变化，模型的答案就会不同。
- **SQLite、R**：一种基于文件的小型数据库，以及一种用于统计的编程语言。

## 用智能体搭建

**形态：** `skill`。一位数据记者在对话中完成一次分析，工作是一套固定流程：确定问题、运行脚本、准备抽样。

**需要：** 文本文件形式的案件文件，案件清单已确认；报社 AI 评审委员会的书面批准，保存为文件；一个可返回结构化答案的模型的 API 连接；放在 skill 旁边的一个小脚本，对每份文件运行所有问题，并把答案和每次查询的设置写入 SQLite 文件；抽样之前写好的准确率阈值。不得离开报社系统的文件，不放进模型能够触及的地方。

| 步骤 | 搭建方式 |
|---|---|
| 选题 → 🛑 plan | 见检查点。 |
| 拉取并确认案件清单，扫描原始文件 | 由人和工程师完成。skill 检查清单上的每个案件是否都有文本文件，并列出缺口。 |
| 是/否二元问题集 + 精确定义 ⟲ 提示词测试 | skill 与记者一起起草二元问题和定义，在一小批文件上运行，把答案和原文并排展示，修改到记者认可为止。 |
| 批量结构化输出查询 | 脚本用结构化输出，对每份文件运行每个问题。 |
| 存储答案 + 查询元数据 | 同一个脚本把答案、提示词版本和模型名称写入 SQLite。 |
| 🛑 sample | 见检查点。 |
| 分析 | 智能体根据存好的答案计算计数和随时间变化的比例，且只在达到阈值之后进行。 |
| 发布报道 + 数据方法说明 | skill 根据存好的设置和抽样结果起草方法说明。报道由人撰写并发布。 |

**检查点：** `plan`：一个 `PreToolUse` 钩子在批准文件出现之前拦住批量查询脚本，所以没有批准，运行就无法开始。`sample`：skill 抽取随机样本，为每位记者生成不含模型答案的空白答题表，然后停下。只有每个抽样案件都有两名记者作答之后，它才把他们的答案与模型的作比较，列出分歧交人解决，并对照阈值报告结果。低于阈值时它不会开始分析。

**与来源相比：** 唯一的来源出自 2025-05，其公开实例报道的是 2025 年用 GPT-4o 做的一次分析。2026-11 的一次搜索找到一篇 2026-08 的 IRE 文章，同样主张在发表前用人工标注核对模型的标注 （[IRE, 2026-08](https://ire.org/2026/08/13/using-llms-in-data-journalism-can-be-trustworthy-if-these-five-elements-are-in-your-methodology/)）；没有发现这一做法已被取代。模型是一个变体，可以更换。结构化输出和批量提交是来源用手工方式实现的功能，本搭建方式予以保留。来源的团队有约 20 名员工参与验证，另有两名外部顾问；一个 skill 无法取代这些人。本搭建方式不包含从 PACER 拉取案件和扫描起诉状，来源把这两件事交给了工程团队。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 编辑与数据、调查类编辑一起界定一个问题，该问题需要对大量法院文件做精确的计数和随时间变化的百分比 [[1]](#sources)。
2. 🛑 **计划**：依照 Bloomberg 的生成式 AI 政策，由一个评审委员会在工作开始前批准这次 AI 使用 [[1]](#sources)。
3. 工程师从 PACER 拉取案件，确认案件清单，并扫描起诉状原文，让 LLM 能够读取 [[1]](#sources)。
4. 主笔起草问题。团队用数周时间迭代提示词，选用是/否二元问题而非开放式问题，并确定精确定义（例如，什么算作 'redistricting' 案件）[[1]](#sources)。
5. Python 脚本以结构化输出批量运行查询，使每个答案都按固定格式返回。SQLite 存储答案和查询元数据，R 负责分析 [[1]](#sources)。
6. 🛑 **抽检**：记者对随机抽取的案件独立回答同样的问题，每个案件至少两名记者。对分歧进行审查和讨论，并对照预设的准确率阈值检验结果。约 20 名员工参与 [[1]](#sources)。
7. 报道连同描述 AI 分析的数据方法说明一并发布 [[1]](#sources)。

**产出：** 一个由原始文件构建、经验证的数据集，以及已发布的调查报道和方法说明。
**失败模式 → 防护：** 含糊或开放式的问题会给出无法解析或前后不一致的答案 → 二元问题、精确定义、结构化输出。模型错误扩散到数百份文件 → 发布任何数字之前，先对照预设阈值做随机抽样的双重编码。
**与相近工作流的区别：** AWF-0074 记者笔记改写台是辅助模式，根据记者笔记起草单篇报道。本工作流从数百份原始文件生成数据集，检查点是带双重编码的统计抽样，而不是逐篇草稿的阅读。产出、检查点和自主程度都不同。
