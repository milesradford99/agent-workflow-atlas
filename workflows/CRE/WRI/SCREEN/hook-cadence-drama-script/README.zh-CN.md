# 钩子节奏短剧剧本

**与从故事节拍到分场剧本（Beat-to-scene screenplay）的区别：** 产出是 60–100 集的系列剧，并有一个付费卡点集作为节奏目标，各集以并行的批次起草。
**工具包：** [在 Claude Code 中运行本流程](variants/claude-code.md)
**标签：** 国内上线要经过国家广电总局（NRTA）的分级审核，按投资规模和题材分为三类。平台不得在没有许可证或备案号的情况下承载微短剧 [[14]](#sources)。**输出到：** AWF-0015, AWF-0016.

## 背景

微短剧用 60 到 100 集、每集约 90 秒来讲一个故事，在手机上看，免费开头之后按集付费。这个格式决定了怎么写。每集都要在三秒内用一个能拦住拇指的开场，并以一个让人非看下一集不可的切点收尾；而平台在观众走到卡点之前一分钱不赚，所以第 1 到 10 集和卡点集承载了整门生意。于是制片人从数据入手：头部剧用了什么结尾、卡点放在第几集、反转多久来一次。本工作流把这份研读变成一张钩子表——一集一行，写明结尾钩子类型、标出卡点——然后以 10 集为一批起草，每个提示词都带上上一集的回顾，逐集机械检查钩子、结尾、台词长度和人物预算，最后交给主笔，由他手改开篇集和卡点集。决定有没有人付费的那部分写作留给人；模型提供的是在固定形式下的产量。

**术语：**
- **微短剧**：为手机做的短剧集，每集不到二十分钟，通常 60–100 集。
- **钩子（hook）**：让人停下手指的开场节拍。
- **反转**：新信息把局面翻过来。
- **卡点（paywall point）**：免费观看结束、开始付费的那一集。
- **钩子密度表**：一集一行的表，含事件、结尾钩子类型、付费标记与成本。
- **场次表**：交给制作环节的场景分解表。
- **伏笔（setup and payoff）**：前面埋下、后面用到的细节；条目为两头各记一份台账。
- **备案 / 许可**：国内上线所需的备案或发行许可。

## 用智能体搭建

**形态：** `project`。剧本、钩子表、人物库和连贯性台账要在几十次会话之间留存并保持同一版本——来源里最主要的失效就是模型写过十几集后忘了设定——这需要一个带 `CLAUDE.md` 和技能的仓库，并已提供 Claude Code 工具包。

**需要：** 研读结果以表格形式存在——头部剧早期各集的结尾钩子类型与卡点位置；人物库，每个条目三个字段、不超过 50 字；钩子表与伏笔台账作为受版本管理的文件；检查脚本（长度、句长、场景数、前三秒冲突、结尾截断、红线词）；平台的内容规则，以及这部剧所属的分类。智能体不能在固定的五类之外发明钩子类型，也不能在没有新版本的情况下覆盖已批准的剧集。

| 步骤 | 搭建方式 |
|---|---|
| 研读头部短剧 | 从第三方投放榜单拉数据，由助理把每个结尾归入固定的五类钩子；产出是一张频次表，下一步的论证就从它出发。 |
| 核心设定 | Skill 把创意变成大纲和人物库；`CLAUDE.md` 固定"三字段、50 字"的人物格式，使人物规模小、一眼看得清。 |
| 🛑 plan | 制片人与主笔在任何分集大纲之前选定观众愿意付费的情绪；这个选择被写进钩子表的表头之后才开始起草。 |
| 60–100 集一句话梗概 | Skill 铺出钩子表，标出卡点、标明免费集，并附一份伏笔台账，使每处反转都能追溯到埋它的地方。 |
| 🛑 plan | 制片人、编剧和导演一起读钩子表找薄弱结尾；每集的分场大纲在写整集之前先确认。 |
| 每 10 集一批：起草各集 | 十个一批，每个提示词带上一集回顾和本集任务，剧本旁配连贯性台账；批次大小就是模型记忆上限的显式化。 |
| 每个集：检查 3 秒钩子、结尾悬念、台词长度、人物与场景预算 | 脚本跑机械检查——前三秒冲突、结尾截断、每分钟 180–250 字台词、每句 10–12 字、场景切换不超过三次——让主笔只用读脚本读不出来的东西。 |
| 🛑 review（主笔改写第 1–10 集 + 付费卡点集） | 主笔手改决定收入的那几集，并把最强的反转挪进卡点集；搭建把改写版作为正式版本保存。 |
| 内容规则检查 → 场次表 | 红线扫描加分类核对，然后以带日期的版本名导出场次表和每集卡片。 |

**检查点：** `plan`：两次——大纲之前定付费情绪，任何一集之前定钩子表——因为这两处改起来便宜、发现晚了代价大。`review`：主笔对第 1–10 集和卡点集的改写是编辑关卡，刻意放在钱的位置上；搭建把改写保存为独立版本，于是原稿与改写可对比。

**与来源相比：** 来源出自 2026-07 到 2026-10：一份制片人流程复盘、一篇编剧访谈、一篇杂志报道，以及一个开源 Codex 技能。本轮没有重新打开它们；重新核的是法规。条目标签里描述的分层审核不再是"待落地"：《微短剧发展管理办法》[自 2026-09-01 起施行](https://www.news.cn/20260731/9d0579e4587648fb83580e0fec008e12/c.html)，含按投资与题材的三级分类、备案与许可制度、十一条内容红线，以及生成内容每集加 AI 标识。这让内容规则检查成为合规步骤而不是预防措施，并且应当针对这部剧的分类来执行——分类在制作前就该定，而不是等到送审。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 先研究市场再选故事：从第三方数据平台（该制片人用新红和灰豚）拉取近 7 天投放量前 50 的短剧，记录第 1–5 集各自的结尾钩子类型，以及付费卡点集的情绪高点。由助理在 Excel 里给钩子打标签（身份反转、情感绑架、生死危机、打脸爽点）并统计频次 [[15]](#sources)。
2. 搭建核心设定。AI 把故事创意转成思维导图和大纲 [[16]](#sources)。人物表每个不超过 50 字，分三个字段（身份标签、核心软肋、触发动作），存放在飞书多维表格的人物库里 [[15]](#sources)。人物规模要小，关系一眼就能看清 [[18]](#sources)。
3. 🛑 **计划**：在给任何一集写大纲之前，制片人和主笔先选定观众愿意付费的情绪（例如主线选虐渣复仇而不是母子相认）[[15]](#sources)。
4. 在钩子密度表里按每集一行铺排全剧（集数、事件、从五个固定类别中选的结尾钩子类型、付费标记、预估成本、备注）。第 1–3 集免费，必须以强悬念收尾；第 8–12 集是常见的付费卡点，并高亮标出 [[15]](#sources)。再加一张分段高潮表和一张伏笔登记表（每个伏笔在哪里埋下、在哪里回收）[[18]](#sources)。
5. 🛑 **计划**：制片人、编剧和导演一起读钩子表，找出薄弱的结尾。让模型给出每集的分场大纲，并在写整集之前先确认 [[15]](#sources) [[18]](#sources)。
6. 以 10 集为一批起草。每个提示词都带上前一集的回顾和本集的任务，否则模型写过十几集后就开始忘记设定；每写完 10 集，检查主悬念是否仍在上升 [[18]](#sources)。一个开源的 Codex 技能把这一步做成 `/分集规划 1-10` 和 `/连写 1-10`，并带有跨集连贯性台账 [[19]](#sources)。
7. 检查每一集：前 3 秒出现冲突、在结尾钩子处截断、每分钟台词约 180–250 字、每句 10–12 字，通过朗读来计时 [[15]](#sources)；每集场景切换不超过 3 次 [[18]](#sources)。同一技能还附带脚本，检查时长、台词长度、场景数、前 3 秒冲突、结尾截断和红线词 [[19]](#sources)。
8. 🛑 **审阅**：主笔改写第 1–10 集和付费卡点集。台词、关系的微妙之处和爽点的时机仍由人来把握 [[16]](#sources)，最强的反转放进付费卡点集 [[15]](#sources)。
9. 做内容规则检查，然后导出场次表和每集卡片（钩子类型、字数、关键画面），使用带日期的版本名 [[15]](#sources)。平台先过 AI 审核再过人工审核；一家公司的 AI 短剧有近 70% 未通过，多数是因为暴力内容或人脸逐渐变得像某位名人 [[17]](#sources)。国内上线还需要 NRTA 备案或许可 [[14]](#sources)。

**产出：** 一份 60–100 集的剧本，附钩子表、场次表和各集卡片，交给制作环节（AWF-0015 或 AWF-0016）。用于 AI 制作的剧本需要更多的场景和人物描述，大约 5万至 8万字 [[17]](#sources)。
**失败模式 → 防护：** 薄弱的结尾被拿去做广告素材，点击率崩掉 → 表里每个结尾都要有明确的钩子类型 [[15]](#sources)。观众在付费卡点前流失 → 先拍第 1–5 集，做小规模投放测试，把一个反转提前一集（ROI "回升了0.2左右"）[[15]](#sources)。模型在剧集中途忘记设定 → 每个提示词都带回顾和本集任务，并每 10 集检查一次 [[18]](#sources)。编剧和分镜师用的不是同一版本 → 一份共享文档加版本命名规则 [[15]](#sources)。产出更快但质量没有提升（"产能确实提高了，但质量未必提高"）→ 台词和爽点时机由人把握 [[16]](#sources)。审核被拒 → 提交前先筛查暴力内容和人脸漂移 [[17]](#sources)。
