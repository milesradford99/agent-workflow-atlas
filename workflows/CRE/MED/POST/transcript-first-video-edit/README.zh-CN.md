# 先文稿后剪辑的视频制作

**工具变体：** `descript-whisper-remotion-claude-code` · `premiere-text-based-editing`

## 背景

对着镜头说话的人——老师、创始人、YouTuber——录了一小时，需要其中二十分钟成片：重拍剪掉、空白剪掉、每个字都有字幕、标题条和片尾是台里的样式。剪辑软件把这件事变成手工活：拖、剪、摆、再听一遍。本工作流从文字开始。素材先转成文字稿，稿子当文档来编辑，删掉的句子就是剪掉的部分。然后智能体把技术步骤写成代码——提取和混音、把人声下垫上配乐、把每句字幕卡到对应的词、画出叠层——作者要改的时候几分钟就能重渲。作者保留两个文字稿做不了的判断：留哪些话，因为那是视频在讲什么；以及最后的通看，因为重复的句子或错位的字幕，只有从头看一遍才看得见。其余部分是一套作者自己拥有、还可以继续扩展的工程。

**术语：**
- **文字稿优先剪辑（transcript-first editing）**：靠删文字来剪视频，于是片子跟着文档走而不是跟着时间线走。
- **重拍（take）**：同一段话的一次尝试；通常只留最后一次。
- **语气词（filler word）**："嗯""那个""怎么说呢"——要有选择地删，因为有些带着意思。
- **逐词时间戳（word-level timing）**：每个说出的词有起止时间，字幕和跟词动的图形都靠它。
- **Remotion**：用 React 组件渲染视频的框架，于是"一次剪辑"就是可以版本管理、可以重跑的代码。
- **下三分之一字幕条（lower third）**：画面下方的人名或标题条。
- **渲染（render）**：把合成结果输出成最终的视频文件。
- **通看（watch-through）**：从头到尾、按速度播放导出的文件，作为最后一道检查。

## 用智能体搭建

**形态：** `project`。一位作者剪一条素材，但价值在那些固定资产上——品牌组件、转写词典、渲染脚本——它们要被反复复用，而且在每条视频上表现一致，这就需要一个带 `CLAUDE.md` 和仓库的项目，而不是一次性的 skill 调用。

**需要：** 录制素材，以及带逐词时间戳的文字稿；一个装了 Remotion 的 Node 工程，以及智能体可用的 ffmpeg；品牌资产——字体、颜色、标识、下三分之一组件、片头片尾；有授权的配乐；一份说讲者行话如何拼写的词典，因为转写一定会把人名写错；以及版本管理的习惯，因为每次剪辑都是一次代码改动。智能体不需要发布权限：上传由作者完成。

| 步骤 | 搭建方式 |
|---|---|
| 导入录制素材 | 素材放进工程目录并纳入版本管理；`CLAUDE.md` 写明输出格式、帧率和命名，于是每条视频都以同样的方式开工。 |
| 编辑文字稿（剪掉重拍和跑题内容） | Skill 把文字稿当文本处理并给出确切的删减位置；它只提方案、不做决定，因为删掉的词从成片里找不回来。 |
| 🛑 review（作者确认内容剪辑） | 作者读标好的稿子，删掉或恢复段落；删减清单是一个文件，所以这个决定可见、可回退。 |
| 收紧停顿和语气词 | 脚本执行作者定的规则——超过阈值的停顿、语气词清单、保留清单——而不是由智能体逐个判断每处停顿。 |
| 智能体编写 ffmpeg 音频提取和配乐混音 | 由智能体编写并运行的 ffmpeg 命令，配乐以固定偏移量与人声混合并淡入淡出，于是混音可复现，而不是靠耳朵调。 |
| 逐词 Whisper 文字稿 | 对"实际导出的文件"转写，而不是对源文件，因为代理文件的时间轴扛不过这次剪辑。 |
| 智能体构建 Remotion 字幕和叠层 | 仓库里的组件，由时间戳 JSON 驱动；词典脚本在渲染前修好人名，而这些组件正是可复用的部分。 |
| 预览 ⟲ 智能体修复 | 作者在预览器里看，用话描述要改什么；智能体改组件并重渲——这就是替代拖时间线的循环。 |
| 🛑 review（预览） | 作者在正式渲染前确认观感，因为渲染是最慢的一步，而错误的图形提前改很便宜。 |
| 渲染 → 🛑 sign-off（1.5 倍速通看） | 先渲染，再由作者按速度完整通看一遍，查重复句子、字幕错误、配乐错位和图形不匹配。 |

**检查点：** `review`：两道关卡都是作者的，而搭建让它们变得便宜而不是可选——删减清单是一个可以改的文件，预览是一个浏览器窗口。`sign-off`：通看是唯一能抓住前面检查抓不到的毛病的一步，所以"渲染成功"不能算完成；渲染的退出码只说明文件生成了，不说明它对。

**与来源相比：** 来源出自 2026-04：一份 8 周个人制作的记录，本月已打开，也是本条目的公开实例。此后有这些变化：胶水层开始被产品化。Remotion 现在发布了自己的智能体技能，作者当初要自己建立的组件约定和动画规则，如今[安装进工程后由智能体在每次会话中读取](https://www.claudiva.com/guides/edit-video-claude-code/)，而一句"删掉所有嗯啊、剪掉超过 0.6 秒的停顿、加上逐词字幕"就足以产出第一版成片。也有更进一步的打包技能，直接从脚本生成画面。这把本搭建的工作从"写组件"变成"挑选组件"：值得留在自己仓库里的是品牌组件、词典和通看的纪律，因为正是这些让产出属于你而不是泛泛之物。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 把原始素材导入 Descript，把文字稿当作文本来编辑，删掉重复、跑题和失败的重拍。🛑 **审阅**：每一处内容剪辑都由作者决定（每段 30 分钟的录制约需 8 分钟）[[1]](#sources)。
2. 把超过 0.2 s 的字间停顿缩短，有选择地删除语气词，然后导出一份干净的、仅含说话人的 MP4 [[1]](#sources)。
3. Claude Code 编写并运行 FFmpeg 命令，提取单声道 16 kHz 音频，并在说话人声音之下混入有授权的配乐，带淡入淡出 [[1]](#sources)。
4. Whisper API 以 JSON 输出逐词时间戳。一个词典脚本修正专业术语的拼写错误，渲染前还要肉眼检查字幕 [[1]](#sources)。
5. Claude Code 构建 Remotion（React）组件，由该 JSON 驱动动画字幕，另有可复用的下三分之一字幕条、片头和片尾 [[1]](#sources)。
6. 🛑 **审阅**：作者在 Remotion Studio 中预览，并向 Claude Code 描述需要的修改，由它修改组件，直到预览满意，然后渲染 [[1]](#sources)。
7. 🛑 **签发**：必须以 1.5 倍速完整通看一遍，查出重复的句子、字幕错误、配乐错位和图形不匹配 [[1]](#sources)。

**产出：** 一个带字幕和品牌图形的最终 MP4，可直接上传到 YouTube 或社交平台。
**失败模式 → 防护：** 文字稿来自代理文件时出现时间偏移 → 对实际导出的文件重新转写。字幕中专业术语拼错 → 词典脚本加字幕检查。重复的句子在剪辑后仍然留存 → 最后的通看。
**与相近工作流的区别：** AWF-0015 AI 镜头工厂生成的是全新的视频镜头。本工作流剪辑的是真实录制的素材，内容上的取舍由人负责。
