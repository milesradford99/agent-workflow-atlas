# 编辑精选的直播切片

**工具变体：** `framedrop` · `mediacorp-ai-smartcut`

## 背景

一档节目同时也是一批短视频的来源：一条报道、一段访谈、一次精彩的交锋，就是社交平台上会被看完的东西，而且必须在节目还有人讨论的时候发出去。总得有人看完一整档新闻，判断哪些片段能独立成立，把它们剪到脱离上下文也说得通，重新排成竖屏，写好标题再发布。这对几条短片来说是几个小时的活，而且发生在一天里编辑部人手最紧的时候。在这里，切分在节目播出的同时就做了：系统跟着语音和画面找出一个故事在哪里结束、下一个在哪里开始，把导语和它对应的专题片或访谈放在一起，切出每个片段、转成竖屏、附上元数据。节目结束后，编辑打开一叠预先剪好的片段，挑出值得发的，修一修字幕和标题，发布。这道复核不是形式：把一句引语切断了就是更正或投诉，竖屏版把人的脸裁出画外就没法用，所以这两个判断都留在编辑手上。

**术语：**
- **新闻档（bulletin）**：一档排定的新闻节目，直播或录播。
- **片段（segment）**：节目里的一条报道或一段讨论，有起点和终点。
- **专题片（package）**：新闻档里插播的预录报道。
- **竖屏化（verticalise）**：把 16:9 画面改成 9:16 手机屏，通常意味着跟着主体取景，而不是裁中间。
- **元数据（metadata）**：CMS 与社交平台需要的标题、描述、标签和时长。
- **断章取义（out of context）**：剪出来的片段让人以为说话者讲了完整片段其实并不支持的内容。
- **重构图（reframing）**：把宽画幅自动跟随主体裁成竖屏的过程。

## 用智能体搭建

**形态：** `platform`。切分、重构图和竖屏渲染是在直播信号上跑的语音与视频模型工作，通用智能体跑不了；智能体负责的是元数据、字幕文本、队列，以及编辑用来复核的那张清单。

**需要：** 带时间码的播出信号；一个用语音和画面做切分的模型或服务，以及把导语与其专题片配对的规则；一步能产出竖屏文件的重构图与渲染；CMS 与社交平台账号，发布权限留在编辑手上；节目的串联单（如果有），那是最强的切分信号。搭建不能自行向任何社交账号发布，编辑的修剪决定必须能覆盖自动边界，而不是反过来。

| 步骤 | 搭建方式 |
|---|---|
| 接入直播节目 | 直播或文件按时间码采集，于是每个片段都能指回节目自己的时钟。 |
| 按语音和画面线索切分（配对导语与专题片/访谈） | 切分服务找边界；只要编辑部有串联单，串联单覆盖模型的判断，每个片段都带上"为什么切在这里"的理由。 |
| 每个片段：剪辑 + 竖屏化 + 元数据 | 渲染服务负责切与重构图；智能体依据转写写标题、字幕文本和标签，并标出重构图把说话人裁出画面的片段。 |
| 🛑 review（编辑在节目结束后挑选、剪辑，并修正字幕/标题） | 编辑队列展示预剪片段、转写和标记清单；挑选、修剪与发布都是 CMS 里的动作，本搭建对它只有读权限。 |
| 发布到网站、应用、TikTok/Instagram/YouTube | 由编辑逐渠道发布；搭建记录发了什么、发到哪里，好让表现能与节目本身对比。 |

**检查点：** `review`：没有编辑就什么都发不出去，而发布凭据属于编辑自己的账号，不在流水线里。搭建的任务是让这次复核既快又不糊弄：每个片段都带着转写、切在这里的理由，以及自动重构图或音频需要留意处的标记——来源明确指出仍需要人处理的就是这些。

**与来源相比：** 来源出自 2025-08，另有一份未注明日期的厂商故事；两者本月均已打开。此后有这些变化：本条目所选的检查点已经变成厂商主打的说法。2026 年的直播切片平台把自动找时刻与人工决定这一步配对，并且明说——其中一家卖点是"AI 找时刻，发布什么由你决定"，还内置竖屏重构图与一键发布到社交账号。这并不改变这里的形态，改变的是自建的成本，也让一个未决问题更清楚：编辑的工作从"剪"变成"选"，于是产能上限变成一个人能多快判断一队预剪片段，而不是一个编辑能剪多少条。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 在节目或黄金时段新闻播出时接入直播信号 [[1]](#sources)[[2]](#sources)。
2. 系统根据语音和画面线索，把节目切分成不同的讨论或报道，并把导语与对应的专题片或访谈配对 [[1]](#sources)[[2]](#sources)。
3. 每个片段被剪成一条短片，自动转为适合社交平台的竖屏，并附上元数据，可直接进入 CMS [[1]](#sources)[[2]](#sources)。
4. 🛑 **审阅**：节目结束后，编辑团队审阅预先剪好的片段，挑选最好的并发布。在 Mediacorp，音频优化和动态重构图仍需要人工把关 [[1]](#sources)[[2]](#sources)。
5. 在节目结束后数分钟内发布到网站、应用和社交渠道 [[1]](#sources)[[2]](#sources)。

**产出：** 直播结束后不久，在网页、应用和社交平台上线的按报道或按精彩时刻划分的短片。
**失败模式 → 防护：** 片段边界切错（Mediacorp 报告准确率约 90%）→ 发布前由编辑审阅 [1]。重构图和音频问题 → 这些环节由人把关 [1]。某句话被断章取义 → 每条短片都由人挑选并剪辑 [2]。
**与相近工作流的区别：** 最接近的是 AWF-0138（自主直播综述）。那个工作流把体育综述直接发布到 CMS，人只在事后抽查表现。这里每个新闻或访谈片段在发布前都由编辑审阅并挑选，所以检查点和自主程度（分段）都不同。AWF-0077 是与作者一起根据文字稿剪辑一段录制内容，而不是处理直播流。
