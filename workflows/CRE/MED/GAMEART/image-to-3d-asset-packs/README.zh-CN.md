# 图生 3D 资产包

**工具变体：** `meshy` · `tripo` · `zbrush` · `blender` · `substance-painter`

## 背景

一个 3D 游戏资产，比如一辆车、一件道具或一个角色，由表面网格、把表面展开成平面以便绘制的 UV 图，以及表面贴图构成。手工制作一个要花美术师很长时间，而向其他开发者出售资产包的工作室需要几十个风格一致的资产。这里由图生 3D 的生成模型根据概念图建出第一版非常精细的模型，美术师决定哪些结果值得保留，再把它们修整到游戏引擎所需的标准。智能体可以准备参考图表、记录哪些生成结果被保留或淘汰，并整理装配清单。几何体由模型生成，由美术师批准，因为生成的网格常常结构有问题，只有美术师才能判断一个模型是否干净到可以放进资产包出售。

**术语：**
- **图生 3D（image-to-3D）**：根据同一物体的一张或几张图像建出 3D 模型的生成模型。
- **多视图概念图**：从多个角度（正面、侧面、背面）画出的物体，没有透视畸变，用作 3D 生成的输入。
- **高模（hi-poly）**：表面多边形数量极多、非常精细的模型；对游戏来说太重。
- **重拓扑（retopology）**：把高模的表面重建成游戏引擎能运行的干净、轻量的网格（低模）。
- **UV 图**：把模型表面展开后的平面布局，贴图就绘制在上面。
- **PBR**：基于物理的渲染，一组贴图（颜色、粗糙度、金属度等），让表面在任何光照下都看起来正确。
- **烘焙（baking）**：把高模的细节复制到低模的贴图上。
- **预制件（prefab）**：在游戏引擎里装配好、可重复使用的现成物体。
- **Unity / Unreal**：两种常用的游戏引擎。

## 用智能体搭建

**形态：** `platform`。几何体来自图生 3D 生成模型，后期修整来自 3D 雕刻和绘制工具，通用智能体替代不了。通用智能体可以以 `skill` 的形态承担准备和记录工作，因为一位美术师一次处理一个资产。

**需要：** 资产包的参考图；工作室所用图像生成和图生 3D 服务的账号；3D 工具（雕刻工具、网格编辑器和贴图绘制工具），由美术师操作；每个资产一份日志文件；使用每张参考图的权利。不要把他人未授权的模型送进这些服务。

| 步骤 | 搭建方式 |
|---|---|
| 参考资料 → 草图（美术师 + 2D AI） | 美术师画草图。skill 收集并命名参考资料，列出每个资产需要的视图。 |
| 无透视畸变的多视图概念图 | 在 2D 图像工具里生成。skill 为每个视图写提示词，并检查正面、侧面、背面是否齐全。 |
| 每个资产：(图生 3D 高模 ⟲ 重新生成) | skill 旁边的脚本把各视图提交给图生 3D 服务，并把每次生成连同设置一起保存。 |
| 🛑 review (美术师保留或淘汰) | 见“检查点”。 |
| ZBrush 清理 → 重拓扑 + UV → 贴图 | 由美术师在 3D 工具里完成。skill 记录哪些被保留，以及每个资产还需要什么。 |
| 🛑 review (美术师收尾拓扑/UV/外观) | 见“检查点”。 |
| 渲染 + Unity/Unreal 装配 | 美术师和引擎。skill 起草资产包的资产和预制件装配清单。 |

**检查点：** `review`：每批生成之后，skill 把结果与概念图并排做成一张表，然后停下，直到美术师把每一个标为保留或淘汰；淘汰的重新生成，保留的继续往下走。最后 skill 再停一次，给出每个资产的拓扑、UV 和外观清单；由美术师在 3D 工具里收尾并签发。智能体对资产包文件夹和引擎项目都没有写入权限。

**与来源相比：** 唯一的来源和唯一的公开实例出自 2026-10，因此无需查找更新的记载。本次会话中两个页面都无法打开（网站拒绝了请求），所以条目正文是这些步骤仅有的依据。来源描述的是美术师使用具名的生成服务和 3D 工具，没有描述由智能体来运转这个流程。这套搭建方式只增加了准备和记录，生成和修整仍由工具和美术师完成。`variants` 下的服务和工具名称变化很快，使用前请先核对。

## 步骤

*以下按来源所述。*

1. 美术师收集参考资料，然后手绘草图，或用 2D AI 模型（通过 Fal）生成草图 [[1]](#sources)。
2. 美术师准备无透视畸变、专为 3D 生成而做的多视图概念图 [[1]](#sources)。
3. Meshy 用 Image-to-3D 或 Multi-Image-to-3D 构建高模，按需重新生成 [[1]](#sources)。
4. 🛑 **审阅**：美术师筛选生成结果。约 20–30% 到不了生产环节，约 30% 还需要多轮调整，角色大约有 60–70% 的情况需要重新生成 [[1]](#sources)。
5. 美术师在 ZBrush 中清理高模。Meshy 的重拓扑提供一个起点，美术师在 Blender 或 TopoGun 中收尾，AI 助手承担一部分常规 UV 工作 [[1]](#sources)。
6. 美术师的贴图从 Meshy 生成的 PBR 贴图开始。复杂资产在 Substance Painter 中手工处理 [[1]](#sources)。
7. 🛑 **审阅**：凡是需要精确的地方，美术师手工完成拓扑、UV 和最终外观，然后做最终渲染，并在 Unity 或 Unreal 中装配 [[1]](#sources)。

**产出：** 带烘焙 PBR 的可直接用于游戏的低模资产，打包成适用于 Unity 和 Unreal 的资产包。
**失败模式 → 防护：** 汽车和复杂角色的拓扑差、UV 凌乱 → 美术师手工重建。角色的保留率低 → 多视图概念图加多轮重新生成，并由美术师筛选。
**与相近工作流的区别：** AWF-0079 概念图驱动的 SD 资产流（Concept-led SD asset stream）用自训练模型，根据美术师的概念图制作 2D 资产。本工作流产出带重拓扑、UV 和烘焙的可入引擎 3D 网格，并为生成结果增加了保留/舍弃的筛选环节。产出不同，多出的检查点也不同。
