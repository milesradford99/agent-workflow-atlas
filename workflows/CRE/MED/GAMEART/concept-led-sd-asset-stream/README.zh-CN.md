# 概念图驱动的 SD 美术资产

**工具变体：** `stable-diffusion-controlnet`

## 背景

游戏需要大量 2D 图片：可收集的卡牌、装饰、背景。通常由概念美术师设计每一张，再由其他美术师渲染，一套下来要好几天。这里由一个用游戏自身美术风格训练过的图像生成模型，根据美术师的概念图、草图或粗糙的 3D 模型，生成每个资产的第一版，再由美术师在上面重绘，直到达到工作室的标准。只靠文字提示词，模型的输出难以预测，还会出现结构错乱、风格走样之类的瑕疵，所以先由美术师给出概念图，最后由美术师批准。智能体可以准备训练集、记录设置和批次，并对照说明检查输出；图片本身来自图像模型，而是否达到游戏的要求由美术师决定。

**术语：**
- **Stable Diffusion**：一种开源图像生成模型，可以安装在工作室自己的机器上，并用自己的图片继续训练。
- **微调 / 定制模型**：用工作室的美术作品继续训练，让模型画出游戏的风格。hypernetworks 和 embeddings 是这类的两种小型附加件。
- **img2img**：从一张已有图像出发生成新图，从而固定构图。
- **去噪强度**：img2img 可以偏离起始图像多远；数值低则贴近起始图。
- **ControlNet**：一种附加件，让模型跟随引导图里的姿势、轮廓或深度布局。
- **局部重绘（inpainting）**：只重新生成图片中被标出的部分。
- **3D 白模（blockout）**：由简单几何体搭成的粗糙 3D 场景，用来固定机位和构图。
- **放大（upscaling）**：放大图片并补充细节。

## 用智能体搭建

**形态：** `platform`。图片来自用工作室风格训练出的图像模型，通用智能体替代不了。通用智能体可以以 `skill` 的形态承担准备和记录工作，因为一位美术师一次处理一个资产，并且全程在对话中。

**需要：** 工作室自己的美术作品（并有权用于训练）作为风格数据集；图像模型及其训练工具的本地安装；每个资产的概念图、草图或 3D 白模；说明目标的简报（尺寸、风格、画面必须包含什么）；存放生成候选和美术师重绘稿的文件夹。

| 步骤 | 搭建方式 |
|---|---|
| 选定工具 + 准备风格数据集 | skill 检查数据集有无重复，用美术师的用语为每张图写标注，并列出缺什么。工具由人来选。 |
| 训练定制模型 | 由脚本运行训练。skill 记录每次训练的设置和一张样图表，以便比较各次训练。 |
| 🛑 plan (美术师的概念图) | 见“检查点”。 |
| 每个资产：从概念图、草图或 3D 白模出发做 img2img/ControlNet → 放大 | skill 旁边的脚本按 skill 为该资产类型记录的设置提交生成，然后运行放大。 |
| (美术师调整 ⟲ 达到目标) | 美术师在图像编辑器里对输出重绘。skill 对照简报的尺寸和内容清单检查结果，记下还缺什么。 |
| 🛑 review (美术师批准) | 见“检查点”。 |

**检查点：** `plan`：在美术师的概念图、草图或白模放入项目文件夹、并且美术师说开始之前，skill 不会为该资产排队生成。`review`：skill 把完成的资产与其概念图和简报并排展示，然后停下；由美术师批准或退回。智能体没有把资产复制进游戏美术文件夹的工具，所以只有美术师才能把批准的作品放进去。

**与来源相比：** 来源 1 出自 2023-07，来源 2 没有日期。社区指南里报道的较新做法：一份 2026 年的独立开发者指南说，基于节点图的界面 ComfyUI 是串联模型、ControlNet 和放大器的常见方式，并说最后的修整仍然需要人（[Stray Spark Studio](https://www.strayspark.studio/blog/comfyui-game-asset-pipeline-indie-2026)）；一份 2025 年的工作室报告发现，要得到可用的输出，定制训练是必要的（[Room 8 Group](https://room8group.com/wp-content/uploads/2025/01/AI-in-2d-gam-dev_-Report_final.pdf)）。两者都是第二手的说法，不是对这个工作流的重新运行。来源报道的是由美术师主导、配有内部 AI 部门的流程，而不是由智能体来运转，所以这套搭建方式只增加了准备和记录。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 团队选择支持微调和局部重绘（inpainting）、并可本地安装的工具（Stable Diffusion）。为每个新的美术系列准备数据集（几个小时），并训练定制模型；团队训练了 100 多个（hypernetworks、embeddings）来找到有效的参数 [[1]](#sources)。
2. 由专门的内部 AI 部门负责工具分析、训练、流水线集成和对美术师的支持 [[1]](#sources)。
3. 🛑 **计划**：先由美术师做出详细的概念图，因为只靠文字提示词的结果难以预测 [[1]](#sources)。
4. 团队用 img2img 从概念图出发生成。场景元素可以从草图加文字开始，背景可以从基础 3D 模型出发，用低去噪强度（最高 0.4）和/或 ControlNet 来确定角度和构图。细节复杂或带动画的物体按部件分别生成 [[1]](#sources)。
5. 团队放大后，美术师手工修整，直到资产达到目标。🛑 **审阅**：美术师批准或重做输出；一份类似的复盘提到美术师拥有“艺术否决权”（'artistic veto power'）[[1]](#sources)[[2]](#sources)。

**产出：** 2D 游戏资产（可收集的卡牌、装饰、背景），交给游戏的美术集成环节。
**失败模式 → 防护：** 结构瑕疵和风格不一致 → 美术师在上面重绘、融合并拼接多次生成的结果，同时用风格训练过的模型保持外观一致。只靠提示词的输出不可预测 → 始终从概念图、草图或 3D 输入出发。
**与相近工作流的区别：** AWF-0015 AI 镜头工厂为短剧制作视频镜头。AWF-0008 设计到代码针对的是 UI。游戏资产方面没有相近的工作流。
