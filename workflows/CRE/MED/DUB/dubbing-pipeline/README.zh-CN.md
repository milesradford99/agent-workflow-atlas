# 配音译制流水线

**标签：** 出海应用。2025 年第一季度，ReelShort 和 DramaBox 的应用内购买收入分别约为 $130M 和 $120M [[18]](#sources)。厂商宣称的 AI 配音吞吐量（例如 "120 minutes in 4–5 hours"）属于证据 B，未经核实。

## 背景

配音就是把视频里的口语换成另一种语言，由新的演员或合成声音来念，再加上字幕。短剧是分集讲述的连续故事，每集一两分钟，在手机上观看；出海应用把它们卖给海外观众。一部剧可能长达上百集、几十个角色，要手工配成多种语言，既慢又贵。直译还会出观众一眼就能看出的错：称谓被译成了错误的关系，笑话或文化典故让人看不懂，或者一句台词太长，装不进演员的口型。智能体负责转写、术语表、翻译、把每句台词适配到时间段，以及生成声音。母语者仍要检查结果，发布前仍要由人签发，因为误译或文化禁忌会直接到达付费观众面前，由发行方负责。

**术语：**
- **ASR**：自动语音识别，把语音转成文字的软件。
- **说话人分离（diarization）**：在多人说话的录音里，弄清每句台词是谁说的。
- **术语表与文化注记**：针对一部剧，列出每个人名、称谓、地点、货币、单位和习语在各目标语种里的译法。
- **敬语（honorifics）**：体现关系或地位的称呼形式（例如日语的礼貌等级）。
- **台词适配**：缩短或改写译文，使其以自然语速念出来时，正好落在原台词占用的时间里。
- **声音克隆（TTS）**：根据几段参考音频模仿某个角色声音的文字转语音。
- **口型同步**：调整画面或音频，使嘴型与新语言对上。
- **SRT**：带时间的纯文本字幕文件。
- **闪避（ducking）**：有人说话时压低背景音乐。
- **译后编辑**：由人来修改机器翻译。
- **质检（QA）**：这里指母语者通听一遍。
- **IAP**：应用内购买，即观众在应用内花的钱。

## 用智能体搭建

**形态：** `platform`。声音和口型同步来自语音和视频模型，通用智能体替代不了。通用智能体可以以 `project` 的形态承担剧本、术语表和翻译步骤，因为多个语种要并行处理，而且有两条规则每次都必须成立：没有人就不能发布，以及固定的台词长度上限。

**需要：** 剧集视频文件，有剧本的话也要；语音识别服务、声音生成服务和口型同步工具的账号；每个角色的参考音频，并拥有克隆它们的权利；客户的交付规格（语种、字幕格式、审核要求）；每个语种的母语审阅人。未经客户批准，不要把未发布的剧集放进服务里。

| 步骤 | 搭建方式 |
|---|---|
| 剧集 + 剧本 → 说话人分离的 ASR 与剧本对齐 | skill 旁边的脚本运行语音识别服务。skill 把文本与剧本对齐，并建立角色名册。 |
| 每部剧的术语表 + 文化注记 | skill 根据名册和各市场的规则写出术语表文件；后面的步骤查它，而不是猜。 |
| 🛑 plan | 见“检查点”。 |
| 每个语种：(翻译 ⟲ 适配台词时长) | 每个语种一个子智能体，对照术语表翻译。脚本测量每句台词的时长，把超时的退回去改写。 |
| 声音克隆 TTS → 口型同步 → 字幕 | 由脚本调用声音生成和口型同步服务。skill 写出 SRT 文件和配乐混音清单。 |
| 🛑 sample → 🛑 sign-off → 发布 | 见“检查点”。 |

**检查点：** `plan`：skill 把语种清单、交付规格、名册、声音参考和审核要求写入文件，然后停下，直到客户联系人批准。`sample`：母语审阅人完整收听第 1 至 10 集，之后抽检；智能体把这些文件放进他们的队列，审阅人通过之前不进入下一批。`sign-off`：智能体没有上传或发布的工具，所以由人从平台自己的界面发布每个语种。

**与来源相比：** 来源和公开实例出自 2025-04 至 2026-10，都在最近 12 个月内，因此无需再查找更新的记载。它们描述的是一条自建的流水线（来源 19）、一家厂商的服务（来源 20）和行业报道（来源 21），这些都用微调模型加人工审核来做这些步骤。上面的搭建方式是为通用智能体做的设计，并不复现它们的模型。口型同步不在 Dashverse 的流水线内；它出现在这里，只是因为行业报道提到了相关工具。条目标签行里厂商宣称的吞吐量未经核实。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 流水线从剧集反推出剧本。Dashverse 把语音转文字、语音活动和视觉信号连同视频一起喂给多模态 LLM，分块处理全剧，并在各块之间对齐角色身份。它还会标注每句台词的情绪和非语言声音，并建立全剧的角色名册（年龄、性别、角色、别名、称谓）[[19]](#sources)。剧本缺失或杂乱时，先清洗并规范化文本 [[20]](#sources)。
2. 团队建立每部剧的术语表和文化注记：本地化的角色名、称谓、地点、货币、单位和习语，每项都结合上下文做映射，让翻译去查词条而不是猜 [[19]](#sources)。再加入各市场的规则，例如日语的敬语等级、拉美的亲属称谓和阿拉伯市场的敏感内容 [[20]](#sources)。
3. 🛑 **计划**：批量工作开始前，团队与客户商定目标语种、交付规格、角色名单、声音参考、字幕格式、审核要求和上线排期 [[20]](#sources)。审阅人仍然可以对翻译、人名和选角进行把关 [[19]](#sources)。
4. 流水线对每个语种先翻译，再把每句台词适配到对应的时间段。Dashverse 把台词路由到按语种、按语体微调的模型，并通过改写过长的台词来避免把音频加速超过 1.15×；在一个中译印地语的样本中，首次生成的中位时长是时间段的 1.45×，最终采纳版本是 1.02× [[19]](#sources)。Transn 的译后编辑人员检查语义、自然度、角色声音和台词长度 [[20]](#sources)。
5. 流水线给台词配音。Transn 根据几段参考音频克隆每个角色的声音 [[20]](#sources)。Dashverse 则从约 3,000 个人工标注的预置声音中选角，因为克隆会带上口音和误读，并使用 `[whispers]` 或 `[sobs]` 这样的动作标签，而不是抽象的标签 [[19]](#sources)。
6. 流水线做同步、混音和字幕：时长预测和音视频同步 [[20]](#sources)；重新混入背景音乐，并在对白下做闪避，生成 SRT 字幕 [[19]](#sources)。Dashverse 的流水线不含口型同步；行业报道中提到了 Heygen 等口型同步工具 [[21]](#sources)。
7. 🛑 **抽检**：母语者质检。流程设计的计划是第 1–10 集全检，之后抽检。被引用的团队检查得更多：Dashverse 审阅每一部剧，约 95% 的说话人标签、89% 的翻译台词和 96% 的选角保持生成时的样子 [[19]](#sources)；Transn 的 AI 审核会标出漏译、人名不一致、敏感措辞、同步和音频问题，低置信度的那部分（约 15%）由人处理 [[20]](#sources)。
8. 🛑 **签发**：交付前由人复查，即使没有任何改动也不能跳过 [[21]](#sources)。团队为这部剧选定交付档位（快速预览、社交媒体，或带人工精修的高端应用版）[[20]](#sources)，然后发布。

**产出：** 每个语种的已配音、混音并带字幕的剧集，以及术语表、声音设置和审核规则，供同类型的下一部剧复用 [[20]](#sources)。
**失败模式 → 防护：** 在有 20–40 个角色的长剧中，说话人分离的效果会下降 → 集成标注加跨块对齐；审阅人重新标注了 5.2% 的台词 [[19]](#sources)。直译会改变剧情（oppa 被译成 bhaiya，彩票奖金额被缩小）→ 翻译前先建好术语表和角色名册 [[19]](#sources)。模型在泰米尔语和泰卢固语里默认用书面语体 → 用约 340,000 行自有对白微调 [[19]](#sources)。台词太长 → 改写以适配；只在很窄的范围内加速 [[19]](#sources)。误译或文化禁忌（"臣妾做不到啊" 被译成一个干不了活的女仆）→ 强制人工复查 [[21]](#sources)。某个市场的敏感表达 → AI 标记加人工文化审阅 [[20]](#sources)。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。来自 [Where are the real runs?](../../../../../research/2026-11-real-runs.md)；每个数字都已对照原页面复核。

- [Goel & Tetali, Dashverse](https://insiders.dashverse.ai/building-an-ai-dubbing-pipeline-for-micro-dramas/) (2026-10-12)。说话人分离重建剧本 → 每部剧的术语表 → 适配时长的翻译 → 选角 TTS → 人工审阅每一部剧。"about 1,400 hours of micro-dramas across 16 languages"；审阅人保留了 "about 95%…89%…96%"。*第一手：是；可信度：高。*
- [传神语联 via 数据猿, Tencent Cloud](https://developer.cloud.tencent.com/article/2708997) (Transn multilingual short-drama case, 2026-07-14)。故事理解 → AI 翻译 → 适配时长的译后编辑 → 声音克隆配音 → AI 加人工质检。"每月配音短剧数量300部起，配音集数超2000集"；"AI负责约85%"。*第一手：厂商；可信度：中。*
- [娱乐资本论 on 钛媒体](https://www.tmtpost.com/7526126.html) (Who holds the key to AI dubbing?, 2025-04-08)。一家工作室用 AI 配音工具重跑客户的一部剧，人工复查是强制的。"把一周的工作压缩到了一天"。*第一手：访谈（工作室未具名）；可信度：低。*
