# 药师核验的处方录入

**与相近工作流的区别：** PRO/HLT（CLINDOC、RCM、CLINTRIAL、DRUGDISC）中没有特别接近的。按流程最接近的是 AWF-0148 的报关单准备（提取 → 持证审阅人 → 提交），但这里的智能体是通过计算机操作来操作 PMS，并且每个条目在发药前都要经过两次药师核验。
**工具变体：** `tjm-labs`

## 背景

长期护理药房收到的处方以电子处方、传真和排队订单的形式进来，必须有人一条条敲进药房管理系统：按姓名、出生日期和地址匹配患者，按 NPI 匹配开方医生，然后是药品、数量、天数与用法。这是打字，不光鲜，而错误正是从这里进入一个容不下错误的流程——抄错一个数字，三步之后就变成错误的剂量。一个操作技师所用界面的机器人可以完成录入，但真正有意思的设计决定是：当传真模糊、或药名在目录里匹配不上时它怎么办。这里的答案是停下来。它记一条带原因的"机器人跳过"，把这一项留给人；管制药品默认留给药师，而不是先录入再更正。之后两次药师核验夹住这段工作——一次紧接录入之后，一次在药离开药房之前——于是机器人的产出被唯一有执照核验它的人查了两遍。让这套安排随时间变好的是：机器人作为一位有名字的技师登记在系统里，它的错误因此像人的错误一样被计数，跳过清单每天有人读。

**术语：**
- **PMS（pharmacy management system）**：处方录入所用的药房管理软件。
- **电子处方（e-script）**：电子形式的处方，区别于传真。
- **SIG**：印在标签上的用法说明。
- **NPI**：美国国家提供者标识，用于匹配开方医生。
- **机器人跳过（bot skip）**：机器人拒绝录入的条目，带原因记录。
- **跳过率（skip rate）**：机器人拒绝录入的条目占比，是覆盖能力的主要指标。
- **QV1 / QV2**：两次药师核验，分别在录入之后与发药之前。
- **错误队列（error queue）**：被驳回、由技师更正的条目清单。
- **计算机操作（computer use）**：智能体通过图形界面而不是 API 操作应用。

## 用智能体搭建

**形态：** `service`。处方从三条渠道持续进来，机器人无人值守地处理这条队列，人出现在两道核验关口与一次每日复查上。这不是某个人要的单一交付物，也没有按患者累积、可由 project 持有的东西——它是一条必须一直流动的队列。

**需要：** 通过员工所用的同一套界面进入 PMS 的权限，因为能走 API 的机器人会绕过药房所依赖的那些控制；它用来匹配的药品目录与保险规则，且须是现行的，因为过期目录会产出自信的错误录入；一条遇任何歧义即触发的跳过规则，并记录原因，因为猜比留空更糟；把机器人作为一位有名字的技师登记进系统，这才让它的错误可追踪、可归责；一个每天有人读跳过清单的复查时段，因为跳过率会随处方结构漂移；以及有人值守的两道核验关口，因为整套安全论证都建立在它们真实存在之上。智能体不能在无药师的情况下录入管制药品，不能用相似度去化解匹配不上的药名，也不能是最后一个碰过某张处方的东西。

| 步骤 | 搭建方式 |
|---|---|
| 收到处方（电子处方 \| 传真 \| 队列） | 三条入口，各有各的失败方式：电子处方是结构化的，传真需要阅读，队列里的条目可能已经被录了一半。 |
| 机器人操作 PMS 界面：匹配患者、开方医生、药品、数量、SIG | 在真实应用上做计算机操作而不是调 API，于是机器人受与技师相同的校验规则约束，也留下相同的审计痕迹。 |
| 不确定 / 无法识别：机器人跳过（记录原因） | 跳过就是安全机制：任何歧义都让这一项停下并附上编码原因，管制药品默认扣留而不是先录入。 |
| 🛑 review（QV1 药师核验；驳回到错误队列） | 每次录入之后立即核验；驳回进入技师的错误队列并留下记录，录入错误率之所以可知，全靠这一步。 |
| 🛑 sign-off（QV2 发药前最终核验） | 药离开药房之前的第二次核验是最后一道人工关口，搭建无法发药。 |
| 每日复查跳过项和错误 → 新一轮训练 | 跳过清单与错误队列每天被读、并同步给厂商；新增能力按慢节奏加，而不是让机器人去多试一点。 |

**检查点：** `review`：QV1 在处方还留在药房手里时抓住录入错误，而错误队列把每一次驳回变成一个留痕的案例，而不是一次没留下痕迹的更正。`sign-off`：QV2 是药师在发药前的最后一道检查，而设计让机器人根本够不到它——安全论证在于有两位持照者看过，而不是机器人足够准。

**与来源相比：** 来源出自 2026-09-16，以及一份未标日期、2026-11 更新的厂商页面；截至 2026-11 没有找到更新的记述。这些来源没讲清的地方值得记下来，而不是替它补。那个头条数字——跳过率在 60 天内从 20% 多降到 10% 以下——是在一个不断变化的处方结构上的滚动数字，所以它会随药房收方结构变化而移动，条目应当读作一条轨迹而不是一个定下来的比率。第二件是让其余部分成立的那个细节：机器人被登记为一位有名字的技师，它的错误因此进入与人类相同的报表。那是系统管理层面的决定，不是模型层面的，也最容易被照搬这套流程的团队跳过，因为它需要有人在 PMS 里为这个机器人"身份"负责。条目其余部分未变，证据等级仍为 A：这份记述来自运行它的人和药师本人，而不是厂商案例。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 训练方式照搬技师入职：记录员工如何录入新患者、查保险、录处方；每周复盘，持续 4 到 5 周；然后在每天五到十张处方上试跑约六周，才在一家机构上线 [[1]](#sources)。
2. 机器人读取电子处方与传真，并通过技师所用的同一套界面录入药房管理系统：按姓名、出生日期与地址匹配患者，按 NPI 匹配开方医生，然后是药品、数量、供应天数与用法 [[1]](#sources)[[2]](#sources)。
3. 遇到无法识别的内容时它停下并标记"机器人跳过"，在运行表中记录原因；管制药品默认留给药师 [[1]](#sources)[[2]](#sources)。
4. 🛑 **审阅**：每条由机器人录入的处方在录入后立即接受 QV1 药师核验；错误被驳回到技师的错误处理队列，机器人被登记为一位有名字的技师，以便追踪其错误 [[1]](#sources)。
5. 🛑 **签发**：药离开药房之前的 QV2 最终药师核验 [[1]](#sources)。
6. 团队每天复查跳过与错误，同步给厂商修复，大约每 90 天新增一项能力 [[1]](#sources)。

**产出：** 录入 PMS 并在发药前经两次药师核验的处方；一份驱动重训的跳过/错误日志。
**失败模式 → 防护：** 机器人对异常处方自行猜测 → 设计上就跳过，绝不即兴发挥 [1][2]。录入错误 → QV1 抓住并驳回到错误队列；错误被记录并与厂商一起修好 [1]。早期跳过率高 → 从 20% 多降到 10% 以下 [1]。
