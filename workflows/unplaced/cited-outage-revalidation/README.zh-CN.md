# 带引用的停运复核

**与相近工作流的区别：** AWF-0213（带引用的并网就绪审查，cited interconnection readiness review）是一次性批量对照电价规则（tariff）检查新的并网申请，最后由工程师做出合规判定。本工作流在固定的时间节点上，每天复核每一个在途的设施停运申请，产出控制室人员据以行动的运行报告。触发方式、节奏、交付物和审阅人都不同。
**工具变体：** `oati-genie`

## 背景

一次输电停运提前数周排定，到当天才放行，而在这中间电网在它脚下变了：负荷预测移动，别的停运获批，一条本来可用的线路变得不可用。于是运营方批准一个申请，实际上是把同一个问题反复决定好几次，而且决定得越晚，思考的时间越少。在一个大型控制区里，体量让人没法认真手工做完这件事——每天有数百个新的发电停运申请和数百个输电申请进来——所以现实的做法一直是：看起来有风险的核一核，其余放过去。一支在固定节点（提前三周、提前两天、提前一天）并可按需复核每一个在途申请的智能体队伍把这件事倒过来：全量都看，异常连同它违背的先例与规程一起标出，报告在复核人上班之前就已就位。它不能做的是行动。可靠性操作留在运行人员手里，既因为标准要求人的权威，也因为一次错误的倒闸决定不是可恢复的错误。

**术语：**
- **停运申请（outage request）**：请求将某设施退出运行，含起止时间。
- **复核（revalidation）**：在固定节点上、开始之前对照当前条件重新检查一个申请。
- **OASIS**：发布输电与停运信息的公开系统。
- **自由文本备注（free-text note）**：申请上的非结构化注释，真实信息常常就在这里。
- **先例（precedent）**：一次可比的既往停运，用来论证某种设置可接受或不可接受。
- **可靠性操作（reliability action）**：影响电网的运行决定，保留给有资格的人员。
- **置信度（confidence）**：智能体自身的确定程度，报告出来而不是用来压下某个标记。
- **变更管理（change management）**：在合规边界内变更系统的受控流程。

## 用智能体搭建

**形态：** `service`。它在夜间与固定节点上对全部在途申请运行，没有人启动，产出是一份在早班之前就位、等着人看的报告。运行人员据此行动；流水线从不对电网行动。这是服务，不是某位运行人员跑一次的 skill，也不是按周期组织的 project。

**需要：** 对停运管理系统、市场系统与规程文件的读权限，数据以复制方式进来而不是在控制边界内做集成；运行规程与操作词典作为带版本的参考，因为只有引用到它所违背的那条规程，标记才可信；历史停运记录，用于先例比对；自由文本备注要被解析而不是忽略，因为例外通常就藏在那里；每份报告固定一个模型版本，因为一次没被注意到的模型更新会同时改变所有申请的分析；以及一个由有权更正申请的人值守的早间复核时段。智能体不能采取可靠性操作，不能批准或驳回停运，也不能成为唯一读过那条备注的东西。

| 步骤 | 搭建方式 |
|---|---|
| 定时检查点（D+21、D+2、D+1） | 固定节点加按需运行，于是申请是随条件变化被反复复核，而不是在提交时核一次。 |
| 每个停运申请：复核建模、市场影响、历史设置、规程、自由文本备注 | 按申请一次核五个维度，自由文本备注对照操作词典读，因为不一致就藏在那里。 |
| 异常标记 + 建议（引用、先例、置信度） | 每个标记带着它所依据的规程或先例与一个声明的置信度，审阅人几秒钟就能否掉一个弱标记，而不用通读报告。 |
| 每晚分析报告 | 报告在夜间组装、接班前就位，这是"仅供参考"与"真有用"的区别。 |
| 🛑 review（运行人员 / 工程师决定并更正） | 运行人员与工程师阅读、决定，并在停运管理系统里做更正；搭建不能更改申请，也不能采取可靠性操作。 |
| 反馈给开发团队 | 运行人员的反馈与被追踪的对话回流到开发，路由错误与弱标记是这样被修掉的，而不是被容忍。 |

**检查点：** `review`：报告只是建议，更正发生在运行人员自己的系统里——搭建对电网没有任何写通路，这既是安全属性也是合规属性，因为标准要求运行操作由人掌握权威。

**与来源相比：** 来源出自 2025-07 与 2026，本轮都没有重新打开。此后有变化的是这次部署周围的法律框架，而不是部署本身。截至 2026-08，没有任何州公用事业委员会就运营型 AI 发布正式指引（[Foley Hoag 2026-09-09 的分析](https://foleyhoag.com/news-and-insights/blogs/energy-and-climate-counsel/2026/september/legal-considerations-for-ai-deployment-in-the-power-sector/)），只有一个州启动了正式调查，问询电力、燃气与水务公司如何在预测、采购与计划中使用 AI——所以运营方是在具体规则的真空中运行这件事，起作用的是通用的可靠性与关键基础设施义务。正是这些义务塑造了这套搭建：标准要求对能够触达关键基础设施的系统施加访问控制与变更管理，而实务界已就本条目采用的架构形成共识——模型放在安全边界之外，读复制数据，只回建议由人执行，并记录运行人员的采纳或推翻。最后这一点在这里很要紧：哪些标记被采纳的记录，既是改进信号，也是"AI 只是提供信息、并未执行运行操作"的证据。要预先考虑的现实约束是变更控制：模型或提示词的更新在受控系统里是一个事件，所以每晚报告背后的版本必须固定，变更要排期，而不是悄悄灰度上去。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 在预定的研究检查点（例如 D+21、D+2、D+1）或按需触发。CAISO 电网每天收到 500 多个新的发电停运申请和 200 多个新的输电停运申请 [[1]](#sources)。
2. 一个编排器协调专门的智能体。Workflow 智能体对全部在途申请执行定时复核：它复核建模、市场影响、历史停运设置、运行规程，以及自由文本停运备注中的异常，数据来自 OASIS、市场系统与规程数据 [[1]](#sources)[[2]](#sources)。
3. 相似度检索智能体按设备、位置与规程把每个申请与历史停运记录比较。关键词智能体对照 CAISO 的操作词典读自由文本备注，并标出不一致 [[2]](#sources)。
4. 报告智能体生成带异常标记与建议的每晚分析报告。每条建议都带可追溯的推理、来源引用、先例与置信度 [[1]](#sources)。
5. 🛑 **审阅**：输电、可靠性与发电方面的运行人员与工程师审阅发现，并自行作出更正。系统仅作建议，不能采取可靠性操作 [[1]](#sources)。
6. 用户通过内置反馈功能提交反馈，回流到开发周期。会话被追踪，访问按角色控制 [[1]](#sources)。

**产出：** 一份每晚的停运复核报告，在复核人开始一天工作之前就绪，另有关于规程与单线图的带引用回答。所有更正由运行人员在停运管理系统中完成。
**失败模式 → 防护：** 意图路由错误会让每个回答都显得错 → 把意图路由当作关键环节。团队并非自己设计的遗留数据结构 → 被点名为最困难的部分。编造的建议 → 各智能体在集成前分别验证，每条发现都带引用，且不采取自主电网操作（对齐 NERC/CIP）。运行人员信任度低 → 培训与反馈闭环。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Fourth collection pass](../../../research/2026-11-fourth-pass.md)。

- [California ISO, Deploying Agentic AI into Facility Outage Management](https://www.nationalacademies.org/cdn/materials/a3191bca-d63d-473b-ae9e-a98add3301c6)（2026，页面未标具体日期）。Genie 已在生产中扩大测试：对次日停运做每晚复核；由运行人员决定。"< 8 min to analyze 500+ next-day outage requests, ready before reviewers start the day"。*第一手：是；可信度：高。*
