# 带引注的并网申请完备性审查

**与相近工作流的区别：** 最接近的是 AWF-0151（首轮提交物审查：施工提交物对照规格，先由项目经理审阅，再由记录审阅人签发）。同样是对照规则检查的模式，但本工作流对照费率规则并行处理整个监管队列的一批申请，交付物是每份申请的带引注完备性报告，并且只有电网运营商的最终判定是检查点（没有逐条的项目经理修改环节）。所属领域不同：电网并网。
**工具变体：** `tapestry-hyperq`

## 背景

电网运营商的并网队列，是拟建电源项目与电网之间的那道门，而这道门在遇到工程问题之前先遇到文书问题。一份申请以一整包材料到来：土地控制文件、单线图、地图、保证金凭证、法律声明。得有人对照费率规则和运营商手册核这一包，把有缺陷的在昂贵的接入研究开始之前退掉或标出来。在当下的体量上——一年一个申请窗口、数百份申请——这次核查决定了队列是往前走还是堵住。本工作流把智能体并行铺在每份申请上，抽取参数、对照费率规则检查，写出一份完备性报告，而每一条发现都带页码、条款或坐标引用。之后由工程师作出合规判定。这个设计的赌注很窄，也值得说清楚：价值不在判断本身，而在于因为有证据附着，人能几秒钟内核完一个判断；以及在一个受监管的队列里，黑箱答案比没有答案更糟。

**术语：**
- **并网申请（interconnection application）**：请求把发电或负荷接入输电网。
- **费率规则（tariff）**：运营商报备的规则，含并网流程及其要求。
- **土地控制（site control）**：证明开发商控制该土地的文件，最常见的缺陷项。
- **完备性审查（readiness review）**：确认申请是否完整到可以进入研究队列的检查。
- **研究阶段（study phase）**：申请完整后进行的工程研究。
- **缺陷（deficiency）**：缺失或不符合的条目，连同其规则一并标出。
- **判定（determination）**：运营商关于某申请合规的正式决定，只有运营商能作。
- **受理周期（intake cycle）**：接受申请的窗口，错过这次下一次要等一年。

## 用智能体搭建

**形态：** `project`。费率规则、从员工往期评级中提炼的指令集、每份申请的报告与审计痕迹，都属于同一个受理周期，并且要为这个周期的争议与申诉一起留存。这是一个按周期组织的、带工作流的仓库，不是某位工程师跑一次的 skill，也不是持续运行的服务。

**需要：** 申请材料包的机器可读版本，包括地图与扫描的法律文件；费率规则与手册作为带版本的文本，因为拿已被取代的规则去检查就是错标；历史评级决定，正是它把一张通用清单变成运营商自己的标准；一种报告格式，使每条发现都带页码、条款或坐标级的引用，因为这让核验变得便宜；p95 运行时间预算，因为研究队列开门之后才到的报告没有用；以及工程师用于判定的时间，要按整批配置而不是按抽样配置。智能体不能出具判定，也不能退掉申请：两者都是运营商的，而错误地退掉一份申请是法律风险。

| 步骤 | 搭建方式 |
|---|---|
| 一批并网申请 | 把本周期受理的申请作为一批处理，逐份列明文件，于是缺一个文件成为一条发现，而不是一个无声的空洞。 |
| 每个申请：摄取文件（PDF、地图、法律文件） | 按申请并行摄取，地图与扫描件被显式处理，因为土地控制证据常常就在一份扫描的地契里。 |
| 智能体提取参数 + 对照费率规则 / 手册检查 | 抽取与合规检查分给不同智能体，对着带版本的费率规则执行，编排层记录每项检查用了哪条规则。 |
| 带逐页引注的完备性报告 + 标出缺陷 | 每份申请一份报告，发现引到页码、条款或坐标，工程师几秒钟就能确认或否定每一条。 |
| 🛑 sign-off（电网运营商工程师作出最终合规判定） | 由工程师作出判定；搭建没有任何通往决定、退件或队列位置的通路。 |
| 完备的项目进入研究阶段 | 运营商放行的申请继续往前走，报告则留作"查了什么、谁查的"的记录。 |

**检查点：** `sign-off`：判定属于运营商，而本工作流唯一的主张是：手里有引用，工程师能更快到达那个判定——这也意味着搭建绝不能成为"判定某项目不完备"的那一环。

**与来源相比：** 来源出自 2026-06-02，本轮没有重新打开。此后有这些变化：运营商开始用自己的话描述这次部署，而它的话比厂商的数字更谨慎。在 2026-03 更新的公开问答中，运营商表示正与开发方一起测试这个工具，[早期结果表明它能简化评估中的某些环节](https://reliablepowertodaytomorrow.com?p=418/)，并将在团队通过基准测试验证结果后公布更多细节——那是一种测试姿态，不是投产声明，而它与一份报告 811 份申请、每份中位 6 分 15 秒的厂商现场笔记并列存在。两者都可能是真的，它们量的是不同的东西，本条目不应把二者平均。队列背景解释了"整批"为什么重要：运营商的过渡队列到 2026 年底仍有约 46 GW 待处理，第一个常规周期的一年一度申请窗口已于 2026-04-27 关闭，而从申请到商业运行的平均时间已升到八年以上。一年只有一次受理窗口，完备性审查就是长达一年的接入研究之前最后一道便宜的筛子——这就是要对整批而不是抽样去做的理由。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. PJM 的费率规则、用户手册，以及员工过去如何给申请评级，被提炼成一套指令；抽取与合规检查被拆分给多个智能体，外加一个编排层 [[1]](#sources)。
2. 本周期内每份申请并行处理：智能体摄取 PDF、地图与法律文件，并对照费率要求执行土地控制的申请完备性审查 [[1]](#sources)。
3. 产出是每份申请一份完备性报告，带页码、条款或坐标级引用，并标出缺陷 [[1]](#sources)。
4. 🛑 **签发**：PJM 的专家工程师依据报告作出最终合规判定 [[1]](#sources)。

**产出：** 每份申请一份有引用支撑的完备性报告，交给电网运营商工程师；被判定为完备的项目进入研究阶段。
**失败模式 → 防护：** 受监管队列中的黑箱判断 → 每项评估都链接到来源页码/条款，判定权留在工程师手里 [1]。复杂申请上的运行长尾 → 跟踪 p95（28 分钟）[1]。
