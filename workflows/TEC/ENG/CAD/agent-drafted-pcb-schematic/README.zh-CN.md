# 智能体辅助的 PCB 原理图

**工具变体：** `openai-codex` · `claude-code` · `kicad-cli` · `kicad-happy` · `jlcpcb`

## 背景

印制电路板（PCB）是电子设备里的那块板：上面装着芯片、接插件和小元件，以及把它们连起来的铜走线。设计一块板从一张草图开始，结束时交付的是一套工厂能照着做出来的文件。原理图说明哪个元件的哪个引脚连到哪里；BOM 列出要采购的具体型号和数量；框图把电路拆成几个功能模块并说明它们之间的关系；投板资料包是板厂和贴装厂需要的东西。做这件事的是电子设计师，而慢的地方通常不是画图本身：每个元件都必须有货、有库存，符号和封装要与实物对得上，每条网络都要按设计师的意图连通。原理图定稿后还要手工布局布线，因为器件摆放和走线决定了这块板能不能顺利做出来。在这里，智能体起草需求、器件清单、框图和原理图，导入元件，跑规则检查，写评审要点。决定权仍在人手上：设计师批准方案、确认每一步接线、自己完成布局并下单，第二位工程师读一遍原理图，首板在工作台上点亮验证。原理图错了就要重新投板，还要等几周，所以这些确认不是走形式。

**术语：**
- **原理图（schematic）**：在任何物理决定之前，说明元件引脚之间如何连接的图。
- **BOM**（bill of materials，物料清单）：要采购的器件清单，含型号与数量。
- **框图（block diagram）**：把电路拆成功能模块并画出模块间连接的粗粒度图。
- **符号、封装（symbol, footprint）**：代表同一个真实元件的原理图符号和焊盘布局；任何一个与实物不符，板子就按图做不出来。
- **ERC**（electrical rules check，电气规则检查）：设计工具自动检查电气错误，例如两个输出同时驱动一条网络。
- **网表（netlist）**：原理图所蕴含的连接关系的机器可读清单，用来核对图纸与实物板是否一致。
- **投板资料包（fab kit）**：交给制造的文件——铜层、钻孔数据、贴装坐标、BOM。
- **点亮验证（bring-up）**：新板第一次上电，找出哪里不工作。
- **立创商城（LCSC）**：元器件分销商，智能体可以查它的目录获取价格和库存。

## 用智能体搭建

**形态：** `project`。一位设计师一次做一块板，但保证这块板做得出来的那些规则——只用项目库里的元件、没有数据手册就不许进 BOM、任何人评审之前检查必须干净——必须在每一次修改时都成立，这需要一个带钩子和独立评审者的仓库，而不是一个 skill。

**需要：** 放在 git 仓库里的 KiCad 工程及其元件库，外加一个存放器件数据手册的目录；一条让智能体驱动设计工具的通道——KiCad 的 MCP 服务器，或 `kicad-cli` 加工程旁边的小脚本；以 CSV 形式放在仓库里的 BOM，供智能体边做边读边改；可查询的器件目录（价格与库存）；一个工作台，以及一位负责评审的第二工程师。不要给智能体导出投板资料给板厂的工具，也不要给它下单的途径。

| 步骤 | 搭建方式 |
|---|---|
| 草图 + 尺寸限制 → 概念渲染图 | Skill 的一步：把草图和历史板子的照片交给视觉模型，把渲染图写进仓库，放在需求文档旁边。 |
| 需求文档 + BOM + 框图 | `CLAUDE.md` 规定文件名，以及“没有数据手册就不许有 BOM 行”的规则；Skill 写出这三份文件，旁边的脚本逐行向器件目录询价。 |
| 🛑 plan | Skill 写完这三份文件就结束本轮；用计划模式，或用 `PreToolUse` 钩子在批准文件存在之前拒绝一切原理图写入。 |
| 逐步：智能体构建 KiCad 原理图，🛑 action | KiCad 的 MCP 服务器提供放置符号、连线、读取网络的操作；权限规则让每次写入都要询问，`PreToolUse` 钩子把写入限制在工程目录内。 |
| 对抗式原理图评审 ⟲ 修复 | 一个 Subagent，只给它原理图、BOM 和数据手册，要求它只报问题、不修问题；它看不到产生这份设计的对话。 |
| ERC 和网表导出 | 脚本调用工具自带的 ERC 和网表导出，把两份报告写进仓库；评审循环一直跑到某次运行不再产生新问题。 |
| 🛑 review（第二位工程师） | Skill 汇总一份评审包——原理图 diff、ERC 和网表输出、未决问题——然后停下；工程师在仓库里或在 PR 上批准。 |
| 手工 PCB 布局 → 导出投板资料 → 下单 | 在智能体之外：设计师在 KiCad 里布局布线，脚本导出铜层、钻孔和贴装数据，下单由人完成。 |
| 调试上板 | 智能体先写自检固件；台面调试和返修仍由设计师完成。 |

**检查点：** `plan`：需求、BOM 和框图写完后本轮结束，在批准文件出现之前无法写入原理图。`action`：每次写入原理图都是一次权限规则的询问，设计师在改动落地前就看到是哪个元件、哪条网络；钩子拒绝工程目录之外的写入。`review`：评审包交给指名的第二工程师，智能体没有导出投板资料或下单的工具，订单由人提交。

**与来源相比：** 来源出自 2026-08：一份第一手记录，也是本条目的公开实例。本月已打开该页面。此后有这些变化：这份记录是手工把流程拼起来的——用 `easyeda2kicad` 导入符号和封装，用 `kicad-cli` 做 ERC，用一份 markdown 文件承载对抗式评审。KiCad 的连接器现在承担了其中一部分。[Konnect](https://cyber-ivy.com/en/articles/konnect-kicad-ai-pcb-tool-check-2026)（0.11.0，beta，2026-08）通过 MCP 把原理图与板级编辑、ERC/DRC 和制造文件导出开放给智能体；[Copperhead](https://copperhead.sh/blog/meet-copperhead)（2026-07）把起草—文档—检查的循环跑完，产物都留在仓库里；上面那个导入符号的步骤，正是当前工具能替代的部分。本搭建方式保留手工布局、第二工程师评审和台面调试：这份记录的设计者自称不是专业电子工程师，而它报告的故障是在板子做出来之后才发现的。本月打开的页面里，没有一份显示有人在没读原理图的情况下就下单。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 从尺寸限制内的手绘草图开始。生成几张概念渲染图 [[1]](#sources)。
2. 智能体起草技术需求文档、核心 BOM 和框图，并根据 LCSC 查询估算成本。🛑 **计划**：设计师审阅并修订这些内容 [[1]](#sources)。
3. 编码智能体根据 BOM 逐步构建 KiCad 原理图，用 easyeda2kicad/pcbparts 选型元件。🛑 **操作**：设计师确认每一步，并负责布局和连线的决定 [[1]](#sources)。
4. 要求做一次对抗式原理图评审，并写入 markdown 文件。修复发现的问题，反复进行直到没有新问题。用 kicad-cli 做 ERC 和网表导出检查，并把真正的问题与导入产生的噪声区分开 [[1]](#sources)。
5. 🛑 **审阅**：第二位工程师评审原理图（30 分钟）。然后手工完成 PCB 布局，导出生产资料包，并订购电路板和贴装 [[1]](#sources)。
6. 调试上板：智能体先写自检固件。设计师在工作台上排查硬件故障 [[1]](#sources)。

**产出：** 一份经评审的 KiCad 原理图，以及向 PCB 厂下单的投板/贴装资料包，另有调试用固件。
**失败模式 → 防护：** LLM 丢失整个项目的全局视角，并在元件没有模型时漏掉故障（开关引脚短路使 BOOT0 被拉低）→ 由人做第二次评审，并在工作台上调试上板。导入元件产生的 ERC 噪声 → 以网表得出真正的发现 [[1]](#sources)。
**与相近工作流的区别：** 最接近的是 AWF-0056（分阶段预览构建），它为 3D 打印零件循环执行 CadQuery → STL → 渲染，并带预览审阅。本工作流产出的是电气原理图和投板资料包。其检查手段是 ERC/网表加对抗式 LLM 评审，设计师确认每一步，下单前由第二位工程师评审。
