# 工程师把关的 CFD 仿真

**工具变体：** `openfoam` · `snappyhexmesh` · `gmsh` · `calculix` · `paraview-pvpython`

## 背景

计算流体力学（CFD）回答的是空气或液体怎么流动的问题——某个外形能产生多少升力、某个零件会不会过热——做法是把物体周围的空间切成上百万个小网格，在每个格子里随时间求解流动方程。做这件事的是仿真工程师：几何与计算域、描述流体的方程、计算域边界上的条件、以及网格，都由他来设定。两件事让它既慢又容易出错。第一，得到一个收敛的结果要跑很多次：网格要加密、求解器要重启、过程要有人盯着。第二，收敛的结果在物理上仍可能是错的——某个边界条件填了一次再没回头看，湍流模型不适合这种流动——而求解器的输出不会主动提示这一点。在这里，智能体根据一份自然语言说明搭建算例，把它用到的每个方程、假设和取值写下来，跑网格与求解的循环，再把结果和已发表的实验或手算结果对比。工程师在任何算力花出去之前先批准物理选择，在有人拿这个数字做决定之前先检查对比结果：拿未经验证的仿真做设计决定，这份责任是工程师的，不是智能体的。

**术语：**
- **CFD**（computational fluid dynamics，计算流体力学）：用数值方法求解流体方程来预测流动。
- **求解器（solver）**：推进这些方程的程序，这里指 OpenFOAM。
- **网格（mesh）**：空间被切成的那些格子；太粗结果就错，太细就算不完。
- **边界条件（boundary condition）**：计算域边缘告诉流体的条件——入口速度、出口压力、壁面转或不转。
- **湍流模型（turbulence model）**：不去解析每一个涡而采用的近似，必须与流动的类型相称。
- **收敛（convergence）**：残差稳定下来，说明数值不再变化；这不等于结果正确。
- **残差（residual）**：每次迭代后方程中剩余的误差。
- **后处理（post-processing）**：把场量变成图和数——升力、阻力、压力分布。
- **验证（validation）**：把结果与实测或独立参考对比，这是唯一能证明设置正确的证据。

## 用智能体搭建

**形态：** `skill`。一位工程师跑一个算例并始终在对话里，中间有两道关卡；算例脚本和检查清单与 skill 一起放在算例仓库里。

**需要：** 放在 git 仓库里的算例，含一个粗略的起始算例和几何；在智能体能运行的位置装好 OpenFOAM 和一个网格工具；一条无头出图的通道（ParaView 的 Python 接口或 matplotlib）；用于对比的已发表实验、参考算例或手算结果；一台可以长时间占用的机器。智能体不能往工程师签字的那个设计记录里写任何东西，也不能在那里面出图。

| 步骤 | 搭建方式 |
|---|---|
| 物理需求说明 + git 中的粗略算例 | 由工程师准备：仓库约定（单位、命名、结果放在哪）写进 `CLAUDE.md`，这样每次运行的组织方式一致，diff 也好读。 |
| 智能体搭建算例并编写假设文档 | Skill 写出算例文件，并写一份假设文档——方程、模型选择、边界取值，以及每项的理由——作为分支上的第一个提交。 |
| 🛑 plan（工程师检查物理选择） | Skill 交出假设文档和 diff 后停下；用计划模式，或用 `PreToolUse` 钩子：在工程师的批准被记录进仓库之前，拒绝任何求解运行。 |
| 网格 ⟲ 网格检查 | Skill 旁边的脚本建网格并调用网格工具自带的检查；Skill 读报告，能修的自己修，然后循环；多套网格的网格研究就是一个带参数的脚本。 |
| 求解 ⟲ 收敛检查 | 求解由脚本在后台启动；另一个脚本依据残差、退出状态和发散标记来判断是否收敛，而不是看有没有超时；Skill 据此诊断并重跑。 |
| 后处理 + 与参考结果/手算对比 | 绘图脚本产图并生成对比表；Skill 把给定参考值填进表里，并对非物理结果做标记，而不是抹平。 |
| 🛑 review（工程师检查物理合理性） | Skill 交出报告、对比表和未决问题后停下；工程师在自己的记录里签字，智能体没有写入那份记录的工具。 |

**检查点：** `plan`：在工程师读完假设文档和 diff 之前不花算力，钩子在批准存在之前拦住求解运行，所以一个看似合理但错误的湍流选择不会悄悄跑完整个批量计算。`review`：报告和对比表交给工程师，他在智能体可写区域之外签字；本搭建方式不给智能体发布或归档报告的工具。

**与来源相比：** 来源出自 2026-05 到 2026-08（一个仓库、两篇文字）；视频来源未注明日期。本月打开了 GitHub 仓库，两篇博客本轮没有重新打开。此后有这些变化：来源是手工搭起检查循环的——网格研究脚本、收敛交叉核对、对比表。此后发表的工作把“检查”变成做决定的一方，而不是模型的意见：[CFD Forge](https://arxiv.org/abs/2610.14104)（2026-10）为每类流动注册确定性的验收检查，并展示了模型单独判断时会接受错误状态；[AI CFD Scientist](https://arxiv.org/abs/2605.06607)（2026）因为求解器日志漏掉静默失败，增加了对渲染流场的视觉检查。两者都能以 skill 旁边脚本的形式落进本条目：验收标准写进代码，智能体的自由度在诊断上。工程师的两道关卡没有变，本月打开的页面里也没有任何东西能替代用实测做验证。

## 步骤

*以下按来源所述。*

1. 照常创建 CAD 和计算域。把一个粗略的 OpenFOAM 算例放进 GitHub 仓库，这样智能体做的每一处改动都能做 diff [[3]](#sources)。
2. 智能体根据一份自然语言的需求说明搭建算例：求解器选择、湍流模型、由第一性原理推导的入口湍流、计算域尺寸。它还会写一份文档，列出所用的方程、假设和取值 [[2]](#sources)[[3]](#sources)。
3. 🛑 **计划**：工程师先阅读假设文档和 git diff，再决定是否信任这套设置 [[3]](#sources)。在基于工具的版本中，由人批准受控的操作 [[1]](#sources)。
4. 划分网格并检查网格。如果求解发散，智能体会检查并重新生成网格。编写网格研究脚本（例如三套 snappyHexMesh 网格），运行并修正错误 [[2]](#sources)[[3]](#sources)。
5. 求解直到收敛。把求解器的收敛信息与正常退出和发散检测交叉核对，因为超时和被强制终止看上去可能像收敛 [[1]](#sources)。如果算例不收敛，再次加密网格 [[3]](#sources)。
6. 用脚本化的 ParaView/Python 绘图做后处理。把结果与已发表的实验或参考算例对比，在 FEA 变体中则与手算对比 [[1]](#sources)[[4]](#sources)。对效率大于 1 之类的非物理结果要标记出来，而不是掩盖 [[1]](#sources)。
7. 🛑 **审阅**：负责的工程师在做任何设计决策之前，先检查物理合理性和验证结果。作者强调，在与实验对照之前，这些结果只是未经验证的预测 [[2]](#sources)[[3]](#sources)[[4]](#sources)。

**产出：** git 中一个已收敛的算例、绘图和渲染图，以及一份含“验证结果与参考值对比表”的报告。它交给负责签字做设计决定的工程师。
**失败模式 → 防护：** 边界条件错误却依然收敛（旋转壁面被留成 noSlip，叶片从未转动）→ 旋流探针，加一份依赖人工判断的诊断清单 [[1]](#sources)。虚假收敛 → 收敛交叉核对 [[1]](#sources)。看似合理但错误的湍流选择 → 工程师审阅假设文档以及与实验的对比 [[2]](#sources)[[3]](#sources)。
**与相近工作流的区别：** 暂无相近者。SRE 和 FEAT 类工作流作用于代码，本工作流作用于求解器算例，验收关口是物理验证。
