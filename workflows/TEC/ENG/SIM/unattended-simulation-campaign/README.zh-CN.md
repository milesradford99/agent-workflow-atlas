# 无人值守仿真批量计算

**与相近工作流的区别：** AWF-0057 工程师把关的 CFD 运行（Engineer-checked CFD run）搭建并求解单个算例，对该算例做物理方案检查和物理审阅。这里的产出是包含数千次运行的试验设计批量计算，加上代理模型和应用；没有人检查单次运行，只检查研究定义和最终的代理模型。
**工具变体：** `move-platform`

## 步骤

1. 🛑 **计划**：资深工程师定义研究（参数、范围、输出）；该页面把“定义研究”计入工程师的实际动手时间 [[1]](#sources)。
2. 先校准模型：智能体运行五连杆悬架模型，把曲线与实测的 K&C 数据对比，发现衬套刚度解释了大部分差距，并应用一致的缩放修正；它会写出一份验证报告 [[1]](#sources)。
3. 在设计空间上规划批量计算（38 个参数：30 个硬点坐标在 +/-15 mm 内、7 个衬套刚度、弹簧刚度），并在夜间分批运行，在本地或 HPC 上均可，保持每个结果都可追溯到其输入 [[1]](#sources)。
4. 检查每个结果的物理合理性，既能发现未收敛的运行，也能发现求解器报告成功但收敛到错误平衡的运行；找出哪些参数组合会让求解器出问题，并重新求解 [[1]](#sources)。
5. 后处理为一个结果集（运动学和柔度曲线，每种配置的硬点载荷峰值）[[1]](#sources)。
6. 调研候选的代理模型技术，在不同样本量下逐一拟合并量化误差；把 6 个最差的预测叠加在仿真曲线上 [[1]](#sources)。
7. 🛑 **审阅**：工程师在代理模型投入使用之前对其做验证（“验证”计入动手时间）[[1]](#sources)。
8. 把代理模型打包成供同事使用的交互式应用，并保留智能体对决策和失败的记录，供下一次研究使用 [[1]](#sources)。

**产出：** 一个结果数据库、一个附误差研究的经验证代理模型、一个交互式应用，以及下一次研究可以起步的、有文档记录的流程。
**失败模式 → 防护：** 悄悄出错的运行（求解器在错误的平衡点报告成功）污染数据集 → 逐次运行的合理性检查 [1]。未经验证的基础模型会产生数千个错误答案 → 先对照实测校准 [1]。代理模型在某些区域较弱 → 审阅最差情形叠加图 [1]。
