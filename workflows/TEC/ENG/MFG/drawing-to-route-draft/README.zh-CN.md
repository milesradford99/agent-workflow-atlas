# 图纸生成工艺路线草案

**工具变体：** `plm-extract` · `vision-llm` · `rules-kb`

## 背景

承接折弯、焊接和机加工的车间，对每一个新零件都要先决定它怎么做：哪些工序、按什么顺序、在哪个工位做、给多少工时。这个决定叫工艺路线，它决定了排程、成本核算，也决定班组拿到什么指令。这件事通常由一位有经验的工艺员来做：他读零件图纸——尺寸、公差、材料、表面处理——再对照车间多年积累的规则，判断哪台设备能达到哪个公差、每道工序要多久。它慢，是因为每个零件都要靠人读图；它脆，是因为这些知识只装在几个快退休的人脑子里。在这里，智能体从产品数据系统拉取 BOM 和图纸，列出每个零件需要的特征，套用车间的规则起草一份带工位和工时的路线，并写明哪些规则它没法套用。班组长仍要逐份检查、调整，然后放行到生产；修改会写回规则，让下一次起草更准。这道关卡不能去掉：放行一条路线就是占用了车间的设备和工时，路线错了要用延期和返工来还。

**术语：**
- **PLM**（product lifecycle management，产品生命周期管理）：存放每个产品 BOM、图纸和版本的系统。
- **BOM**（bill of materials，物料清单）：一个组件所需的零件清单。
- **工艺路线（process route / routing）**：一个零件的工序顺序，以及每道工序的工位和工时。
- **工位（workstation）**：车间里完成某道工序的一个位置，有自己的设备和技能要求。
- **工时（labour-hour estimate）**：一道工序的标准作业时间，用于核价和排程。
- **特征（feature）**：图纸上标出的某种形状——一道折弯、一组孔、一条焊缝——它决定了要做什么工序。
- **知识库（knowledge base）**：此处指车间选择工艺、工位和工时的成文规则，以结构化文档保存。
- **放行（release）**：工艺员认可一条路线的动作；放行之后，生产按它排程。

## 用智能体搭建

**形态：** `skill`。一位工艺员在对话里起草一个零件的路线，一位班组长放行；车间的规则是参考文件，这件事的其余部分不需要更大的形态。

**需要：** 对 PLM 的读权限，通过 MCP 连接器，或一个把 BOM 行和图纸导出到工作目录的脚本；PDF 或图片格式的图纸文件，以及一个把每张图按可读分辨率渲染出来的脚本；放在 skill 旁边的车间规则文件——工艺、工位能力、工时表——以及几份历史已放行路线，用来校对草案；路线表模板，格式要能被厂内系统接受。智能体不能有对生产或排程系统的写权限。

| 步骤 | 搭建方式 |
|---|---|
| 从 PLM 拉取 BOM + CAD | 一个 MCP 连接器，或 skill 旁边的脚本：把某个零件的 BOM 行和图纸导出到工作目录，并按零件号命名。 |
| 提取图纸特征 → 解读特征 | Skill 一次完成：读取每张图纸和零件模型的视图，为每个零件写出特征清单——折弯、孔、焊缝、公差——并注明是从哪张图、哪个标注读到的。 |
| 应用知识库规则（工艺、工位、工时） | 规则以参考文件形式存放；Skill 应用它们，并为草案中每一行注明是哪条规则得出的。 |
| 起草路线 | Skill 写出路线表——工序、工位、工时，以及每行背后的规则——另附一份没有规则覆盖的特征清单。 |
| 🛑 review（班组长调整并放行） | Skill 交出表格后停下；班组长修改后在厂内系统里手工放行，智能体没有任何可以提交路线的工具。 |
| 下发生产 → 记录修改 → 更新知识库 | 运行之后，班组长回复自己改了哪些地方；Skill 把差异追加到规则文件，作为待工艺工程师接受的变更建议，这样修改也像普通编辑一样被审阅。 |

**检查点：** `review`：Skill 交出路线草案和未覆盖特征后结束本轮，放行动作发生在厂内系统里，智能体既没有凭据也没有相应工具。之后每一处修改都以对规则文件的变更建议形式落盘，而不是悄悄生效，这样一条错误的经验不会无人察觉地进入知识库。

## 步骤

*以下按来源所述。*

1. 从 PLM 系统拉取每个新零件的 BOM 和 CAD 图纸 [[1]](#sources)。
2. 先用图像处理提取特征，再用视觉推理模型解读，识别每个工件所需的工艺（折弯、铣削、钻孔、焊接等）[[1]](#sources)。
3. 应用结构化的知识库，其中包含工位规则、工艺定义和工时逻辑。生成一份带工位分配和工时估算的路线草案 [[1]](#sources)。
4. 🛑 **审阅**：班组长检查路线草案，按需调整，并提交给生产。任何输出都可以手工修正 [[1]](#sources)。
5. 记录每一处修改。班组长随工艺演进更新知识库，系统因此不断改进 [[1]](#sources)。

**产出：** 一份已放行的工艺路线（工序、工位、工时），交给生产排程和班组。
**失败模式 → 防护：** 专业图纸没有任何单一模型能读懂 → 分层流水线（图像特征 → 视觉推理 → 规则知识库）。路线有误 → 强制班组长审阅并放行，修改日志回流到知识库 [[1]](#sources)。
**与相近工作流的区别：** 暂无相近者。AWF-0022 发票提取—匹配—路由（invoice extract-match-route）把文档转成已路由的交易，但属于财务领域，交付物和审批人都不同。
