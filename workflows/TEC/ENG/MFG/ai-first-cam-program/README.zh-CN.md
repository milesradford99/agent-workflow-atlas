# AI 优先的 CAM 编程

**工具变体：** `cloudnc-cam-assist` · `autodesk-fusion` · `mastercam`

## 背景

数控（CNC）机床靠一段程序切削金属：程序里是移动、主轴转速和换刀的指令。写这段程序的是 CAM 编程员。编程员从零件的三维模型出发，指定用哪台机床、哪几把刀，CAM 软件算出刀路——刀具走过的路径——再后处理成机床能跑的代码。在 3+2 机床上，零件被摆成一个角度、从几个方向分别加工，这又多出一些平时由人逐个判断的选择。这件事慢，是因为一个车间往往要为几百个只有尺寸不同的同族零件编程，而转速错了、进刀方向别扭、刀具根本够不到某个面这些问题，通常要等到报废一件或崩一把刀才会暴露。在这里，CAM 软件里的 AI 功能给出工序、刀路和切削参数的初稿；编程员仍然逐个打开程序，改掉不合适的地方再下发；操作员先加工一两个零件并检验，之后这个程序才算可信。这两道关卡留在人手上，因为第一道决定零件怎么做，第二道是唯一能证明它做对了的证据。

**术语：**
- **CAM**（computer-aided manufacturing，计算机辅助制造）：把零件模型变成机床指令的软件；设计零件的是 CAD。
- **刀路（toolpath）**：刀具走的路径，连同进给（走多快）和转速（转多快）。
- **3+2**：把零件摆斜，从几个固定方向分别铣削，而不是连续五轴联动。
- **后处理（post）**：把 CAM 里的刀路转换成某一台具体机床代码的步骤。
- **刀具库（tool database）**：车间刀柄和刀具的清单，含几何形状与切削极限；CAM 软件据此选刀和定参数。
- **装夹（work holding）**：零件如何被夹住，这限制了刀具能走到哪里。
- **尺寸变体（size variant）**：形状相同、只有几处尺寸不同的一族零件中的某一个。
- **首件检验（first article inspection）**：批量加工之前，测量刚下机的头几个零件。

## 用智能体搭建

**形态：** `platform`。生成经过碰撞检查的刀路、后处理成机床代码，需要 CAM 内核和这台机床自己的后处理器，验证程序则需要机床本身；通用智能体可以做围绕它们的计划、工艺卡和检查工作，本搭建方式正是这样用它。

**需要：** CAM 系统里的零件模型和车间机床定义，刀具库中已填好本次作业要用的刀柄和刀具；该 CAM 系统对应机型已启用的 AI 功能；对智能体这一侧：零件模型的特征清单（可导出）、刀具库导出文件、车间的切削参数规则、过去相似零件的程序，均需可读；一位持有 CAM 席位的编程员，以及带测量台的机床操作员。不要给智能体把程序下发到机床或启动循环的途径。

| 步骤 | 搭建方式 |
|---|---|
| CAM 中的零件模型 + 机床设置 + 刀具库 | 由编程员在 CAM 系统里完成；智能体可以读导出的特征清单和刀具表，在开工前指出缺项——少一个刀柄、某把刀没有切削数据。 |
| AI 生成工序、3+2 刀路、转速与进给 | CAM 系统自带的 AI 功能，这一步通用智能体替代不了；通过 MCP 让智能体读取它产出的内容。 |
| 🛑 review（编程员逐个调整程序） | Skill 准备评审材料：每个程序的工序清单、进刀方向、刀具与参数，以及它无法确认的车间规则；编程员在 CAM 席位里修改并批准。 |
| 后处理 | 在 CAM 系统里用机床的后处理器完成；智能体按清单核对后处理后的代码（刀号、工件坐标系、程序号），但无权下发。 |
| 试加工一两个零件 → 🛑 review（检验零件） | 由操作员在车间完成；检验结果回到 skill 里，skill 把它记在该零件名下，并为下一个变体标注同族模板。 |

**检查点：** `review`：两道关卡都在智能体够不到的地方，而且都要留痕。编程员的调整发生在 CAM 席位里，智能体在那里没有写入工具，skill 只负责交出评审单、取回已批准的程序；检验由操作员在测量台上完成，智能体只收到测量数据。整个搭建里没有任何途径能把程序下发到机床，所以未经审阅的程序无法启动加工。

**与来源相比：** 来源出自 2024-06，杂志文章在 2025-06 更新；厂商案例研究未注明日期。厂商案例研究本月已打开；杂志文章拒绝自动读取（HTTP 403），没有重新打开，其中的引语仍基于此前那次阅读。它们已超过十二个月，因此重新核对了工具：案例研究描述的 CloudNC CAM Assist，在 2026 年间扩展到了 [Fusion、Mastercam、Siemens NX、GibbsCAM、SolidCAM 和 Creo](https://www.cloudnc.com/blog/what-to-see-at-imts-2026-ai-assisted-cnc-programming-and-where-to-find-cloudnc)，2.0 工作流的策略编辑器（Strategy Editor）会在刀路回到 CAM 系统之前，把拟定的工序和选刀摊开供人审阅——也就是编程员的调整关卡，现在有了明确的评审界面，而不只是特征树。来源里那种“一次建好刀具库、在几百个变体上复用”的做法，仍然是车间自己的工作。本搭建方式没有增加 CAM 系统做不到的事；它把通用智能体放在外围，做阅读、核对和变体台账这些事，生成与验证仍留给平台。

## 步骤

*以下按来源所述。*

1. 在 CAM 系统中建立作业。载入零件几何，选择机床设置（其限制已内置），并在刀具库中填入夹具和切削刀具，供切削参数模块使用 [[1]](#sources)[[2]](#sources)。
2. 运行 AI。几分钟内它就写出约 80% 的程序：工序按文件夹分组，生成 3+2 刀路，并根据所填的夹具和刀具给出转速与进给 [[1]](#sources)[[2]](#sources)。
3. 🛑 **审阅**：编程员打开每个生成的程序并加以调整。包括从另一侧加工某些 3+2 特征，以及简化 AI 搞得过于复杂的策略。原文写道：'Each program still requires optimization.' [[1]](#sources)[[2]](#sources)
4. 对程序做后处理，在机床上试加工“一两个零件”。🛑 **审阅**：较新的员工先检验这些首件，再信任该程序 [[2]](#sources)。
5. 对于相似零件系列（该车间有数百个尺寸变体），用同一刀具库对每个变体重复上述步骤 [[1]](#sources)。

**产出：** 每个零件变体一份经过验证的 NC 程序，下发到车间。
**失败模式 → 防护：** AI 把策略搞得过于复杂，或在 3+2 加工中选了不顺手的进刀侧 → 编程员审阅并修改每个程序。操作员不信任 AI 的输出 → 让他们检查并修改程序的部分内容，并用首件验证。建立刀具库拖慢早期推广 → 一次建好，反复使用 [[1]](#sources)[[2]](#sources)。
**与相近工作流的区别：** 最接近的是 AWF-0059（图纸到工艺路线草稿），它起草带工位和工时的工艺路线。本工作流起草的是机床刀路本身。检查点是编程员逐个调整程序、检验首件，而不是班组长签发工艺路线。
