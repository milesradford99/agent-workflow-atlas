# 分区规划合规研究小组

**工具变体：** `fleece-ai`

## 背景

在法国，建房子要先申请 permis de construire（建筑许可），向所在市镇递交，材料里必须说明项目符合当地规划文件 PLU（plan local d'urbanisme）。这份文件逐地块规定：建筑离边界至少退多远、最高能建多高、能占多少比例的用地、要配多少个停车位，以及地块是否落在历史保护区里——那种情况下还要国家建筑师（ABF）同意。建筑师会写一份研究报告，逐条走一遍这些规则，并给出项目对应的取值，因为漏掉一条的申请会被拒或拖上好几个月。写这份研究又慢又重复：每个市镇的规则都不一样，PLU 动辄几百页，而每个项目都要用同样的格式走同样的流程。在这里，智能体规划研究，按规则领域检索并引用适用条款，逐条把规则与项目尺寸对照，再按公司格式起草说明文字。建筑师在研究报告进入报建材料之前，逐条对着引文核对并签字：签了字的误读是执业责任，而保护区里国家建筑师的同意也不是智能体能拿到的。

**术语：**
- **permis de construire（建筑许可）**：向市镇递交的法国规划许可申请。
- **PLU**（plan local d'urbanisme，地方城市规划）：市镇的规划文件，其书面规则管高度、退线、占地和用途。
- **退线（recul）**：建筑与地块边界或街道之间的最小距离。
- **占地比例（emprise au sol）**：建筑可占地块面积的最大百分比。
- **限高（hauteur）**：以某一指定点起算的最大高度，各市镇规定不同。
- **历史保护区**：列级古迹周边的地块，须由国家建筑师（ABF）认可方案。
- **规则领域（rule area）**：一组相关条款——退线、限高、占地、停车、遗产——研究报告按此组织。
- **报建材料（file）**：完整的许可申请：图纸、研究报告和表格。

## 用智能体搭建

**形态：** `skill`。一位建筑师在对话里做一份研究并签字；来源所说的“小组”，今天就是一个智能体按规则领域并行跑几个 subagent，也就是一个带 subagent 的 skill。

**需要：** 市镇公布版的 PLU——书面规则与图形附件——以及适用于该地块的分区；含各项规则所检验尺寸的项目简报，或注明哪些尺寸尚未确定；地块边界几何；公司的研究报告模板与措辞约定；该区域的遗产保护图。搭建里任何环节都不能递交许可或联系主管部门：这留给建筑师。

| 步骤 | 搭建方式 |
|---|---|
| 项目简报 + 地点 | Skill 的第一步：读简报，确定市镇与现行分区，取回 PLU 文件；公司若有规划门户的连接器或 MCP 服务器就用它，否则读取下载好的文件。 |
| 每个规则领域：子智能体检索当地分区条文 | 每个规则领域一个 Subagent，只给它该领域的指令；每条返回条款编号、引文和页码，找不到的就如实说找不到。 |
| 对照每条规则检查项目参数 | 逐条一个表格：规则值、项目值、差值、结论；简报里缺的数值，该行写“待确认”，而不是判为通过。 |
| 标出风险 | Skill 把硬性不合规与需要判断的情形分开——遗产问题、措辞含糊的条款——并指出是哪一条使它成为判断问题。 |
| 起草说明文字 → 按公司格式汇编 | Skill 按公司模板写研究报告，每条主张都注明所依据的条款。 |
| 🛑 sign-off（建筑师验证并签字） | Skill 交出研究报告和表格后停下；建筑师逐条对照引文核对，并在公司自己的文件系统里签字，智能体在那里没有写权限。 |
| 建筑许可申请 | 在智能体之外：由建筑师递交。 |

**检查点：** `sign-off`：研究报告离开智能体时只是草稿，每条规则都与其引文、项目取值并排摆着，签字发生在它的工具之外，所以它读错的规则是建筑师可以直接驳回的一行字，而不是埋在行文里的假设。本搭建方式不给智能体递交或修改报建材料的途径，也不给它联系国家建筑师的途径。

**与来源相比：** 来源出自 2026-07：一篇厂商博客，也是本条目的公开实例，本月已打开。它给出的数字是厂商自己的，且只提到一家公司的一个生产环境智能体。此后有这些变化：做分区检查的产品从可行性研究扩展到带引文的问答和模型化检查，但它们的覆盖范围是一个辖区一个辖区建起来的——2026 年一份比较文章描述了[一款主要面向澳大利亚的分区与规划规则数字化工具、一款带条文引用的规范问答工具、一款按 ICC 与地方修订审查图纸的工具](https://engtechnica.com/six-zoning-and-code-compliance-tools-bring-checks-earlier-into-architectural-design)，并且都是仅供参考。这正是本条目要填的空：某个市镇没有数字化规则库时，检索 PLU 条款并引用它是智能体的活，而让这份研究可用的是建筑师的签字。本月打开的页面里，没有任何一份显示法国的 PLU 能作为可执行规则集使用。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 主智能体接收项目简报和地点，并制定研究计划 [[1]](#sources)。
2. 子智能体检索并解读适用的 PLU（当地规划法规）条文，逐条核查退线、高度、占地比例、停车和遗产保护方面的限制 [[1]](#sources)。
3. 起草说明文字，并按公司格式汇编研究报告 [[1]](#sources)。
4. 🛑 **签发**：在研究报告用于建筑许可申请之前，“由人验证并签发”（'a human validates and signs off'） [[1]](#sources)。

**产出：** 用于法国建筑许可档案的城市规划监管研究报告。
**失败模式 → 防护：** 误读当地规则 → 逐点核查，并由建筑师签发。
**与相近工作流的区别：** 与 AWF-0058 同属一个类别，但那是审查方一侧的筛查，逐项检查都要批准。这里由申请人的建筑师产出研究报告，只需一次签发。
