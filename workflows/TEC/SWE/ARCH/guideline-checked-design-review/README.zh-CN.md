# 按准则审查设计文档

**与相近工作流的区别：** AWF-0072 带护栏的设计规格（Guardrailed design spec）由智能体撰写规格。这里由人撰写设计文档，智能体对照庞大的准则目录进行审查，并设有安全团队核实的检查点。产出物是评审发现，而不是规格。
**工具变体：** `slack`

## 步骤

1. 开发者在现有的基于 Slack 的流程中发起安全设计评审（Security Design Review）请求 [[1]](#sources)。
2. 分诊：智能体应用单独的内部准则，判断这份设计是否需要评审 [[1]](#sources)。
3. 智能体检索设计文档和相关的内部安全准则（160+ 条，外加 RFC 等标准），并交给上下文工程层处理 [[1]](#sources)。
4. 它对照每条准则检查设计，标出缺失的信息或明显的违规。它被调校得偏谨慎，宁可有些噪声，也要做到零漏报 [[1]](#sources)。
5. 🛑 **审阅**：分析结果先交给产品安全团队核实，之后才反馈给开发者 [[1]](#sources)。
6. 以真实设计文档上的人类专家评审为基准评测智能体，并规划在准则和模型变化时持续做基准评测 [[1]](#sources)。

**产出：** 针对一份设计文档、逐条对照准则的安全发现清单，经安全团队核实后才交给开发者。
**失败模式 → 防护：** 结构混乱的设计文档会降低准确率 → 人和智能体在写得好的文档上都表现更好。准则不断演进 → 规划持续的基准评测。通用智能体会漏掉各组织特有的规则 → 用定制工具编码内部准则集。
