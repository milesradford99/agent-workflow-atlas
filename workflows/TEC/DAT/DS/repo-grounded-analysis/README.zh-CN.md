# 基于代码库的数据分析

**工具变体：** `claude-code` · `cursor` · `datahub` · `glean`

## 背景

数据科学家被问到一个业务问题，比如某个指标为什么变了，就要写一份分析备忘录，交给需要做决定的人（干系人）。这项工作要跨越许多文件和好几天：找到合适的表，写查询和代码，核对数字。风险在于，基于错误的表写出言之凿凿的备忘录，比如那张表已经过时、没人维护，因为新人分不清公司信任哪些表。这里由智能体在团队的代码库里编写并运行代码，代码库里有团队的规则和有文档的数据表，智能体还会标明哪些是事实、哪些是推断。未经核对的表何时可以使用，由分析师决定；备忘录在被人采信之前也由分析师核实，因为这些数字会左右决策，而智能体自己分不清“已验证的表”和“看起来合理的表”。

**术语：**
- **数据科学家 / 分析师**：从数据中回答问题、并判断数字含义的人。
- **分析备忘录（analysis memo）**：一份简短的书面报告，写明结论以及每个论断背后的证据。
- **数据目录（data catalog）**：公司各张数据表的名录，写明含义、负责人、来源和健康状况。
- **已验证的表（verified table）**：数据团队核对过、并在目录中标为可信的表。
- **暂定（provisional）**：可用于探索，但不是最终结果，也不得分享。
- **试运行（dry run）**：向数据库询问一条查询会花多少成本，而不真正执行。
- **钩子（hook）**：在智能体工作的某个固定节点自动运行、并能拦截某项操作的脚本。
- **防护规则（guardrail）**：限制智能体能做什么的规则。
- **沉淀（residue）**：一次会话留给下一次的东西：新写的表说明、修好的技能、一条日志。

## 用智能体搭建

**形态：** `project`。分析要跨许多文件和好几天，而且有两条规则必须每次都成立（检查查询成本，以及对使用未验证表做记录并设卡），光靠 skill 的文字无法保证。代码库里还带有长期积累的知识：表文档、角色设定和许多操作手册。

**需要：** 团队代码库，其中有 `CLAUDE.md`、skills，以及每张表的文档（存什么、由哪条管道产出、用哪条查询定义）；连接到数据目录、内部搜索和代码托管平台的连接器（MCP servers）；只读的数据仓库角色；记录所触及未验证表的日志文件；钩子脚本。含敏感数据的表要完全放在智能体够不到的地方。

| 步骤 | 搭建方式 |
|---|---|
| 会话简报 | `CLAUDE.md` 要求智能体先运行简报 skill：分析师所在领域有什么变化、有哪些工作正在进行，来自代码库和代码托管平台。 |
| 读取代码库文档和实时元数据 | `CLAUDE.md` 规定智能体要像一位刚入职、对未成文的东西一无所知的能干分析师那样行事。智能体读取表文档，并通过目录和搜索连接器获取实时元数据；凡是没有文档的内容，就说“我不知道”。 |
| 可信度检查（已验证的表） | 一个 skill 规定：只有来自目录中标为已验证的表的结果才可信、才能分享；智能体对每张打算使用的表都读取这个标记。 |
| 表未验证？🛑 action | 见“检查点”。 |
| (编写代码 ⟲ 运行并读取输出) | 智能体编写代码，在只读角色下运行并读取输出。`PreToolUse` 钩子对每条查询做试运行，超出成本上限的就拦下。 |
| 附来源的备忘录，区分事实与推断 | 一个 skill 存放备忘录模板：每个论断链接到对应的查询或来源，并标明是事实还是推断。 |
| 🛑 review | 见“检查点”。 |
| 留下沉淀（文档、技能修复、日志） | 收尾 skill 为所触及的每张表提议补文档，也提议修复技能；钩子把所触及的每张未验证表追加到日志里。 |

**检查点：** `action`：`PreToolUse` 钩子会拦下对未标为已验证的表的任何查询，除非分析师在本次会话中批准了这张表；智能体必须先点明表名并展示其元数据。钩子把这次访问记入日志，备忘录把由此得出的每个数字标为暂定，权限规则则拒绝标为敏感的表。`review`：备忘录是草稿，智能体没有发送或发布它的工具；由分析师核实，并由分析师自己分享。

**与来源相比：** 唯一的来源在条目中没有日期；页面说该代码库现在的形态出现在 2026 年 1 月，文章写于大约半年之后，所以它的日期是 2026 年。这次核对时它能打开，并支持每一步。来源说，Markdown 规则只能影响行为，而不能约束行为，所以它给每条重要规则都配了代码层面的强制执行，这正是本搭建方式用钩子来做成本检查和未验证表关卡的原因。来源的代码库有约一百位贡献者和约 250 个技能；本搭建方式从寥寥几个开始，随着团队为表补文档再逐步增加。来源让同一个代码库配合多种智能体工具使用；本搭建方式用的是 Claude Code 的构件。来源说，它的最后一步（代码库研究自己的会话并提议新技能）仍在建设中；本搭建方式把它略去。来源不到 12 个月，所以无需再搜索更新的记录。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 分析师在编码智能体中打开共享的 DS 代码库。代码库提供指令（“上周刚入职的数据科学家”）、约 250 个技能、有文档的数据表和防护规则 [[1]](#sources)。
2. 会话开始时先给出简报，说明有什么变化、有哪些工作正在进行。智能体从 DataHub、Glean 和 GitHub 拉取实时上下文 [[1]](#sources)。
3. 智能体做可信度检查：只有来自 DataHub 中标记为已验证的表的结果，才可信、才能分享。对于没有文档记录的知识，智能体回答“我不知道——这在哪里有文档吗？”[[1]](#sources)
4. 🛑 **操作**：对未验证的非敏感表，智能体必须先点明表名、展示其元数据并获得分析师的明确签字确认，才能查询。该访问会被记录，数字标为暂定 [[1]](#sources)。
5. 智能体编写代码、运行、读取输出并迭代。成本检查会对每条查询做试运行，代码钩子强制执行防护规则 [[1]](#sources)。
6. 智能体撰写结论时，每个论断都链接到对应的查询或来源，并标明是事实还是推断 [[1]](#sources)。
7. 🛑 **审阅**：分析师在草稿被采信或分享之前先核实 [[1]](#sources)。
8. 智能体留下沉淀：为数据表补文档、修复某个技能，或记录所触及的未验证数据。技能的改进通过共享代码库惠及每个团队 [[1]](#sources)。

**产出：** 一份数字带有出处链接的分析备忘录草稿。经分析师核实后交给干系人，代码库中的知识库也随之增长。
**失败模式 → 防护：** 基于已弃用的表写出言之凿凿的报告 → 已验证表规则，暂定访问须经签字确认。硬性限制扼杀采用率 → 限制的是可信度和交付，而不是访问。Markdown 规则被忽略 → 每条规则都配上代码层面的强制执行 [[1]](#sources)。
**与相近工作流的区别：** AWF-0006 受管控的查询：一个问题 → SQL → 图表 → 审阅 → 高管签批。本工作流是在代码库中进行的多文件、多日分析项目，交付物是备忘录，额外的关卡是对未验证数据的访问签字确认。
