# 打分式设计令牌迁移

**与相近工作流的区别：** 最接近的是 AWF-0008（设计稿到代码），它借助截图 diff 从 Figma 画框构建新界面。本工作流改写整个代码库中成千上万处已有的令牌用法。它增加了用于建立规则的试点与审计阶段、codemod 与 AI 之间的分流，以及发布前的全面人工检查。
**工具变体：** `claude-code` · `regex-codemod` · `ambrook-agent-graph-migration` · `figma-mcp`

## 步骤

1. 研发与 UX 就共用的令牌词汇表达成一致。把代码库切分成小的组件切片 [[1]](#sources)。
2. 试点循环：AI 迁移一个切片。🛑 **审阅**：研发和 UX 一起审计结果。每遇到一处错误替换，就让 AI 解释其理由，然后把这一缺口补进集中的规则与 skill 文件。重复直到规则稳定 [[1]](#sources)。
3. 锁定打分矩阵。每个候选令牌按十六进制色值匹配、上下文契合度和主题一致性三项各打 0–3 分 [[1]](#sources)。
4. 正式运行：正则 codemod 处理简单的一对一映射。含糊或多重意图的令牌走 AI 打分矩阵。先迁移浅色主题，这样即使选错，线上渲染的颜色也不变 [[1]](#sources)。
5. 加上 lint 关卡，让迁移成果保持下去。🛑 **审阅**：人工点遍每个界面和每种状态，两种主题都要看（没有快照工具）。手动修复剩余的错误选择 [[1]](#sources)。

**产出：** 一个从工具类令牌迁移到语义化、支持主题的令牌的代码库，可以直接上深色模式。
**失败模式 → 防护：** 对整个代码库下提示词会漏文件，并把不同文件的逻辑混在一起 → 分块，并把简单映射分流给 codemod。意图含糊 → 用经审计的试点结果构建打分矩阵。隐蔽的错误选择 → 先迁移浅色主题，再人工检查两种主题 [[1]](#sources)。
