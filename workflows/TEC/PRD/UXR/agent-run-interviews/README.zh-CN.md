# 智能体执行的用户访谈

**工具变体：** `anthropic-interviewer` · `conveo` · `great-question-ai-moderator`

## 背景

用户研究员通过访谈了解人的需求、经历和行动原因。共用访谈提纲让回答可以比较，但访谈者也要跟进意外回答，不能只照读固定问卷。本工作流让智能体起草提纲、与参与者对话，再整理得到的文字记录。研究员批准方案并解释结论，因为问题可能诱导参与者，反复出现的主题也不能证明样本代表所有人。

**术语：**
- **评分标准 / 自适应访谈（rubric / adaptive interview）**：规定提问与追问方式的指南，以及随参与者回答变化的对话。
- **样本 / 假设**：招募到的群体，以及研究要考察的想法。
- **聚类 / 普遍程度**：把相似回答归在一起，以及某主题在已观察样本中的常见程度。
- **同意 / 一手数据**：对指定研究用途的许可，以及直接从参与者收集的证据。

## 用智能体搭建

**形态：** `service`。参与者与访谈智能体互动，不需要研究员操作每场对话；研究状态和审批保存在会话之外。

**需要：** 获批的招募与同意流程；参与者聊天界面及分访谈存储；研究目标、样本定义和提纲；获批的文字稿分析工具。参与者身份标识与访谈文本分开保存，执行约定的保留规则，不提供公开数据发布工具。

| 步骤 | 搭建方式 |
|---|---|
| 目标 + 假设 → 起草提纲 → 🛑 plan | Skill 起草提纲。服务先保存研究员批准的版本，再开放参与者会话。 |
| 每个参与者：自适应访谈 | Agent SDK 程序把参与者界面连接到 Skill，每场访谈保留独立对话状态与获批提纲。 |
| 主题聚类 → 用原话回答问题 | 脚本与只读 Subagents 整理文字稿；Skill 返回附参与者编号和来源位置的发现，并明确样本分母。 |
| 🛑 review → 结论 + 公开数据 | 服务准备私密的研究结论包；由研究员解释，并单独授权符合参与者同意范围的数据发布。 |

**检查点：** `plan`：访谈开始前，研究员修改并批准提纲、抽样和允许的话题；没有批准，服务拒绝开启会话。`review`：研究员检查文字稿、聚类及引述证据。分析智能体没有公开发布或导出参与者数据的工具；发布由人控制。

**与来源相比：** 来源出自 2025-12，已于 2026-11 打开。检索发现 [Anthropic 后续的 Interviewer 研究](https://www.anthropic.com/research/your-thoughts-on-ai)，出自 2026-09，已于 2026-11 打开，仍由参与者选择是否公开分享。通用智能体可以通过服务开展文字访谈，但参与者界面、同意记录和研究治理仍需实施。本设计不假设能够使用 Anthropic 内部访谈工具或厂商的语音、视频功能；这些需要单独查证并集成。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 研究团队编写系统提示词，写明方法、各样本的假设，以及用户研究团队规定的访谈规划做法 [[1]](#sources)。
2. 智能体根据研究目标起草访谈评分标准，包括问题和计划流程。这样在数百场访谈中问题保持一致，同时允许适度发散。🛑 **计划**：人类研究员编辑并定稿方案 [[1]](#sources)。
3. 智能体按方案与每位参与者进行实时的自适应访谈。在报告的测试中，每场约 10–15 分钟 [[1]](#sources)。
4. 另一个工具对各访谈记录中涌现的主题聚类，并衡量每个主题的普遍程度。智能体用示例原话回答每个研究问题 [[1]](#sources)。
5. 🛑 **审阅**：发布结论之前，由人类研究员与智能体一起分析访谈记录 [[1]](#sources)。

**产出：** 一项涵盖数百到数千场访谈的研究，含主题、各主题的普遍程度和原话。原文中，经参与者同意的访谈数据已公开发布。
**失败模式 → 防护：** 追问不深入 → 由研究员制定详细的研究方案。把主题聚类当作事实 → 人工共同分析访谈记录。样本偏差（众包招募） → 在研究中明确说明这一局限 [[1]](#sources)。

**与相近工作流的区别：** 最接近的是 AWF-0061（引文核验式综合），由人审阅对已有访谈记录做综合的每一步。本工作流中，智能体自己执行访谈。人工检查点在访谈方案和最终分析，产出是一份新的一手数据集。
