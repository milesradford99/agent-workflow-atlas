# 原话核验的研究综合

**工具变体：** [`claude-code` kit](variants/claude-code.md) · `claude-code-skill` · `notebooklm` · `dovetail` · `otter-ai`

## 背景

用户研究员把访谈录音整理成对人的需求及原因的理解。寻找相关段落很重复，但解释它们需要上下文和产品知识。一句听起来正面的陈述，实际可能是在描述令人困扰的权宜办法。本工作流让智能体检索原话，并根据核实过的材料起草报告。研究员逐条检查引语、归纳洞察并排序，最后批准发布，防止貌似合理的摘要变成没有依据的证据。

**术语：**
- **受访者编号 / 时间戳**：代替姓名的标识，以及某段话在录音中的位置。
- **主题 / 亲和图**：反复出现的观察，以及把相关证据归组形成洞察的方法。
- **综合 / 情绪**：解释证据的含义，以及从说话内容推断的感受。
- **TL;DR**：提供给干系人的简短摘要。
- **温度**：影响模型输出变化的设置，不是事实准确性的保证。

## 用智能体搭建

**形态：** `skill`。一位研究员在对话中处理一项研究；[现有套件](variants/claude-code.md)提供流程和原话检查脚本。

**需要：** 带说话人编号与时间戳、已去标识的文字稿；供研究员核对的原始录音；研究问题和报告模板。个人数据留在获批存储中，综合期间不给智能体公共网页、邮件、Confluence 写入或 Slack 发帖工具。

| 步骤 | 搭建方式 |
|---|---|
| 文字稿 → 每个问题：检索原话 → 主题 | Skill 检索证据库并记录受访者编号和来源位置。套件脚本把引文与导出的文字稿核对；内置 Subagents 可以检查不同的问题。 |
| 🛑 review → 人工综合并排序 | Skill 交出原话和建议主题后停下。研究员核验依据，并提供归组和优先级。 |
| 报告草稿 → 🛑 sign-off → 发布 + TL;DR | Skill 仅根据已核验洞察起草报告，把报告和摘要保存为文件。研究员批准，并通过自己的系统发布。 |

**检查点：** `review`：研究员对照文字稿或音频逐条检查引语和主题，包括上下文；子串匹配不能确定含义。`sign-off`：Skill 交出报告和干系人摘要后停下；没有发布工具，因此最终发布由研究员执行。

**与来源相比：** 证据出自 2025-06 至 2026-06，另有 2026-04 的更新。2026-11 已打开 Photoroom，Donska 和 ShopBack 的 Medium 页面拒绝访问。有限检索截至 2026-11 未找到可完整阅读、描述同一流程的更新第一手记录；一项后续研究的页面返回 Cookie 验证，因此未采用。通用 Skill 可以基于导出的文字稿替代定制原话查询界面；解释和排序仍由研究员完成。所链接套件的发布步骤是可选项，需明确批准；本节范围更窄，把发布留在智能体之外。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 研究员把所有录音和转录稿放进同一个证据库，例如 Dovetail，或每项研究一个 notebook [[2]](#sources)[[3]](#sources)。
2. 针对每个研究问题，研究员让智能体给出匹配的原话，并附受访者编号和时间戳或来源链接。一次只问一个问题，一直问到结果穷尽为止 [[2]](#sources)[[3]](#sources)。
3. 研究员要求给出 3 位及以上受访者提到的主题，附直接引语，并明确告诉它不要解读情绪 [[1]](#sources)。
4. 🛑 **审阅**：研究员对照原始录音或转录稿核验每个主题和每条原话。在一次实践中，这一步发现“每天查看仪表盘”其实是在绕开失灵的告警，而不是用户活跃的表现 [[1]](#sources)。
5. 由人对洞察进行聚类并排定优先级（在 Miro 中做亲和图）。AI 只用作唱反调的角色，检查是否有遗漏或偏见 [[2]](#sources)。
6. 智能体根据已核验的洞察起草报告 [[3]](#sources)。
7. 🛑 **签发**：研究员批准报告，随后发布到 Confluence，并把 TL;DR 发到 Slack 频道 [[3]](#sources)。

**产出：** 一份引用可追溯、经过核验的洞察报告，发布到 Confluence 或做成幻灯片，用于支撑设计和产品决策。
**失败模式 → 防护：** 编造原话（ChatGPT 即使在温度 0.1 下也出现过）→ 基于来源的检索加 100% 原话核对 [[3]](#sources)。仅凭字面词语误判情绪 → 提示词禁止解读情绪，并由人重新听录音 [[1]](#sources)。

**与相近工作流的区别：** AWF-0007 反馈到原型：那个工作流把反馈变成原型。本工作流止于经过核验的洞察报告，不做构建。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [New workflows for empty categories](../../../../../research/2026-11-new-workflows.md)。

- [Lana Hung, How we transformed qualitative synthesis](https://medium.com/@LanaHung/how-we-transformed-qualitative-synthesize-with-ai-chatgpt-notebooklm-claude-code-0b4df664a15f) (2026-06-14)。ShopBack 的用户研究团队改用 Claude Code 综合技能，并发布到 Confluence/Slack。"The entire process typically took 3 — 5 days." → "we were able to complete most reports within a single day"。*第一手：是；可信度：高。*
