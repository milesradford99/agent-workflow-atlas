# 长尾客户自主续约

**工具变体：** `gainsight-atlas` · `planhat` · `quivly` · `statisfy`

## 背景

按年订阅销售的软件公司，必须在每份合同到期前拿下客户的续约。大客户通常由客户成功经理（CSM）负责：查看产品的使用情况，提前几周或几个月联系客户，回应异议，商定价格调整。数以百计的小客户，也就是长尾客户，往往因为 CSM 人手不够而得不到这种照顾，有些客户流失仅仅是因为没人联系，或者一笔银行卡扣款失败了。在这里，智能体盯着这些小客户，以 CSM 的名义给每位客户写信，并在固定的折扣上限内完成续约。有三件事仍留在人手里：客户负责人叫停联系的权利、所有超出上限的请求，以及对自动化打法效果的复盘。因为价格让步要花公司的钱，而每一封消息都以公司的名义送到付费客户手上。

**术语：**
- **客户成功经理（CSM）**：负责留住现有客户、促成续约的人。
- **客户经理（AE）**：负责商务关系和合同的销售人员。
- **长尾账户**：数量众多的小客户，单个客户的收入不足以配一名专属 CSM。
- **健康度**：根据使用量、支持工单和账单得出的评分，用来估计客户续约的可能性。
- **ARR（年度经常性收入）**：一个客户的订阅每年带来的收入。
- **CRM**：记录客户、联系人和销售商机的系统，这里是 Salesforce。
- **CPQ（配置、定价、报价）**：生成商机所附报价的工具。
- **电子签**：把续约合同发出做电子签名，这里通过 DocuSign。
- **数字化客户成功经理**：负责自动化、一对多客户成功项目的人，而不是管理自己名下的一批客户。
- **打法（play）**：由某个信号触发的一套预设动作，例如续约前 60 天发提醒。

## 用智能体搭建

**形态：** `service`。每次运行由续约节点和账户信号触发，现场没有人；人只看到事先通知、例外项和结果日志。

**需要：** 通过 MCP 连接器读取 CRM、产品使用、支持和账单数据；一个从 CSM 邮箱发信的邮件连接器；对 CRM 商机和报价工具的写权限；一个电子签连接器；一个状态存储，记录每个账户所处阶段、已发出的事先通知和负责人的答复；把折扣上限和升级规则写成参考文件，上限检查也读取它。智能体不得持有银行卡信息；账单数据只以状态的形式进来。

| 步骤 | 搭建方式 |
|---|---|
| 划分长尾账户 | skill 旁边的参考文件列出客户层级，以及智能体可以处理哪些账户；由人维护。 |
| 每个账户：监测健康度、使用量、账单 | 云端定时任务，或由自己的调度器每天运行 `claude -p`；脚本拉取信号，挑出到达续约节点（90、60、30 天）或越过阈值的账户。 |
| 续约窗口：🛑 action (客户负责人否决窗口) | 运行时把事先通知发给客户负责人，并记入状态存储；之后的运行只有在窗口期过去且无人反对时才继续。 |
| 以客户成功经理（CSM）身份发送个性化触达 → 客户回复 | skill 根据账户历史起草消息；邮件连接器发出，并在下一次运行时读取回复。 |
| 折扣上限内：修订报价 + 更新 CRM + 电子签 | CPQ、CRM 和电子签连接器。`PreToolUse` 钩子对照上限和状态存储检查每一次报价和电子签调用。 |
| 超出上限或特殊情况：🛑 handoff | 账户进入续约专员的队列，附上往来邮件、各项信号和起草好的回复。 |
| 🛑 review (数字化客户成功经理复盘结果、调整打法) | 每次运行都追加写入结果日志；经理阅读日志，修改打法和上限文件。 |

**检查点：** `action`：对于状态存储中事先通知尚未记录放行的账户，`PreToolUse` 钩子会拦下发信调用，所以负责人一旦反对，联系就一定会停下。`handoff`：`PreToolUse` 钩子拒绝任何超过折扣上限的报价或电子签调用，不管智能体怎么决定；skill 把这些账户转到人的队列；智能体无法修改上限文件。`review`：经理事后审阅结果日志和被升级的账户；智能体没有修改打法的工具。

**与来源相比：** 来源和公开实例出自 2026-05 至 2026-11；两个 Planhat 页面未注明日期。四个来源都是厂商材料：一场录制的产品演示、一篇厂商博客和两个厂商页面，没有任何客户讲述自己跑完整个流程。演示展示了事先通知、触达，以及在 8% 上限内完成的一次续约；其他页面只笼统地介绍分层和触发。本搭建沿用了演示中提到的防护——上限放在提示词之外——把它写进钩子。是否让通用智能体在无人阅读的情况下向客户发送带价格的消息，由公司自己决定；更谨慎的做法是把发送一步保留为起草好的消息，那就成了它的 `checkpointed` 近亲 AWF-0049。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 客户成功负责人按客户层级划定覆盖范围；长尾账户由智能体推进打法，战略账户仍由人主导 [[2]](#sources)[[3]](#sources)。
2. 智能体监测每个账户的健康度、使用量、支持和账单信号，并在续约节点（例如 90/60/30 天）触发 [[2]](#sources)。
3. 🛑 **操作**：联系客户之前，智能体先向 AE 发消息，告知续约日期和预期 ARR，让对方有机会提出异议；在 Gainsight 的演示中，AE 回复「Looks good. Go ahead.」 [[1]](#sources)。
4. 智能体从 CSM 的邮箱发出个性化的续约触达，并阅读回复 [[1]](#sources)[[4]](#sources)。
5. 如果客户要求的折扣在硬性上限之内（演示中为 8%），智能体修订报价，更新 CRM（Salesforce）中的商机，并通过 DocuSign/CPQ 发出电子签，无需人工参与 [[1]](#sources)。
6. 🛑 **接手**：智能体把超出上限的请求、自动尝试后健康度仍低于阈值的账户以及特殊情况，连同完整上下文和起草好的消息一并转给人 [[1]](#sources)[[2]](#sources)[[3]](#sources)。
7. 🛑 **审阅**：数字化客户成功经理审阅被升级的账户和操作历史，并删减或调整打法 [[2]](#sources)[[3]](#sources)。

**产出：** CRM 中已完成续约的长尾账户，以及一个需要人介入的账户的优先级队列。
**失败模式 → 防护：** 智能体在价格上让步过多 → 在工作流中设置硬性折扣上限，而不是写在提示词里 [1]。无人负责的账户悄然流失 → 账单和使用量信号驱动触发 [2]。客户始终接触不到真人 → 自动尝试失败固定次数后转交 [3]。
**与相近工作流的区别：** 最接近的是 AWF-0049 续约窗口风险简报：那是产出风险简报和挽留方案，由 CSM 批准每次触达。本工作流中智能体自己推进续约对话，并在折扣上限内成交；人只会看到事先通知和例外情况。交付物（已完成的续约与简报）和自主程度（抽检与分段）都不同。

## 公开实例

覆盖度（截至 2026-11-13）：**薄弱**：只有匿名、与厂商相关或记者转述的说法。收集与复核见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [Gainsight, Atlas in Action](https://pulselibrary.gainsight.com/video/atlas-in-action/) (2026-05-27)。演示中，在 AE 收到事先通知、客户提出 6% 的折扣请求（上限 8%）后，由智能体完成续约。"the estimated ARR for this particular renewal was $210,000 US"。*第一手：厂商；可信度：低。*
- [Planhat, Fluxx customer story](https://www.planhat.com/fluxx) (undated)。续约触达智能体代表 CSM 发送，每位 CSM 负责 100 多个账户。"engaging with renewal conversations six to eight months out"。*第一手：厂商；可信度：中。*
