# 供应商确认的商品纠错

**工具变体：** `openai`

## 背景

平台的商品页是供应商自己写的，而供应商描述自家产品往往含糊：说是"实木"的边桌可能是贴皮，说是"真皮"的包可能是复合皮。客户正是按这些词筛选，所以写错一个词不是错别字——它把人引向与需求不符的商品；而当这个词带有法律含义时，就是消费者保护问题。上百万条商品页靠手工改不可能，而让模型不问自改更糟，因为商品页写了什么，责任在供应商。本工作流让模型对照一份"标签含义指南"逐条审核商品页、分配标签，然后把结果分开处理：有把握的，直接改正并通知供应商；没把握的，或改动有风险的，先请供应商确认。之后由员工对商品样本做实物检查，改动效果用 A/B 测试衡量而不是自称。这个分流就是设计本身：智能体决定的是"什么时候该问"，不是"答案是什么"。

**术语：**
- **商品页（listing）**：供应商提供的商品页面，含标题、描述和属性。
- **标签（label）**：一个受控的属性值——颜色、材质、尺寸——客户据此筛选。
- **标注指南（label guide）**：写明每个标签的含义，以及凭什么证据可以使用它。
- **高风险（high risk）**：改错会带来法律或安全后果的改动，例如材质或阻燃声明。
- **供应商确认（supplier confirmation）**：供应商同意对自己商品页所做的改动。
- **员工实物抽检（associate sample audit）**：员工下单或取样，把标签与实物核对。
- **A/B 测试（A/B test）**：把改正后的商品页与旧页在曝光与点击上对比。

## 用智能体搭建

**形态：** `service`。上百万条商品页按批处理，没人逐条启动；人出现在供应商确认、实物抽检和测试设计这三处。

**需要：** 标注指南作为带版本的文件，每个标签一条，含定义与可依据的证据；商品页本身，以及供应商联系方式；一个能写入商品页、且写入会带上改动来源的通道，让供应商看得出改了什么、为什么改；一条留下记录的供应商确认渠道；用于抽检的取样/下单流程；A/B 测试所需的分析数据。智能体不能改动供应商已提出异议的商品页，也不能在审定模板之外给供应商发消息。

| 步骤 | 搭建方式 |
|---|---|
| 依据网络信息 + 内部定义构建标注指南 | Skill 依据公开标准与公司自己的定义起草指南，由品类团队批准；指南版本写进每一条改动记录。 |
| 每个商品：对照指南审查详情 + 分配标签 | 脚本把商品页批量送审；Skill 只有引用了所用证据才能给出标签，指南未覆盖的情形标为"不改"。 |
| 高置信度：更新商品列表 + 通知供应商 | 写入走商品页工具，改动被打上指南版本与模型版本；供应商通知由固定模板生成并留痕。 |
| 低置信度 / 高风险：🛑 action（供应商确认） | 改动停在发给供应商的确认队列里，回复到达之前商品页保留原值；材质或安全类标签无论分数高低一律走这条路径。 |
| 🛑 sample（员工检查样本） | 按计划抽取改动过的商品页，买回或取样后实物核对，结果按标签分别报告，以便暂停某一类标签。 |
| A/B 测试影响 | Skill 提出测试设计——哪些商品页、看哪个指标、跑多久——但测试由团队解读，在测试之前不把任何改动说成"改进"。 |

**检查点：** `action`：确认队列是有争议或有风险改动的唯一通道，而商品页工具会拒绝"改动记录里既没有达标置信度、也没有供应商回复"的写入，所以智能体说不动这道闸。`sample`：抽检是员工的实物核对，也是模型替代不了的那道检查——它抓的是"很有把握但一直错"的标签，而这恰恰是 A/B 指标看不出来的失效。高风险标签在策略层面就被送往 `action`，而不是写在提示词里。

**与来源相比：** 来源出自 2026-09：一份厂商案例，也是本条目的公开实例，本月已打开。它报告了规模与测试结果，没有公开分流阈值或抽检比例。此后有这些变化：这套分流规则已经被写成目录工作的通用策略。2026 年的一篇从业文章给出了[明确的晋级策略——置信度达标且与已有声明值无冲突才自动；有冲突一律人工；法律或安全属性无论置信度高低一律人工——并提醒就地修改供应商声明的值，会丢掉"供应商说的"与"模型推断的"之间的区别](https://paragraph.com/@techcirkle/building-a-product-catalogue-enrichment-pipeline-that-doesnt-corrupt-your-data)。这正是本搭建方式采纳的部分：改动记录同时保存原值与建议值，这也让供应商的异议有据可答。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 利用网络信息和 Wayfair 的内部定义，生成一份说明每个标签含义的指南 [[1]](#sources)。
2. 模型对照指南审查商品信息，并分配标签（颜色、材质、尺寸） [[1]](#sources)。
3. 高置信度：直接更新内容并通知供应商。🛑 **操作**：低置信度或高风险的改动需先经供应商确认 [[1]](#sources)。
4. 🛑 **抽检**：员工在结构化审计中检查商品样本 [[1]](#sources)。

**产出：** 已纠错的线上商品列表；影响通过 A/B 测试衡量。
**失败模式 → 防护：** 错误地改动供应商内容 → 按置信度和风险分流到供应商确认。
**与相近工作流的区别：** 上文的 Instacart/Walmart 把疑问转给内部审核员。这里由外部供应商批准有风险的改动，并且直接就地编辑线上商品列表，因此检查点的负责人和产出都不同。
