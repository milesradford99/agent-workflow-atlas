# 副驾式属性建议

**工具变体：** `gpt-4o`

## 背景

当一个店铺接入新品牌或新系列时，每件商品带来的只有标题和一张图，别的几乎没有。让目录可用的那些字段——材质、纹样、版型、洗护——必须在上线之前填好，而填它们的是内容专员：看图片、看供应商的描述，然后把手动打进去。这活不光鲜，却直接影响一件商品何时能卖。在这里，副驾在专员动手之前为每个字段给出建议值，而每条建议都是预填并带标记的，让人看得出它来自模型而不是人。随后专员逐条接受或修改：走过表单的那一次点击就是批准，凡是没有人逐字段确认过的内容都不会发布。这就是全部的交换——建议省下的是打字，不是判断；而用这套工具的专员同时也改进提示词，所以模型表现较弱的那些品类，由最懂它们的人来修。

**术语：**
- **条目（article）**：店铺持有的一件商品——记录加上它的属性。
- **属性（attribute）**：材质、纹样、版型之类的具名字段，通常从固定的允许值里选。
- **上架（onboarding）**：把供应商的商品纳入目录的过程。
- **预选值（pre-selected value）**：已经填进表单、等待专员确认的建议值。
- **来源标记（provenance mark）**：显示哪些值由模型提出的可见标记。
- **受控上线（controlled rollout）**：只对部分品类或属性开启副驾。
- **提示词贡献（prompt contribution）**：专员的修改回流到建议的生成方式里。

## 用智能体搭建

**形态：** `skill`。一位内容专员对着表单、一次处理一件商品；这套搭建加的是建议这一步和来源标记，而不是一条流水线。

**需要：** 商品本身的文字与图片，以及供应商材料；属性模式与每个字段的允许值，因为落在允许集之外的建议是制造工作而不是节省工作；一份记录——哪些值被提出、被接受、被修改，按模型与提示词版本分别记；按品类分批上线的清单。智能体不需要发布权限：发布是专员复核之后自己做的事。

| 步骤 | 搭建方式 |
|---|---|
| 新品条目上架 | Skill 从专员正打开的商品记录开始，只把图片和供应商文本当作事实来源。 |
| 提示词生成器建议属性（按来源标记） | 一次建议生成，约束在每个字段的允许值之内，逐字段写出一条建议，并附上它所用的证据——图片的哪一块、供应商的哪句话——以及给表单用的来源标记。 |
| 🛑 review（内容创建专家接受或修改每个预选值） | 表单就是检查点：每个字段都是预填且未勾选的，只有人的点击才表示接受；Skill 没有任何可以发布商品的工具。 |
| 发布 | 在智能体之外，用店铺自己的工具完成。 |
| 专家参与改进提示词 | 被接受与修改的值按字段和提示词版本留存，专员团队据此看到建议错在哪里，进而改提示词或暂停某个品类。 |

**检查点：** `review`：建议永远只是预填的字段。发布是在店铺工具里另做的一个动作，搭建到不了那里；而来源标记让未经确认的值在复核时看得见，所以来源报告的那种失败——约四分之一的建议是错的——代价是一次修改，而不是一条错的上架信息。停用某个品类是这套控制的另一半：建议弱的品类直接关掉副驾，而不是"更用力地审"。

**与来源相比：** 来源出自 2024-09：一份第一手工程记录，也是本条目的公开实例。它已超过十二个月，因此重新检索了这项实践；该页面本轮没有重新打开。此后有这些变化：同一家公司现在公开了属性补全的数字，而那条路径不再逐字段经过人。其 2026 年第一季度业绩称，生成式图像处理[每天为约 6,000 件商品补全缺失的材质成分数据，并且最多 85% 的商品能在三天内上线](https://corporate.zalando.com/en/financials/zalando-q1-2026-results)。那是单条路径上的单个属性，不构成对这套副驾的替代，但它标出了本条目所在的分界线：能从单一来源核实的字段走向自动补全加抽样，需要对商品做判断的字段仍留在人手上。上面的搭建方式把所有字段都留在人这一侧，是对更新材料更保守的读法。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 在构建之前，领域专家在大量条目样本上审阅模型预测，以选定模型 [[1]](#sources)。
2. 在内容创建工具中，GPT-4o 生成的属性建议被预先选中，并以紫色圆点标出其来源 [[1]](#sources)。
3. 🛑 **审阅**：内容创建人员对每个属性做最终决定 [[1]](#sources)。
4. 用户参与改进提示词；上线时可以纳入或排除某些商品和属性 [[1]](#sources)。

**产出：** 在店铺中上线的条目属性，缩短了上线时间。
**失败模式 → 防护：** 约 25% 的建议有误 → 每个值都由人批准。小众品类表现较弱 → 按品类受控上线。
**与相近工作流的区别：** AWF-0048 缺口匹配式知识维护产出的是知识库文章。这里的产出是结构化的商品数据，逐字段批准（辅助），而不是作为文档起草后再审阅。
