# 分发式竞品周报

**工具变体：** `claude-cowork-skill-slack-notion`

## 背景

竞争情报团队帮助产品营销人员了解竞争对手的变化，以及客户在销售沟通中提出的问题。许多消息只是单个案例，但反复出现的异议或已确认的产品变化，可能需要更新销售指导。本工作流汇集限定时间段内的信号，把有用条目交给负责人。智能体可以过滤并起草简报。竞争情报负责人检查解释，产品营销人员决定如何修改材料，因为销售团队会依赖这些内容。

**术语：**
- **CI / PMM**：竞争情报，以及产品营销经理。
- **商机作战室 / 异议**：支持某个销售机会的频道，以及潜在客户提出的顾虑。
- **竞争卡片（battlecard）**：将产品与替代方案比较的简明销售指导。
- **分级门槛 / 发布中心**：哪些信息值得关注的书面规则，以及记录产品发布的地方。

## 用智能体搭建

**形态：** `service`。每周扫描无人值守运行；负责人收到草稿，各条目负责人收到获批的后续事项。

**需要：** 获批的只读 Slack 和 Notion MCP server (connector) 工具；书面分级门槛；产品领域与负责人对应表；现有竞争卡片；私密审阅队列。商机和客户细节留在获批系统中。扫描运行不能修改销售材料或向大范围频道发帖。

| 步骤 | 搭建方式 |
|---|---|
| 每周：最近 7 天 → 分级 → 剔除噪音 | 调度器启动 `claude -p` (headless)。Skill 读取限定时间窗、去重，并套用书面的证据门槛。 |
| 结构化简报 + 负责人 + 更新建议 | Skill 为每项写出来源链接、负责人、满足门槛的原因，以及建议修改的竞争卡片位置。 |
| 🛑 review → 🛑 handoff | 服务把草稿存入负责人的审阅队列。获批条目再分派给对应 PMM，由其更新材料。 |

**检查点：** `review`：CI 负责人在广泛分发之前查看草稿及来源证据。扫描运行没有发帖工具；批准后才启动单独的分发步骤。`handoff`：对应 PMM 收到证据和建议，亲自修改竞争卡片；智能体不能编辑销售事实来源。

**与来源相比：** 来源出自 2026-04，已于 2026-11 打开。针对更新实例和所列工具的检索，截至 2026-11 未找到更新实例。原流程已经把扫描打包为 Skill；服务补上调度、持久运行记录及审阅队列，不虚构额外的专家角色。原帖说明作者持续参与，但没有记载严格的技术性发帖前审批。本设计明确增加这道防护，并保留负责人对竞争卡片修改的判断。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 智能体每周从内部 Slack 频道（竞品新闻、商机协作、活跃的商机作战室）和 Notion 产品发布中心拉取内容，限定在最近 7 天 [[1]](#sources)。
2. 智能体对照书面的门槛分级：某个异议出现在 2+ 个商机中、竞争对手有已确认的公开动作，或现有竞争卡片存在缺口。过滤掉一次性的提及 [[1]](#sources)。
3. 智能体起草结构化简报，把每一条标注给负责该产品领域的 PMM，并附上更新什么、在哪里更新的建议 [[1]](#sources)。
4. 🛑 **审阅**：竞争情报（CI）负责人持续参与，审阅发布到 PMM 频道的简报草稿 [[1]](#sources)。
5. 🛑 **接手**：负责的 PMM 作为领域专家，处理该条目并更新竞争卡片 [[1]](#sources)。

**产出：** 每周发布到 PMM 频道的简报，带有标注了负责人的竞争卡片更新项。
**失败模式 → 防护：** 噪音淹没频道 → 明确的分级门槛 [[1]](#sources)。单人成为瓶颈 → 把条目分派给各自负责的 PMM，而不是集中交给一位分析师 [[1]](#sources)。大范围拉取来源时的上下文限制（评论者提出）→ 限制每次运行的来源数量。

**与相近工作流的区别：** AWF-0030 议题树研究（Issue-tree research）产出一次性的战略答案。本工作流是对内部商机信号的周期性扫描，并分派给竞争卡片（battlecard）的负责人。
