# 直播口播稿起草

**工具变体：** `deepseek` · `doubao` · `douyin-jichuang`

## 背景

在中国的直播带货里，主播在抖音等平台上对着直播间观众卖货，每个商品都需要一份口播稿作为依据。口播稿先给出一个让人停下来听的理由，点出买家的问题，再列出商品的好处，每个商品约 40-60 秒。手工写一份，要先收集商家条款，再阅读别人对这个商品写了什么，然后改成口语，一天的商品清单要这样反复做。风险在措辞上：广告法和平台规则禁止夸大或虚假宣传，还有一份违禁词清单，直接照搬网上文案的脚本很容易踩线。智能体负责起草脚本并过滤违禁措辞。法务（公司的法律人员）仍要逐份检查脚本是否合规，因为公司要为直播里说的话负责；主播也要把每份脚本调整成自己的风格，因为话是主播来讲的。

**术语：**
- **口播稿 / 口播话术**：直播中某个商品的口语化脚本。
- **SKU**：单独销售、单独上架的一个具体商品规格。
- **机制**：本场直播的促销办法，如折扣、组合或赠品；**零售价 / 直播价**是日常价格和直播间价格。
- **种草**：推荐商品、引发购买欲望的帖子或视频，字面意思是“种下草”；**小红书**是许多种草内容发布的社交平台。
- **KOL / KOC**：关键意见领袖（粉丝众多）和关键意见消费者（有一定影响力的普通顾客）。
- **切入点、痛点、卖点**：脚本的三个部分：开场角度、买家的问题、商品的卖点。
- **敏感词 / 违规词**：平台或广告法禁止或标记的词，例如绝对化用语。
- **法务**：公司的法律人员。
- **主播**：直播间的主持人。

## 用智能体搭建

**形态：** `skill`。团队成员在对话中准备一场直播的商品清单，所以一个负责写每份脚本并运行过滤的 skill 就够了；两次审阅是人来读输出。

**需要：** 每个 SKU 的商家商品表（名称、零售价、机制、直播价）；同一批商品的种草文案和评论，由人从平台导出或收集（遵守各平台的条款）；作为参考文件的违禁词和夸大宣传清单，并随平台规则保持更新；含三个部分的脚本模板。不要让智能体接触直播工具。

| 步骤 | 搭建方式 |
|---|---|
| 商家商品信息 → 收集 KOL/KOC 种草文案 + 评论 | skill 把商品表和收集到的文案当作文件读取。 |
| 生成口播稿 (切入点, 痛点, 卖点)，并用违禁词和夸大宣传过滤 | skill 按模板为每个 SKU 用口语化中文起草一份脚本，只使用商品表里的事实。放在 skill 旁边的脚本把每份草稿与违禁词清单做匹配，skill 改写被标记的内容，并把它们列给审核人。 |
| 🛑 review (法务合规审核) | 见“检查点”。 |
| 🛑 review (主播个性化调整) | 见“检查点”。 |
| 直播 | 由人主持直播，智能体不参与。 |

**检查点：** `review`，两次。第一次，skill 列出每份脚本及其过滤结果后停下，由法务把每份标为通过或退回，只有通过的才往下走。第二次，主播把通过的脚本改成自己的风格。智能体没有把脚本送进直播系统的工具，所以脚本能上播，只是因为有人把它放了进去。过滤只是词语匹配，不是法律意见，所以不能代替第一次审阅。

**与来源相比：** 来源出自 2025-03 至 2025-04，距这次检查已超过一年。这次会话中两个来源都打不开，因此它们的报道只能依据条目原文。来源描述的是团队使用通用对话模型（先用豆包，后换成 DeepSeek 以获得更口语的语气）并预先设定规则；没有报道由智能体运行整个流程，本搭建方式是为此做的设计。新华网 2026-05 的一篇报道指出，直播电商平台正在整治用 AI 仿冒公众人物肖像和声音的行为（[news.cn](https://www.news.cn/tech/20260514/404dcffbf8744e3f9592a3beecd6d13c/c.html)），所以合规审核还应确认脚本没有借用真人的姓名、声音或形象。截至 2026-11，没有找到关于这套脚本起草流程的更新记述。先拆解热销视频、再把同样的逻辑用于短视频脚本的那一步，不在本搭建方式之内。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 团队成员录入商家的商品信息：名称、零售价、机制、直播价 [[1]](#sources)。
2. 智能体从小红书等种草平台收集 KOL/KOC 对同一商品的介绍和评论 [[1]](#sources)。
3. 团队提示模型把商品事实和收集到的文案重新组合成口播话术：切入点、痛点、卖点；预先设定的规则过滤敏感词、违规词以及夸大或虚假的宣传（每条脚本约 40-60 秒） [[1]](#sources)。
4. 🛑 **审阅**：法务逐条检查每份口播稿是否合规 [[1]](#sources)。（另外，同一平台还让 AI 预审商家资质和品牌授权，并输出结构化的审核意见 [[2]](#sources)。）
5. 🛑 **审阅**：主播在开播前把脚本调整成自己的风格 [[1]](#sources)。
6. 脚本进入直播；先拆解热销视频，同样的逻辑也复用于短视频脚本 [[1]](#sources)。

**产出：** 每个商品一份经合规检查的口播稿，交给主播用于直播。
**失败模式 → 防护：** 文案太书面、不口语 → 换模型（豆包换成 DeepSeek），输出更口语化 [1]。网上的文案把违规或夸大内容带进脚本 → 规则过滤加法务审核 [1]。
**与相近工作流的区别：** 最接近的是 AWF-0018 聚类-简报-起草式内容：那是产出带排名跟踪的 SEO 文章。本工作流则根据商家条款和种草文案，为每个 SKU 产出直播带货的口语化脚本，以法务合规审核和主播个性化调整为检查点。交付物和检查点都不同。

## 公开实例

覆盖度（截至 2026-11-13）：**薄弱**：只有匿名、与厂商相关或记者转述的说法。收集与复核见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [新榜 / 虎嗅, interview with 交个朋友 VP 刘亚平](https://www.huxiu.com/article/4263055.html) (2025-04-21)。AI 口播稿嵌入交个朋友的直播工作流；法务审核后再由主播修改。"成功将单条口播稿的时间从人工的20～40分钟缩短至2分钟，单人力单日输出量也从20条提升至100+条"。*第一手：访谈；可信度：高。*
