# 聚类简报成文内容

**约束：** Google 2024 年 3 月的“规模化内容滥用”（"scaled content abuse"）政策针对的是主要为了排名而批量生成、没有增加价值的页面，无论是否自动化 [[19]](#sources)。这就是为什么专家意见环节和编辑审阅是这个物种的组成部分，而不是可选项。

## 背景

许多公司在自己的网站上发布文章，让搜索相关话题的人找到他们，这种做法叫搜索引擎优化（SEO）。内容营销人员看人们搜什么来选题，把相近的搜索归成一组，让一篇文章回答一组；研究已经排在前面的页面写了什么，给文章写简报，向了解产品的人要事实和案例，然后发布。几周后检查页面排名有没有上升，没有就重新修改。手工做这件事很慢，而只靠关键词批量生成页面的捷径，恰恰是 Google 垃圾内容政策针对的对象。智能体负责归类、阅读竞品、写简报、起草和检查。写哪些选题仍由人批准，因为只为排名而做的页面可能受到处罚；每篇文章发布前也由编辑审阅，因为网站上的每一个论断都由公司负责。

**术语：**
- **SEO（搜索引擎优化）**：调整网站页面，让搜索引擎在相关搜索中展示它们。
- **Search Console**：Google 的免费工具，告诉网站所有者哪些搜索给哪些页面带来了访问。
- **关键词聚类**：一个页面能回答的一组相关搜索。
- **SERP（搜索结果页）**：一次搜索得到的结果列表；“前 10 名”指排在最前面的十个页面。
- **搜索意图**：搜索者想要什么（答案、对比、买东西），决定什么样的页面能排上去。
- **简报**：一篇文章的写作说明：目标关键词、读者提出的问题、竞品涵盖的内容、篇幅。
- **专家（SME，领域专家）**：公司内外了解产品、能提供真实案例和数据的人。
- **术语覆盖度**：文章在多大程度上用到排名靠前的页面用的词和话题，用 Surfer、Clearscope 等工具打分。
- **内链**：网站内一个页面指向另一个页面的链接。
- **CMS（内容管理系统）**：编辑和发布网站页面的系统。
- **PR（拉取请求）**：提交审阅、通过后才应用的修改提议。
- **规模化内容滥用（scaled content abuse）**：Google 对主要为排名而批量生产、对读者没有帮助的页面的称呼。

## 用智能体搭建

**形态：** `skill`。由一位编辑在对话中处理一批选题：计划批准一次，之后每篇文章的简报、草稿和检查都摆在编辑面前，由编辑过目后才会发布。

**需要：** 搜索数据的访问权限，可以是通过 MCP 连接器连到 Search Console，也可以是 SEO 工具的导出文件；产品文档，以及专家笔记、访谈或原创数据，以文件形式提供；网站的文风指南和获准的内链目标清单，作为参考文件放在 skill 旁边；一个保存每个页面改动和排名检查记录的地方。智能体没有 CMS 的发布权限。

| 步骤 | 搭建方式 |
|---|---|
| 种子主题 → SEO API → 关键词聚类 | skill 通过连接器拉取搜索数据，或读取导出文件，把聚类和页面计划写入文件。 |
| 🛑 plan | 见“检查点”。 |
| 每个文章：搜索结果前 10 名 → 简报 | 内置子智能体，每篇获批文章一个，读取排名靠前的页面并返回简报。 |
| 产品文档 + 专家意见 → 起草 | 主对话根据简报、产品文档和专家材料起草。缺少专家意见的地方，skill 会停下来问编辑。 |
| 事实、文风、链接检查 | 一个没见过起草过程的子智能体，逐条核对论断与来源，对照文风指南检查草稿，并对照获准清单检查链接。 |
| 🛑 review → CMS | 见“检查点”。 |
| 第 30/90 天检查排名 → 更新 | 同一个 skill 的后续会话读取 Search Console 和页面记录，提出带前后数据的修改建议。 |

**检查点：** `plan`：skill 把聚类和页面计划写入文件然后停下。只起草编辑标为获批的页面，计划里写明每个页面在排名之外增加了什么价值。`review`：skill 展示草稿和检查结果后停下。智能体没有发布到 CMS 的工具，所以由编辑发布；更新建议只有在人应用之后才会到达线上页面。

**与来源相比：** 来源出自 2025-12 至 2026-09；Google 政策页面是 2024-03 的，并不是一次实例。来源 20（FutureSearch）把更新循环作为定时任务运行，以拉取请求的形式提出修改。同样的循环也可以用云端定时任务（截至 2026-11 为研究预览）运行，但本搭建方式把整个流程放在编辑的一次会话里。来源 21（Olsina）讲的是一个人用 AI 工具做简报、起草和编辑，没有智能体在运行流程；另一个公开实例（The SEO Agent Team）没有说明人工关卡；本搭建方式加上了条目步骤所要求的停顿。本搭建方式里没有仅凭工具评分来选关键词的步骤。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 智能体拉取种子主题和搜索数据。一个实例通过 MCP 服务器（`mcp-server-gsc`）从 Claude Code 调用 Google Search Console API，并把原始 JSON 存到磁盘 [[20]](#sources)。另一个实例把目标关键词喂给 SEO 工具（Semrush ContentShake、Also Asked），并让 AI 按搜索意图给大型关键词清单分组 [[21]](#sources)。
2. 智能体建立关键词聚类和页面计划。由脚本计算变化量并把查询映射到页面，另有一个智能体读取未匹配的查询，标出需要新建页面的空缺 [[20]](#sources)。
3. 🛑 **计划**：由编辑批准撰写或修改哪些聚类和页面。按 Google 的规模化内容政策，只有在排名之外还能增加价值的内容才会推进 [[19]](#sources)。
4. 对每篇文章，智能体研究排名靠前的结果并写简报：目标关键词、用户提出的问题、竞品的切入角度和字数建议。详细的简报产出的草稿，比只给一个主题提示词好得多 [[21]](#sources)。
5. 智能体加入产品文档和专家意见（独家案例、客户成果、原创数据）[[21]](#sources)。它在通用 LLM（Claude 或 ChatGPT）里以简报为上下文起草，把结果当作原材料 [[21]](#sources)。
6. 智能体和编辑检查事实、文风和链接。对照一手来源核实每个论断，去掉套路化的 AI 措辞，对照排名靠前的页面给术语覆盖度打分（Surfer、Clearscope）但不堆砌关键词，让格式匹配搜索意图，并加入 AI 建议的内链 [[21]](#sources)。
7. 🛑 **审阅**：编辑在发布前审阅草稿。在 FutureSearch 的循环里，建议的修改以 PR 加报告的形式送达，一位非技术成员花约 20 分钟挑选采用哪些。没有任何内容自动生效 [[20]](#sources)。
8. 团队带着生成的元数据发布到 CMS [[21]](#sources)。
9. 智能体在第 30 天和第 90 天检查排名并更新页面。它把每次改动记入每个页面的 `experiment_history`，附前后数据和结果（改善、持平或倒退），下一轮运行在提出新改动前先读取这份历史 [[20]](#sources)。

**产出：** CMS 中已发布、经编辑批准的文章，外加驱动下一轮更新的、按页面记录的实验日志。
**失败模式 → 防护：** 编造事实，例如不存在的以太坊升级，或把功能归到错误的链上 → 强制对照一手来源或专家做事实核查 [[21]](#sources)。页面先上榜，随后因互动数据暴露意图不匹配而下滑 → 依据搜索意图选择格式 [[21]](#sources)。与竞品混为一谈的通用页面，或主要为排名而批量生成的页面 → 专家意见和原创数据 [[19]](#sources) [[21]](#sources)。工具的激进建议导致关键词堆砌 → 自然覆盖，并做可读性检查 [[21]](#sources)。全站标题千篇一律 → 轮换标题格式 [[20]](#sources)。智能体未经审核就改线上页面 → 改动走 PR，由人来应用 [[20]](#sources)。

## 公开实例

覆盖度（截至 2026-11-06）：**部分**：有第一手实例，但只覆盖流程的一部分，或检查点设在别处。来自 [Where are the real runs?](../../../../../research/2026-11-real-runs.md)；每个数字都已对照原页面复核。

- [Daniel Hnyk, FutureSearch](https://futuresearch.ai/blog/self-optimizing-seo-pipeline/) (2026-03-18)。Search Console → 按页面的分析智能体 → PR；由人挑选做哪些改动。"69 changes proposed"；"The human spends 20 minutes deciding"。*第一手：是；可信度：高。*
- [Victoria Olsina, *AI for SEO Content: 6-Month Test*](https://victoriaolsina.com/blog/ai-seo-content/) (2025-12-26)。简报 → AI 草稿 → 创始人补充意见 → 人工编辑和事实核查。"from 2-3 to 8-10 long-form articles monthly"。*第一手：是（未点名网站）；可信度：中。*
- [The SEO Agent Team](https://www.theseoagent.ai/blog/ai-seo-case-study) (updated 2026-09-19)。关键词队列 → 8 个聚类 → 草稿 → 检查 → 发布，没有说明人工关卡。"61 new pages in roughly fifteen weeks"。*第一手：厂商（自家网站）；可信度：中。*
