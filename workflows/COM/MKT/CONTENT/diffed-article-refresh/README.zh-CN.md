# 带对比的文章更新

**工具变体：** `claude-code` · `n8n` · `rag`

## 背景

公司博客会积累成百上千篇文章，时间一长就过时：产品多了新功能，竞品发布了更好的页面，搜索结果变了，文章排名下滑。内容编辑或 SEO 专员（搜索引擎优化：让页面在人们搜索时被展示出来）会更新其中最差的那些。这意味着要弄清哪些内容已经过时，看现在排名靠前的页面讲了什么，然后用原有的文风重写文章，又不破坏仍然有效的部分。手工做，耗费的编辑时间不亚于写一篇新文章。智能体负责调研、起草更新，并准确展示它改了什么。编辑仍要对照原文阅读这些改动并发布，因为一篇行文流畅的草稿可能描述并不存在的功能，而公司要为页面上写的内容负责。

**术语：**
- **SERP（搜索结果页）**：一次搜索得到的结果列表；调研这一步读取其中排名靠前的页面。
- **目标关键词**：这篇文章希望排上去的搜索词。
- **语义相似度检查**：比较文章与竞品页面在含义和话题上有多接近。
- **风格指南**：公司关于文风、结构和措辞的书面规则。
- **产品提及核对**：把文章中每处描述公司产品的地方，与产品实际能做的事逐一核对。
- **diff（对比）**：原文与新文并排显示，高亮每处改动。
- **CMS（内容管理系统）**：编辑和发布网站页面的系统。
- **短代码、结构化数据标记**：页面里供 CMS 或搜索引擎读取的特殊标记，例如嵌入的组件或结构化数据；改坏它们会让页面出问题。

## 用智能体搭建

**形态：** `skill`。编辑一次更新一篇文章，并且在对话中读 diff，所以一个装有流程、风格指南和以往草稿的 skill 就够了。

**需要：** 文章的线上 URL 和目标关键词；获取搜索结果和竞品页面的方式（SEO 工具的 API 或导出文件，或智能体自带的联网能力）；作为参考文件放在 skill 旁边的风格指南和几篇以往获批的草稿；产品真实功能的最新清单；站内链接。智能体没有发布到 CMS 的工具。

| 步骤 | 搭建方式 |
|---|---|
| 文章 URL + 目标关键词 → 抓取线上文章 | skill 抓取页面并存成文件。每一步都把输出存成文件，因此任何一步都可以重跑。 |
| SERP + 竞品调研 → 与自家文章做相似度检查 | 内置子智能体读取排名靠前的页面，返回它们涵盖内容的摘要；skill 拿它与文章对比。 |
| 更新方案 → 标出过时内容 → 核对产品提及 | 主对话写出方案，列出过时段落，并把每处产品提及对照功能清单核对。 |
| 起草更新 | 主对话依据风格指南和以往草稿，用原有文风起草，链接、短代码和标记原样保留。 |
| 并排 diff | 由脚本把原文件与草稿对比，生成高亮的视图。 |
| 🛑 review | 见“检查点”。 |
| 适配 CMS 格式 → 发布 | skill 准备可直接进 CMS 的文本。由人发布。 |

**检查点：** `review`：skill 展示 diff 和产品提及核对结果后停下；编辑对照原文读 diff，修改，然后才发布。智能体没有 CMS 发布工具，所以没有编辑的同意，任何内容都到不了线上网站。

**与来源相比：** 来源出自 2026 年（Kokoc，无月份）和 2026-06（Semrush）。来源 1 起初用 n8n 工作流搭建，调研可行而起草不行，后来改用 Claude Code，每一步一个 skill；本搭建方式用一个 skill 加内置子智能体就能覆盖同样的内容。来源 2 讲的是公司自建的智能体，按计划从共享表格取任务；这个队列不属于本搭建方式，它从编辑指定的一篇文章开始。来源中关于节省时间或成本的报告，这里不再重复。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 编辑把已有文章的 URL 和一个目标关键词交给智能体 [[1]](#sources)。Kokoc 的优化师把任务排在一张共享的 Google Sheet 里，由智能体按计划取走 [[2]](#sources)。
2. 智能体抓取线上文章，调研 SERP 和排名靠前的竞品，并对现有文章与竞品做语义相似度检查 [[1]](#sources)。
3. 智能体综合出更新方案，找出过时内容，并做产品提及核对，避免草稿描述并不存在的功能 [[1]](#sources)。Kokoc 把文章与排名靠前页面的“理想结构”对比并排出修改的优先级，根据当前排名选择小改还是全面重写 [[2]](#sources)。
4. 智能体依据风格指南和以往草稿，用原有的文风起草更新；每个技能都把输出存成文件，因此任何一步都可以重跑 [[1]](#sources)。Kokoc 的智能体还会保留内部链接、短代码和结构化数据标记，并输出可直接进 CMS 的 HTML [[2]](#sources)。
5. 智能体生成原文与新稿的并排对比，高亮改动 [[1]](#sources)；Kokoc 的智能体会为编辑记录改了什么 [[2]](#sources)。
6. 🛑 **审阅**：文章走正常的编辑流程（审阅、修订、编辑、配图）；编辑借助 diff 对照原文，抓出编造的内容 [[1]](#sources)；Kokoc 的编辑在排版人员发布之前做最后的事实核查和验证 [[2]](#sources)。

**产出：** 一篇已有文章的更新版，加上改动 diff，经编辑签发后发布到 CMS。
**失败模式 → 防护：** 编造的产品功能细节看上去很可信 → 产品提及核对加上与原文的 diff，让这类问题一分钟就能抓出 [1]。模型改动代码、插入内容或格式 → 约束输出并保留原有区块 [2]。
**与相近工作流的区别：** 最接近的是 AWF-0018 关键词簇简报起草内容，它规划关键词簇并根据简报撰写新文章（计划检查点 + 草稿审阅），只在最后的循环里提到更新旧文。本工作流的输入是一篇已经上线的文章，交付物是修订方案加 diff，没有计划检查点，编辑的审阅是基于 diff 进行的。AWF-0177（直播带货脚本）与此无关。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Fourth collection pass](../../../../../research/2026-11-fourth-pass.md)。

- [Semrush, I rebuilt our content update pipeline in Claude Code](https://www.semrush.com/blog/how-i-rebuilt-our-content-update-pipeline/) (2026-06-25)。Semrush 的九技能更新流水线；编辑通过 diff 发现了一个编造的功能。"a reviewer can catch them and check in one minute instead of 20 minutes". *第一手：是；可信度：高。*
- [Kokoc.com, Как мы автоматизировали процесс обновления статей](https://kokoc.com/keysi/kak-my-avtomatizirovali-protsess-obnovleniya-statey-v-blog-s-pomoshchyu-rag-agenta/) (2026)。代理机构用智能体加编辑检查更新了其 1,200 篇博客文章中约 10% 的内容。"Затраты снизились на 80% — осталась только необходимая редакторская проверка.". *第一手：是；可信度：高。*
