# 广告变体矩阵

## 步骤

1. 从客户评价、论坛帖子和用户证言中挖掘买家的语言，并就产品和优惠做一次结构化访谈，产出定位简报。之后可以让 Claude 扮演理想客户，在写任何广告之前对信息做压力测试 [[1]](#sources)。基于真实评价写的脚本，用的就是买家自己的话 [[2]](#sources)。
2. 建立矩阵。把 8–12 个角度（痛点、愿景、社会认同、异议处理）与受众细分对应起来 [[1]](#sources)。在 Meta 上按影响力给各个维度排序：概念，其次是形式，再次是买家画像，然后是发布身份，之后是钩子，最后是文案。在同一个概念上只换钩子或只换文案，看起来仍是同一条广告 [[3]](#sources)。一个品牌可以维持 3–5 条画像线，每条 2–3 条广告 [[3]](#sources)。
3. 🛑 **计划**：由营销人员批准本周投放哪些单元格，规模与命中率相匹配。大约 5–7% 的测试广告会成为爆款，所以每周规划 5–10 个概念，每个 2–3 个变体，并把花费按 80/20 分配给已验证的爆款和测试 [[3]](#sources)。
4. 为每个单元格生成文案（UGC、长篇故事和直接响应形式的主文案、标题和描述），以及包含场景、演员指导和视觉提示的创意简报 [[1]](#sources)。然后用图像模型做静态图，用 Arcads、Argil、Creatify、HeyGen 或 Mirage Studio 等工具做数字人 UGC 视频，变换场景、机位和背景，而不是只跑一个静态的数字人镜头 [[1]](#sources) [[2]](#sources)。
5. 检查宣称和品牌安全：确保脚本承诺不超出产品实际能做到的，并鉴于 FTC 对未披露 AI 内容的执法，在每条数字人广告开头加上 AI 生成声明 [[2]](#sources)。
6. 🛑 **审阅**：由人过滤 AI 的产出，通常从 10–20 个变体筛到值得测试的 3–5 个，并对简报和最终选择负责。未经审核就发布 AI 产出，是文中点名的失败模式 [[3]](#sources)。
7. 批量上传；在相同的优惠、脚本和受众上比较工具或概念时，每个测试组一个广告组 [[2]](#sources)。在创意库里按概念、形式、画像和发布身份给每个素材打标签 [[3]](#sources)。
8. 每周读取效果。爆款的标准是：学习期结束后连续 7 天 CPA 不高于目标，每天 1–2 个转化。其余的砍掉，并用 Meta 的 "Use Existing Post" 推广爆款，让它们保留已有互动 [[3]](#sources)。用新的数字人和脚本放大已验证的类型 [[4]](#sources)。
9. 规划下一个矩阵。当频次超过 3.0、CPM 上涨超过 20% 或 CTR 下降超过 15% 时轮换放量素材（健康的账户每 7–14 天更新一次），并且每 90 天把胜率最高的概念原型反馈进简报模板 [[3]](#sources)。

**产出：** 一组经过审阅、带标签、已在广告组中上线的广告变体，外加每周的爆款/落后者复盘和为下一个矩阵提供种子的创意库。
**失败模式 → 防护：** 诡异的或只有单一场景的静态数字人，看起来像 AI 且很快疲劳 → 用高拟真度的工具，并变换场景和角度 [[2]](#sources)。承诺过度的脚本，ROAS 看起来不错，但后来导致退货和差评 → 审阅前先做宣称检查 [[2]](#sources)。未披露 AI 内容 → 强制加声明 [[2]](#sources)。同一画像上的大量钩子变体几个月内就触顶 → 改为扩展画像和概念 [[3]](#sources)。过度细分的广告系列总卡在学习期 → 减少数量、放宽范围 [[3]](#sources)。复制爆款会重置社会认同 → 用 "Use Existing Post" [[3]](#sources)。未经审阅的 AI 产出 → 人工审阅环节 [[3]](#sources)。来源并未证实：把竞品广告库挖掘和客服工单作为输入。两个有记录的实例都没有描述这两项。
