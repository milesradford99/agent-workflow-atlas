# 广告变体矩阵

## 背景

靠社交媒体付费广告在线卖货的公司（主要投在 Meta 旗下的 Facebook 和 Instagram），需要源源不断的新广告：同一条广告对同一批人连放几周，效果就会下滑，成本随之上涨。效果营销人员或小型代理团队决定测试哪些信息，把每条做成文案、静态图和短视频，用小额预算投放测试，只留下少数能回本的。手工做的难处在于量：每周几十个变体，每个都要文字、简报和画面，而大多数注定会输。智能体负责起草调研摘要、测试矩阵、文案和创意简报，并筛查脚本里有没有产品兑现不了的宣称。图片和数字人视频由生成工具制作。投放什么、上传前每条广告是否通过，仍由营销人员决定，因为每条广告花的是公司的钱，并以公司名义公开作出承诺，消费者保护法会让公司为这些承诺负责。

**术语：**
- **角度（angle）**：广告主打的购买理由，例如痛点、愿景、社会认同或对异议的回应。
- **钩子（hook）**：广告的开场一句或头几秒，用来让人停止划屏。
- **人群画像（persona）**：广告所面向的一类典型买家。
- **矩阵（单元格）**：由角度、钩子、形式和画像组成的测试网格；一个单元格就是其中一种组合。
- **静态图（static）**：静止图片形式的广告。
- **UGC（用户生成内容）**：模仿普通顾客对着镜头说话的视频；**数字人 UGC** 用 AI 生成的出镜人代替真实创作者。
- **创意简报**：制作一条广告的说明：场景、演员指导、视觉提示。
- **宣称检查、品牌安全**：检查广告没有承诺产品做不到的事，也没有会让品牌难堪的内容。
- **广告组（ad set）、批量上传**：Meta 广告管理工具里共用一份预算和受众的广告单元；一次把许多广告装进广告组。
- **学习期**：广告上线后，Meta 的投放系统还在摸索该给谁看的那段时间。
- **CPA、ROAS、CPM、CTR、频次**：每次获客（成交或注册）成本、广告支出回报率、千次展示成本、点击率，以及每人平均看到这条广告的次数。
- **创意疲劳**：同一批受众看同一条广告次数太多，效果随之下降。
- **"Use Existing Post"**：Meta 的一个设置，让新广告沿用已有帖子投放，从而保留那条帖子的点赞和评论。
- **FTC**：美国联邦贸易委员会，负责执行广告真实性规则。

## 用智能体搭建

**形态：** `platform`。静态图和数字人视频出自图像与数字人视频生成工具，广告要在 Meta 的广告管理工具里上线；通用智能体可以以 `skill` 的形态承担调研、矩阵、文案、简报和宣称检查，由一位营销人员在对话中处理一周的矩阵。

**需要：** 产品和优惠说明；导出的客户评价、论坛帖子和用户证言；作为参考文件放在 skill 旁边的品牌语气和产品允许使用的宣称清单；从广告管理工具导出的上周效果数据；图像工具和数字人视频工具的账号。不要给智能体任何能创建、上传广告或为广告充值的广告管理工具。

| 步骤 | 搭建方式 |
|---|---|
| 广告库、评价、工单 | skill 读取导出的评价和证言，在对话中完成产品访谈，然后写出定位简报。 |
| 角度 × 钩子 × 形式 × 人群画像矩阵 → 🛑 plan | skill 把矩阵写成表格文件，单元格数量按本周测试预算确定，然后停下。 |
| 每个单元格：文案、静态图、数字人 UGC 视频 | 内置子智能体为每个单元格写文案和创意简报。图片和数字人视频在生成工具上制作，工具有 API 时通过 API，否则由人来做。 |
| 宣称 + 品牌安全检查 | 一个没见过起草过程的子智能体，对照宣称清单逐条检查脚本，并确认带有 AI 声明。 |
| 🛑 review | 见“检查点”。 |
| 批量上传 | 由人在广告管理工具里上传。skill 可以写好带标签（概念、形式、画像、发布身份）的上传表。 |
| 按周：读取效果 → 砍掉落后者 → 下一个矩阵 | skill 读取效果导出数据，按参考文件里的爆款标准判断，列出该砍和该留的广告，并以爆款为起点开始下一个矩阵。 |

**检查点：** `plan`：skill 写完矩阵文件就停下，只为营销人员批准的单元格起草文案。`review`：skill 展示各个变体及宣称检查结果后停下，由营销人员挑出要测试的。智能体没有上传广告或修改预算的工具，所以在人把广告装进广告管理工具之前，没有一条广告会花钱或面向公众。

**与来源相比：** 来源出自 2025-12 至 2026-07；来源 1 未注明日期。来源 1 是一个 Claude Code 工作流，只覆盖调研、角度、文案和简报。来源 2 和 4 讲的是团队使用数字人视频工具，来源 3 是一家代理公司的测试规则；没有一个来源报告由智能体从矩阵一路运行到上传和每周淘汰。视频这一步依赖生成工具，搭建方式把它留在工具里。挖掘竞品广告库和客服工单出现在流程里，但没有来源描述过。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 营销人员让 Claude 从客户评价、论坛帖子和用户证言中挖掘买家的语言，Claude 再就产品和优惠做一次结构化访谈，产出定位简报。之后可以让 Claude 扮演理想客户，在写任何广告之前对信息做压力测试 [[1]](#sources)。基于真实评价写的脚本，用的就是买家自己的话 [[2]](#sources)。
2. 智能体建立矩阵，把 8–12 个角度（痛点、愿景、社会认同、异议处理）与受众细分对应起来 [[1]](#sources)。团队在 Meta 上按影响力给各个维度排序：概念，其次是形式，再次是买家画像，然后是发布身份，之后是钩子，最后是文案。在同一个概念上只换钩子或只换文案，看起来仍是同一条广告 [[3]](#sources)。一个品牌可以维持 3–5 条画像线，每条 2–3 条广告 [[3]](#sources)。
3. 🛑 **计划**：由营销人员批准本周投放哪些单元格，规模与命中率相匹配。大约 5–7% 的测试广告会成为爆款，所以每周规划 5–10 个概念，每个 2–3 个变体，并把花费按 80/20 分配给已验证的爆款和测试 [[3]](#sources)。
4. 智能体为每个单元格生成文案（UGC、长篇故事和直接响应形式的主文案、标题和描述），以及包含场景、演员指导和视觉提示的创意简报 [[1]](#sources)。然后团队用图像模型做静态图，用 Arcads、Argil、Creatify、HeyGen 或 Mirage Studio 等工具做数字人 UGC 视频，变换场景、机位和背景，而不是只跑一个静态的数字人镜头 [[1]](#sources) [[2]](#sources)。
5. 团队检查宣称和品牌安全：脚本的承诺不能超出产品实际能做到的；鉴于 FTC 对未披露 AI 内容的执法，每条数字人广告开头都要加上 AI 生成声明 [[2]](#sources)。
6. 🛑 **审阅**：由人过滤 AI 的产出，通常从 10–20 个变体筛到值得测试的 3–5 个，并对简报和最终选择负责。未经审核就发布 AI 产出，是文中点名的失败模式 [[3]](#sources)。
7. 团队批量上传；在相同的优惠、脚本和受众上比较工具或概念时，每个测试组一个广告组 [[2]](#sources)。并在创意库里按概念、形式、画像和发布身份给每个素材打标签 [[3]](#sources)。
8. 营销人员每周读取效果。爆款的标准是：学习期结束后连续 7 天 CPA 不高于目标，每天 1–2 个转化。其余的砍掉，并用 Meta 的 "Use Existing Post" 推广爆款，让它们保留已有互动 [[3]](#sources)；再用新的数字人和脚本放大已验证的类型 [[4]](#sources)。
9. 营销人员规划下一个矩阵：当频次超过 3.0、CPM 上涨超过 20% 或 CTR 下降超过 15% 时轮换放量素材（健康的账户每 7–14 天更新一次），并且每 90 天把胜率最高的概念原型反馈进简报模板 [[3]](#sources)。

**产出：** 一组经过审阅、带标签、已在广告组中上线的广告变体，外加每周的爆款/落后者复盘和为下一个矩阵提供种子的创意库。
**失败模式 → 防护：** 诡异的或只有单一场景的静态数字人，看起来像 AI 且很快疲劳 → 用高拟真度的工具，并变换场景和角度 [[2]](#sources)。承诺过度的脚本，ROAS 看起来不错，但后来导致退货和差评 → 审阅前先做宣称检查 [[2]](#sources)。未披露 AI 内容 → 强制加声明 [[2]](#sources)。同一画像上的大量钩子变体几个月内就触顶 → 改为扩展画像和概念 [[3]](#sources)。过度细分的广告系列总卡在学习期 → 减少数量、放宽范围 [[3]](#sources)。复制爆款会重置社会认同 → 用 "Use Existing Post" [[3]](#sources)。未经审阅的 AI 产出 → 人工审阅环节 [[3]](#sources)。来源并未证实：把竞品广告库挖掘和客服工单作为输入。两个有记录的实例都没有描述这两项。
