# 分级授权广告优化

**工具变体：** `google-ads-api` · `ga4` · `claude-code` · `n8n` · `github-issues`

## 背景

投放搜索广告的公司（用户搜索时，Google 显示在结果上方的广告）会维护一个广告账户：里面有若干广告系列，每个系列有预算、每次点击愿意出的价格，以及想出现和不想出现的搜索词清单。搜索广告优化师每天或每周检查账户：哪些搜索词带来了浪费的点击，哪些广告开始疲劳，花费是否按计划推进，分析工具里的销售数据和广告平台自己的统计是否一致。这些工作大多是小幅、重复的调整，人一忙就容易漏掉。智能体按计划运行，读取两边的数据，自己完成这些小的、可撤销的改动，并记下每项改动如何撤销。凡是会提高总支出、开关广告系列、调整账户结构或改变销售统计口径的决定，仍由人来做，因为这些决定牵涉真金白银，而且出错后不容易发现。

**术语：**
- **否定词（negative keyword）**：加进账户的词或短语，包含它的搜索不再展示广告。
- **出价、节奏（pacing）**：每次点击愿意出的价格；以及预算是否在整个周期内均匀花出。
- **区间（band）**：预设的范围，智能体在此范围内调整出价或日预算，无需询问。
- **转化、衡量**：记录下来的一次成交或注册，以及统计它们的追踪配置。追踪出故障，会让表现好的广告系列看起来出了问题。
- **GA4**：Google 的网站分析工具，这里作为第二份统计，用来核对广告平台的数字。
- **SQL（销售合格线索）**：销售团队认为值得跟进的注册；其中一个来源把目标设为每个 SQL 的成本（美元）。
- **冲刺（sprint）、一轮（pass）**：在一个来源里，冲刺是一项书面工作，有目标、期限和智能体可以改动的范围清单；一轮是智能体针对它运行一次。
- **审计日志簿**：持续记录每项改动、改动理由和撤销方法。

## 用智能体搭建

**形态：** `service`。由定时任务启动每次运行，无人在场，人只看到审批队列和每周日志。

**需要：** 对广告平台报表和分析数据的只读权限，通过每个系统一个小脚本或 MCP 连接器获取；另一组只能做允许的低风险改动的脚本（添加否定词、在区间内调整出价或预算、暂停广告或素材），每个都保存改动前的状态；把目标数字、各区间和负责说“可以”的人写进参考文件；存放日志簿和待决策项的地方（代码仓库或数据库表）；广告平台已批准用于线上账户的 API 访问。不要给智能体任何能提高总预算、切换广告系列、调整账户结构或修改转化设置的脚本。

| 步骤 | 搭建方式 |
|---|---|
| 定时：拉取广告平台 + 分析数据 | 云端定时任务，或由你自己的调度器启动 `claude -p` 或 Agent SDK 程序。只读脚本或 MCP 连接器以结构化行的形式返回数据。 |
| 智能体输出决策 → 按权限层级分流 | skill 的指令：读规则文件和未完成事项，然后每行写一条决策，格式固定（操作、对象、幅度、置信度、理由）。由脚本按一张表给每类操作分配层级。 |
| 否定词、出价、预设区间内的节奏调整、素材暂停：自动执行 + 记录改动前状态 | 限定范围的改动脚本。每个脚本在改动之前先把改动前状态写进日志簿，超出区间的改动一律拒绝。 |
| 提高预算、开关广告系列、结构、衡量：🛑 action | 见“检查点”。 |
| 异常交叉核对 (广告 vs 分析) | 由一个子智能体或一个脚本，把广告平台与分析工具里的转化数对比，凡是建立在两者差异之上的决策一律暂缓。 |
| 日志 + 撤销记录 → 🛑 review | skill 的最后一步把本次运行写入日志簿，并为每项改动生成撤销脚本；每周一次运行对照目标数字汇总日志簿。 |

**检查点：** `action`：智能体没有执行这四类受控改动的工具。它把每项写成带理由的待批事项，然后本次运行结束；由人在队列里说“可以”，沉默视为否决。哪些改动可以不经人（各区间、允许的操作类型清单）的限制，应放在改动脚本或 `PreToolUse` hook 里，让它们无法被绕过，而不是只写在 skill 的文字里。`review`：每周的运行把变更日志和目标数字表发给规则文件里指定的人，由他阅读并重设数字。

**与来源相比：** 来源出自 2026-08 至 2026-10。来源 1 用 Claude Code 做推理，用 n8n 负责调度和审批关卡；来源 2 用每小时运行的脚本，只在冲刺到期或触及上限时唤醒智能体；现在云端定时任务（截至 2026-11 为研究预览）或 `claude -p` 就能提供调度，不需要这两样。这些来源是两位从业者各自在自己账户上运行该方法的记述；本搭建方式是依据它们做出的设计，没有实际运行过。来源 1 说，用历史账户状态回放并给智能体决策打分的评估框架本该先建；本搭建方式不含这一项。来源 1 还说，转化量很小的账户不太值得这样做。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 由人设定目标数字（例如每个销售合格线索的成本，以美元计）和支出上限，并指定负责说“可以”的人 [[2]](#sources)。
2. 定时任务（每天早晨，或由每小时运行的监控脚本，只在冲刺到期或触及上限时唤醒智能体）以带类型的工具把广告平台和分析数据交给智能体 [[1]](#sources)[[2]](#sources)。
3. 智能体读取规则和未完成的工作，然后以固定的、机器可解析的格式输出决策，每条附一句通俗的理由 [[1]](#sources)[[2]](#sources)。
4. 智能体无需批准即可做出低风险、可逆的改动：搜索词否定、预设区间内的出价和节奏、广告/素材暂停。每次改动都连同改动前的状态一起记录，可一步撤销 [[1]](#sources)[[2]](#sources)。
5. 🛑 **操作**：智能体提高总预算、开关广告系列、改动结构、改动衡量/转化设置或涉及品牌信息之前，都需要人明确说“可以”。沉默视为否决 [[1]](#sources)[[2]](#sources)。
6. 智能体对比广告平台和分析工具的信号，把任何看起来建立在追踪故障之上的决策放入队列 [[1]](#sources)。
7. 🛑 **审阅**：每周由人审阅变更日志和日志簿，并重建目标数字表 [[1]](#sources)[[2]](#sources)。

**产出：** 线上广告账户的变更，附完整的审计日志和撤销脚本；每周的目标数字报告和一个等待批准的决策队列。
**失败模式 → 防护：** 转化追踪故障让最好的广告系列看起来出了问题，智能体提议大幅削减预算 → 广告与 GA4 的异常检查把它放入队列，且衡量改动始终由人负责 [[1]](#sources)。任务范围蔓延 → 一次冲刺从不授予提高预算或切换广告系列的权限 [[2]](#sources)。
**与相近工作流的区别：** AWF-0019 广告变体矩阵：它产出创意变体，供审阅后批量上传。本工作流管理线上账户（出价、预算、否定词），低风险改动无需逐项批准即可执行，对支出和结构改动设关卡。产出是账户变更而不是创意；自主程度按每类操作的权限层级划分。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Second collection pass](../../../../../research/2026-11-second-pass.md)。

- [Hammad Yousuf, SARA](https://withhammad.com/blog/how-i-built-an-autonomous-google-ads-optimization-system-sara) (2026-08-09)。有三级权限的生产环境智能体；一次由追踪故障引起的预算削减被关卡拦下。"weekly optimization went from 9 hours to 2, with +18% ROAS QoQ"。*第一手：是；可信度：高。*
- [Anton Patrai, AI agent for Google Ads](https://apatrai.com/posts/how-to-set-up-an-ai-agent-for-google-ads) (2026-10-21)。一家 B2B 软件公司，2026 年 9–10 月；冲刺以 GitHub issue 形式管理，每一轮都有日志。"$273 spent on 77 people from ads, one SQL, 19 passes that moved a sprint and 41 that recorded why nothing moved"。*第一手：匿名（未具名公司）；可信度：高。*
