# 计划转日历的社媒排期

**工具变体：** `claude-oktopost` · `multi-agent-linkedin-x` · `openclaw-deepseek-wechat`

## 背景

社媒团队把已有素材和计划中的活动变成适合不同渠道的帖子。工作包含选日期、改写措辞和把草稿录入日历，反复格式化却容易让事实错误或不合适的口吻被忽略。本工作流让智能体起草并安放已经批准的想法，编辑判断仍由人掌握。排期之前，每条帖子仍需核实事实和检查口吻，因为一旦发布，机构就要对这条消息负责。

**术语：**
- **素材盘点 / 买家阶段**：可用材料清单，以及潜在客户处于购买决策的哪个阶段。
- **排期工具 / 草稿日历**：稍后发送帖子的工具，以及按日期安排的拟发帖子。
- **草稿箱 / 人工定时发送**：中国发布平台里的草稿文件夹，以及由人安排最终发送时间。
- **数据汇总 / 平台风控**：实际结果的摘要，以及平台限制不受欢迎的自动化行为的规则。

## 用智能体搭建

**形态：** `skill`。一位编辑在对话中规划和审阅日历；并行的起草角色可以写成同一个 Skill 中的指令。

**需要：** 获批的素材清单与规划文档；事实来源和口吻示例；仅能写草稿的排期工具 MCP server (connector) 工具，或本地日历导出；只读的数据指标导出。保密活动信息留在批准的存储中，不提供立即发布或发送工具。

| 步骤 | 搭建方式 |
|---|---|
| 素材 + 规划文档 → 🛑 plan | Skill 列出来源材料、选题、日期和缺口；编辑批准要起草的内容。 |
| 每个帖子：分渠道起草 → 排期草稿 | Skill 改写获批材料，通过权限受限的 MCP server (connector) 工具保存草稿；脚本检查必填字段和日期。 |
| 🛑 review → 🛑 action → 已排期 | Skill 交出草稿预览和事实核验链接后停下。编辑逐条审阅，并在发布系统中排期。 |
| 数据汇总 | 后续请求时，Skill 汇总只读指标导出，记录下一轮计划要解决的问题。 |

**检查点：** `plan`：编辑批准选题与日期。`review`：Skill 展示每条帖子、支持其事实的来源及渠道背景。`action`：编辑在自己的账号里发布或排期；智能体只能访问草稿。若 API 把草稿与发布合在一起，需封装或拦截，防止草稿操作悄悄变成定时发送。

**与来源相比：** 来源出自 2026-03 至 2026-07，全部已于 2026-11 打开。检索发现 [Oktopost 的插件更新](https://www.oktopost.com/blog/oktopost-claude-plugin-v1-2-0/)，出自 2026-09，已于 2026-11 打开，新增日历事件、媒体整理和定向控制。搭建可以使用该连接器，不必重做排期集成，同时仍把发布留给人。来源同时包含编辑交互和周期性多智能体循环；最小的日历起草搭建只需一个 Skill，指标在需要时提供。历史平台风控观察不能证明今天的发帖政策；连接之前需确认所选平台当前支持的权限。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 内容团队维护一份现有素材的清单，按行业、使用场景和买家阶段对应，并找出覆盖缺口 [[2]](#sources)。智能体把原有帖子改写成每条多个不同的切入角度 [[1]](#sources)。
2. 🛑 **计划**：由人制定规划文档（帖子选题和发布日期）并批准日历计划；智能体不决定发布什么 [[1]](#sources)[[2]](#sources)。
3. 智能体为每个渠道起草帖子，并以草稿形式放到排期工具（Oktopost，或微信的草稿箱）中对应的日期上 [[1]](#sources)[[3]](#sources)。
4. 🛑 **审阅**：由人审阅、核实事实并修改每条帖子，使其读起来像真人写的 [[1]](#sources)。在人工审阅之前，团队增加一道自动合规检查，筛查夸张标题和敏感词 [[3]](#sources)。
5. 🛑 **操作**：由人批准并发布或排期。在中国的平台上，智能体写入草稿，由人定时发送（人工定时发送）[[1]](#sources)[[3]](#sources)。
6. 系统把每日数据（阅读、点赞、评论关键词）汇总成报告，用来指导下一批选题 [[3]](#sources)。

**产出：** 一个月份的已批准帖子，排入社媒排期工具，外加一份为下一轮计划提供输入的数据周报。
**失败模式 → 防护：** 文案千篇一律或带 AI 腔 → 必须由人修改 [[1]](#sources)。全自动发布会触发平台风控，导致限流或封号（小红书）→ 半自动发布，加人工审阅 [[3]](#sources)。事实有误 → 每条帖子都核实事实 [[1]](#sources)。

**与相近工作流的区别：** AWF-0018 聚类—简报—起草（Cluster-brief-draft）产出长篇 SEO 文章。AWF-0019 广告变体矩阵（Ad variant matrix）产出用于测试的付费广告变体。本工作流则填充自然流量的、按日期排布的社媒日历，每条帖子的发布都需要批准。
