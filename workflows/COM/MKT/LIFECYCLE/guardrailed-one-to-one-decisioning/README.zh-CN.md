# 带护栏的一对一决策

**工具变体：** `hightouch-ai-decisioning` · `moengage-campaign-decisioning` · `monocle`

## 背景

通过邮件、短信或应用通知联系客户的营销团队，通常事先决定谁在什么时候收到哪条消息，办法是针对人群做活动。一对一决策把这件事换成对每位客户单独决定：发哪条消息、走哪个渠道、什么时间发，或者干脆不发，选择范围是团队已批准的内容。生命周期营销人员的工作是设定目标和限制，并持续提供好内容。为每位客户手工做选择不可能，而让系统自行优化又可能追错目标（点击很多但从不下单）或过度打扰客户。这里由决策系统在营销人员设定的限制内做每一次选择，并留出一组不受这种处理的客户，用来看它到底有没有帮助。目标和限制仍由人在上线前一次性批准，并由人阅读结果，因为决策系统无法判断品牌、优惠，以及对客户是否公平。

**术语：**
- **消息素材（message asset）**：系统可以从中选择的已批准内容（一封邮件、一条短信、一个优惠）。
- **护栏（guardrails）**：对谁可以收到什么的限制：哪些客户、多频繁、哪些创意、哪几天；也包括“Exclude VIPs from discounts”这样的白话规则。
- **目标权重**：多个目标互相牵制时，每个目标各占多大分量，例如点击与订单及订单金额、短期与长期。
- **对照组（holdout group）**：特意不采用新方法的一组客户，用来把他们的结果与被新方法触达的客户作比较。
- **提升（lift，增量效果）**：新方法带来的额外结果，以对照组为基准衡量。
- **强化学习、多臂老虎机（bandit）**：从每次响应中学习哪种选择对哪类客户最有效、同时仍会尝试其他选项的方法。
- **频率上限、成本上限**：每位客户在一段时间内收到消息的最大数量，以及最大花费。

## 用智能体搭建

**形态：** `platform`。针对每位客户的选择要从每次响应中学习，并以对照组衡量，这需要一个能实时访问客户数据和发送渠道的决策引擎，通用智能体无法替代。通用智能体可以以 `skill` 的形态承担准备和审阅：盘点消息素材、起草供批准的目标和护栏、阅读结果。

**需要：** 消息素材清单（从发送平台导出）；写成文字、供批准的目标和权重、护栏及对照组比例；一个接入客户数据和渠道的决策产品；它导出的结果。不要把客户层面的个人数据放进智能体的对话，只给它汇总结果。

| 步骤 | 搭建方式 |
|---|---|
| 盘点消息素材 | skill 读取导出的素材，逐条列出渠道、优惠、有效期，以及可能已过时的说法。 |
| 设定目标 + 目标权重 + 护栏 + 对照组 → 🛑 plan | skill 把目标、权重、护栏和对照组规模起草成一页，交营销人员审阅。由人把批准的设置配置到引擎里。 |
| 每个客户：智能体选择消息、渠道、时机，或不发送 → 发送 → 从结果中学习 | 决策平台。通用智能体的工具集里没有能做这件事的东西。 |
| 与对照组比较 | 平台的报告。skill 可以读取导出数据，对照已批准的目标检查结果。 |
| 🛑 review (营销人员阅读洞察，更新内容) | 见“检查点”。 |

**检查点：** `plan`：skill 在一页设置草稿之后停下；由人把批准的设置录入平台，智能体无权访问平台的配置。`review`：skill 汇总结果（哪些消息、地区和主题表现好，以及相对对照组的提升），列出要新增、更新或下线的内容，然后停下。因为不审批任何单次发送，抽检体现在营销人员阅读这些结果上。

**与来源相比：** 来源出自 2025-07 至 2025-10，另有两个未注明日期的厂商页面。四个来源都是厂商材料，唯一的客户案例也出自厂商之手；没有一个报道由通用智能体来做针对每位客户的选择。Monocle（来源 3）现在称自己属于 OuterSignal。所以本搭建方式只覆盖文字类环节；决策这一步需要 `variants` 中列出的某个厂商产品。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 营销团队盘点智能体可能用到的所有现有和新增消息素材 [[1]](#sources)。
2. 团队定义护栏：谁可以收到哪些消息、多频繁、哪些创意、哪几天；设定带权重的短期和长期目标（例如点击与订单及订单金额）[[1]](#sources)[[2]](#sources)，并设置对照组 [[2]](#sources)[[3]](#sources)。
3. 🛑 **计划**：营销团队在上线前批准目标、权重和护栏 [[1]](#sources)[[2]](#sources)。
4. 智能体为每位客户选择消息、渠道、时机和频率，包括是否发送，并从每次响应中学习（强化学习 / 多臂老虎机）[[2]](#sources)[[4]](#sources)。
5. 系统相对对照组衡量提升效果 [[2]](#sources)[[3]](#sources)。
6. 🛑 **审阅**：营销人员阅读智能体给出的洞察（哪些消息、地区、主题表现好），并新增、更新或下线内容 [[1]](#sources)[[2]](#sources)。

**产出：** 持续运行的个性化消息流，附相对对照组的实测提升，以及供团队参考的内容洞察。
**失败模式 → 防护：** 智能体优化了错误的结果 → 使用包含长期价值的加权目标 [1]。过度发送或不符合品牌的优惠 → 频率上限、成本上限，以及“Exclude VIPs from discounts”这类白话规则 [3][4]。
**与相近工作流的区别：** 最接近的是 AWF-0054 带护栏的活动搭建（Guardrailed campaign build）：那里每个活动在导出前都要搭建、QA 并获批。这里不审批任何单次发送；人们只一次性批准护栏，并审阅汇总结果。自主程度是抽检，而不是分段。
