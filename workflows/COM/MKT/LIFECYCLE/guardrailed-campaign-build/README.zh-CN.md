# 带护栏的营销活动搭建

**工具变体：** `claude-code-skills` · `claude-codex-stripo-braze`

## 背景

面向已有客户（新注册用户、订阅者、往期买家）的公司，会向他们发送一连串邮件，称为旅程：欢迎系列、新手引导系列、召回提醒等。生命周期营销人员设计每条旅程，决定哪些客户进入，写好每封邮件，在公司的邮件平台上搭建，并记录哪个活动带来了什么结果。手工做的话，大部分时间花在制作上：写每封邮件，用模板搭建，在工具之间搬文件，逐个检查链接。错误很容易出现，而且会直接到达真实客户：链接写错、产品名称根本不存在、一年前才成立的说法。智能体负责设计、文案和模板搭建，并对照固定清单检查自己的产出。方案由人批准后才开始搭建，最终邮件也由人批准后才进入发送工具，因为发出去的邮件收不回来。

**术语：**
- **生命周期营销**：在客户与公司关系的各个阶段与已有客户沟通，主要通过邮件。
- **ESP（邮件服务商平台）**：存放受众并发送邮件的平台；来源里用的是 Braze。
- **旅程（journey）**：由客户行为或时间触发的一串邮件；也叫活动或项目。
- **人群（segment）**：决定哪些客户进入某条旅程的规则。
- **UTM 参数**：加在链接上的标记，让分析工具能分辨一次点击来自哪个活动。
- **登记表（registry，slug）**：列出每个活动的名称和 UTM 标记的清单，让每个活动有唯一固定的身份。
- **PRD**：产品需求文档，这里指活动的书面简报。
- **模块化模板**：由可复用区块组成的邮件版式；来源里的邮件编辑器是 Stripo。
- **URL 白名单、产品名称词典**：文案只能使用的链接和产品名称。
- **QA（质量检查）清单**：邮件发出前对成品做的检查：链接、在各邮件客户端的渲染、收件人。
- **A/B 测试**：把两个版本发给可比的两组人，看哪个效果更好。

## 用智能体搭建

**形态：** `skill`。营销人员在对话中一次搭建一个活动，所以一个装有流程、登记表和 QA 清单的 skill 就够了。

**需要：** 活动简报；命名规则和登记表文件；URL 白名单和产品名称词典；当前的产品上下文（最新的功能和定价说明）；模块化模板和品牌规范；邮件需要图片时，一个图像工具和存放图片的地方；一个脚本，把搭建好的 HTML 里的链接与登记表和白名单做 diff。不要给智能体任何能写入 ESP 或发送邮件的工具。

| 步骤 | 搭建方式 |
|---|---|
| 需求简报 → 命名 + UTM 登记 | skill 先生成活动名称、slug 和完整的 UTM 参数，并写入登记表文件。 |
| 旅程设计 → 人群规格 | skill 把旅程和人群定义写成文件。 |
| 🛑 plan | 见“检查点”。 |
| 文案（当前产品上下文 + URL 白名单） | skill 根据产品上下文文件写每封邮件，只使用白名单里的 URL 和词典里的名称。 |
| 模块化模板 HTML → (搭建 ⟲ QA 清单) | skill 填充模板并运行 QA 清单：对照登记表的链接 diff 脚本、渲染、人群检查。它修复失败项并重跑，直到清单通过。 |
| 🛑 action (复核并导出到 ESP) | 见“检查点”。 |
| A/B 测试 → 胜出版本回流到下一份简报 | 营销人员在 ESP 里运行测试。之后的会话读取结果，根据胜出版本写下一份简报。 |

**检查点：** `plan`：每一步都写出文件，skill 在旅程和人群文件写完后停下，让营销人员在任何文案或 HTML 出现之前阅读并修改。`action`：skill 在 QA 报告和搭建好的邮件之后停下。智能体没有写入 ESP 的工具，所以由营销人员像来源里那样，手动把批准的邮件导出到 ESP。

**与来源相比：** 来源出自 2026-05 至 2026-07。来源 1 在这次会话中打不开，它的报道依据条目原文，条目里说它的仓库使用虚构数据。来源 2 是一位从业者的帖子，描述围绕一个营销工具连接器搭建的流程，该连接器同时连到 ESP 和邮件编辑器，并说最后的导出是唯一保留手动的一步。本搭建方式不提供任何 ESP 写入工具，从而保持这一步由人操作。两个来源都不是本搭建方式所重复的实例；步骤里 10.5% 的渲染错误是第一版的结果，不是对本搭建方式的断言。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 在搭建任何内容之前，智能体先生成活动名称、登记 slug 和完整的 UTM 参数，让活动从第一天起就可衡量 [[1]](#sources)。
2. 智能体把简报（Notion 中的 PRD，或一个目标）转成旅程或活动设计，以及人群定义 [[1]](#sources)[[2]](#sources)。
3. 🛑 **计划**：由人审阅简报和人群。每一步都产出可以做 diff 和审阅的文件，之后才会碰到发送工具 [[1]](#sources)。
4. 智能体依据当前的产品上下文撰写文案，配合 URL 白名单和产品名称词典，并用模块化模板（Stripo）搭建邮件，生成的图片托管在 ESP 中 [[1]](#sources)[[2]](#sources)。
5. 智能体运行 QA 清单：链接和 UTM 与登记表做 diff、渲染效果、人群合理性、护栏。它修复失败项并重复，直到清单通过 [[1]](#sources)。
6. 🛑 **操作**：营销人员在正式上线前，于手动导出到 Braze 时复核、调整并批准最终素材 [[2]](#sources)。随后做 A/B 测试，在一个项目中每两周一次 [[1]](#sources)。

**产出：** ESP 中可直接投产的邮件和旅程，以登记 slug 追踪，便于归因。
**失败模式 → 防护：** 编造 URL 和产品名称 → 第一版在 QA 中出现 10.5% 的渲染错误；先上线白名单和词典护栏 [[1]](#sources)。旧活动重复一年前的说法 → 把当前的产品上下文作为输入拉取进来 [[1]](#sources)。
**与相近工作流的区别：** AWF-0019 广告变体矩阵（Ad variant matrix）产出付费广告素材变体。本工作流在 ESP 中搭建自有渠道的旅程，带人群规格、UTM 登记和渲染 QA，之后再手动导出。
