# 提议确认式管道巡检

**工具变体：** `claude-salesforce-mcp`

## 背景

销售管道是公司眼下正在争取的全部交易，以记录的形式保存在 CRM 里。收入运营（RevOps）负责销售系统和收入预测，它需要每个未结商机都写明当前的下一步、切合实际的预计成交日期，以及买方一侧该有的人，因为预测和每周的管道例会都建立在这些记录之上。手工维护几百个商机既繁琐又乏味，于是记录日渐陈旧，例会材料也是用早已过时的快照做出来的。在这里，智能体每个工作日巡检整条管道，把记录与聊天、邮件、日历和会议纪要中的近期沟通对照，并发布一份问题清单，附上建议的修正。每项修正写入前都由人确认，每周例会也仍由人来开，因为这些记录支撑的预测是管理层要对外承诺的数字，而每个商机都由对应的销售负责。

**术语：**
- **CRM**：客户关系管理系统，记录客户、联系人和交易。
- **管道、未结商机**：所有尚未赢单或丢单的交易；其中的一笔。
- **收入运营（RevOps）**：负责销售系统、数据和收入预测的团队。
- **下一步**：推进一笔交易的、带日期的具体行动，例如已排定的演示。
- **预计成交日期**：交易预期签署的日期；已经过去的日期说明记录过时了。
- **采购决策委员会**：客户那边决定这次采购的人；**委员会信息单薄**指已知的人太少。
- **回写**：写进 CRM 记录的修正。
- **异常视图**：只列出有问题的商机、每项附上建议修正的清单。
- **管道例会**：销售负责人逐一过未结商机的每周会议。

## 用智能体搭建

**形态：** `service`。巡检每个工作日按计划启动，现场没有人，人只看到异常视图和请他们确认的回写。

**需要：** 通过 CRM 的 MCP 服务器对实时 CRM 的只读访问；通过连接器读取聊天、邮件、日历和会议纪要；一份列出本次运行质量检查项的文件；发布异常视图的地方，例如共享文档或聊天频道。不要给定时运行任何写入 CRM 的工具。沟通内容和联系人属于个人信息：要使用所在机构批准的连接器。

| 步骤 | 搭建方式 |
|---|---|
| 每天读取 CRM 实时管道 | 云端定时任务每个工作日通过 CRM 的 MCP 服务器读取实时数据，从不使用导出文件。 |
| 核对 Slack/邮件/日历/笔记中的沟通 | 每个渠道一个连接器；由一个动态工作流给每个子智能体分配一批商机及其近期沟通。 |
| 每个未结商机：带来源和日期的下一步，检查停滞 / 超过预计成交日期 / 决策委员会信息单薄 | 同一批子智能体为每个商机返回带日期和来源的下一步，以及适用的标记。 |
| 运行质量自检 | 检查项文件；本次运行对照它给自己打分，并把未通过的项列在视图最上方。 |
| 发布异常视图 | skill 的最后一步：发布视图，每条建议回写都是一个可供人确认的条目。 |
| 🛑 action (人工确认回写) | 另起一个交互式会话或一个 Agent SDK 程序，只写入已确认的条目；CRM 更新工具受询问规则约束，或经由 `canUseTool` 转给审批人。 |
| 🛑 review (每周管道例会) | 由人在例会上进行，从异常视图开始。 |

**检查点：** `action`：定时运行没有写入 CRM 的工具，只能提出建议；每条回写都在第二步完成，只写入人确认过的条目，而且每次更新执行前都会询问。`review`：每周例会是人的会议，不在智能体的工具范围之内。

**与来源相比：** 唯一的来源出自 2026-09。它是一家咨询公司讲述在自己的管道上运行 Claude 加 CRM 的组合四个月，报告了各项检查以及每次回写都由人确认的规则，但没有说明这次运行是如何调度的。云端定时任务（截至 2026-11 仍是研究预览）可以提供工作日的定时触发，不必自建调度器。本搭建方式把提议和写入拆开，让无人值守的运行始终不持有写入工具。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 每个工作日，智能体读取实时管道，绝不使用导出文件或保存的副本 [[1]](#sources)。
2. 智能体核对 Slack、邮件、日历和会议纪要中的沟通，这样当有人昨天刚和联系人谈过时，这段关系就不会被误标为冷淡 [[1]](#sources)。
3. 对每个未结商机，智能体写出带日期和来源的下一步，梳理采购决策委员会，并标记停滞的商机、已经过期的预计成交日期和缺失的签字人 [[1]](#sources)。
4. 智能体用 15 项质量检查给这次运行评分，并公开报告未通过的项 [[1]](#sources)。
5. 🛑 **操作**：除非有人点击确认，否则不会向 Salesforce 回写任何内容 [[1]](#sources)。
6. 🛑 **审阅**：每周的管道例会从异常视图开始，而不是从手工制作的演示稿开始 [[1]](#sources)。

**产出：** 覆盖全部商机的每日异常视图、经人工确认的 CRM 修正，以及一份现成的管道例会材料。
**失败模式 → 防护：** 仪表盘建立在过期快照上 → 只读取实时记录 [[1]](#sources)。误报“冷淡” → 跨渠道核对 [[1]](#sources)。无人监督的写入损害信任 → 先提议，再由人确认回写 [[1]](#sources)。
**与相近工作流的区别：** 同批的 DEAL 工作流是逐通电话、由销售批准的更新。本工作流是由 RevOps 负责的、覆盖全部商机的每日巡检。AWF-0006 受管控的查询（Governed query）回答临时问题，不维护记录。
