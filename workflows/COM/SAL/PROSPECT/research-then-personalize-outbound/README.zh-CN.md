# 先调研再个性化外呼

**从业者模式：** 先跑成本低的信息补全，只对符合 ICP 的账户才花智能体调研的积分（Claygent）[[22]](#sources)。

## 背景

外呼拓客是去联系那些并没有找过你的公司。销售或增长团队先界定想要什么样的客户，建立一份符合条件的公司和人员名单，找到能用的邮箱地址，为每家公司找一个“现在联系”的理由，再发出一组以这个理由开头的简短邮件。手工调研每个账户很慢，于是团队往往退回到千篇一律的邮件；而大规模地草率去做，邮件里就会出现调研撑不住的说法，或者发往失效的地址，损害公司发送邮件的能力本身。智能体负责调研，并且只依据有出处的证据来写每封邮件的开场白。全量运行之前由人检查一个小样本，运行之后抽查一部分成品行，并批准启动，因为这些邮件是以公司的名义发给真实的人，发出去就很难收回。

**术语：**
- **ICP（理想客户画像）**：对值得去卖的公司的描述；这里写成几种**买家原型**，即几类典型买家。
- **信号（触发事件）**：让一家公司值得现在就联系的事件，例如新合同、融资或职位变动。
- **信息补全（enrichment）**：给名单中的一行补充数据，例如经过验证的邮箱；**瀑布式信息补全**是依次询问几家数据供应商，直到有一家给出结果。
- **catch-all 地址**：对任何名字都接收邮件的邮件域名，因此其中的地址无法确认是否真实存在。
- **退信**：因无法投递而被退回的邮件。
- **积分**：数据工具按行收取的查询和 AI 列费用单位。
- **Clay、Claygent**：一款把许多数据供应商接在一起、形似电子表格的工具；Claygent 和 “Use AI” 列是它内置的 AI 调研步骤。
- **填充率**：调研问题得到回答的行所占的比例。
- **开场白（first line）**：第一封邮件里个性化的开头一句。
- **序列、序列工具**：给每个联系人定时发送的一组邮件，以及负责发送的工具。
- **SPF、DKIM、DMARC**：让收件服务器信任发件域名的邮件认证记录。
- **次级域名、预热**：专门用于陌生邮件的独立域名，以及在活动开始前逐步增加发送量的一段时间。
- **SDR（销售开发代表）**：跟进回复并预约会议的销售。
- **CRM**：记录账户和联系人的客户关系管理系统。

## 用智能体搭建

**形态：** `project`。由一位活动负责人在对话中运行，但调研要在两个检查点之间扇出到数百个账户，而且有两条规则必须对每一行、每一次发送都成立（没有证据就没有开场白；未经批准不得启动），这需要脚本检查和钩子。

**需要：** 一份 ICP 文件，写明各个原型、打分规则，每个原型一条开场白提示词；为各个信号来源和每家信息补全供应商准备的脚本或 MCP 服务器，各带自己的 API 密钥，按成本排序；存放名单的表格文件或数据库；序列工具的导入格式；已配置 SPF、DKIM 和 DMARC 并在启动前完成预热的发件域名，这一步在智能体之外完成。联系人数据属于个人信息：给每个联系人发邮件的合法依据和退订处理由活动负责人负责。不要给智能体任何发送邮件或启动序列的工具。

| 步骤 | 搭建方式 |
|---|---|
| ICP → 建立名单 | 一个 skill 读取 ICP 文件，通过脚本或 MCP 服务器从各信号来源建立账户名单，并按公司域名去重。 |
| 每个账户：瀑布式信息补全 | skill 旁边的脚本按成本顺序调用各供应商，拿到第一个经验证的地址就停，catch-all 地址算作未验证。 |
| 调研智能体回答固定问题并附来源 URL → 打分分层 | 一个动态工作流为每个合格账户运行一个子智能体，带固定问题和 JSON schema。每个回答都附证据 URL 和不超过 25 个词的引文，否则回答 "none"。同一个子智能体给账户打分并归入原型。 |
| 每个联系人：仅依据调研写开场白 | 在同一个工作流里使用该原型的提示词。脚本会退回开场白背后没有带证据 URL 的调研字段的行。 |
| 🛑 plan (20 行样本) | skill 先对 20 行运行工作流，写入文件后停下。 |
| 🛑 sample (5–10%) | 全量运行后，skill 随机抽取 5–10% 的行连同证据 URL，以及与上一次运行对比的填充率和成本，写入复核文件后停下。 |
| 🛑 action → 启动序列 | skill 按序列工具的导入格式导出文件。由人导入并启动。 |
| 分流回复 | 不在本搭建方式之内：如来源 21 所述，由序列工具和 CRM 分流回复。 |

**检查点：** `plan`：skill 写完 20 行的文件后停下，只有在人同意后才开始全量运行。`sample`：skill 写完复核文件后停下；人阅读一部分没有逐行检查过的成品行，导出要等人看完。`action`：智能体没有发送邮件或向序列工具上传的工具，`PreToolUse` 钩子还会拦下任何调用序列工具 API 的命令，所以在人导入文件并启动之前，没有任何邮件会发到任何人手里。

**与来源相比：** 来源出自 2026-06 至 2026-10。它们描述的是从业者在 Clay（一款内置 AI 调研列、形似电子表格的数据工具）中执行这些步骤，再用自动化工具（n8n）分流；没有通用智能体在运转整个流程，调研步骤是在表格里逐行运行的。本搭建方式把这些步骤移到通用智能体加脚本上。Clay 现成接好的众多数据供应商在这里没有照搬，每家供应商都需要自己的脚本和密钥。回复分流和发件域名的预热都留在本搭建方式之外。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 活动负责人把 ICP 定义为买家原型，再依据信号建立账户名单：抓取服务（ZenRows）读取公开数据库（USASpending.gov、SAM.gov、FedRAMP Marketplace），搜索服务（Exa）搜索行业媒体，Clay 的原生信号再加入职位变动和公司新闻。表格每天刷新，并按公司域名去重 [[21]](#sources)。
2. 对每个账户，表格运行瀑布式信息补全，先用最便宜、覆盖最广的供应商，最后才用昂贵的专业供应商 [[22]](#sources)。一个 HR 科技的实例先用 FullEnrich，再用 Leads Magic，最后用 Blitz API 做实时验证。活动负责人打开 "Only mark 'Safe to Send' emails as valid"，这样 catch-all 地址不会被算作已验证 [[21]](#sources)。
3. 调研智能体（Claygent 或 Use AI 列）只对通过资格筛选的行运行，并用 "Only run if" 设置门槛 [[21]](#sources) [[22]](#sources)。它拿到的是写得“像规格说明一样”的固定问题，并带 JSON 输出 schema [[22]](#sources)。每个回答返回一个状态，加上 `evidence_url` 和不超过 25 个词的 `evidence_quote`，提示词要求在找不到时回答 "none" [[21]](#sources)。典型的问题是最新一轮融资和招聘重点 [[20]](#sources)。
4. AI 提示词对照目标画像给每个账户打分，打分之后才去查联系人。每个账户被归入一种原型；自动化工具（n8n）在 [[21]](#sources) 中就是这样做的。
5. 对每个联系人，智能体只依据调研字段写开场白：每种原型有自己的提示词链，每封邮件都以把该账户放进队列的触发事件开头。在一次营销活动中，针对具体事件的开场白平均比基于功能的开场白效果好 3.4x [[21]](#sources)。
6. 🛑 **计划**：活动负责人在全表运行之前检查 20 行样本（调研回答、证据 URL、评分、开场白）。从业者会在单独的测试表里用 25–50 行做这件事，检查 "fill rate and accuracy" 和每行的积分成本 [[22]](#sources)。
7. 🛑 **抽检**：全量运行之后，审阅人阅读 5–10% 的成品行，检查每条开场白都能追溯到一个证据 URL，并在放大之前，把填充率和成本与上一次运行做对比 [[22]](#sources)。
8. 🛑 **操作**：发送基础设施就绪后，由人批准启动：配置了 SPF、DKIM 和 DMARC 的次级域名，预热三到四周（一个客户是 30 天，另一个是三周）[[21]](#sources)。
9. 序列工具（EmailBison 或 Salesforge）启动序列，回复被分流：n8n 把账户推入 CRM（HubSpot 或 Attio），对打开两次却没有回复的潜在客户，会在 15 分钟内向 SDR 发出 Slack 提醒 [[21]](#sources)。

**产出：** 一个已启动的序列，每个开场白都有被引用的调研字段支撑，有互动的账户被分流到 CRM 和 SDR。
**失败模式 → 防护：** 过期名单导致高退信率（"22%"）→ 重建带验证的瀑布流程，首次发送时 "bounced at 1.3%" [[21]](#sources)；退信率高于 2% 就 "signal list quality problems" → 邮件瀑布流程始终以验证收尾 [[22]](#sources)。catch-all 地址默认被算作有效 → 使用 "Safe to Send" 设置，并在联系人进入营销活动前复查 [[21]](#sources)。调研无法支撑的个性化 → 每个字段都带证据 URL 和引述，找不到时回答 "none" [[21]](#sources)。在不匹配的行上浪费积分 → 用 "Only run if" 设门槛，只调研合格的行 [[21]](#sources) [[22]](#sources)。发送域名被烧毁（14% 退信，邮件被扣在 Microsoft 365 隔离区）→ 新的次级域名和邮箱，并做预热 [[21]](#sources)。触发事件偏弱，例如新高管入职 → 优先使用更强的信号 [[21]](#sources)。
