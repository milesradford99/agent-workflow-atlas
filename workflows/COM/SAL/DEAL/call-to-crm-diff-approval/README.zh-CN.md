# 通话转 CRM 差异审批

**工具变体：** `claude-salesforce-mcp` · `claude-code-fathom-gmail`

## 背景

一通销售电话结束后，销售（rep）要把了解到的情况记进 CRM，也就是公司共享的客户与商机数据库，再给客户发一封跟进邮件。每一次与潜在客户或现有客户的通话都会引出这件事。手工做既慢又容易被跳过，于是记录越来越旧；匆忙之下，笔记里还可能写进一个谁都没说过的预算或承诺。智能体阅读通话转录稿和商机历史，提出对 CRM 字段的具体修改，并起草跟进邮件。每一处修改在写入前都要销售批准，跟进邮件也由销售亲自发出，因为 CRM 里的数字会进入公司的收入预测，而那封邮件是以销售的名义对客户做出的承诺。

**术语：**
- **CRM**：客户关系管理系统，记录客户、联系人和商机。
- **商机（opportunity，商机记录）**：CRM 中对应一笔潜在交易的条目，含金额、阶段和预计成交日期。
- **阶段（stage）**：一笔交易推进到了哪一步，例如需求探索、方案、谈判。
- **ARR**：年度经常性收入，即一笔订阅交易每年的金额。
- **复盘（debrief）**：对通话的结构化总结：谁参加了、预算、谁签字、痛点、异议和后续步骤。
- **差异（diff）**：将要改动的字段清单，每项列出当前值和拟改值。
- **回滚（rollback）**：把记录恢复到写入之前的值。

## 用智能体搭建

**形态：** `skill`。一位销售一次处理一通电话，并全程在对话中批准修改和草稿，所以一个 skill 就够了。

**需要：** 通话转录稿，来自会议录音工具的导出文件或它的连接器；一个 CRM 的 MCP 服务器，能读取客户、商机和活动历史，并能更新字段；一个只能创建草稿的邮件或文档工具；放在 skill 旁边的几封该销售过去写的邮件，作为其口吻的范例。通话转录稿和 CRM 记录包含个人信息和商业数据，要使用所在机构批准处理这类数据的环境。不要给智能体发送邮件的工具。

| 步骤 | 搭建方式 |
|---|---|
| 通话转录 → 拉取客户历史 + 商机记录 | skill 的第一条指令：读转录稿，再通过 CRM 的 MCP 服务器取出客户、未结商机和近期活动。 |
| 提取复盘要点（人员、预算、异议、后续步骤） | 在主对话中填写放在 skill 旁边的复盘模板。每个字段都引用它所依据的转录原句，找不到就留空。 |
| 提出字段变更 + 跟进草稿 | skill 列出一张表（字段、当前值、拟改值、转录引文），并以销售的口吻把跟进邮件写成草稿。 |
| 🛑 action (销售批准差异) → 写入 CRM 并提供回滚 | 权限规则设为在调用 CRM 更新工具前询问。写入之前，skill 先把当前值存入一个文件，销售要求时可以恢复。 |
| 🛑 review (销售修改并发送跟进) | 见“检查点”。 |

**检查点：** `action`：skill 列出差异后停下；CRM 更新工具受询问规则约束，每次写入前都会向销售展示具体字段。`review`：跟进邮件只以草稿形式存在，智能体也没有发送工具，所以由销售修改、附上文件，并从自己的邮箱发出。

**与来源相比：** 来源出自 2026-06 至 2026-09。来源 2 是一位销售讲述自己用单个 Claude skill 处理通话转录稿，正是这里选的形态。来源 1 是一家 CRM 厂商的客户故事，讲销售人员借助 Claude 使用 CRM 数据，回写时有审批和回滚；它报告的是做法，而不是每一个步骤。本搭建方式没有包括步骤 1 的会前简报，那是通话前另行运行的一次。它也不假定 CRM 的 MCP 服务器提供回滚，而是由 skill 自己记下旧值。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 会议前，智能体把客户历史、过往邮件、通话、营销活动和未结商机汇总成一份简报 [[1]](#sources)。
2. 通话结束后，智能体阅读转录稿并整理复盘：对方是谁、预算、谁来签字、客户自己话语里的痛点、异议及其是否已解决，以及带负责人和日期的后续步骤。所有内容都必须能从转录稿中核实 [[2]](#sources)。
3. 智能体提出 CRM 变更（通话记录、ARR、阶段），并以销售的口吻起草跟进邮件和方案 [[1]](#sources)[[2]](#sources)。
4. 🛑 **操作**：销售在写入任何内容之前先看到拟议的变更。获批的值写入 CRM，之后立即提供回滚 [[1]](#sources)。
5. 🛑 **审阅**：销售阅读方案和跟进邮件，附上文件并点击发送。智能体从不自行发送 [[2]](#sources)。

**产出：** CRM 中更新后的商机记录和已记录的通话，外加由销售发出的跟进邮件和方案。
**失败模式 → 防护：** 编造数字或承诺 → 要求每个字段都能追溯到转录稿 [[2]](#sources)。不希望发生的写入 → 确认技能加回滚 [[1]](#sources)。销售不再认真审阅 → 保持发送环节手动 [[2]](#sources)。
**与相近工作流的区别：** AWF-0020 先调研再个性化的外呼（Research-then-personalize outbound）在任何沟通之前调研潜在客户并起草首封邮件。本工作流在真实通话之后运行，并把字段级变更写入 CRM，由销售把关。
