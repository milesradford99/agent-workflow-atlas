# 农技员中转的农业咨询

**与相近工作流的区别：** 最接近的是 AWF-0154（按地块登记的农艺建议）：它按整个季节制定针对具体地块的养分方案，由农户核对地块并交给技术员接手。本工作流是针对任意作物或主题的按需问答，没有地块模型，人工检查点是农技推广员在每条答复到达农户之前先审阅（辅助，而不是分段）。
**工具变体：** `farmer-chat`

## 背景

小农的作物起了虫，他有问题要问，而公共农技推广系统根本没这么多人答：几千个农场摊到几个推广员，还隔着一天路程的乡野。一个能用农户语言回答、还能看叶子照片的助手能补上一部分缺口，但补不全，因为一句错的打药建议会毁掉一季，而没人为此负责。实践中的答案是一个中间人：助手先交给农技推广员和带头农户，而不是直接给农户；他们结合自己知道的地里情况判断过，再转达下去。背后的知识是刻意精选的——培训视频转写、带标注的呼叫中心日志、作物研究简报，每一份都由农业部审定——所以助手是从获批材料里检索，而不是从开放网络里拼。答不上的问题会被分类，而分类决定该补什么：语料就是这样长起来的，不需要谁去猜缺什么。

**术语：**
- **农技推广员（extension agent）**：下乡走访、回答农户问题的公共或非政府组织顾问。
- **带头农户（lead farmer）**：在邻里之间传递建议的受信赖的农户。
- **RAG**（retrieval-augmented generation，检索增强生成）：先检索相关的获批文档，再据此回答，而不是凭模型记忆作答。
- **审定知识库**：其中每份文档都已由主管部门批准通过的语料库。
- **知识缺口（knowledge gap）**：语料答不了的问题，按超出语境、收录不足、内容缺失分类。
- **作物照片诊断**：从一张照片判断虫害或病害。
- **转达（relay）**：推广员用自己的话把答复传给农户。

## 用智能体搭建

**形态：** `skill`。一位推广员一次问一个问题，农户就在面前或在电话那头，由他决定这个答复够不够好、能不能转达；工作是这场对话，而不是一条流水线。

**需要：** 已审定的语料，每份文档记录其批准情况与来源日期，因为一条被取代的建议比没有更糟；多语检索与作答，答复语言按对话设定；用于作物诊断的照片通道，并带置信度信号；可得的天气与病虫害预警数据源；以及一份内容团队能据以行动的缺口日志。助手不得在语料之外作答而不声明，也不得在本配置下被农户直接触达。

| 步骤 | 搭建方式 |
|---|---|
| 农户提问（语音 / 文字 / 作物照片） | 推广员打字、说话或上传照片；Skill 先把语音转写，因为听错的问题会得到一个自信的错误答案。 |
| 推广员提问 → 在审定知识库上做 RAG | 检索限定在获批语料内，每段都带来源与日期；最匹配都很弱时返回"未覆盖"，而不是给出最接近的一段。 |
| 用当地语言作答 | 答复以农户的语言由检索到的段落组织而成，段落一并给推广员看，于是转达之前就能核对。 |
| 🛑 review（推广员判断并转达） | 推广员读答复及其来源，用自己的话转达，或再问一次；Skill 没有通往农户的通道，这正是让这道审阅起作用而不是形同建议的原因。 |
| 未能回答：归类缺口 | 单独一遍，把每个未答问题标为超出语境（问的不是它的活）、收录不足（文档存在但不在语料里）或内容缺失（没人写过）——三种不同的修法。 |
| 更新知识库 | 内容团队处理"收录不足"和"内容缺失"两份清单，每份新文档都带着批准记录入库。 |

**检查点：** `review`：推广员既是检查点也是投递路径——助手到不了农户，所以没人转达的答复就不会到达。这也让失效模式可见：来源报告三分之二的未答问题属于内容缺失，所以这道审阅不只是一个过滤器，它还是告诉内容团队下一步写什么的传感器。

**与来源相比：** 来源出自 2024-09 与一份未注明日期的厂商故事，自采集以来未变，本轮没有重新打开。此后有这些变化：同样的安排在印度已成为公共支持型咨询的标准形态，而关于其局限的证据也更硬了。2026 年一篇该领域专栏报道，语音服务触达的人数已经很大——某邦平台一年内接了超过 100,000 名农户用方言打来的提问——而[仍有四分之一到三分之一的问题没有答案，可测量的增益来自内容：一个微调的小模型把专家核实事实的召回率从 26.2% 提到 50.3%，成本约为前沿模型的 15%](https://agronewstoday.com/article/ai-smallholder-farmers-small-language-models)。这正是本条目设计的论据：在审定语料上检索，并在答复与田间之间留一个人。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 用培训视频转写稿、带标注的呼叫中心日志和作物研究简报构建一个精选知识库；印度农业部审定其中所有文档 [[2]](#sources)。
2. 农技推广员（或带头农户）通过文字、语音或作物照片提问；助手从知识库检索（RAG），并用当地语言作答，同时提供天气和病害诊断服务 [[1]](#sources)[[2]](#sources)。
3. 🛑 **审阅**：在最初的推广阶段，聊天机器人是作为农技推广员的助手部署的，而不是直接面向农户，因此推广员会先审阅建议再转达 [[2]](#sources)。
4. 未能回答的提问由 LLM 分为超出语境、收录不足和内容缺失三类；内容缺失的缺口推动知识库补充 [[1]](#sources)。

**产出：** 由农技推广员转达给农户的咨询答复；以及未能回答的提问日志，用于更新知识库。
**失败模式 → 防护：** 聊天机器人给农户错误建议 → 精选知识库，并以农技推广员作为审阅环节 [2]。知识缺口：66% 的未答提问属于内容缺失 → 缺口归类和知识库更新 [1]。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [Digital Green, Farmer.Chat (arXiv 2409.08916)](https://arxiv.org/abs/2409.08916) (2024-10-08)。在肯尼亚、印度、埃塞俄比亚和尼日利亚部署；用户包括农技推广员、带头农户和农户。"Deployed in four countries, Farmer.Chat has engaged over 15,000 farmers and answered over 300,000 queries."。*第一手：是；可信度：高。*
- [OpenAI, Digital Green](https://openai.com/index/digital-green/) (n.d.)。CEO 解释先从农技推广员入手的推广方式，相当于一个人工审阅环节。"As of January 1, 2024, over 4,500 extension agents are using Farmer.Chat across both Kenya and India."。*第一手：厂商；可信度：中。*
