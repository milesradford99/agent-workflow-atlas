# 农艺师把关的推送农事建议

**与相近工作流的区别：** AWF-0211（推广员中介的建议，extension-agent mediated advice）回答单个农户的问题，每个答案由推广员转达。AWF-0154 一次为一位农户提供按地块登记的当季建议。本工作流中没有人提问：农艺师批量发布分群、配音的推送活动，随机化 A/B 评估是第二个检查点。交付物、触发方式和检查点都不同。
**工具变体：** `paddyai` · `ivr-push-calls`

## 背景

靠电话触达小农的农事服务是"推"而不是"等问"：这周该追第二次氮肥了；雨后注意叶锈病；咖啡果小蠹开始活动了。这些建议必须贴合分群——某区两亩咖啡的农户，和十亩水稻的农户，该听到的不是同一句话——而且要用农户自己的语言说出来，因为很多接收者用的是功能机，看不了文字。每周写、译、录几十个版本，农艺团队手工做不完，于是起草、翻译和配音被自动化。农艺师仍然在每条建议发出前读一遍；发出之后，这场活动要在一项随机试验里与人工撰写、真人配音的建议对比，因为"农户听了"不等于"建议是对的"。已发表的结果恰恰是让人不舒服的那部分：AI 建议的收听率略低于人工版，记忆率也更低——这正说明真正的工作是审阅和逐个脚本的对比，而不是生成。

**术语：**
- **农事建议（advisory）**：一小段季节性指导，主动推送给农户，而不是应要求提供。
- **分群（segment）**：按作物、农场规模、区域、天气和语言划分的一群农户。
- **IVR**（interactive voice response，交互式语音应答)：发起呼叫并播放录音的电话系统。
- **TTS**（text-to-speech，文字转语音）：把写好的建议变成语音。
- **收听率（listening rate）**：接通来电中听了这条消息、以及听了多少的比例。
- **记忆回访（recall survey）**：事后打电话问农户记住了什么。
- **A/B 测试**：把同一活动的两个版本随机分组对比。
- **可操作细节（actionable detail）**：让建议可用的那个具体用量、时机或产品名。

## 用智能体搭建

**形态：** `service`。活动每周发往几万部电话，没人逐次启动；农艺团队在发布前答一个队列、发布后做一次结果复盘，评估跑在平台自己的随机分组上。

**需要：** 农艺师的知识以文件形式提供——作物日历、当季指导、往期建议——其中具体用量和时机要原样保留；农户名单及其分群属性，以及每个分群的语言与方言；一步翻译，并由母语者抽查，因为一句在方言里读起来别扭的警告，比不打这个电话更糟；每种语言一个 TTS 音色，做过可懂度测试；IVR 平台，且能保留一个随机对照组；记忆测量所需的问卷。智能体不能发布活动：发布动作属于农艺与服务交付团队。

| 步骤 | 搭建方式 |
|---|---|
| 农艺师知识 + 农户分群 | 知识是 Skill 读取的参考集，分群定义是一张表；一条消息按分群起草，而不是按农户，因为这个渠道无法再细。 |
| 为每个分群起草建议 | 每个分群一遍，把作物日历的日期和指导里的用量"引用"进消息，而不是转述——试验的发现正是生成会丢掉这些细节。 |
| 翻译成当地语言 | 逐语言翻译，再由母语者抽查；方言词和变音符号是机器翻译最容易错的地方。 |
| 文字转语音 | 每种语言一个固定音色，节奏定一次就不再改，因为季中换声音会让靠声音识别服务的听众困惑。 |
| 🛑 review（农艺团队和服务交付团队在发布前检查建议） | 一个发布队列：每个分群的脚本与音频，可操作细节被高亮，让审阅人先看这些；批准是呼叫平台里的权限，本次运行没有。 |
| 每周 IVR 推送外呼 | 平台按分群外呼，并保留一个随机对照组收听人工撰写、真人配音的版本，于是对比在任何一通电话拨出之前就已设计好。 |
| 与人工撰写的建议做 A/B 测试 | 收听与时长来自平台数据，记忆来自回访；两者都带样本量和显著性报告，而不是合成一个头条数字。 |
| 🛑 review（团队阅读结果并对比脚本） | 团队把数字与两份脚本并排读，指出生成版丢掉了什么——一个用量、一个时机、一个条件——这份清单就是下一轮提示词修订的依据。 |

**检查点：** `review`：两次，且都关乎内容而不是数量。发布关卡是农艺师逐条读脚本和音频，可操作细节排在最前面；结果关卡是逐个脚本对比的地方，因为收听率的差异只说明"有东西变了"，说不清变的是什么，答案在文字里。搭建不能发布活动，对照组配置在平台里，所以这场对比不会被悄悄取消。

**与来源相比：** 来源出自 2026-02 与 2026-10：一份项目页和实验登记条目，本月均已打开；该引用的是登记条目，而不是更早的项目页。此后有这些变化：周边证据朝同一方向变得更硬。2026 年一篇关于印度农事服务的专栏指出，这个领域的弱点是内容与选题而不是对话——[仍有四分之一到三分之一的农户提问没有答案，而一个经过微调的小模型把"专家核实事实"的召回率从 26.2% 提到 50.3%，成本约为前沿模型的 15%](https://agronewstoday.com/article/ai-smallholder-farmers-small-language-models)。那是另一种工作流（回答问题而非推送建议），但指向与本条目的发现相同：瓶颈不是模型，而是具体、可核实的内容。所以上面的搭建方式把农艺师的用量和时机当作要"引用"的资产，而不是转述。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 农艺师提供知识：作物日历、最佳实践、季节性指导和往年建议的存量。农户属性（作物类型、农场规模、当地天气、沟通偏好）划分出各个分群 [[1]](#sources)[[2]](#sources)。
2. PaddyAI 为每个分群起草一份建议，翻译成当地语言（咖啡服务用卡纳达语），并转成语音通话用的音频。它能生成农艺师无法手工写出的大量定制版本 [[1]](#sources)[[2]](#sources)。
3. 🛑 **审阅**：农艺团队和服务交付团队保持在环，确保发给农户的每条建议都合适。早期版本还在农户焦点小组中测试过可理解性 [[1]](#sources)。
4. 建议通过 Coffee Krishi Taranga 服务每周发出一次 IVR 推送外呼，该服务由 PxD 与印度咖啡局（Coffee Board of India）共同运营 [[2]](#sources)。
5. 效果以对照人工撰写、真人配音建议的 A/B 测试来衡量：接听率、收听率和平台数据中的收听时长，另有电话回访调查，了解记忆和理解情况 [[2]](#sources)。
6. 🛑 **审阅**：团队把结果与脚本本身对照阅读，发现 AI 脚本有时会漏掉具体的建议操作或技术细节，于是调整 PaddyAI，保留这些可操作的内容 [[2]](#sources)。

**产出：** 面向每个农户分群、用当地语言配音的每周农事建议，通过 IVR 平台送达，另有一条实验登记条目，用来驱动下一轮提示词修订。
**失败模式 → 防护：** AI 脚本做了简化，丢掉可操作或技术性的细节 → 发布前由农艺师审阅，A/B 测试后逐个脚本对比。参与度低于人工脚本（收听率低 2–3.5 个百分点）→ 扩大规模前设 A/B 关卡。项目页面初步声称参与度略高，最终登记结果并不支持；请引用登记结果。登记页面的摘要说 AI 脚本“tend to be longer”，结果部分却写“12% shorter”；请采用结果部分的数字。
