# 地块登记式农艺建议

**与相近工作流的区别：** 没有相近的。最接近的是 AWF-0042 导师批准的 AI 回合（Tutor-approved AI turns），但那里每一轮都由人批准。
**工具变体：** `chatgpt-whatsapp`

## 背景

一块地的养分方案，本质是一个带位置的计算：这块地需要多少肥，取决于那里土壤本来有什么、农户上一季施了什么、他想打到多少产量。粗分辨率公布的土壤图提供第一个输入，农户自己的回答提供其余。之后建议还得在对的时机到达——出苗时、刚见虫时、追肥之前——而且要可执行，这就是为什么最后一步是人：本条目背后的试验发现，在技术员或带头农户协助落实的那一组，产量增幅明显更大，而任何消息渠道本身都补不上这个缺口。登记这一步比看上去更重要：整个方案都挂在"哪个多边形才是他家的地"上，所以先把边界显示在地图上请农户确认，再算任何数；投递则走农户已经在用的那个通讯应用。

**术语：**
- **地块登记（plot registration）**：记录地块边界，使建议能与之绑定。
- **多边形（polygon）**：地图上圈出地块的轮廓，由农户确认。
- **土壤属性图（soil property map）**：公布的土壤性状预测图，分辨率远粗于一块地。
- **养分方案（nutrient plan）**：针对这块地与目标产量，施多少什么肥、什么时候施。
- **追肥（top dressing）**：生长季中而非播种时施的肥。
- **基肥（basal fertiliser）**：播种时的施用，试验用它衡量遵从度。
- **接手（handoff）**：把农户交给技术员或带头农户，协助把方案落实下去。

## 用智能体搭建

**形态：** `service`。一季的提示要在几个月里发给很多农户，走通讯应用，现场没人；人出现在登记处、季中的例外处，以及落实需要帮助的接手处。

**需要：** 土壤属性图，以及把它裁剪到地块的办法；一个能产出农户已确认边界的登记流程；地块的管理历史；把土壤、历史与目标产量变成养分方案的规则集，用量是农艺师批准过的；农户在用的通讯渠道，并明确语言与识字假设；按作物阶段排布的季中提示日程；用于接手的技员或带头农户网络；季末对比所需的收获数据。方案的算术必须是规则代码而不是模型估算，因为肥料用量是农户要花钱买的数字。

| 步骤 | 搭建方式 |
|---|---|
| 农户通过 WhatsApp 登记地块 | 通讯应用里的登记流程记录位置并画出边界；Skill 只问规则需要的问题，因为每多问一句就多一分放弃登记的可能。 |
| 🛑 review（农户在地图上核对地块多边形） | 在任何计算之前，把轮廓给农户看，由他确认或修正；多边形错了，就会为别人的地算出一份自信的方案，所以后面一切都挂在这道关卡上。 |
| 土壤图数据 + 管理历史 | 把地块裁剪到土壤图上；历史来自农户上一季的陈述；两者都按地块 id 存档。 |
| 目标产量 + 养分方案 | 规则代码用三个输入算出方案，Skill 用农户的语言解释——用量、时机和花费，因为算不出钱的方案不会被照着做。 |
| 生长季提示 | 按作物阶段排定的日程去问观察结果——出苗、虫害、叶色——回答或进规则、或进人工；渠道支持时也收照片。 |
| 基于规则的建议 | 建议来自规则集而不是自由生成，所以同一个观察每次问都得到同一个推荐。 |
| 🛑 handoff（带头农户 / 技术员协助落实） | 当农户报上规则解决不了的问题，或方案没被照做，案件带着地块、方案和观察记录交给技术员或带头农户。 |
| 收获数据 | 季末记录产量，这是下一季目标和项目主张能被检验的依据。 |

**检查点：** `review`：多边形确认，因为之后每个数字都是对"被确认的那个边界"算的。`handoff`：技术员这一步才是实测结果出现的地方——试验显示有技术员支持的那组增幅大得多——所以本搭建把接手当作流程的一部分而不是可选项，并按明确触发条件路由（观察未决、错过阶段、方案未被执行）。

**与来源相比：** 来源出自 2025 年与 2026-09：平台自己的论文，以及一篇关于产量的观察性预印本。预印本本轮没有重新打开，其作者可能与平台提供方有关联，条目已注明这一点。此后有这些变化：周边证据朝同一方向更谨慎了。2026 年一份关于南亚咨询证据的综述指出，[技术表现的证据强于农户实际收益的证据](https://www.agriculturejournal.org/abstract?var=27413)，而且信任是有条件的：2026 年一项生产者调查中，只有约四分之一受访者表示会在不另行核实的情况下信任 AI 的农业建议。这支持了本搭建坚持的两件事——落实环节有个人、季末有产量记录——而不是新增了什么。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 农户为地块做地理配准，并在地图上核对地块多边形（🛑 **审阅**）[[1]](#sources)。
2. 根据 iSDA 土壤属性图和农户的回答，生成目标产量和养分方案 [[1]](#sources)。
3. 整个生长季中提示农户反馈观察情况，并由规则模型返回量身定制的建议 [[1]](#sources)。
4. 🛑 **接手**：带头农户或技术员协助落实；有技术员支持的那一组产量增幅更大 [[2]](#sources)。

**产出：** 逐地块的养分方案和生长季建议。
**失败模式 → 防护：** 农户不按方案执行 → 产量与基肥施用的遵从度相关；技术员的支持有帮助。
