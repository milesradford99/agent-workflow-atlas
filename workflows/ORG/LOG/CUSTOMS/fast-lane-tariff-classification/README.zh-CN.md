# 快速通道税则归类

**工具变体：** `traide-ai`

## 背景

货物过境之前，每件产品都需要一个协调制度（Harmonized System）税则号，这是海关用来确定关税、适用进口规定的国际编码表。经销大量电子产品的分销商，必须在每个新品发货前为它定下一个税则号。归类员阅读产品数据手册，提取有关键意义的特征，再按一套固定的解释规则一步步得出税则号；两个人读同一份数据手册，可能得出不同的号。智能体负责提取特征、提出税则号，并逐步写出推理过程。贸易合规人员仍要检查每条建议，因为税则号是向海关作出的申报，公司要为此负责，而产品数据不充分的条目需要归类员来判断。

**术语：**
- **HS 税则号**：协调制度中为海关对产品归类的编码。
- **GRI 1-6**：归类总规则（General Rules of Interpretation）共六条，按顺序适用，用来决定一件产品在协调制度中属于哪里。
- **注释、章注**：解释每个品目和每一章涵盖范围的官方文本。
- **SKU**：公司备货销售的一种独立产品。
- **核心产品数据（主数据）**：公司对每个产品的中央记录，之后的报关单从中取用。
- **贸易合规与海关团队、归类员**：负责归类决定的人员；归类员对智能体没能定下来的条目做返工。
- **快速通道**：建议原样被接受，不需要返工。

## 用智能体搭建

**形态：** `service`。新品以每月约 1,250 件的流量到来并进入审阅队列，所以智能体启动时没有人在场，人稍后再看每条建议。

**需要：** 来自产品数据系统的新品数据流或导出文件；对数据手册和提取可用的公开产品页面的读取权限；放在 skill 旁边、作为参考文件的协调制度文本、注释和章注；对话之外用来保存每个条目的提取特征、建议和状态的存储；贸易合规人员逐条处理的审阅队列（工单看板或共享表格）。不要给智能体写入核心产品数据的权限。

| 步骤 | 搭建方式 |
|---|---|
| 新品 (约 1,250 件/月) | 云端定时任务，或自己的调度器运行 `claude -p` 或 Agent SDK 程序，取出存储里还没有的条目。 |
| 从数据手册 / 公开来源提取产品特征 | 一个 skill 读每份数据手册并记录特征，每项注明出处；可以用子智能体并行处理条目。缺失的特征列出来，不自行补全。 |
| 按 GRI 1-6 给出理由，并结合注释/章注，归类 HS 税则号 | 同一个 skill 按顺序适用规则，查阅参考文件并写出理由，按标题引用注释。 |
| 🛑 review (贸易合规人员原样接受 = 快速通道 \| 返工) | 见“检查点”。 |
| 把编码和依据写入核心产品数据 | 由一个小脚本而不是智能体，把已接受条目的编码和依据写入产品数据系统。 |

**检查点：** `review`：每个条目及其理由进入审阅队列。智能体没有任何能写入核心产品数据的工具，所以在有人接受之前什么都进不去；负责写入的脚本只读取标为“已接受”的条目。产品数据缺失或含糊的条目标给归类员，而不给出建议。接受和返工的结果记录在存储中。

**与来源相比：** 唯一的来源是一篇厂商成功案例，日期 2025-10-16，其唯一的公开实例就是同一页面。2026-11 的一次检索只找到厂商材料，包括 traide 目前未注明日期的首页，它仍然描述按 GRI 步骤归类并留有审计轨迹；截至 2026-11 没有找到更新的第一手记录。来源描述的是一个厂商平台；本搭建方式用 skill、参考文件和审阅队列取代它，不包含该平台自己的界面和它与产品数据系统的连接。原样被接受的条目比例是厂商报告的数字，不能说明本搭建方式的情况。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 每月新到的商品排队等待归类；厂商平台自动从产品数据手册或公开来源提取相关的核心产品数据 [[1]](#sources)。
2. 平台提出协调制度（HS）税则号，并按 GRI 1-6 解释每一步归类，引用注释和章注 [[1]](#sources)。
3. 🛑 **审阅**：贸易合规和海关团队检查每条建议；在 Ingram Micro，最多 80% 走“快速通道”（无需人工返工直接接受），其余由归类员返工 [[1]](#sources)。
4. 被接受的归类及其依据写入公司现有的核心产品数据，后续报关可以复用 [[1]](#sources)。

**产出：** 已归类的产品主数据（每个条目有税则号和有据可查的依据），供报关单取用。
**失败模式 → 防护：** 归类结果取决于谁来读数据手册 → 标准化提取和按 GRI 步骤给出依据，使结果与处理人无关 [1]。产品数据含糊或不完整 → 该条目退出快速通道，转人工返工 [1]。

**与相近工作流的区别：** 最接近的是 AWF-0148（报关行审阅的报关单准备）：它根据进口商文件构建一份货运报关单，并匹配已有的零件库，在 ABI 申报前由报关行签发。本工作流是在任何货运发生之前，针对每个新 SKU 建立零件库本身；交付物是主数据中的归类结果，检查点是贸易合规人员对每个条目选择接受或返工，而不是对报关单签发。
