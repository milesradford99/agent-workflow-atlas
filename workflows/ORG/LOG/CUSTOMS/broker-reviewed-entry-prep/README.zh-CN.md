# 报关单预录与经纪人复核

**工具变体：** `cervo` · `avathon`

## 背景

每一批进入美国的货物都要有一份报关单：向美国海关与边境保护局提交的申报，说明货物是什么、在哪里生产、应缴多少关税。进口商（把货物运进来的公司）把发票和装箱单交给报关经纪人，也就是政府颁发执照、可以代进口商申报的人，再由报关行的录入员把数据录进申报系统。每个产品行都需要一个税则编码、一个原产国，适用贸易措施时还要加上额外关税编码，而这些编码变化很快，所以报关单做起来慢，编码一错还可能被罚。智能体读取单据，为每个字段提出取值并标明出处，再套用报关行存好的产品记录和进口商自己的规则。录入员核对字段，只有持证报关经纪人才能提交，因为经纪人要对所申报的内容负法律责任。

**术语：**
- **报关单（CBP 表格 7501）**：申报进口货物及应缴关税的文件。
- **报关经纪人、录入员**：代进口商办理申报的持证专业人员；报关行里为经纪人准备报关单的职员。
- **HTS 编码**：协调关税税则（Harmonized Tariff Schedule）编码，用来给产品归类并确定基础税率。
- **原产地拆分**：一件产品在多个国家生产时，把价值和重量分到各个国家，每一部分适用的关税可以不同。
- **Chapter 99、Section 232 / 301 / 122 叠加**：美国根据不同的贸易措施加征的额外关税。每项措施有自己的编码，一件产品可能在基础税率之上同时适用几项，所以叫“叠加”。
- **零件库（parts library）**：报关行为每个产品存好的记录（税则编码、原产地、额外关税的处理），重复发货时沿用，保证答案一致。
- **SOP 规则**：进口商对其报关单如何准备的长期要求，例如单据的特殊之处或归类上的选择。
- **ABI、NetCHB**：自动化经纪人接口（Automated Broker Interface）是经纪人软件向美国海关传送报关单的电子通道；NetCHB 是来源中提到的报关行软件。

## 用智能体搭建

**形态：** `skill`。录入员一次准备一份报关单，并且全程在对话中，所以一个 skill 就够了，流程、零件库和进口商规则都作为参考文件放在它旁边。

**需要：** 进口商的商业单据（发票、装箱单之类）文件；放在 skill 旁边、作为电子表格或 CSV 的零件库，每一行注明出处和最后更新日期；每个进口商一份规则文件；一套报关行批准、可以处理进口商商业数据的环境（有来源称，其团队无法把这类数据放进通用 AI 工具）。不要给智能体接通 ABI 或美国海关。

| 步骤 | 搭建方式 |
|---|---|
| 进口商单据 → 提取为报关单字段，附置信度 + 出处 | skill 的第一条指令：读每份单据，填一张表：字段、取值、来源单据和页码、置信度。找不到的字段标为缺失，绝不猜测。 |
| 匹配零件库 (HTS、原产地、Chapter 99 / Section 232 叠加) | skill 在零件库文件里查每个项目，抄下其编码和关税处理。不在文件里的项目标出来交给录入员，不凭记忆归类。 |
| 进口商专属的 SOP 规则 | skill 打开 `rules/<importer>.md` 并套用；规则覆盖零件库的地方，在表中注明。 |
| 🛑 review (录入员 / 持证经纪人核对字段 + 置信度) → 推送到 ABI (NetCHB) → 🛑 sign-off (经纪人提交) | 见“检查点”。 |
| 关税变更：批量更新零件库 | 第二个 skill：给它一份规则变更的通知，它写出零件库的建议副本，每个改动的行都做标记，由人批准后副本才替换原文件。 |

**检查点：** `review`：skill 最后给出字段表，把低置信度、缺失和被规则覆盖的字段排在最前，然后停下；录入员修改并批准。之后 skill 才把取值写成录入员能载入或手工录入自己 ABI 软件的形式。`sign-off`：智能体没有 ABI 或申报用的连接器，所以由持证经纪人从自己的系统提交。

**与来源相比：** 来源出自 2025-10 至 2026-10；三篇 Cervo 案例未注明日期。C.H. Robinson 的新闻稿在 2026-11 无法打开，所以这里对它的使用依据的是条目本身的文字。来源描述的是厂商产品：文档提取器、可批量编辑的实时零件库、用于设定进口商规则的智能体工作室，以及与 ABI 的连接。本搭建方式用文件和一个 skill 完成同样的步骤，不包含产品的界面、ABI 连接和关税模拟器。每个字段的置信度是模型对自己读取结果的判断，不是厂商的打分，录入员应对照所示出处核对。无需查找更新的记录：最新的来源出自 2026-10。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 智能体接收进口商的商业单据并提取报关数据，每个字段都附置信度和出处 [[2]](#sources)[[3]](#sources)。
2. 智能体应用动态零件库（HTS 编码、原产地拆分、Section 232/301/122 叠加）以及在厂商智能体工作室中设定的进口商专属 SOP 规则 [[1]](#sources)[[2]](#sources)。
3. 🛑 **审阅**：录入员在工具中审阅报关单，再推送到自己的 ABI，能看到 'confidence levels and source data for each field' [[3]](#sources)。
4. 🛑 **签发**：经纪人通过 NetCHB 始终 'fully in control of review and submission' [[2]](#sources)。
5. 规则变化时，在生效日期之前批量更新零件库 [[3]](#sources)。

**产出：** 由持证经纪人申报的报关单（CBP 表格 7501）。
**失败模式 → 防护：** 关税规则变化快于零件数据 → 批量更新零件库。归类错误的处罚 → 经纪人审阅每一份报关单；Krenz & Hannan 的审计已改为覆盖 100% 的报关单。

**近期实践（2026）：**
- 单据接收：收到的单据（来自发货人、承运人和政府机构，共四十多种类型）被拆分、分类并附到对应的货件上，系统会在提取完成前索要缺失的单据（C.H. Robinson，2026-10-26）。[[5]](#sources)

**与相近工作流的区别：** 形态上最接近的是 AWF-0041 可直接审阅的 1040 报税准备（Review-ready 1040 prep）（带置信度提取 → 报税员审阅 → 高级人员签发）。但它通不过互换测试：产出是带关税叠加逻辑和持续维护零件库的报关申报，由持证报关经纪人签发。
