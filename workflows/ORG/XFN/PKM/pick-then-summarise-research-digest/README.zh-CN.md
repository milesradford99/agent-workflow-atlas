# 先选后读的文献摘要简报

**工具变体：** `claude-code` · `obsidian` · `hermes-agent` · `netnewswire` · `github-pages`

## 背景

研究人员和关注某个领域的从业者需要跟上新论文，而每天出现的论文远多于任何人能读完的数量。反复查看同样的检索网站，再判断哪些结果值得点开，既重复又耗神，仔细读完选中的论文还在这之后。这里由一个定时脚本按读者的主题检索新论文，列成每日简报。读者决定留下哪些，只对这些论文，智能体才写出方法、所发现效应的大小和证据的摘要，而不是把摘要段落（abstract）重复一遍。读者两次留在环节里：选哪些论文由他自己决定，因为只有他知道什么对自己的工作重要；引用或据此行动之前，他要对照论文核对每份摘要，因为摘要可能把方法说错。

**术语：**
- **arXiv、Google Scholar**：前者是在期刊发表之前或同时公开研究论文的免费文库，后者是学术论文的搜索引擎。
- **预印本（preprint）**：在同行评审之前就公开发布的论文。
- **简报（digest）**：列出当天新论文并附链接的简短页面或笔记。
- **效应量（effect size）**：研究中测得的差异或结果有多大，而不只是有没有测到。
- **cron**：计算机上的调度程序，按设定的时间运行脚本，例如每天早上。
- **RSS 源**：期刊或网站把新文章列出来，供阅读程序订阅的一种订阅源。
- **DOI**：已发表论文的永久标识和链接。

## 用智能体搭建

**形态：** `service`。定时检索和每晚的摘要任务都在没人操作的情况下运行，读者只看到简报和摘要。

**需要：** 一份主题配置文件，以及一份已展示论文的记录；一个 arXiv 检索脚本（每周一次再加 Google Scholar，前提是你的脚本能访问它）；检索结果写入的每日笔记或简报页面；一个研究文件夹，读者把选中的 PDF 放进去；运行这些任务的地方，例如读者自己的电脑。智能体只需要对研究文件夹有读取权限，对简报有写入权限。

| 步骤 | 搭建方式 |
|---|---|
| 日常定时任务：按主题配置检索 arXiv (每周加 Google Scholar)，跳过已展示的论文 | 由 cron 或其他调度器运行的一个普通脚本。不需要智能体：它查询各网站，剔除已见记录里的论文，把新论文写进当天的简报。 |
| 简报链接到每日笔记 | 同一个脚本添加链接。 |
| 🛑 plan (读者保存选中的 PDF) | 见“检查点”。 |
| 夜间：每个已保存的 PDF：智能体总结方法、效应量、证据 | 一个定时任务（文件能从云端访问时用云端定时任务，否则由自己的调度器启动 `claude -p`），对每个新保存的 PDF 运行一个 skill；skill 要求给出方法、效应量和其他证据。 |
| 摘要出现在次日简报 | 任务的最后一步把每份摘要追加到次日简报，并标明尚未核对。 |
| 🛑 review (读者在引用或据此行动前核对) | 见“检查点”。 |

**检查点：** `plan`：简报只列出论文；读者把 PDF 存进研究文件夹之前，不会有任何论文被做摘要，夜间任务也只被授予这个文件夹。`review`：摘要标明为未核对，智能体没有发布、引用或发送它们的工具；读者先打开论文对照，再决定是否采信摘要。

**与来源相比：** 来源出自 2026-01 至 2026-05。来源 1 在作者自己的电脑上用 cron 运行两个 Python 脚本，并调用 Claude Code 智能体做摘要；这套搭建方式保留了这种分工，并在文件能从云端访问时，把云端定时任务列为另一种选择。步骤 7 和来源 2 描述的是用其他工具搭成的变体（Research Radar）：本地的订阅阅读器、一个叫 Hermes Agent 的调度层和另一个模型，外加一个质检任务；它不在 shape 之内，这套搭建方式也不复现它。这套搭建方式不断言摘要有多准确：来源 1 报告了一份摘要帮助作者发现一篇论文的缺陷，而读者的核对正是审阅这一步存在的原因。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 读者维护一份研究主题配置，以及一份已展示论文的记录 [[1]](#sources)。
2. 每天早上由检索脚本查询 arXiv，周日再加上 Google Scholar。新结果进入一份简报（列出当天新论文并附链接的页面），从带日期的 /today 笔记（读者的每日待办页）链接过去 [[1]](#sources)。
3. 🛑 **计划**：读者浏览简报，只把有希望的 PDF 保存到研究文件夹，这一步就是防止信息过载的过滤器 [[1]](#sources)。
4. 每晚由脚本找出新保存的 PDF，让 Claude Code 智能体总结方法、效应量和其他证据，而不只是摘要 [[1]](#sources)。
5. 这些摘要出现在次日的简报中 [[1]](#sources)。
6. 🛑 **审阅**：读者在使用之前先阅读并核对每份摘要。Torres 曾借此发现一处方法上的缺陷，并公开撰文论述 [[1]](#sources)。
7. 变体（Research Radar）：每天 09:15 的定时任务按研究画像过滤 20 多个 RSS 源，为每篇论文标注等级（细读、略读、知晓）并附 'why it matters' 说明，10:00 的质检（QA）任务检查字段和 DOI。随后页面提交到 GitHub Pages，由作者决定读什么。智能体从不往 Zotero（文献管理工具）添加内容，也不删除任何东西 [[2]](#sources)。

**产出：** 每日的新论文简报页面或笔记，加上针对读者所选论文的、聚焦证据的摘要。
**失败模式 → 防护：** 信息过载 → 只有读者保存的 PDF 才会得到深度摘要。摘要误述了方法 → 引用前由读者审阅。格式错误的输出破坏页面 → 单独的质检定时任务修复小问题，拦截严重问题 [[2]](#sources)。重复 → 在配置中记录已见过的论文。
**与相近工作流的区别：** AWF-0087 以 diff 审阅的笔记库维护（Diff-reviewed vault upkeep）中，智能体按口述指令编辑已有的笔记库，检查点是对修改做 git diff 审阅。本工作流中，智能体按计划引入新的外部文献。产出是简报加摘要，检查点是读者挑选要处理哪些论文，然后阅读摘要。
