# 每日收件箱分流

**智能体套件：** [在 Claude Code 中运行](variants/claude-code.md)
**防护：** 收到的邮件是不可信输入（提示词注入的攻击面）。智能体绝不能自行发送。

## 背景

大多数职场人一天开始时，面对的是塞满邮件的收件箱、需要安排的日历请求，以及聊天应用里的消息。要弄清哪些今天必须回复、该怎么说、什么时候开会，在真正开始工作之前就要花掉不少时间，也容易让人干脆放着不管，直到堆积如山。这里由智能体每天早晨读取这三处，给每一项分类，需要回复的写好草稿，建议会议时间，并汇总出最重要的五件事的简报。每封邮件仍由机主自己读、自己发，每个邀请也由机主自己接受。一条回复代表机主对外说话，发出去就收不回来；而收到的消息出自外人之手，所以智能体不能自己据此行动。

**术语：**
- **分流（triage）**：按每一项所需的处理来分类：需要回复、需要阅读、需要转交，或者不用处理。
- **私信（DM，direct message）**：Slack、WhatsApp 或 iMessage 等聊天应用里的私人消息。
- **草稿**：存放在邮件程序草稿箱里、尚未发出的回复。
- **日历占位**：日历上暂时占住的一段时间，还不是确认的日程。
- **提示词注入（prompt injection）**：写在邮件或消息里的文字，目的是让智能体听从发件人的指令，而不是机主的指令。
- **致命三要素（lethal trifecta）**：智能体同时能读取私有数据、接触不可信内容、向外发送消息，三者合在一起，攻击者就能窃取数据。
- **待办事项追踪表**：机主向他人做出的承诺的一份持续更新的清单。

## 用智能体搭建

**形态：** `service`。这次运行在 07:00 启动，现场没有人，机主只看到简报和草稿。[套件](variants/claude-code.md)把这套搭建方式写成了文件。

**需要：** 邮件、日历和（如果用到）聊天的连接器（MCP 服务器），各自设为所能提供的最窄权限：邮件连接器可以读取、加标签和创建草稿，没有发送工具；日历连接器只读。一份根据机主已发邮件提炼的语气规则文件，以及一份规则文件（重要发件人、可转交的人、哪些可以归档）。简报需要一个存放位置，例如按日期命名的文件。把每一条收到的消息都当作待分类的数据，绝不当作指令。

| 步骤 | 搭建方式 |
|---|---|
| 07:00 定时：邮件、日程、私信 | 连接器能从云端访问时，用云端定时任务；否则用自己的调度器启动 `claude -p` 或一个 Agent SDK 程序。 |
| 分类 (处理 / 知悉 / 转派 / 归档) | 一个 skill：读取自上次运行以来未回复的邮件、当天日程和未读私信，把每一项放进一个类别，并附一行理由。 |
| 每个邮件线程：回复存为草稿 | 同一个 skill，调用连接器的创建草稿工具，依据机主的语气规则和 `CLAUDE.md`。收件人地址取自线程本身。 |
| 会议时段建议 | skill 读取空闲和忙碌时段，把两三个建议时段写进草稿；不创建任何日程。 |
| 前 5 项简报 | skill 的最后一步写出按日期命名的简报文件：最重要的五项、各类别的数量、草稿清单和可疑消息。 |
| 🛑 action (每条消息由本人发送，每个邀请由本人接受) | 见“检查点”。 |

**检查点：** `action`：机主在自己的邮件客户端里打开草稿，然后编辑并发送，或者拒绝。连接器没有给智能体发送、转发、接受、拒绝或删除的工具；如果以后有这类工具被加进来，权限拒绝规则或针对这类工具名的 `PreToolUse` 钩子会让运行停下。智能体只负责准备草稿和占位。凡是索要凭据或更改付款信息、或者直接对助手说话的消息，都放在简报的“可疑”标题下，不写草稿。

**与来源相比：** 来源出自 2025-06 至 2025-12；其中两个是没有日期的代码仓库，2026-11 都没能打开（站点拒绝了请求），所以依据本条目的文字阅读。来源 2 用桌面端定时任务运行分流，因为它会接触本地数据；这不在 STANDARD.md 列出的构件之内，所以这套搭建方式改用云端定时任务或 `claude -p`。云端任务需要它能访问到的连接器，纯本地的邮件环境可能做不到。来源 1 描述的是机主要求智能体做分流的交互式会话，而不是定时运行；草稿权限和语气规则出自它。来源 3 允许发送且没有说明审批步骤，这套搭建方式没有沿用。搭建方式加入了禁止发送的拒绝规则或钩子，因为仅在 `CLAUDE.md` 里写明只是请智能体别发，来源 4 说明了为什么这还不够。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 一个定时任务运行分流，用的是桌面端的定时任务，因为它会接触本地数据 [[2]](#sources)。智能体通过 MCP 连接 Gmail、日历和通讯录 [[1]](#sources) [[2]](#sources)，如有需要再加入 Slack、WhatsApp 或 iMessage 来处理私信 [[3]](#sources)。
2. 智能体把每一项归入某个层级：立即回复、今天处理，或知悉/归档 [[3]](#sources)。按领域分类也可行，比如审稿邀请、合作者邮件、各类邀请和行政截止日期 [[2]](#sources)。一份需要回复的简单清单（未读优先）同样可行 [[1]](#sources)。
3. 对每个邮件线程，智能体起草回复。它找到原始线程及其邮件 ID，明确写出 `To:` 地址，搜索上下文，把回复存为草稿，绝不发送 [[1]](#sources)。语气规则来自机主已发送的几百封邮件，提炼后写入 CLAUDE.md [[1]](#sources) [[3]](#sources)。
4. 智能体建议会议时段：当某个线程需要约时间时，把日历占位作为待批准的操作提出，而不是直接订下事件 [[2]](#sources)。
5. 智能体撰写早间简报，涵盖日程、任务、紧急消息和会议准备 [[3]](#sources)，另附摘要和待办事项追踪表（机主所做承诺的持续清单） [[2]](#sources)。
6. 🛑 **操作**：机主在自己的邮件客户端中查看草稿，然后编辑并发送，或者拒绝 [[1]](#sources)。每个提议的操作（包括日历占位）都要等待批准，不会自动发送任何内容 [[2]](#sources)。

**产出：** 一个已分流的收件箱、放在邮件客户端草稿箱中的回复草稿、建议的日历占位，以及一份简短的早间简报。机主逐项发送、接受或丢弃。
**失败模式 → 防护：** 未经批准就发送（一个原型接受了作者不想要的写书邀约）→ 只给智能体草稿权限，不提供发送工具 [[1]](#sources)。有发送能力却没有说明审批步骤的方案 [[3]](#sources) → 直接移除发送权限，而不是依赖提示词。来自收件邮件的提示词注入，因为私有数据、不可信内容和对外消息凑在一起就构成“致命三要素”（lethal trifecta）→ 让发送动作不在智能体的能力范围内 [[4]](#sources)。回复发错地址，因为工具不会从线程里取收件人 → 在提示词中明确写出 `To:` [[1]](#sources)。邮件会经过第三方服务 → 连接私人收件箱之前先权衡这一点 [[1]](#sources)。MCP 连接中断 → 该技能会优雅降级，而不是直接失败 [[2]](#sources)。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。来自 [Where are the real runs?](../../../../../research/2026-11-real-runs.md)；每个数字都已对照原页面复核。

- [Harper Reed, *Getting Claude Code to do my emails*](https://harper.blog/2025/12/03/claude-code-email-productivity-mcp-agents/) (2025-12-03)。通过 MCP 接入邮件、日历和通讯录 → 只生成草稿；每条消息由他本人发送，此前发生过一次未经批准的发送。"the past couple hundred emails I have sent"（用于训练语气）。*第一手：是；可信度：高。*
- [Pedro Sant'Anna, `/triage-inbox`](https://github.com/pedrohcgs/claude-code-my-workflow)。定时的早晨分流 → 分类 → 草稿 → 建议的日历占位；每个对外操作都需要确认。triage-inbox v2.0（配置，没有运行记述）。*第一手：是；可信度：高。*
- [Mike Murchison, claude-chief-of-staff](https://github.com/mimurchison/claude-chief-of-staff)。`/gm` 简报 + 三级分流并附草稿；**允许发送**，且没有说明审批步骤。"from 90 minutes of morning inbox processing to about 5"。*第一手：是；可信度：中。*
