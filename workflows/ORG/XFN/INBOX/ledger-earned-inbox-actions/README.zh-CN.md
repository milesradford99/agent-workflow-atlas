# 账本赢得授权的邮箱操作

**与相近工作流的区别：** 最接近的是 AWF-0031 每日邮箱分诊（Daily inbox triage，辅助：每封邮件由人发送，每个邀请由人接受，智能体只起草）。本工作流中智能体通过闸门直接操作邮箱，每类操作凭负责人的决定记录赢得自主权，并有升级签发和自动降级。检查点安排和自主程度不同，交付物也不同（邮箱确实被清理了，而不是简报加草稿）。AWF-0145 是日历审计，与邮件无关。
**工具变体：** `claude-scheduled-task` · `gmail` · `outlook`

## 步骤

1. 一个定时的 Claude 任务每天在 Gmail 和 Outlook 中读取几次未读邮件。对每封邮件，它从三种操作中选一种：删除、标为已读，或存一份回复草稿。它不能发送，也不持有邮箱密钥 [[1]](#sources)。
2. 每个变更请求都交给闸门，只有闸门持有凭据。在 L0 级别，每个请求都要等待。🛑 **操作**：负责人在手机上批准或拒绝 [[1]](#sources)。
3. 账本记录每个决定，按任务、按邮箱分别保存。只有明确的批准、拒绝或“标记为错误”才算数；沉默不计入 [[1]](#sources)。
4. 🛑 **签发**：某个任务最近 100 次决定中被拒绝的不超过 2 次，就有资格升一级，并由负责人确认。在 L1 级别，常规请求（例如来自已批准发件人的删除）自动通过；新发件人仍要等待。最近 10 次中被拒绝 3 次，该任务退回逐次询问 [[1]](#sources)。
5. 每个任务在每个级别都有每小时和每日的上限 [[1]](#sources)。
6. 每次运行开始时，智能体回读上次运行以来的决定和备注，把它们变成规则（例如某个发件人保持未读）。它也从负责人发出的邮件和对草稿的修改中学习 [[1]](#sources)。
7. 每次运行以一份简报收尾，说明查看了什么、做了什么、在等什么。闸门把数量与账本核对。🛑 **操作**：草稿最高只到 L2，所以回复始终由负责人亲自发送 [[1]](#sources)。

**产出：** 一个邮箱：已赢得授权的任务（目前只有删除）自行运行，其余的等待批准；另有按任务记录的账本，决定每个任务的自主级别。
**失败模式 → 防护：** 一个全局信任设置对大多数任务都不合适 → 按任务建账本，并设升级与降级规则。数量失控 → 每小时和每日上限（“37 封 Gmail 删除请求被上限拦下”）。简报与实际脱节 → 闸门交叉核对数量。罕见任务（草稿）永远达不到 100 次决定的门槛 → 负责人打算按任务频率调整门槛。
