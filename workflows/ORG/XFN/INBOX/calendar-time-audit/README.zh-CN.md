# 日历时间审计

**工具变体：** `claude-code` · `cursor` · `google-calendar-api`

## 背景

高管的日历上塞满了没人核对过价值的会议：有的写成一份共享文档就够了，有的可以让同事代为参加，有的来自高管根本不认识的人。回头看两周的时间都花在哪里、再决定下周砍掉什么，既费时间，所以很少有人做。这里由智能体读取日历、给会议分类、把时间分布与该岗位本应投入的方向做对比，并提出取消和转交的建议。每一条由本人决定，因为哪些会议在政治上或人情上重要，只有本人清楚。日历的改动由助理来做，因为智能体没有修改日历的权限，也不能替本人对外写信。

**术语：**
- **助理（EA，executive assistant）**：负责管理高管日历和往来信函的人。
- **可转交的会议**：总监或同事可以代为参加并事后汇报的会议。
- **重复预订**：两个会议排在同一时间段。
- **上下文切换**：在互不相关的话题之间切换得太频繁，以致没有整块时间做需要专注的事。
- **只读权限**：只能查看日历，不能新建、移动或删除日程的连接。

## 用智能体搭建

**形态：** `skill`。一个人大约每周做一次审计，并且全程在对话中逐条接受或拒绝建议，所以一个 skill 就够了。

**需要：** 通过日历连接器（MCP 服务器）获得的、对本人日历的只读访问；一份简短的上下文文件，写明本人的角色以及该角色应把时间花在哪里；可以代为参加例会的人员名单。不要给智能体日历写入范围，也不要接入邮件连接器。

| 步骤 | 搭建方式 |
|---|---|
| 周度：只读方式读取最近两周日历 | 本人启动 skill，由它通过只读连接器读取两周的日程。 |
| 对会议分类 (可写成文档、可转交、可跳过、重复预订、频繁切换上下文) | skill 自身的指令，五个类别在一份参考文件中定义；智能体给每个日程打标签。 |
| 对照岗位期望比较时间分配 | skill 把每一类的时长与上下文文件中的岗位说明做对比。 |
| 下周：可取消或转交的会议 | 智能体读取下周日程，逐项列出，写明理由；转交的会议写明谁可以代为参加。 |
| 🛑 review (本人逐项接受或拒绝) → 🛑 handoff (助理执行日历变更) | 见“检查点”。 |

**检查点：** `review`：skill 给出清单后停下；本人把每一项标为接受或拒绝。`handoff`：skill 最后把已接受的事项写成给助理的一份说明；日历连接是只读的，智能体无法执行这些改动，由助理在日历里操作。

**与来源相比：** 来源出自 2025-11 至 2025-12。两篇都描述一位高管自己运行这套做法，用的是 Claude Code 智能体和她自己的本地应用；这项审计除了日历只读权限之外不需要其他工具。来源里的 'Brutal Truth' 模块是一条提示指令，这里只保留为与岗位期望的对比。来源中的实例是访谈和播客文字稿，所以上面的搭建方式是设计，不是已报道的做法。本搭建方式略去了来源里与审计并列出现的邮件分流，见 AWF-0031。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 负责人通过官方 API，以只读方式连接 Google Calendar，并连接不带发送权限的 Gmail。令牌放在被 git 忽略的 .env 文件中。上下文文件描述负责人的角色和风格 [[1]](#sources)[[2]](#sources)。
2. 负责人提示智能体分析过去两周的时间是怎么花的 [[2]](#sources)。
3. 智能体标出这些情况：可以改成文档或 Slack 更新的会议、总监或同事可以代为参加的会议、来自陌生组织者或议程不清的会议、重复预订，以及频繁的上下文切换 [[1]](#sources)[[2]](#sources)。
4. 一个叫 'Brutal Truth' 的模块（负责人给智能体设定的一组指令）把时间分布与该岗位的期望做对比，指出低于该岗位层级的工作 [[1]](#sources)。
5. 智能体查看下周，建议可以取消的会议 [[2]](#sources)。
6. 🛑 **审阅**：负责人把输出当作初稿，逐项接受或拒绝每条建议 [[2]](#sources)。
7. 🛑 **接手**：负责人把结论交给她的助理（EA），由助理修改日历。智能体对日历没有写权限 [[1]](#sources)[[2]](#sources)。

**产出：** 一份时间分配审计和下周的取消与转交清单，交给助理，由助理修改日历。
**失败模式 → 防护：** 建议忽略背景（有些会议有政治上的重要性）→ 负责人逐项接受或拒绝。智能体擅自操作他人日历 → 只读的日历范围，且无发送权限。会议所需的数据缺失（如链接）→ 负责人修正并优化提示词；她建议在调校到位之前先运行智能体 '3 or 4 times'。
**与相近工作流的区别：** AWF-0031 每日收件箱分流（Daily inbox triage）每天处理邮件、日历和私信，产出回复草稿和前 5 项简报，每条消息都由人发送。本工作流的产出是对时间使用情况的回顾性审计，加上向前的取消与转交计划。它每周运行一次，检查点是先审阅、再移交给助理（EA），而不是逐条消息发送。
