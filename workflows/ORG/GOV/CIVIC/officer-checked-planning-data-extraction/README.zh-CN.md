# 规划档案数据提取与人工核验

**与相近工作流的区别：** AWF-0082 模型分流的档案解密（Model-triaged records release）中，分类器决定是否解密，只有不确定的档案交给人，质检为抽样。本工作流的产出是由扫描规划档案生成的结构化地理空间数据集，官员在导出前对每一项输出都做审阅和修正。产出不同，且是全量审阅而非抽样。
**工具变体：** `extract`

## 背景

地方政府手里攥着几十年的规划决定，都是纸：树木保护令、保护区划定、限制某片区域免许可改建的指令。每一份都是带文字和地图的扫描件，而地图是最要紧的部分，因为复印图上画的一条边界，决定了某一棵树或某栋楼是否受保护。议会需要把这些档案变成数据——机器可读、经过地理配准、可全国发布——而手工重录正是那种永远拿不到预算的活。本工作流读扫描件：文字字段进入议会的模式，地图边界被描成多边形、对齐到国家地图坐标，而负责该档案的官员在导出之前核对并修正每一个字段、每一条边界。审阅是全量而不是抽样，哪怕工具准确率已经很高，因为产出是发布到全国的法律性划定：官员的修正就是议会对"这条边界是对的"的声明，而这个声明不能由一个平均准确率不错的模型来作。

**术语：**
- **TPO**（tree preservation order，树木保护令）：保护特定树木的划定，附有地图。
- **保护区（conservation area）**：拆除与改建需许可的划定区域。
- **Article 4 direction**：取消某区域部分"许可开发权"的指令。
- **模式（schema）**：议会数据必须符合的字段与类型定义。
- **多边形（polygon）**：GIS 中存储的划定区域矢量边界。
- **地理配准（georeferencing）**：把扫描地图对齐到真实世界坐标。
- **地面控制点（ground control point）**：扫描件与参考地图上都可见、用来对齐的特征点。
- **IoU**（intersection over union，交并比）：两个多边形的重叠程度，用来给边界精度打分。

## 用智能体搭建

**形态：** `skill`。一位规划官员一次处理一份档案，并对它的每个字段与边界签字；提取是官员手里的一套工具，而不是一个不需要他就能跑的服务。

**需要：** 扫描档案与议会的模式；一条文本提取路径，每个字段都带它在页面上的位置；一步边界描绘，用视觉与分割模型，且扫描分辨率足以描线；用于地理配准的国家地图参考，以及用来对齐的控制点；一个复核界面，官员能并排看到扫描件、字段和多边形；面向议会自有系统与国家平台的两套导出格式。智能体不能导出：导出是官员的动作，划定也是他的。

| 步骤 | 搭建方式 |
|---|---|
| 上传扫描的规划档案 | 官员上传，Skill 读页面结构——标题、日期、决定正文、地图图幅——于是提取知道自己在看什么，而不是从一大片文字里猜字段。 |
| 按模式提取文本字段 | 结构化输出式提取，每个值都带它来自的页面区域；读不出的字段留空给官员，而不是填一个看起来合理的日期。 |
| 将地图边界描绘为多边形 | 在图幅上做分割得到多边形，Skill 说明它描的是哪一处标记，因为一张复印图上常常有好几处。 |
| 地理配准到 Ordnance Survey | 控制点对国家地图匹配，套用变换，并报告残差——官员需要知道这个形状是挪了一米还是五十米。 |
| 🛑 review（规划官员核对并修正每一项输出） | 复核是按字段、按边界做的，不是按档案：官员看到值、它的来源区域，以及叠在底图上的多边形，改正错的，而他的修正就是记录版本。 |
| 导出标准格式 → 国家平台 | 导出是另一步动作，用官员的凭据；本次运行没有发布路径，这正是让划定成为议会的声明而不是工具的产出的原因。 |

**检查点：** `review`：对每一项输出做全量复核，刻意如此，即使多数只需小改——因为要命的失败不是平均误差，而是某条发布出去的边界把一棵受保护的树划到了自己的保护令之外。搭建让复核可行而不是走过场：每个值带着来源区域，每个多边形叠在底图上，官员是在核对一个主张，而不是重读整份文件。

**与来源相比：** 来源出自 2025-06 与 2026-06：来自建设该服务的部门的两份第一手记录，本月均已打开。此后有这些变化：这项服务从 alpha 走进英格兰每一个议会，公开的细节也从准确率转向了复核负担——2026 年的记录说官员复核全部输出，而约三分之二的情况只需少量修改。这正是这类搭建应当据以规划的数字：只有当多数条目很快时，全量复核才承担得起，所以界面的职责是让容易的三分之二变快，把官员的注意力留到需要它的那三分之一。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 规划官员用 GOV.UK 邮箱登录，上传 PDF 或扫描件，例如树木保护令（Tree Preservation Order）、保护区（Conservation Area）或 Article 4 Direction [[1]](#sources)。
2. LLM 用结构化输出，把日期、地点和决定提取到 Digital Planning 平台的模式中 [[2]](#sources)。
3. 视觉语言模型结合 OpenCV 和 SAM，把地图边界描绘成多边形 [[2]](#sources)。
4. 系统对照 Ordnance Survey 地图寻找地面控制点，把每个多边形对齐到真实世界坐标 [[2]](#sources)。
5. 🛑 **审阅**：官员“review everything that Extract produces, check the output and makes corrections”[[1]](#sources)。
6. 官员以标准化格式导出数据，用于自己的系统和国家 Planning Data Platform [[1]](#sources)。

**产出：** 经过地理配准、符合模式的规划数据集，存入市议会系统并发布在公开的 Planning Data Platform 上。
**失败模式 → 防护：** 边界错位 → alpha 阶段的 IoU 和中心距离检查，加官员修正。日期误读（alpha 阶段正确率 94%）→ 官员检查每个字段。准确率看起来很高后产生过度信任 → 审阅全部输出，而非抽样。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Second collection pass](../../../../../research/2026-11-second-pass.md)。

- [MHCLG, Extract live for every council](https://mhclgdigital.blog.gov.uk/2026/06/17/extract-is-here-ai-powered-planning-data-for-every-council-in-england/) (2026-06-17)。已上线的服务：50 个市议会在使用；官员审阅所有输出；多数只需少量修改。"In around two thirds of cases, only minor edits were needed before the data was ready to use"。*第一手：是；可信度：高。*
- [MHCLG, Extract alpha](https://mhclgdigital.blog.gov.uk/2025/06/12/extract-using-ai-to-unlock-historic-planning-data/) (2025-06-12)。alpha 阶段在文本、日期和边界上的准确率；每份档案的成本和耗时。"The system identified dates correctly 94% of the time."。*第一手：是；可信度：中。*
