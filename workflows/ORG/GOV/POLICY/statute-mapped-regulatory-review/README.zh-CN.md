# 对照法律的规章审查

**与相近工作流的区别：** AWF-0080（主题签发式征询意见分析）是同一类中最接近的：它分析公众对征询的回应。本工作流则是对照法律审计现有的规章体系，输出按机构划分的删减/精简建议；检查点是机构对每条建议作出决定，而不是主题签发加抽样映射。
**工具变体：** `vulcan-technologies`

## 背景

一个州的行政法规是几十个机构在几十年里堆起来的规则，其中一部分早已偏离了授权它们的法律：收费被抬到法律允许之上，某条要求在母法废止后仍然活着，两个机构用略有不同的阈值管同一件事。没有人是故意这么写的；它是累积出来的。要发现这些，就得把每条条款和授权它的法律并排读，这是以"律师年"计的工作量，于是永远做不完。本工作流把"读"规模化：法典、指引、法律与判例进入同一个可检索的库，拆成条款，每条都对照其授权法律分类为强制、裁量或越权；重复与冲突在机构内部与跨机构范围内被标出，与其他州比较，并起草更短的通俗改写。每一个分类都是一个法律论证，所以产出是按机构划分的报告，而"推进哪些"的决定属于机构而不是工具——由协调员和机构律师决定，变更随后走规章制定、指引修订或请求立法。

**术语：**
- **行政法规汇编（administrative code）**：一个州行政机构规章的汇编。
- **条款（provision）**：一条规章里一项独立的要求，也是这里的分析单位。
- **授权法律（authorising statute）**：赋予某机构制定某条规则权力的法律。
- **强制 / 裁量 / 越权（mandatory / discretionary / unauthorised）**：法律要求、法律允许但可选、或超出法律授权。
- **重复规定（duplication）**：同一要求出现在不止一份规章或指引里。
- **规章制定（rulemaking）**：修改规章的正式程序。
- **指引（guidance）**：说明机构如何理解自身规则的非约束性文件。
- **热力图（heat map）**：把注意力投在哪里更划算的直观排序，这里用于挑选需要细看的规章。

## 用智能体搭建

**形态：** `project`。法律与规则的语料、分类模式、按机构出具的模板，都要在一个跨越数月、覆盖数千条条款的审计中保持一致与留存——这是常设知识加并行工作者的扇出，需要一个带仓库和工作流的项目，而不是一次性的 skill 调用。

**需要：** 法典、指引、法律和判例的文本，带引用元数据与生效版本；把法典拆成独立条款，每条带引用；一个跟踪后续变化的抓取器，否则审计边跑边过时；法定授权模式，让分类成为一个带引用的字段而不是一段话；按机构划分的报告模板；以及跨州比较的语料。智能体不能修改规章，也不能把任何东西作为"决定"发给机构：报告是建议，而对法定授权的判断是它没有资格出具的法律意见。

| 步骤 | 搭建方式 |
|---|---|
| 载入规章、指引、法律与判例 | 一次导入进可检索库，每份文档记录生效版本，因为拿已废止的法律去审计比不审计更糟。 |
| 每个条款：对照授权法律 | 一个 Dynamic workflow 按条款扇出：每个工作者拿到一条条款和可能授权它的法条，必须返回带所依据引用的分类。 |
| 分类 mandatory / discretionary / unauthorized | 每个分类都带理由与引用；找不到明确授权的工作者返回"不明确"，而不是"越权"，因为两者在法律上差别重大。 |
| 标出重复或冲突条款 | 第二遍按要求跨机构聚类，这是唯一能看见"任何单条条款都显露不出"的重复的办法。 |
| 跨州比较 → 起草精简文本 | 只在他州文本已在语料中时才做比较；改写标为草案——改写给机构的是提案，不是变更。 |
| 按机构出具报告 | Skill 按机构各出一份报告：计数、条款、建议与建议文本。 |
| 🛑 review（机构规章协调员决定推进哪些） | 每个机构的协调员与律师读自己的报告并选择；搭建没有任何通往规章制定、指引或立法请求的路径，所以分类不经人决定变不成变更。 |

**检查点：** `review`：分类是路线图而不是判决——由机构和其律师决定，来源也说机构不会只依赖这份分析。搭建用两种方式守住这一点：保留"不明确"这一类，使工具不被逼着做它做不了的法律判断；每条建议都带着产生它的引用，审阅人几秒钟就能驳回。

**与来源相比：** 来源出自 2025-07 到 2026-04：项目主任本人的叙述、一篇厂商访谈，以及一篇独立报道。主任那篇本月已打开；另两篇本轮没有重新打开。此后有这些变化：没有找到推翻其叙述的材料，而条目自己的谨慎仍然成立——试点是在一个更大的人工项目末期开展的，所以 35.7% 这个头条数字不能归给这次 AI 审查。那正是本条目最容易被误引的数字，而来源一致表明分类工作只是若干输入之一。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 厂商把州行政法典（全部 66 个行政分支机构的规章）、指引文件，以及州和联邦的法律与判例收集到同一个数据库，并把规章拆分为独立条款；一个智能体爬虫负责跟踪后续的法律和规则变化 [[1]](#sources)[[2]](#sources)[[3]](#sources)。
2. 多个专门的智能体并发运行：把每条规章要求与授权它的法律比对，并分类为 mandatory（强制）、discretionary（裁量）或 unauthorized（无授权；例如引用了已废止的法律，或收费超出法律允许的范围）[[1]](#sources)[[2]](#sources)。
3. 智能体标出被多项规章或指引文件重复规定的条款（机构内部和跨机构），并起草更短的通俗改写 [[1]](#sources)。
4. 有针对性的跨州比较，把各项要求（例如执照所需的培训时数）与其他州对标；ORM 主任还介绍了用 AI 绘制成本收益热力图，以挑选需要更仔细审视的规章 [[1]](#sources)[[2]](#sources)。
5. ORM 把发现汇编成每个机构的报告：强制/裁量/无授权要求的概况、合并、取消或精简的建议，以及建议的法规文本 [[1]](#sources)。
6. 🛑 **审阅**：每个机构审阅发现，决定推进、搁置或进一步研究哪些变更；机构官员“决定还能再做哪些删减” [[1]](#sources)[[4]](#sources)。变更随后进入规章制定、更新指引，或针对强制条款提出立法修正请求 [[2]](#sources)。

**产出：** 按机构出具的规章精简报告；经机构批准的变更进入规章制定或指引修订流程。第 51 号行政令（Executive Order 51）把 AI 审查纳入每四年一次的定期审查。
**失败模式 → 防护：** AI 误读法律授权 → 分类结果只是路线图；由机构协调员和律师决定，ORM 主任表示各机构不会只依赖 AI 分析。影响难以归因 → 试点是在一个更大的人工项目末期开展的，因此对外宣传的削减幅度并非全部来自 AI（引用数字时要说明）。
