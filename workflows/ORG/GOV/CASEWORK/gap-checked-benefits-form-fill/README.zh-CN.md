# 缺口核查的福利表单填写

**工具变体：** `nava-form-filling-assistant`

## 背景

公共机构或社区组织的个案工作者帮助居民申请福利，例如 Medicaid（公共医疗保险）或 SNAP（食品补助）。申请表很长，所需的信息其实已经分散在机构的多个数据库和福利门户里，个案工作者只好在客户等待时把同样的数据反复录入，缺失的材料往往到很晚才被发现。智能体检索这些记录，在填写之前先列出表单还缺什么，再填写字段并说明每个值取自哪里。个案工作者仍要检查每个字段并提交：申请是以客户的名义提出的，填错可能导致福利被推迟或拒绝，而记录里没有的情况，只有个案工作者能去问客户。

**术语：**
- **个案工作者（caseworker）**：帮助客户申请福利、并对申请负责的工作人员。
- **Medicaid、SNAP**：美国的两项公共福利，分别提供医疗保险和食品购买补助。
- **福利门户**：项目用来提交申请的在线系统。
- **缺口分析**：填写之前，检查现有记录回答不了表单中的哪些字段。
- **来源标注**：填好的字段上的一条说明，指明该值取自哪条记录。

## 用智能体搭建

**形态：** `skill`。一位个案工作者一次处理一份申请，并且就在与客户的面谈中，所以一个装有流程和表单字段清单的 skill 就够了。

**需要：** 放在 skill 旁边的空白申请表及其必填字段清单；通过 MCP 连接器对机构数据库和福利系统的只读访问；一套经所在机构批准、可以处理客户个人信息的环境，智能体只读取会话中打开的那一个个案。不要给智能体任何能写入门户的工具。

| 步骤 | 搭建方式 |
|---|---|
| 个案工作者打开客户个案 → 智能体检索机构数据库和福利门户 | 个案工作者指定个案。skill 通过只读的 MCP 连接器读取客户已有的数据。没有连接器的门户不在这套搭建之内，由个案工作者补充门户上显示的内容。 |
| 对表单做前置缺口分析 | skill 的下一条指令：把表单的必填字段与已找到的数据对照，写出缺少的内容，然后停下。 |
| 个案工作者与客户补齐缺失材料 | 对话本身。skill 等待，并接收个案工作者补充的内容。 |
| 智能体填写字段，并标注每项的取数依据 | skill 把填好的表单写成一份文件副本，每个字段附一条说明，指明该值取自哪条记录。技术细节放在文件末尾，不夹在字段之间。 |
| 🛑 review (个案工作者修正并确认) → 个案工作者提交 | 见“检查点”。 |

**检查点：** `review`：skill 逐字段展示填好的表单和来源标注，然后停下，由个案工作者修正数值并补全缺口。提交没有搭建出来：连接器是只读的（权限规则拒绝任何写入类工具），所以由个案工作者自己在门户中提交。

**与来源相比：** 来源的时间为 2026-03 到 2026-04，公开实例出自 2026-03。它们所述的开源工具用多个智能体自行在数据库和门户之间操作；这里的搭建是一个通过连接器读取数据的 skill，不去操作门户的界面。来源报道的是约十几名工作人员参与的试点，没有给出这类搭建效果如何的证据。来源 2 列出了一场 2026-08 的试点结果演示，本条目没有打开它。这里不作任何效果上的断言。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 个案工作者与居民面谈，开始办理福利申请，例如 Medicaid 或 SNAP [[1]](#sources)。
2. 智能体在机构的数据库和福利系统中检索客户已有的数据 [[1]](#sources)[[2]](#sources)。
3. 智能体做缺口分析：填写之前，先扫描申请表并列出缺少的内容，让个案工作者和客户可以着手收集病历等材料 [[1]](#sources)。
4. 智能体填写表单字段。每个由 AI 填写的字段都标注数据来源的说明。处理细节收在可折叠面板里，因为工作人员觉得它会在与客户交谈时分散注意力 [[1]](#sources)。
5. 🛑 **审阅**：个案工作者检查带标注的字段，修正错误并补全缺口（“Caseworkers review for accuracy, fill in anything missing, and submit”）[[3]](#sources)。
6. 个案工作者提交申请 [[2]](#sources)[[3]](#sources)。

**产出：** 一份完整的、经个案工作者确认的福利申请，在与客户的面谈中准备好并提交到项目门户。
**失败模式 → 防护：** 从过期记录中取到错误数据 → 逐字段的来源标注加个案工作者修正。智能体界面分散对客户谈话的注意力 → 处理细节默认折叠。个案工作者与客户之间的信任受损 → 第一阶段的发现促成了面向信任与采用度的设计调整。
**与相近工作流的区别：** AWF-0081 摘要辅助的个案决定（Summary-aided casework decision）中，决策者借助摘要裁定庇护申请。本工作流中，智能体依据现有记录组装并填写福利申请表，并先做缺口分析。产出是已提交的申请而非决定，检查点是提交前由个案工作者做的字段级审阅。
