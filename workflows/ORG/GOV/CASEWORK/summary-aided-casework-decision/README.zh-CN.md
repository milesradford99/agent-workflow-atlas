# 摘要辅助的个案决定

**工具变体：** `home-office-acs` · `home-office-aps`

## 背景

向一个国家请求难民保护的人会提出庇护申请。申请要经过面谈，随后由受过培训的官员，也就是决策者，决定是否批准。决策前，决策者要读面谈记录，篇幅可能达到 50 页甚至更多，还要查找政府官方的国别信息，了解申请人母国的状况。这两件事靠人工都很费时。智能体负责概括面谈记录，并检索国别信息、给出出处。决策者仍要对照面谈记录核对摘要，打开检索结果引用的每一份原文，并且只能由决策者本人作出并签署决定：这是一项后果严重的法律决定，而摘要可能出错或漏掉内容。

**术语：**
- **决策者（decision-maker）**：依法对庇护申请作出决定的官员。
- **面谈记录**：申请人庇护面谈的书面记录。
- **国别政策信息说明（CPIN）、原籍国信息请求（COIR）**：英国内政部发布的说明和信息答复，介绍申请人母国的状况，作为决定的政策依据。
- **Calibre**：决定作出之后，用来检查抽样决定质量的质量框架。
- **抽检（dip-sampling）**：只检查少量随机抽取的已作出的决定，而不是全部。

## 用智能体搭建

**形态：** `skill`。一位决策者一次处理一个案件，并且全程在对话中，所以一个装有流程和政策说明的 skill 就够了。

**需要：** 文件形式的面谈记录；作为参考文件放在 skill 旁边的政策说明，或通过 MCP 连接器访问存放这些说明的文档库；一套经所在机构批准、可以处理庇护申请人个人信息的环境。不要给智能体任何记录决定或写入案件系统的工具。

| 步骤 | 搭建方式 |
|---|---|
| 面谈记录 → 总结案情 | skill 读取面谈记录并写出摘要，摘要中的每一句话都注明出自记录的哪一页，这样后面的核对可以直接对照原文。 |
| 🛑 review (决策者核对摘要) | 见“检查点”。 |
| 政策问题 → 检索带出处的国别政策说明 | 决策者在对话中提问。skill 检索说明，并为每一点给出说明的标题和章节。 |
| 决策者阅读完整原文 | skill 列出它引用过的每一份说明，并提醒决策者在依赖之前先打开原文。 |
| 起草决定 | 决策者自己写决定。skill 可以把案情事实和引用的说明整理成一份文件，作为工作辅助。 |
| 🛑 sign-off (决策者作出决定) → 🛑 sample (质量抽检) | 见“检查点”。 |

**检查点：** `review`：skill 展示带有面谈记录出处的摘要，然后停下，直到决策者表示已核对完毕。`sign-off`：智能体没有记录或发出决定的工具，skill 的写法是准备材料而不是建议结果；由决策者在案件系统中操作。`sample`：这一步发生在 skill 之外，属于机构自己的质量流程。skill 把每个案件的摘要和政策答复存成文件，方便质量团队抽取样本并检查。

**与来源相比：** 来源发布于 2025-04，试点在 2024-05 至 2024-12 进行。[TechTimes 的一篇报道](https://www.techtimes.com/articles/329581/20261028/home-office-asylum-ai-fails-one-five-checks-quality-testing-second-tool-has-stopped.htm)（2026-10-28）转述 Open Rights Group 的调查，称政策检索工具于 2025-07 向全体庇护决策者推广，摘要工具于 2026-04 推广，并称对 2026-04 至 2026-07 期间 203 份摘要的抽查中，有 45 份在第一阶段未通过；报道还称内政部没有进行独立审计的计划。这些是二手数字，没有对照原始文件核实。来源中试点的摘要没有指向面谈记录的出处，因此人工核对只能手工完成；这里的搭建让 skill 补上出处。内政部使用的那些工具通用智能体拿不到，这套搭建也不复现它们。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 一个 LLM 工具读取庇护面谈记录（可能长达 50 页甚至更多），写出简明的案情摘要（Asylum Case Summarisation）[[1]](#sources)。
2. 试点之前，技术专家审阅了每一份摘要。其中 9% 被判定为不准确或不完整而剔除，这些案件走常规流程 [[1]](#sources)。
3. 🛑 **审阅**：决策者借助摘要重新熟悉案情，并对照面谈记录核对。摘要没有指向记录的出处标注，所以这一步核对只能手工完成 [[1]](#sources)。
4. 决策者向一个聊天式检索助手提出针对个案的政策问题，该助手覆盖国别政策信息说明（Country Policy Information Notes）和原籍国信息请求（Country of Origin Information Requests）（Asylum Policy Search）。它返回带出处的摘要 [[1]](#sources)。
5. 决策者在依赖其引用的说明或请求之前，必须先打开完整原文 [[1]](#sources)。
6. 🛑 **签发**：只有决策者可以作出决定。这些工具自身不能作出决定，也不能给出决定建议 [[1]](#sources)。
7. 🛑 **抽检**：质量团队用常规的质量框架（Calibre）对决定质量做抽检，并与对照组比较 [[1]](#sources)。

**产出：** 由个案办理人撰写并负责的庇护决定，外加一份抽检质量记录。在试点中，AI 摘要和政策检索的回答只是辅助工具。
**失败模式 → 防护：** 摘要不准确或不完整 → 使用前先筛查摘要（试点中剔除了 9%）。用户对摘要没有十足信心（23%）→ 决策者重读面谈记录，而摘要缺少出处标注使这一步更费力。过度依赖政策摘要 → 必须打开完整原文。试点规模小且依赖自报 → 持续监测，并在全面推广前做部署后评估 [[1]](#sources)。
**与相近工作流的区别：** AWF-0021 流程智能体（Procedure agent）按既定流程办理客户请求。这里的智能体只负责准备材料，每一项决定都由法定的决策者作出并签署（辅助级自主度，高风险）。
