# 议题树研究

**智能体套件：** [在 Claude Code 中运行](variants/claude-code.md)

## 背景

战略或研究团队会被问到一个业务问题，例如某个市场在怎样变化、一批竞争对手如何比较，并要用一份供领导据以行动的幻灯片来回答。工作是把问题拆成几部分，逐部分查资料，把事实和数字汇集到一处，核对，然后说明它们意味着什么。人工做要搜索好几天，风险是图表里有一个没人能追溯、或从没核对过的数字。智能体负责拆解问题、并行研究各部分、把每条论点和它的来源放在一起、让独立的核查员重新打开每个来源，并起草报告。提出问题的人仍要在研究开始前批准计划，并在报告生成前阅读研究发现，因为问题归他们所有，什么算好来源由他们决定，结论也由他们负责。

**术语：**
- **议题树（issue tree）**：把核心问题按分支拆成子问题。
- **MECE（相互独立、完全穷尽）**：一种拆分方式，每一项恰好属于一个分支，也没有遗漏的分支。
- **论点表**：每条事实一行，含来源原文所写的数字、来源、日期和置信度评级。
- **结论页（so-what page）**：陈述一项发现及其对问题意味着什么的幻灯片，而不只是罗列数据。
- **第一手来源**：由亲历者或亲眼所见的人写下的记述，而不是别人的转述。
- **离群值**：与其他值相差很远的数值；它会拉偏平均数，却几乎不影响中位数（中间的那个值）。
- **SEO 内容农场**：为了在搜索结果里排名靠前、而不是为了提供信息而写的网站。
- **Artifact**：Claude 应用在对话旁边生成并展示的页面、图表或幻灯片。

## 用智能体搭建

**形态：** `project`。一个 skill 可以承载流程，但两处停顿必须每次都生效，核查员又不能看过研究过程，这就需要自定义子智能体和常设的项目规则。[套件](variants/claude-code.md)把这套搭建写成了文件。

**需要：** `CLAUDE.md` 里的一节，写明运行文件夹的结构和两处停顿；研究 skill；分支研究员和核查员各自的任务书模板；子智能体可用的网络搜索和网页抓取；公司的报告模板，运行前先填好。要告诉智能体哪些来源类型算数、不得联系任何人、不得收集个人联系方式。

| 步骤 | 搭建方式 |
|---|---|
| 核心问题 → MECE 议题树 | skill 把问题改写成一句话，问题含糊时给出几个更清晰的版本，并把议题树和研究规则写入 `plan.md`。 |
| 🛑 plan | 见“检查点”。 |
| 每个分支：深度研究 | 每个分支一个自定义子智能体，在同一条消息里全部启动，每个都拿到一份填好的任务书，写明目标、输出格式、可用来源和边界；每个都必须抓取它所引用的每一个页面。 |
| 论点表 (论点、数字、来源、日期、置信度) | 主智能体把各分支的表合并成一个文件，每条论点一行，并注明来源之间的冲突。 |
| 每个数字：重新抓取来源 | 没有做过研究的新核查子智能体重新打开每个来源，逐行给出结论。表有几百行时，可以用动态工作流在两个检查点之间运行这些核查。主智能体采纳更正，并删除无法核实的行。 |
| 结论页 | 主智能体写出各项发现，每项都对应论点表中的行，并把判断标明为判断。 |
| 🛑 review | 见“检查点”。 |
| 套用公司模板生成报告 | skill 先确认模板存在，然后每项发现做一页幻灯片；幻灯片上的每个数字都必须在论点表里。 |

**检查点：** `plan`：`CLAUDE.md` 的这一节和 skill 都要求智能体展示 `plan.md` 并等待；由于没有它就不该开始研究，可以用 `PreToolUse` 钩子在计划文件标记为已批准之前拦下分支子智能体。`review`：skill 在展示论点表（附更正和删除的数量）和研究发现之后停下，只有问题负责人批准或修改之后才生成报告。这里没有任何东西会到客户手里，所以 `review` 靠指令层面的停顿就够了。

**与来源相比：** 来源出自 2025-06 至 2026-11（有一个未注明日期：`claude-code-heavy` 仓库，该站点返回 403，无法打开）。来源 3 是本目录自己的实例，套件复用了它的任务书。来源 2 描述的是 Anthropic 为自家产品搭建的研究系统，来源 1 是一支营销团队用电子表格手工完成这项工作；这套搭建沿用了它们的形态（一个主智能体、并行的工作者、单独核对引用的一遍），但用内置子智能体，而不是它们的代码。计划存成文件是因为审批关卡需要它；来源中保存计划的理由（防止上下文被截断而丢失）在这里并不依赖。这套搭建不包括来源中的付费数据工具，也不包括在设计工具里打磨最终图表。没有另外搜索更新的记录，因为最新的来源出自 2026 年。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 问题负责人选定核心问题。扩大规模之前，先用一个你已经熟悉的案例（比如你自己的公司）测试方法，并让智能体说明它是如何找到每一项的 [[1]](#sources)。在本仓库的这次实例中，维护者从四个建议的问题中选了一个 [[3]](#sources)。
2. 主智能体构建 MECE 议题树：拆分后每一项恰好属于一个分支，每个分支下的子问题保持一致 [[3]](#sources)。主智能体把计划存入记忆，以免上下文被截断后丢失 [[2]](#sources)。
3. 🛑 **计划**：在开始任何研究之前，问题负责人批准议题树、研究规则（例如只用第一手来源、只用公开渠道、不联系任何人）和交付物 [[3]](#sources)。
4. 每个分支：深度研究。主智能体为每个分支并行启动一个子智能体，每个都有一份说明目标、输出格式、工具和可用来源以及边界的任务书 [[2]](#sources) [[3]](#sources)。对数据密集的问题，一次只收集一个数据点：先固定它的定义，在 1–5 行上测试方法，用可行的最便宜方法，并把它保存到技能中 [[1]](#sources)。
5. 主智能体把发现合并成论点表（论点、数字、来源、日期、置信度），作为唯一的事实来源，每个实体一行 [[1]](#sources) [[3]](#sources)。允许“未知”作为答案，而不是强行回答是或否 [[1]](#sources)。
6. 每个数字：重新抓取来源。由独立的核查智能体重新打开每个来源，并在页面上核对每个数字。在本仓库的这次实例中，这涉及 65 个来源和约 20 处更正 [[3]](#sources)。Anthropic 的系统用一个单独的引用智能体来完成这一步 [[2]](#sources)。此外还要人工抽查一部分行、每个离群值以及最难的字段 [[1]](#sources)。
7. 主智能体撰写结论页。它在快速生成的图表 artifact 中尝试不同的切分方式，并对比中位数与平均数，因为离群值会拉偏平均数 [[1]](#sources)。
8. 🛑 **审阅**：问题负责人阅读研究发现，批准或退回 [[3]](#sources)。同时公布方法上的注意事项：哪些结果不显著、哪些数字比较模糊 [[1]](#sources)。
9. 主智能体套用公司模板生成报告（本仓库的这次实例中是一个 Slides artifact [[3]](#sources)；MKT1 的最终图表在 Figma 中打磨 [[1]](#sources)）。

**产出：** 一份带结论页的研究报告，以及支撑它的论点表，每个数字都能追溯到经过重新核查的来源。
**失败模式 → 防护：** 智能体用看似合理的数字填补空缺（整数暴露了这一点）→ 明确的“标出未知项”规则和“未知”选项 [[1]](#sources)。错误流入已发布的图表（两份通讯在发出后做了更正）→ 重新抓取和抽查这两步要在 🛑 review 之前完成 [[1]](#sources)。子智能体重复彼此的工作 → 任务书中写明边界 [[2]](#sources)。智能体偏好 SEO 内容农场 → 在任务书中写入来源质量规则 [[2]](#sources)。某个分支只读了搜索结果文本 → 重新抓取这一步能发现问题，任务书也应要求直接抓取原页面 [[3]](#sources)。过时的事实，比如已离职的高管 → 人工检查这些字段 [[1]](#sources)。生成报告时公司模板还是空的 → 运行前先填好 [[3]](#sources)。判断类结论（比如覆盖度评级）未经检查 → 也让核查智能体审阅这些结论 [[3]](#sources)。

## 公开实例

覆盖度（截至 2026-11-06）：**部分**：有第一手实例，但只覆盖流程的一部分，或检查点设在别处。来自 [Where are the real runs?](../../../../../research/2026-11-real-runs.md)；每个数字都已对照原页面复核。

- [Emily Kramer, MKT1](https://newsletter.mkt1.co/p/state-of-marketing-report-part-3-how-to-research-in-claude-code) (2026-05-06)。一次一个数据点地研究 100 家公司；电子表格是事实来源；抽查；已发布的报告。"100 high-growth B2B startups, 90+ data points each"；"burned 250 Clay credits"。*第一手：是；可信度：高。*
- [Hadfield et al., Anthropic Engineering](https://www.anthropic.com/engineering/multi-agent-research-system) (2025-06-13)。主智能体 → 3–5 个并行子智能体 → 引用环节；人工只参与评估。"outperformed single-agent Claude Opus 4 by 90.2%"；"about 15× more tokens"。*第一手：是（自家产品）；可信度：高。*
- [Graydon Trusler, claude-code-heavy](https://github.com/gtrusler/claude-code-heavy)。Worktree → 2–8 个并行研究助手 → 综合。"Assistants: 6"；"~11,500 words"。*第一手：是；可信度：中。*
