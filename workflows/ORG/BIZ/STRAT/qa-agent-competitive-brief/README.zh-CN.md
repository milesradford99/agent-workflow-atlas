# 质检智能体竞品简报

**与相近工作流的区别：** 最接近的是 AWF-0030 议题树研究（Issue-tree research）：针对一次性的关键问题，先经 🛑 plan，再产出幻灯片。本工作流没有计划关卡，而是常设的每周简报，由第二个智能体做论断质检，只设一次人工审阅，把关对在用销售资料的修改。交付物（周期性简报加对战卡修改）和检查点安排都不同。
**工具变体：** `notion` · `multi-agent-qa`

## 背景

销售团队需要知道竞品改了什么、该怎么回应，而负责这件事的人通常是一个还兼着十几件别的活的产品市场。每周的产出是一份简短简报——竞品发布了什么、对定位意味着什么、哪些销售话术该改——而贵的不是写，而是写错：销售在一笔在谈的单子里引用了过时或编造的竞品说法，丢的是单子和信任。本工作流刻意把活分给两个智能体。一个研究并撰写；另一个以对手的姿态读这份简报，把每个论断对照它的来源核查，而且只要简报说竞品在某方面领先，就先对照公司自己的产品文档查一遍再往下走。来源必须通过日期检查才能进入简报，这条是"旧文章被当成新闻"之后加的。产品经理在有任何内容进入对战卡之前先读结果，因为对战卡是要拿到客户面前用的，销售在屋里没法核实。

**术语：**
- **对战卡（battlecard）**：销售用的一页纸，按客户异议逐条对比竞品与本产品。
- **定位（positioning）**：相对于替代方案，产品如何被描述、为什么赢。
- **竞品情报（competitive intel）**：竞品已发布、定价或宣布的事实。
- **质检智能体（QA agent）**：只负责攻击前一个智能体论断的第二个智能体。
- **时效检查（recency check）**：在把来源当作新闻引用之前，先核实其发布日期。
- **长期差异点（evergreen differentiator）**：能持续几个季度成立的差异，属于对战卡。
- **每周情报（weekly intel）**：本周才变的事，属于简报，不属于对战卡。
- **抽检（spot-check）**：细读一部分，而不是全部。

## 用智能体搭建

**形态：** `service`。按周定时运行，没人启动，产出落在一份共享文档里，唯一的人工动作是那道让修改进入销售资料的批准。

**需要：** 竞品信息源清单，被定义并维护着，标明哪些页面算权威；一个有固定模板的文档落点；公司自己的产品文档、官网与博客，用来回答"我们是不是真的落后"；对战卡资料，以及让本次运行无法编辑它们的权限模型；以及日程。智能体可以写简报，但没有批准记录就不能发布到对战卡，也不能引用一个它验不了日期的来源。

| 步骤 | 搭建方式 |
|---|---|
| 周五定时：研究智能体轮询信息源 | 按日程运行，信息源清单固定；增删一个来源就是改这份清单，像其他改动一样被审阅，于是覆盖面不会悄悄漂移。 |
| 核对每个来源的日期 | 检查放在写之前而不是之后：读不出发布日期的页面直接排除，而不是当它是新的——当初引发这条的失败，就是旧文章被当成新闻。 |
| 在 Notion 生成简报 | 一个 Subagent 按固定模板写：变了什么、定位影响、建议的对战卡修改，每条都带来源。 |
| 质检智能体逐条核查论断 | 一个指令不同的第二个 Subagent——它看到简报与来源，被告知去找错，返回一份"撤下、弱化或加限定"的清单；它不改写简报。 |
| 竞品领先于我们：对照自家文档 | 最要紧的一类论断：任何"他们有 X 而我们没有"，在存活之前都要对照公司自己的文档，因为虚假的差距会让销售显得毫无准备。 |
| 撤下无依据的论断 | Skill 执行质检清单，并记录撤掉了什么，于是当周简报与当周更正都看得见。 |
| 🛑 review（产品经理抽检） | 产品经理读简报和质检清单；只有他批准，修改才能进对战卡，而本次运行在那里没有写权限。 |
| 将获批的修改写入对战卡 | 由人、或由一道带审批的独立步骤执行——绝不由研究运行本身执行。 |

**检查点：** `review`：产品经理的抽检刻意保留在两个智能体之后，而不是被它们替代，因为质检智能体只能把论断对照来源，而销售真正需要的是这条论断对"今天的产品"也成立。搭建让这次复核变便宜——简报到手时无依据的论断已被撤下、来源已附上——也让这道关卡变实：对战卡在本次运行的写权限之外。

**与来源相比：** 来源出自 2026-06：一份第一手工程记录，本月已打开，也是本条目的公开实例。此后有这些变化：没有找到推翻它的材料——围绕"智能体质检竞品情报"的有限检索返回的是同一套做法的厂商与从业者材料，而不是更晚的实例。条目自己的那个点值得留着：[这条流水线每周只占用人不到五分钟](https://www.trmlabs.com/resources/blog/meet-the-agents-how-noor-and-vera-are-accelerating-competitive-intelligence-at-trm)，而人的时间花在无法自动化的那一步——判断哪些变化对正在谈的单子要紧。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 每周五下午，研究智能体（Noor）从一组既定的竞品信息源取材，按固定的 Notion 格式写出简报：发生了什么变化、对定位意味着什么、建议更新哪些对战卡 [[1]](#sources)。
2. 每个来源进入简报前都必须通过时效检查（核实发布日期）。这是在旧文章被当成新闻引用之后加上的 [[1]](#sources)。
3. 22 分钟后，另一个质检智能体（Vera）开始运行。它通读整份简报，把每个论断与来源材料对照，标出不准确、无依据或有误导的内容 [[1]](#sources)。
4. “第 8 步”：只要简报把某个竞品说成在某方面领先，质检智能体就先对照该公司自己的官网、博客和产品文档核查，之后才能往下走 [[1]](#sources)。
5. 智能体把长期差异点（应写入对战卡）与每周情报（只留在周五简报里）分开。这样减少了不必要的对战卡修改 [[1]](#sources)。
6. 🛑 **审阅**：产品经理对结果做抽检，获批的修改才会进入销售使用的对战卡。哪些变化对在谈的交易重要，仍由销售赋能团队判断 [[1]](#sources)。

**产出：** Notion 里的每周竞品情报简报，以及交给销售团队的一小批获批的对战卡修改。
**失败模式 → 防护：** 过时来源被当成新闻 → 强制日期检查。智能体自己检查自己，会漏掉分档（tier）相关或虚假的“差距”论断 → 独立的质检智能体，加上对照内部文档的检查。对战卡修改过多 → 重新训练，把长期差异点与每周情报分开。错误情报在交易中途到达销售 → 有意保留产品经理人工抽检。
