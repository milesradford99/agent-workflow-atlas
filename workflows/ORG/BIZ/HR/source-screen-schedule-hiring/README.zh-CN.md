# 寻访筛选排期招聘

**工具变体：** `linkedin-hiring-assistant`（2025 年 9 月底前推出全球英文版；寻访候选人，通过 InMail 问答筛选，安排面试 [[29]](#sources)） · `paradox` · `juicebox`

## 背景

给一个岗位招人，要先找到可能合适的人，再根据资料判断谁值得联系，给他们写信、约面试，并替面试官做好准备。招聘人员每个岗位都要重复这一套，而且跨好几个渠道（职业社交网络、招聘网站、公司自己的招聘管理系统）；把每份资料与岗位标准对照，是缓慢又重复的阅读。智能体负责搜索、逐项对照、起草消息、约日历和整理面试材料。搜索标准、每一条发出的消息，以及最后谁晋级、谁被淘汰，仍由人批准。针对自动化招聘工具的规定把法律责任放在雇主身上，淘汰又是对一个人的决定，公司必须能说清理由，所以智能体只提供证据，不下结论。

**术语：**
- **寻访（sourcing）**：通过搜索个人资料，找到还没有投递的候选人。
- **ATS（招聘管理系统，applicant tracking system）**：公司用来保存候选人及其招聘进度的软件。YC 的来源中用的是 Ashby。
- **WAAS（Work at a Startup）**：创业公司发布岗位、接收应聘的招聘网站。
- **岗位手册（playbook）**：针对一个岗位的文件，列出应聘者的评分依据。
- **短名单**：筛选后为某个岗位保留下来的候选人。
- **外联**：给还没有投递的候选人发的第一条消息；**InMail** 是 LinkedIn 上发给未建立联系的人的私信。
- **面试材料包（候选人简介）**：给面试官看的、关于候选人背景的简短文字。
- **偏见审计**：由独立方检验自动化工具是否对不同人群区别对待。
- **纽约 LL144、欧盟 AI 法案、Digital Omnibus**：针对招聘中使用自动化工具的规定。纽约市 Local Law 144 要求做偏见审计并通知候选人；欧盟 AI 法案把招聘类 AI 归为高风险；Digital Omnibus on AI 是调整其义务适用时间的欧盟法律。

## 用智能体搭建

**形态：** `skill`。一位招聘人员一次处理一个岗位，并在对话中逐阶段批准，所以一个 skill 加上放在旁边的岗位文件就够了；各个渠道可以由内置子智能体并行读取。

**需要：** ATS、邮箱和日历的连接器（MCP），以及每个提供连接器的招聘网站或候选人来源的连接器；每个在招岗位一份岗位文件，写明资质要求和消息模板，由招聘人员编写。不要接入任何能淘汰候选人、更改候选人阶段或发出结果通知的工具。候选人资料属于个人数据：只放在所在机构批准的系统里，并在使用任何打分之前，与法务确认上述规定要求怎样的通知和审计。

| 步骤 | 搭建方式 |
|---|---|
| 职位描述 → 🛑 plan | skill 把职位描述和用人经理的标准整理成岗位文件和搜索计划，然后停下。见“检查点”。 |
| 每个渠道：寻访 → 按评分项给出匹配理由 | 内置子智能体各负责一个渠道，返回一张表：候选人、每项资质、在资料中找到还是缺少，以及能证明它的那一行。 |
| 🛑 action → 外联 | skill 依据岗位模板为每位候选人保存一份消息草稿。发送是连接器调用，受“询问”的权限规则约束。见“检查点”。 |
| 每位候选人：证据摘要 (不做淘汰决定) | 每位候选人一段文字，列出每项资质的正反证据。skill 的指令禁止评分或建议淘汰，也没有任何工具能据此行动。 |
| 排期 | 日历连接器查找空闲时段并创建事件；邀请要在批准之后才发出。之后 skill 检查 ATS 里显示的是否是同一个事件。 |
| 面试材料包 | 依据证据摘要写成候选人简介，存成文件交给面试官。 |
| 🛑 sign-off (由人决定) | 见“检查点”。 |

**检查点：** `plan`：skill 把标准和搜索计划写进岗位文件，然后停下，等招聘人员批准或修改。`action`：招聘人员阅读并修改每份草稿；发送消息和邀请的工具在权限规则里设为“询问”，所以没有确认就不会有东西发出。`sign-off`：skill 最后展示证据摘要并停下。智能体没有淘汰候选人或更改候选人阶段的工具，所以由招聘人员或用人经理自己在 ATS 里操作。

**与来源相比：** 来源出自 2025-09 至 2026-07；YC 仓库、纽约 FAQ 和两个 LinkedIn 页面未注明日期。其中两个来源（纽约 FAQ 和 YC 仓库）撰写本节时无法重新打开（页面读取器收到这两个站点的 403），所以对它们仍以条目文字为准。上文关于欧盟时间的说明已经过时：Cuatrecasas 的页面现在报告，Digital Omnibus on AI 已于 2026-07-24 作为法规 (EU) 2026/1744 公布，独立高风险系统（含招聘）的义务自 2027-12-02 起适用（[source 28](https://www.cuatrecasas.com/en/global/labor-and-employment/art/digital-omnibus-on-ai-how-does-it-impact-employment-relations)）。YC 仓库是一组 Claude Code 命令，这套搭建方式与它一致，只是 YC 的经理还会通过智能体批准淘汰，而本搭建不允许这样做。LinkedIn 的 Hiring Assistant 是在 LinkedIn 自己的网络中搜索的厂商产品，通用智能体做不到这一点；本搭建只能从有连接器的渠道寻访，来源也没有展示厂商内部的步骤。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

**为什么“给证据，不下结论”很重要（合规）：**
- **纽约 LL144。** 要求在使用自动化招聘工具之前每年做一次独立的偏见审计，公开审计结果摘要，并提前 10 个工作日通知候选人。责任在雇主，而不在供应商 [[27]](#sources)。
- **欧盟 AI 法案。** 把招聘类 AI 归为高风险。其义务原定于 2026 年 8 月 2 日生效，Digital Omnibus 暂定将其推迟到 2027 年 12 月 2 日。请确认法律上实际生效的是哪个日期 [[28]](#sources)。

让智能体只提供*证据*、不下*结论*，可以降低这两方面的风险。

1. 招聘人员从职位描述和用人经理的标准出发。Hiring Assistant 会把招聘人员的标准转成搜索查询 [[32]](#sources)。在 YC 的做法中，用一个 playbook 文件记录每个职位的评分依据 [[30]](#sources)。
2. 🛑 **计划**：招聘人员选定职位，并定义给候选人打分所依据的资质要求 [[31]](#sources) [[32]](#sources)。用人经理调整标准时，招聘人员更新标准，几分钟内就能得到新的一批候选人 [[31]](#sources)。
3. 每个渠道：寻访。招聘人员从 LinkedIn 拉取候选人，并“in a click”导出到 ATS 的候选短名单 [[31]](#sources)。在 YC 的做法中，每天开始时的 `/triage` 会扫描收件箱、Work at a Startup (WAAS) 的申请人、Ashby ATS 和日历 [[30]](#sources)。
4. 智能体按评分项写出匹配理由：依据招聘人员的资质要求给每位候选人打分 [[31]](#sources)，并显示个人资料中符合哪些资质、缺少哪些 [[32]](#sources)。`/review-applicants` 依据 playbook 给新申请人评级 [[30]](#sources)。
5. 🛑 **操作**：招聘人员在外联信息发出前阅读并编辑草稿。LinkedIn 起草的消息可以编辑 [[32]](#sources)。在 YC 的做法中，`/outreach` 依据职位模板起草个性化邮件，经理审阅一封结束沟通的邮件并修改，然后才说“send it” [[30]](#sources)。
6. 每位候选人：智能体写出证据摘要，而不是结论。`/candidate-brief` 写一段背景简介，`/candidate-status` 在 WAAS、Ashby、Gmail 和日历中核对候选人的情况 [[30]](#sources)。供应商声明 Hiring Assistant “does not make autonomous or automatic decisions” [[32]](#sources)。
7. 排期：智能体的 `/schedule` 查找空闲时段，创建 Zoom 或线下面试事件，发送邀请，并推进候选人在 ATS 中的阶段。改期后再检查 ATS 事件是否已同步 [[30]](#sources)。YC 仓库里的面试准备就是第 6 步的候选人简介 [[30]](#sources)。
8. 🛑 **签发**：由人决定谁进入下一轮、谁被淘汰。按纽约 LL144，自动化工具的偏见审计和候选人通知义务由雇主而非供应商承担 [[27]](#sources)，而欧盟 AI 法案把招聘类 AI 视为高风险 [[28]](#sources)。

**产出：** ATS 中的候选人管线：已寻访并打分的短名单（附按评分项的理由）、已发出的外联、已约定的面试和候选人简介。晋级与淘汰的决定交给用人经理。
**失败模式 → 防护：** 一条指令批量淘汰（“reject all of these” 在约 2 分钟内发出了 8 封拒信）→ 逐个候选人签发，而不是按批次 [[30]](#sources)。日历、ATS 和邮件不同步 → 每次排期变更后检查同步情况 [[30]](#sources)。骚扰候选人 → README 对此提出警告，并说明该工具不是用来取代判断的 [[30]](#sources)。模型偏见 → LinkedIn 对每个模型做公平性审查 [[32]](#sources)，而雇主按 LL144 仍需自己的独立审计 [[27]](#sources)。配置文件中的 API 密钥和令牌 → 放在被 git 忽略的文件里 [[30]](#sources)。
