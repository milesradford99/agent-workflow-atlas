# 逆向设计课程开发

## 背景

开发一门课之所以慢，是因为每个部分都要和其他部分配得上。通行的方法“逆向设计”从终点出发：先确定学生应当能做什么（学习目标），再确定怎样判断他们是否做到了（评估），最后才规划课时。教师要为每个模块做一遍，再编写材料、为需要更多支持的学生准备版本，并检查每个目标确实都有评估。智能体可以起草每一层并做对齐检查。教师始终负责，因为只有教师了解学科和学生，也因为一门课如果考错了内容或含有错误，受害的是修这门课的人。

**术语：**
- **学习目标**：对学生学完一个模块或一门课之后能做什么的可衡量表述。
- **布鲁姆层级（Bloom's level）**：一套思维能力的阶梯（记忆、理解、应用、分析、评价、创造），用来标明一个目标的难度。
- **评分量规（rubric）**：列出评判一份作业所依据的各项标准的评分指南。
- **分步作业（scaffolded assignment）**：把一个较大的任务拆成若干个分别评分的小部分。
- **课程地图**：一张表，把每个学习目标与服务于它的材料、活动和评估联系起来。
- **分层版本**：针对不同水平的学生调整过的课时材料。
- **无障碍**：残障学生能否使用这些材料，例如是否有字幕、结构是否易读。
- **LMS**：学习管理系统，学生在其中查看课程内容并提交作业。
- **教学设计师**：帮助教师设计课程结构的专业人员。

## 用智能体搭建

**形态：** `skill`。一位教师开发一门课，并且全程在对话中，所以一个按顺序逐层推进、在两个批准节点停下的 skill 就够了。

**需要：** 课程标准或目标、年级和学科；教师想用的现有教学大纲或阅读材料；磁盘上用来写课程地图和课时文件的位置；能生成你的 LMS 可导入文件的方式，或由教师自己手动上传。不要给智能体任何学生个人数据或学校内部信息，也不要给它 LMS 的写入权限。

| 步骤 | 搭建方式 |
|---|---|
| 课程标准 → 按布鲁姆层级的学习目标 | skill 起草课程级和模块级学习目标，给每个标上布鲁姆层级，并绘出分布。可以让一个全新上下文的子智能体按既定标准检查。 |
| 🛑 plan | skill 把学习目标写入计划文件，然后停下。 |
| 评估 + 评分量规 → 模块计划 | skill 为每个目标起草评估和评分量规，再做出把一切与目标关联起来的课程地图。 |
| 🛑 plan | skill 把课程地图写入文件，在任何课时材料之前再次停下。 |
| 每个课时：材料 + 分层版本 | 在主对话中每个课时过一遍；内置子智能体可以并行写几个课时。 |
| 检查每个目标都有评估、准确性、无障碍 | 由脚本列出课程地图中没有评估的目标；一个只读子智能体检查准确性和无障碍，返回问题清单。 |
| 🛑 review → 导入 LMS | skill 呈现内容后停下。由教师自己导入 LMS。 |

**检查点：** `plan`：skill 停下两次，一次在学习目标之后，一次在课程地图之后，教师把计划文件标记为已批准之前不生成任何课时材料；再加一条权限规则，对写入课时文件夹先询问，就更牢靠。`review`：skill 最后给出完整内容和问题清单，由教师凭自己的学科知识审阅；智能体没有 LMS 工具，所以没有教师的参与，什么都到不了学生手里。

**与来源相比：** 来源 1 出自 2025-03；来源 2 未注明日期。2026-11 的一次搜索找到了工作顺序相同的较晚指南，例如 [UConn eCampus, Using GenAI for course design](https://ecampus.uconn.edu/2026/04/22/using-genai-for-course-design/)（2026-04），它的示例提示词按逆向设计排序；没有找到对这类工作流的独立评估。来源 1 的系统（ARCHED）用不同的智能体分别生成和分析学习目标，这套搭建方式把分析交给一个子智能体检查；它没有 LMS 集成，这套搭建方式也没有加。来源 2 是大学写给教师的、使用聊天工具的指南，不是智能体的一次运行；来源并未报告有人跑通了这整套流程。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 教师从课程标准和课程目标出发：设定年级、学科和目标布鲁姆层级 [[1]](#sources)，并概述课程目标 [[2]](#sources)。然后用 AI 起草可衡量的课程级和模块级学习目标，再逐步打磨 [[2]](#sources)。在 ARCHED 中，一个智能体生成学习目标，另一个按教学标准分析这些目标，并绘出各认知层级的分布；教师可重新生成并选择保留哪些 [[1]](#sources)。
2. 🛑 **计划**：教师批准学习目标集合，重点检查“理解”附近相邻层级的布鲁姆分类，因为分类错误多集中在这里 [[1]](#sources)。
3. 教师和 AI 编写与每个学习目标对齐的评估和评分量规。TWU 的示例提示词要求为分步作业的每一部分给出评分量规，再由教师调整 [[2]](#sources)。ARCHED 没有对评估题的生成效果做评测 [[1]](#sources)。
4. 教师把模块计划做成课程地图，将材料、活动和评估与学习目标关联起来 [[2]](#sources)。
5. 🛑 **计划**：在制作任何课时材料之前，教师先批准课程地图。
6. 对每个课时，AI 结合年级、时间限制和学生的薄弱环节等背景生成材料（讲稿或幻灯片内容、讨论题、活动、分步作业）[[2]](#sources)，并生成分层版本。
7. 教师把每个生成的条目加入课程地图，以检查每个学习目标都有对应评估 [[2]](#sources)，再检查准确性和无障碍。
8. 🛑 **审阅**：教师凭自己的学科知识审阅全部内容，教学设计师从旁协助 [[2]](#sources)。
9. 把批准后的课程导入 LMS。ARCHED 没有 LMS 集成，一位试点专家认为这是一个缺口 [[1]](#sources)。

**产出：** 一门对齐的课程（学习目标、带评分量规的评估、模块地图和课时材料），已导入 LMS。
**失败模式 → 防护：** 学习目标归入了错误的布鲁姆层级 → 分析环节加教师审批 [[1]](#sources)。AI 规划整门课程或取代教师的专业判断 → 采用人在回路的方式，由教师迭代并决定 [[2]](#sources)。材料偏离学习目标 → 课程地图的对齐检查 [[2]](#sources)。学生隐私 → 绝不向 AI 提供学生或学校的个人信息 [[2]](#sources)。
