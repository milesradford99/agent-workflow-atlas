# 分段确认的课程备课

**工具变体：** `oak-aila-gpt4o-cohere-rerank`

## 背景

教师备一节课，要写教案（学生应学到什么、已经知道什么、要讲的要点、常见误解、关键词），再做课件、课前和课末小测以及练习单。每节课都要这样做，教师往往是从同事的课出发，而不是从一张白纸开始。智能体可以在现有课时库里找出相近的课，按学校的标准模板起草教案的每一段，并生成课件和小测。基础课时和每一段都由教师批准，因为只有教师了解自己的班级，也因为错误或不适合儿童的材料会直接送到一屋子学生面前。

**术语：**
- **学段（key stage）**：英格兰学校教育的阶段（例如第二学段对应 7-11 岁）；课时是为某一学段编写的。
- **课程语料库**：由现有的、经过质量审核的课时组成的库，新课时以它为基础。
- **内容锚定**：以选定的现有课时为基础构建新课时，使其内容建立在已审核的材料上。
- **RAG（检索增强生成）**：模型在写作之前先拿到从文档库中检索出的段落。
- **重排（rerank）**：按与需求的契合程度重新排列检索结果。
- **常见误解**：学生对该主题常有的错误想法，列出来是为了让教师加以纠正。
- **内容审核**：自动检查，把内容分为安全、需要指引或有害。
- **课前和课末小测**：课堂开始和结束时的简短测验。
- **Aila**：Oak National Academy 的 AI 备课助手，即来源所描述的工具。

## 用智能体搭建

**形态：** `skill`。一位教师一次备一节课，并且全程在对话中，所以一个装有模板、并在每一段停下的 skill 就够了；独立的内容审核由一个子智能体承担。

**需要：** 经过审核的课时库，以文件形式或通过 MCP 连接器提供，供智能体检索；带各段落的课时模板；用来写教案、课件、小测和练习单文件的位置。不要给智能体任何学生数据，也不要给它向学生发布的途径。

| 步骤 | 搭建方式 |
|---|---|
| 教师给出学科 + 学段 + 标题 | skill 的第一步：询问这三项，并写出教案骨架。 |
| 检索相近课程课时 + 重排 → 🛑 plan | skill 在课时库中检索，把最匹配的结果按与需求的契合度排序，展示后停下，由教师选定基础课时。 |
| 每个模板段落：起草 → 🛑 review | 在主对话中一次一段，依据基础课时起草；每段之后 skill 都会停下，直到教师同意或提出修改。 |
| 并行内容审核 (安全 / 需指引 / 有害：停止) | 一个没有看过对话的只读子智能体，只拿到课时文本，返回三个标签之一并说明理由。 |
| 下载教案 + 课件 + 测验 + 练习单 | 只有每一段都获同意、且审核标签不是 `toxic` 之后，skill 才写出文件。 |

**检查点：** `plan`：教师选定基础课时之前，skill 除了骨架什么都不写。`review`：skill 在每一段之后都停下；教师同意或修改后它才继续。`toxic` 标签会终止运行，skill 不写出可下载的文件；再用一个 `PreToolUse` 钩子，在没有审核结果记录之前阻止写入输出文件夹，即使 skill 的指令被漏掉，这一点也依然成立。

**与来源相比：** 来源的日期是 2024-12，描述的 Aila 还处于测试阶段，所以比这次核对早了 12 个月以上。2026-11 的一次搜索发现已经宣布了一项对 Aila 的独立试验（见[教育捐赠基金会（Education Endowment Foundation）的新闻页](https://educationendowmentfoundation.org.uk/news/new-trial-ai-powered-lesson-planning)）；没有打开其结果，也没有发现步骤有任何变化。来源描述的是一个定制的网页应用，用的是托管模型、向量化的课时库和单独的审核模型；这套搭建方式用一个 skill 和一个子智能体取代该应用，用你的课时库自带的检索取代向量库。来源是一份政府算法透明度记录，是 Oak 自己对其流水线的描述。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 教师输入学科、学段或课时标题。Aila 将其归入对应的学科和学段，并生成教案骨架 [[1]](#sources)。
2. 一次性 RAG 在约 10,000 节 Oak 课时的向量库中检索，对结果重排后展示给教师 [[1]](#sources)。🛑 **计划**：教师可以选定其中一节作为基础课时（“内容锚定”）。
3. Aila 按 Oak 的模板依次起草各段：学习成果、先备知识、核心学习要点、常见误解、关键词、课前小测、学习循环、课末小测 [[1]](#sources)。
4. 🛑 **审阅**：Aila 在进入下一段之前请教师确认每一段，其设计目标并不是“一键”生成课时。教师可以提出修改要求，例如“把难度调高” [[1]](#sources)。
5. 一个不带课时上下文的独立审核模型，把内容分为安全、需要指引或有害三类。有害内容会终止课时生成，教师可以申诉 [[1]](#sources)。
6. 教师下载教案、课件、课前和课末小测以及练习单。反馈组件和支持工单分流为后续维护提供输入 [[1]](#sources)。

**产出：** 一份可编辑的单课时资源包（教案、课件、两份小测、练习单），供教师在课堂上使用。
**失败模式 → 防护：** 内容缺乏依据或不安全 → 以经过审核的课时语料库为锚点，并设独立的审核环节，可终止生成 [[1]](#sources)。走过场式确认 → 设计上要求逐段确认 [[1]](#sources)。
**与相近工作流的区别：** 最接近的是 AWF-0027 逆向设计课程（COURSE）。那个工作流依据课程标准设计整门课程，在目标和模块上设有计划关卡，并导入 LMS。本工作流则以现有课程语料为锚点，构建一节可直接上课的课时，在每个模板段落上设教师关卡，并有自动内容审核的终止机制，因此产出和检查点的安排不同。
