# 分段确认的课程备课

**与相近工作流的区别：** 最接近的是 AWF-0027 逆向设计课程（COURSE）。那个工作流依据课程标准设计整门课程，在目标和模块上设有计划关卡，并导入 LMS。本工作流则以现有课程语料为锚点，构建一节可直接上课的课时，在每个模板段落上设教师关卡，并有自动内容审核的终止机制，因此产出和检查点的安排不同。
**工具变体：** `oak-aila-gpt4o-cohere-rerank`

## 步骤

1. 教师输入学科、学段或课时标题。Aila 将其归入对应的学科和学段，并生成教案骨架 [[1]](#sources)。
2. 一次性 RAG 在约 10,000 节 Oak 课时的向量库中检索，对结果重排后展示给教师 [[1]](#sources)。🛑 **计划**：教师可以选定其中一节作为基础课时（“内容锚定”）。
3. Aila 按 Oak 的模板依次起草各段：学习成果、先备知识、核心学习要点、常见误解、关键词、课前小测、学习循环、课末小测 [[1]](#sources)。
4. 🛑 **审阅**：Aila 在进入下一段之前请教师确认每一段，其设计目标并不是“一键”生成课时。教师可以提出修改要求，例如“把难度调高” [[1]](#sources)。
5. 一个不带课时上下文的独立审核模型，把内容分为安全、需要指引或有害三类。有害内容会终止课时生成，教师可以申诉 [[1]](#sources)。
6. 教师下载教案、课件、课前和课末小测以及练习单。反馈组件和支持工单分流为后续维护提供输入 [[1]](#sources)。

**产出：** 一份可编辑的单课时资源包（教案、课件、两份小测、练习单），供教师在课堂上使用。
**失败模式 → 防护：** 内容缺乏依据或不安全 → 以经过审核的课时语料库为锚点，并设独立的审核环节，可终止生成 [[1]](#sources)。走过场式确认 → 设计上要求逐段确认 [[1]](#sources)。
