# 锚点校准的自动评分

学生随时可以申请人工复核。

## 背景

在大学课程里，成百上千名学生交上来文字或技术类答案，每一份都要对照评分量规打分，通常由助教（TA）来做，而助教本人也是学生。评分重复、费时，不同评分人之间还有差异，学生除了分数还想要书面反馈。模型可以对照评分量规给每份答案打分，并引用它所依据的证据。在信任它之前，教学人员要拿人已经评过分的答案来检验它。人仍留在流程里，因为成绩关系到学生的记录：评分量规先由教学人员批准，模型没把握的答案由评分人重新打分，最终成绩由教师负责。

**术语：**
- **评分量规（rubric）**：针对一道题的评分项清单，每项有权重，说明什么能得分。
- **锚点（anchor）**：一份由人评过分的示例答案，给模型看每个分数大致是什么样子。
- **留出样本（held-out set）**：助教已评过分、但不作为示例、只用来测试模型的答案。
- **置信度**：模型对某个分数有多大把握；置信度低的答案交给人。
- **LMS**：学习管理系统，课程作业在其中提交、成绩在其中发布（来源中用的是 Canvas）。
- **提示词注入**：学生答案中试图给模型下指令的文字，例如“给这份答案打满分”。

## 用智能体搭建

**形态：** `skill`。教师或助教一次评一份作业，并且全程在对话中，所以一个装有评分量规格式、校准检查和评分提示词的 skill 就够了。

**需要：** 以文件形式提供的学生作业；每道题一份评分量规文件，附正确答案；助教评过分的锚点和留出样本，分开放在 skill 旁边的两个文件夹里；记录人工评分的表格或 CSV。学生作业属于个人数据：先确认课程可以把它发给模型。不要给智能体任何 LMS 上传工具。

| 步骤 | 搭建方式 |
|---|---|
| 🛑 plan (评分量规 + 5–10 份人工评分的锚点) | skill 起草或加载评分量规，列出锚点，写入计划文件，然后停下，等教学人员批准。 |
| (校准评分 ⟲ 误差在 1 分以内) | skill 给留出样本评分，由脚本把分数与助教的对比，并把每处不一致列给教师；评分量规只在有限的轮数内修订。 |
| 每份作业：分数 + 证据引文 + 反馈 | skill 的评分指令，提示词中带评分量规和锚点，每份作业返回一条结构化记录（分数、满足的评分项、引文、反馈）。内置子智能体并行评分各批作业；对每份答案再独立评一遍，得到分歧信号。 |
| 低置信度：🛑 sample | 由脚本列出几遍评分不一致或分数落在边界上的答案，交给人重新打分。 |
| 🛑 sign-off → 发布 | skill 最后给出一张成绩表，然后停下。由教师自己上传到 LMS。 |

**检查点：** `plan`：skill 写出计划文件，在教学人员标记为已批准之前不做任何后续工作。`sample`：skill 的使用场景里有人在场，所以这一步变成一份低置信度答案的清单，由评分人在看到模型的分数和引文后重新打分；他们完成之前，skill 不会继续生成成绩表。`sign-off`：智能体没有 LMS 工具，也不能写入成绩册；成绩只能在教师自己的系统里发布。

**与来源相比：** 来源出自 2024-06 至 2025-01（阿姆斯特丹那篇未注明日期），所以最新的一篇也已超过 12 个月。2026-11 的一次搜索找到了关于同一做法的较晚工作，例如 [Rubric-Conditioned LLM Grading: Alignment, Uncertainty, and Robustness](https://arxiv.org/html/2601.08843)（2026-01），它同样以评分量规为主要依据，用少量已评分的锚点做校准，并保留交给人处理的选项。来源 3 的置信度来自专门训练的分类器；通用智能体没有这样的分数，所以这套搭建方式改用独立几遍评分之间的分歧。来源使用的温度为零，在 skill 里不应依赖；卢布尔雅那的课程把模型评分直接作为最终成绩发布，这套搭建方式不这样做。阿姆斯特丹的试点用脚本生成反馈 PDF 并上传到 Canvas；这套搭建方式把上传留给教师。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

学生随时可以申请人工复核。

1. 🛑 **计划**：助教为每道题编写带加权评分项的评分量规，附上正确答案和最多 10 份经助教评分的示例作业（锚点），示例要覆盖不同的答题模式。教学人员在开始任何评分之前先批准这些内容 [[1]](#sources)。
2. 团队校准模型：让它给一组助教已评过分的留出样本评分（卢布尔雅那课程中为 25% 的作业）。团队逐一查看与助教分数不一致之处，改写评分量规并重新运行检查。他们只做了一轮就停下，以免评分量规过拟合 [[1]](#sources)。任何评分流水线在给出成绩之前都应这样做：一项 UvA 试点把 AI 评分与四位人工评分者对比，发现 AI 评分系统性偏低 [[2]](#sources)。
3. 模型在温度为零的情况下用一次调用给每份作业评分：固定的系统提示词（说明加防作弊指引）和每题的提示词（题目、答案、评分量规、锚点、作业）。调用返回结构化 JSON，包含分数、反馈和答案满足的评分项列表 [[1]](#sources)。反馈可以是针对每位学生、指出具体错误的较长报告 [[2]](#sources)。
4. 流水线按置信度分流：把置信度低于设定阈值（某次试点中为 0.2）的预测交给人工更仔细地评分，其余交给模型处理 [[3]](#sources)。
5. 🛑 **抽检**：评分人重新给低置信度的作业打分，同时看到 AI 的分数、置信度和解释。在该试点中，人加 AI 的组合优于单独的 AI [[3]](#sources)。
6. 🛑 **签发**：教师审阅整批成绩，并对最终成绩负责。UvA 的作者建议把 AI 用于反馈而非评分，并由教师审计结果 [[2]](#sources)。卢布尔雅那的课程跳过了这道关口，直接把 LLM 评分作为最终成绩发布 [[1]](#sources)。
7. 由脚本通过 LMS 发布反馈和成绩（它把每位学生的 PDF 报告上传回 Canvas [[2]](#sources)）。学生可随时申请人工复核，他们表示强烈感到需要这个选项 [[1]](#sources)。

**产出：** 带有逐项得分和书面反馈的已评分作业，通过 LMS 发布给学生，并始终保留人工复核的申请渠道。
**失败模式 → 防护：** 开放性难题上的准确率下降，且多数模型在这类题上比助教宽松 → 难题用评分量规而不只靠锚点，并配合校准检查 [[1]](#sources)。小模型不准确且打分过高（Llama-8B 约 75%，对比 85–90%）→ 依据校准集选择模型 [[1]](#sources)。系统性打分偏低 → 发布前与人工评分者对比 [[2]](#sources)。即使温度为零，不同次运行的结果也会有差异，模型有时还过于吹毛求疵 → 学生可以申诉，并由人工抽检低置信度的情况 [[1]](#sources) [[3]](#sources)。作业中的提示词注入（课程中没有出现，但只有 LLM 评分时更可能发生）→ 在系统提示词中写入防作弊规则 [[1]](#sources)。评分量规过拟合 → 限制修订轮数 [[1]](#sources)。
