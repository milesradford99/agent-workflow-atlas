# 有护栏的课程辅导助手

**与相近工作流的区别：** 最接近的是 AWF-0042 辅导员批准的 AI 回合（TUTOR），那是辅助模式：辅导员批准每一轮 AI 回复后学生才能看到。本工作流中学生直接与辅导助手对话。人在论坛回答发布之后检查，助教在样本上评判提示词或模型版本，因此自主程度（抽检）和检查点安排不同。
**工具变体：** `cs50-ai-azure-gpt4o`

## 步骤

1. 所有工具共用一个后端。后端先去除学生提问中的个人信息，再套上课程专用的系统提示词，要求模型扮演 CS50 助教，只做引导、不直接给答案 [[1]](#sources)。
2. 论坛提问使用基于课程事实的 RAG 来减少幻觉。duck 直接在 IDE、网页和 Ed 论坛上回答学生 [[1]](#sources)。
3. 🛑 **审阅**：duck 在 Ed 上的每条回答都可以由教职人员认可、修改或删除 [[1]](#sources)。
4. 团队从日志中挖掘行为漂移，例如回复中带有代码块，或出现 'here's an example' 之类直接给出完整解答的措辞 [[2]](#sources)。
5. 他们构建候选修复方案：少样本提示词，或基于 50 段精选的师生对话做微调 [[2]](#sources)。
6. 🛑 **抽检**：助教（teaching fellow）对同一批学生提问比较两个版本的回复并留下书面反馈。模型评分的评测在扩大使用之前，先与助教的选择做一致性核对 [[2]](#sources)。

**产出：** 一个与课程对齐、学生 24/7 使用的 AI 辅导助手，论坛回答有教职人员监督，每次提示词或模型变更前有经助教验证的评测闭环。
**失败模式 → 防护：** “指令稀释”，即模型忽略过长的提示词；从 GPT-4 切换到 GPT-4o 后，含代码块的消息从 20% 升到 25% → 上线前做助教两两评测并进行微调 [[2]](#sources)。过度热心的回答损害学习效果 → 引导式回答的提示词，加上对直接给答案措辞的监控 [[2]](#sources)。
