# 专家资料转电子课程

**与相近工作流的区别：** AWF-0027 逆向设计课程（Backward-design course，COURSE）与它最接近，但从学习成果出发。本工作流从领域专家（SME）的源文档出发，并以 SME 的准确性审阅为关口，面向企业内训模块。需要确认它是否算作变体。
**工具变体：** `leai` · `articulate-rise-ai`

## 背景

企业培训通常是用没人专门为学习者写过的东西拼出来的：一份产品手册、一场网络研讨会的录像、一张贴在柜门内侧的工作辅助卡、某位专家把流程讲了一遍的转写。教学设计师把它变成一门课——目标、课节、随堂检测、结课测验——而专家必须过一遍，因为设计师判断不出手册第四步是不是还现行。瓶颈在第一稿和随后的审阅循环：设计师写出看起来合理的东西，专家批注，设计师重写。内置模型的制作工具把第一稿压缩到几分钟，代价是审阅关口要承担比以前更多的工作，而不是更少。一份看起来已完成的第一稿，会诱使审阅人去核对标题而不是数字；而合规课程里真正要命的错误——一条讲反的规则、一个早已不存在的步骤、一道正确答案永远是最长选项的题——恰好能从这种读法底下溜过去。所以本工作流保留两道关口，一道在大纲，一道在草稿，并把最贵的注意力放在"错误事实会直达学员"的地方。

**术语：**
- **领域专家（SME）**：拥有被教授的那套流程、并能判断某句话是否仍然成立的专家。
- **教学设计师（instructional designer）**：负责目标、顺序与测评设计的人，而不是学科内容本身。
- **大纲（outline）**：课节结构加学习目标的提案，此时还没有任何课节正文。
- **随堂检测（knowledge check）**：课节中间的小问题，区别于结尾的记分测验。
- **制作工具（authoring tool）**：装配并发布课程的软件。
- **认知层级（cognitive level）**：一道题要求多少思考（记忆还是应用），正是 AI 起草的测验容易拉平的东西。
- **干扰项（distractor）**：错误的备选项，它的可信度决定这道题是否真的在测什么。
- **事实基准（source of truth）**：手册与专家说法不一致时，以哪份文件为准。

## 用智能体搭建

**形态：** `project`。一门课的建设要跨数周、跨多次会话：源语料、已批准的大纲、课节草稿、题库和一份文体规范，都得在设计者、专家与同行审阅人反复过版本的过程中留存并保持一致。这需要一个带工作流的仓库，而不是一次对话，也不是一个无人值守运行的服务。

**需要：** 专家的源文件，并带上各自的日期，因为最常见的缺陷就是把已被取代的流程当现行内容教；受众与绩效目标，因为"做一门关于 X 的课"只会产出一门覆盖了 X 却什么都没改变的模块；专家可投入的审阅时间，而且在起草开始前就排好，否则草稿只能等着，速度优势也就消失了；一份文体规范，免得模型的腔调变成课程的腔调；以及测评规则——多少题、哪个认知层级、及格线多少——在生成之前就写下来，因为先出题再补理由的测验一定是记忆层的。智能体不能发布，也不能判定某份来源是否现行：那是专家的判断，也正是第二道关口存在的全部理由。

| 步骤 | 搭建方式 |
|---|---|
| 收集领域专家资料 | 一次导入，记录每份来源的日期与责任人，并标出两份来源互相矛盾之处——这种矛盾是专家的第一项审阅任务，而不是可以取平均的东西。 |
| AI 生成大纲和学习目标 | 模型把来源映射成顺序并提出结构与目标；每个目标都必须注明来自哪份来源，这样设计师能看见某个没有任何来源支撑的目标。 |
| 🛑 review（教学设计师调整结构） | 设计师用提示加手改重写大纲；批准后的版本冻结为文件供起草步骤读取，此后的结构漂移就以 diff 的形式可见。 |
| 起草课节和测验 | 课节正文与题目对着冻结的大纲生成；每条事实性陈述保留指向来源段落的链接，题目按声明的认知层级生成，及格规则事先定好。 |
| 🛑 review（领域专家 + 同行） | 专家对着来源核事实，而不是对着流畅度点头；同行核对顺序与测评效度。两人都从引用清单入手而不是从头读到尾，这是审阅人能在结构漂亮的段落里发现一个错数字的唯一办法。 |
| 在制作工具中搭建 → 发布 | 交互与版式在制作工具里装配，模块由人来发布，因为搭建本身没有发布通路。 |

**检查点：** `review`，两处：第一道关口是结构性的，属于教学设计师，因为模型会很乐意做出一门组织良好但讲错问题的课；第二道是事实性的，属于专家加一名同行，因为模型的错误是流畅的。搭建用两种方式守住第二道关口：每条陈述都附引用，题目按固定认知层级生成，于是审阅人核的是真假，而不是在时间压力下重写结构。

**与来源相比：** 来源出自 2025-11 与 2026-08：两份厂商案例。两份本轮都没有重新打开。此后有这些变化：失败模式现在有据可查而不是靠推测，而且很具体。2026 年一份建设生物医学课程的报告记录：AI 草稿缺乏深度且含不准确内容，AI 写的测评题与学习目标错位、偏向记忆层，还有一处细节值得记住——存在结构性的破绽，正确答案永远是最长的那个选项，学员什么都不懂也能得分。另一项让四个模型做真实教学设计任务的对照测试，暴露的是与"无能"相反的问题：一个模型写出了全研究中最好的练习活动，而它给学员的反馈教了一条错误的同意规则、引用了一条并不存在的程序条款；另一个做审阅的模型把两个平台问题排在"每个学员都会撞上"的缺陷之前——只奖励覆盖面的评分表抓不到错数字。同一批文献还解释了为什么本条的关口不能只是"有人看过"：在 2026 年波士顿咨询的现场实验（758 名顾问）中，面对超出模型能力的任务，有 AI 辅助的答案正确率只有 60 到 71%，而无 AI 时为 84.5%，并且评审人认为错误的 AI 答案比正确的人工答案更连贯、更有说服力。流畅不是准确的代理，所以关口必须是一次引用核对。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 把原始的专家素材（文档、视频、演示、转写、工作辅助卡）上传到 AI 制作工具 [[1]](#sources)[[2]](#sources)。
2. AI 生成结构化的课程大纲、学习目标与关键概念摘要 [[1]](#sources)[[2]](#sources)。
3. 🛑 **审阅**：教学设计师通过提示按受众与形式重塑目标和结构 [[1]](#sources)。
4. AI 起草课节文案、随堂检测与测评题目，并调整技术内容的语气 [[1]](#sources)[[2]](#sources)。
5. 🛑 **审阅**：专家与同行审阅草稿的准确性。仍然需要有人把输出"人化" [[2]](#sources)。
6. 在制作工具中搭建交互与版式并发布 [[1]](#sources)[[2]](#sources)。

**产出：** 一份经审阅、带测评的电子课程模块，发布到公司的学习平台。
**失败模式 → 防护：** AI 文案平板 → 人工编辑加一份 AI 文体规范 [[2]](#sources)。与源文档的准确性漂移 → 专家审阅关口 [[1]](#sources)[[2]](#sources)。
