# 对照底稿的月结智能体

**工具变体：** `promptql` · `puzzle-ai-close`

## 背景

每个月末，财务团队要关账：确保这个月的交易完整、正确，以便出具报告，并让数字不再变动。财务主管（controller）带领会计团队，对关账负责。关账是一长串领域（应计费用、租赁、预付款、固定资产、工资、银行对账等等），每个领域都要有会计从多个系统里提取数据，重建一份支撑表格，草拟更正分录，并说明与上月相比有什么变化。其中很大一部分，就是拿上月的文件换上新数字重做一遍。在这里，智能体按上月文件的做法准备每个领域，草拟分录和变动分析，并标出任何看起来不对的地方。财务主管仍要提供系统里没有的背景，决定每一处判断，在账簿锁定前复核全部内容并签发关账，因为数字由财务主管负责。

**术语：**
- **关账（月结）**：把一个期间的账簿定稿的过程；之后该期间的数字就固定了。
- **底稿**：某一领域的支撑文件，写明源数据、计算和检查，留作复核和审计之用。
- **会计分录（JE）**：账簿里关于借记和贷记某个金额的记录，用来更正或补全数字。
- **应计费用、预付款**：在费用发生的当月入账、早于发票到达的费用；提前支付、分摊到以后各月的成本。
- **固定资产、租赁**：使用年限长的设备，以及租入的房产或设备，各有一张把成本分摊到各期的明细表。
- **对账**：核对同一件事的两份记录（例如银行对账单和总账）是否一致。
- **分摊**：把共同的成本分给各部门或各主体。
- **波动分析（flux）**：解释每个科目与上一期相比为什么变动。
- **锁账**：不再允许向已关账的期间录入分录。
- **财务主管（controller）**：对关账负责并签发的资深会计。

## 用智能体搭建

**形态：** `project`。一个 skill 可以跑一个关账领域，但这里有十几个领域并行，每个都有自己的源数据和底稿格式；有两条规则必须每次都成立（任何智能体都不碰银行，也都不锁账或过账）；而且财务主管的复核应当把输出与上月的文件对照。这就需要自定义子智能体、钩子和常驻的项目文件。

**需要：** 通过 MCP 连接器或导出文件，对会计系统、工资系统和团队已在使用的文件的读取权限；每个领域上月的底稿，作为要对齐的样板；会计人员设定的规则，每个领域一份参考文件；一份 `CLAUDE.md`，写明关账日历、底稿格式，以及“智能体不得有银行权限”的规则；存放底稿草稿和分录草稿的文件夹。不要给任何智能体银行连接、过账工具或锁账工具。

| 步骤 | 搭建方式 |
|---|---|
| 上月底稿 + 规则 | 每个关账领域一个 skill，旁边放着上月底稿和会计人员的规则，作为参考文件。 |
| 每个关账领域：提取源数据 → 准备底稿 + 检查 | 每个领域一个自定义子智能体，只带只读工具，按上月的样子建立底稿，并运行该领域的检查。可以用动态工作流让各领域同时进行。 |
| 草拟分录 + 波动分析 | 同一个子智能体把草拟的分录写入文件，并写出一张波动表，为每个大的变动配上解释。 |
| 标出异常 | 每个子智能体返回对不上的项目清单，附上证据。 |
| 🛑 review (财务主管复核全部内容) | 见“检查点”。 |
| 锁账 → 🛑 sign-off (关账) | 财务主管在会计系统中完成这两步。 |

**检查点：** `review`：项目在运行结束时按领域逐一呈现全部底稿、草拟分录和异常，然后停下；由财务主管补充缺少的背景，并决定每一处判断。`sign-off`：智能体没有过账工具、锁账工具，也没有银行连接，这通过拒绝这些工具的权限规则来设定，所以由财务主管过账、锁账并签发关账。

**与来源相比：** 来源出自 2026-08（一位财务主管的 LinkedIn 帖子），另有一份未注明日期的厂商案例。来源 1 讲的是使用厂商工具（`promptql`），每个领域一个智能体；来源 2 讲的是一款厂商的关账产品，由人复核异常。两者都没有展示智能体的内部做法，所以上面的搭建方式是依据步骤做出的设计，不是对任何一方的照搬。这套搭建方式不包括来源所说的全月持续运行的交易匹配；需要的话，把它另做成一个定时任务（[AWF-0164](../exception-only-reconciliation/) 是只看例外的版本）。正如来源所报告的，工资的时间差异仍需要人去追查。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 会计人员给每个智能体提供上月的底稿（“match this”）和会计人员设定的规则 [[1]](#sources)[[2]](#sources)。
2. 交易匹配全月持续运行。到关账时，由不同的智能体分别处理应计费用、租赁、固定资产、应交税费、预付款、对账、工资、分摊、财务报表和损益波动分析。每个都有自己的源数据、底稿、检查、会计分录和复核点 [[1]](#sources)。
3. 智能体准备底稿，并标出任何看起来不对的地方。AI 匹配银行流水项，人只复核异常项 [[1]](#sources)[[2]](#sources)。
4. 🛑 **审阅**：财务主管补充背景信息、做出判断，并在关账前复核全部内容 [[1]](#sources)。
5. 🛑 **签发**：在 AI 标出异常之后，对关账签发 [[2]](#sources)。

**产出：** 一个已关账的期间，每个领域都有完整的底稿和会计分录，经财务主管复核，可用于报告和审计。
**失败模式 → 防护：** 工资时间差异仍需人去追查 → 由人处理异常 [[1]](#sources)。智能体拥有银行权限 → 有意不授予 [[1]](#sources)。糟糕的自动化会放大错误 → 由会计人员设定规则，AI 负责执行 [[2]](#sources)。
**与相近工作流的区别：** AWF-0022 发票提取、匹配与分流（Invoice extract-match-route，AP）处理单张发票。本工作流产出跨多个科目的期末底稿和会计分录，并由财务主管对关账签发。
