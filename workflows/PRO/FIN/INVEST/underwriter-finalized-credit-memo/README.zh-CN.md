# 承销人定稿的信贷备忘录

**工具变体：** `gemini-vertex-docai` · `moodys-credit-memo` · `ncino-banking-advisor`

## 背景

企业向银行申请贷款时，银行里一位叫承销人的员工要评估这笔贷款能否收回，并把结论写成信贷备忘录：借款人是谁、数字说明什么、风险在哪里、承销人建议怎么办。备忘录送入银行的信贷审批流程，由其他人决定是否放贷。承销人首先要读完贷款档案，档案可能有数千页、多种格式（财务报表、纳税申报表、合同、扫描件），再一节一节把事实提取出来，所以一份备忘录可能要花大约一周。在这里，智能体负责提取细节并起草各节。承销人审阅、修改并定稿，贷款决定则由银行自己的信贷流程作出，因为银行要为每一笔贷款向监管机构和存款人负责，智能体从不作出这个决定。

**术语：**
- **承销人（underwriter）**：评估贷款申请并撰写信贷备忘录的银行员工。
- **信贷备忘录**：说明借款人财务状况和风险、并附承销人建议的文件。
- **贷款档案**：借款人提供的、加上银行为某笔贷款申请收集的全部文件。
- **信贷审批流程**：银行在承销人工作之外设立的正式审查，决定是否发放贷款。
- **Document AI**：Google 的一项服务，从扫描件、PDF 等非结构化文件中提取字段和文字。
- **公司概况数据（firmographics）**：关于一家公司的基本事实，如行业、规模和所在地。

## 用智能体搭建

**形态：** `skill`。一位承销人一次处理一份贷款档案，并且全程在对话中，所以一个装有备忘录模板和流程的 skill 就够了。

**需要：** 文件形式的贷款档案；银行的备忘录模板；读取扫描件和多种格式文件的手段（放在 skill 旁边的文档提取脚本或服务）；备忘录所用信用数据的读取权限（如有，通过连接器）；一套经银行批准、可以处理借款人财务记录和个人数据的环境。不要给智能体任何记录或发送信贷决定的工具，也不要接入邮件工具。

| 步骤 | 搭建方式 |
|---|---|
| 上传交易文件 | 承销人把贷款档案放进一个文件夹；skill 列出里面有什么、看起来缺什么。 |
| 提取字段（Document AI） | skill 旁边的脚本或提取服务把每份文件转成文字和字段，并注明各自出自哪一页。 |
| 每个备忘录章节：总结 + 起草 | 内置子智能体各负责一节或一组文件，返回带来源页码的章节草稿。 |
| 汇编备忘录草稿 | 在主对话中把各节放入银行的模板，并标出缺口和相互冲突的数字。 |
| 🛑 review → 🛑 sign-off | 见“检查点”。 |
| 每一步归档到共享 Drive | skill 把提取表和草稿写进这笔交易的文件夹，每一步一个文件。 |

**检查点：** `review`：skill 最后给出备忘录草稿，并列出相互冲突或没有来源的数字，然后停下；由承销人修改并定稿。`sign-off`：智能体没有记录信贷决定或转发备忘录的工具，所以银行的信贷审批流程从承销人自己的系统里接手。

**与来源相比：** 来源出自 2025 年（Banesco 页面未注明日期，条目把它放在 2024-10 之后）至 2026-04。两者都是厂商的说法：一个是 Google 介绍自己的产品，一个是介绍某银行使用穆迪的产品。两者都没有详细展示步骤，也都没有描述信贷审批这一步。上面的搭建方式用通用工具代替了所述的产品，来源并没有说明这样是否得到同样的结果。穆迪的介绍还提到，通用模板不适合该银行的组合，所以可能需要为每类借款人各做一份模板。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 承销人上传某笔交易的贷款档案。在 Banesco USA，每笔交易有数千页，涉及多种文件类型 [[1]](#sources)。
2. 文档提取服务（Google 的 Document AI）从非结构化文件中提取细节。语言模型（部署在 Google 的大规模模型运行平台 Vertex AI 上的 Gemini）对材料做总结，并逐节起草，这原本是承销人一节一节手工完成的工作 [[1]](#sources)。
3. 智能体在几分钟内汇编出信贷备忘录草稿；人工流程大约要一周 [[1]](#sources)。穆迪（Moody's）介绍了同样的模式，数据来自其评级、公司概况、股权结构、财务数据和申报文件，并使用银行的模板 [[2]](#sources)。
4. 🛑 **审阅**：承销人在 Google Docs 中审阅、修改并定稿 [[1]](#sources)。
5. 🛑 **签发**：定稿的备忘录进入银行既有的信贷审查和审批流程。两个来源都没有详细描述这一步；智能体从不作出信贷决定。
6. 承销人通过 Gmail 与相关方沟通，共享 Drive 文件夹保存每一步的记录 [[1]](#sources)。

**产出：** 每笔贷款申请对应一份定稿的信贷备忘录，交信贷审批，并与交易档案一起保存。
**失败模式 → 防护：** 通用模板无法满足各组合细分领域的需求 → 那家欧洲银行为一个重点细分领域做了定制模板，并计划制作各行业专用的模板 [[2]](#sources)。摘要可能把提取错误带进信贷档案 → 承销人在审批前修改并定稿每一份备忘录 [[1]](#sources)。
**与相近工作流的区别：** 最接近的是 AWF-0023 事件驱动的模型更新（Event-driven model update，INVEST），它更新股票模型，并在合规签发后发布研究报告。本工作流产出的是单笔贷款的信贷备忘录，由承销人定稿，并输入受监管的信贷决策，因此产出物、检查点负责人和风险都不同。分类说明：FIN 下没有贷款/信贷类别，所以 INVEST 是最接近的。

## 公开实例

覆盖度（截至 2026-11-06）：**薄弱**：只有匿名、与厂商相关或由记者转述的说法。收集与复核见 [Second collection pass](../../../../../research/2026-11-second-pass.md)。

- [Google Workspace, Banesco USA customer story](https://workspace.google.com/customers/banescousa) (undated)。一家资产 50 亿美元的社区银行用 Gemini 起草信贷备忘录；承销人在 Docs 中定稿。"280 credit memos we annually process"。*第一手：厂商；可信度：中。*
- [Moody's, Major European bank transforms credit analysis](https://www.moodys.com/web/en/us/insights/ai/major-european-bank-transforms-credit-analysis-with-moodys-agentic-solutions.html) (2026-04-20)。一家未具名的欧洲银行用基于模板的智能体草稿取代了外包的备忘录起草。"first drafts in less than 15 minutes"。*第一手：厂商；可信度：中。*
