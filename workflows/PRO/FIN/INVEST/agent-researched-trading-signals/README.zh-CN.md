# 智能体研究的交易信号

**工具变体：** `alphagpt` · `claude-code-skills`

## 背景

量化投资机构不靠个人挑股票，而是按写成计算机代码的规则来管理基金。每条规则就是一个交易信号：一种可以度量的规律，例如“买单多于卖单的股票往往上涨”，基金据此下注。研究员先提出一种规律，写代码在多年的历史数据上检验它（回测），并确认结果不是运气，而且在经济上说得通。可能的规律远多于研究员的人数，每一条又要花几天来编码和检查。在这里，三类智能体角色分别提出规律、写代码、检验结果，并保留完整的日志。每个信号在动用真金白银之前，仍要由人把关：技术人员审查代码并测试，投资委员会决定这个信号的逻辑和结果是否值得动用资本。拿真钱去交易，这个决定必须由公司的人来负责。

**术语：**
- **信号**：基金据以交易的、市场数据中的一条规则或规律。
- **假设**：对某种规律为何成立的、可检验的陈述。
- **回测**：把一条规则放到历史数据上运行，看它当时会有怎样的表现。
- **统计显著性、p-hacking**：结果是否不太可能出于偶然；以及试了太多种变化，其中一些仅凭偶然就显得显著。后者也叫多重检验问题。
- **经济逻辑**：除了数字之外，这种规律为什么还会继续有效的理由。
- **偏离（drift）**：智能体说的是一个想法，代码实际检验的却是另一回事。
- **投资委员会**：批准基金可以交易什么的资深小组。
- **实盘交易**：动用真实资本，区别于在过去的数据上测试。
- **阿尔法（alpha）**：基金获得的、超出整体市场所给的那部分收益。

## 用智能体搭建

**形态：** `project`。一个 skill 装不下这件事：工作要在许多假设之间并行展开，评估者必须在没写过代码的情况下评判代码，而且有三条规则必须每次都成立（没有两道批准就不部署信号；每一步都留日志；数据不出公司）。这些需要自定义子智能体、钩子和常驻的项目文件。

**需要：** 公司的研究数据和研究代码库，在一个与交易系统没有连接的沙箱环境里可读；一份 `CLAUDE.md`，写明研究方法（显著性门槛、风险限额、什么算经济逻辑）；存放日志，以及每个信号的代码、回测和报告的位置；一套经公司批准、可处理自有数据的环境。不要给智能体生产交易系统或信号部署系统的任何凭据。

| 步骤 | 搭建方式 |
|---|---|
| 创意智能体提出可检验的假设 | 一个 skill 或子智能体把每个假设写成单独的文件，附上所需数据和预期方向。 |
| 实现者基于公司研究数据编写 Python → 回测 | 一个自定义子智能体在沙箱里依据公司的代码库写代码并运行回测。可以用动态工作流同时跑许多假设。 |
| 评估者（显著性、风险、经济逻辑、创意与代码一致性） | 一个单独的只读子智能体，拿到假设文件、代码和结果。它套用 `CLAUDE.md` 里的门槛，并把代码实际做的事与假设所说的对照。 |
| 不通过：丢弃 \| 通过：记录完整轨迹 | 由脚本把未通过的移入归档，把每个通过信号的假设、代码、结果和决定写入日志。 |
| 🛑 review (技术团队) | 见“检查点”。 |
| 🛑 sign-off (投资委员会) → 上线交易 | 由委员会决定，其余由公司自己的部署流程完成。 |

**检查点：** `review`：项目为每个通过的信号准备一份审阅材料（代码、测试、回测、日志）后停下；技术人员审查，并运行他们自己的单元、集成和情景测试。`sign-off`：智能体没有部署或交易的凭据，`PreToolUse` 钩子拦住对生产信号目录的任何写入，所以只有公司自己的流程在委员会批准之后才能让信号上线。智能体可以准备委员会的材料（假设、逻辑、结果），但不能做决定。

**与来源相比：** 来源出自 2025-07 至 2026-05。它们描述的是一家公司自有的系统（`alphagpt`）：三个智能体、一个编排器，以及内部的研究工具和数据库；这些没法从公开材料中复制，上面的搭建方式是在你自己的研究环境上使用通用的智能体工具。来源 2 是一场会议演讲，在这里无法读取，所以它所报告的后续工作（用 Claude Code 产出信号，公开实例中称有 750 个）依据的是本条目的转述。来源没有给出这套搭建方式可以引用的业绩数据。想法数量越多，多重检验就越严重，所以 `CLAUDE.md` 里的显著性门槛必须考虑一共试过多少个假设，而不只是最后一个。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. “创意人”智能体头脑风暴出可检验的投资假设（例如订单失衡、招聘效率）；Man Group 称它能“在几分钟而不是几天内产出几十个可行的想法” [[1]](#sources)。
2. “实现者”智能体借助 Man Group 的研究工具和自有数据库，把每个想法写成生产级 Python 代码，并运行回测 [[1]](#sources)[[2]](#sources)。
3. “评估者”智能体沿用与人工研究相同的门槛：统计显著性检验、风险评估和经济逻辑检查；内置的一致性检查会对比所述想法与实际代码，以发现偏离和 p-hacking [[1]](#sources)。
4. 工作流编排器协调这三个角色；日志系统记录每个假设、前提和决策，供事后审阅 [[1]](#sources)。
5. 🛑 **审阅**：技术团队对信号做代码审查，运行单元、集成和情景测试，并评估实现风险 [[1]](#sources)。
6. 🛑 **签发**：投资委员会按人工信号同一套框架审阅假设、经济逻辑和研究结果；只有获批的信号才进入实盘交易 [[1]](#sources)[[3]](#sources)。

**产出：** 一个获批上线交易的信号，附带代码、回测和决策日志；它与人工研究的信号一样并入系统化组合。
**失败模式 → 防护：** 想法数量大导致多重检验 / p-hacking → 沿用同样的研究方法门槛并持续监控；想法与代码偏离或幻觉 → 在想法、实现和评估之间做自动加人工的一致性检查；各自为政的本地技能导致回测不一致 → 共享的、由负责人审阅并经评测的技能库 [1][2]。
**与相近工作流的区别：** AWF-0166（挑战者智能体投委会备忘录）和 AWF-0023（事件驱动的模型更新）都是针对已有交易或模型，产出供人决策的文档；本工作流的交付物是全新的、已编码并回测的交易信号，上线交易前要过技术团队的代码审查和投资委员会签发两道关。替换测试在交付物和检查点上不通过。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Fourth collection pass](../../../../../research/2026-11-fourth-pass.md)。

- [Man Group, What AI Can (and Can't Yet) Do for Alpha](https://www.man.com/insights/what-ai-can-do-for-alpha) (2025-11-12)。公司自述的三智能体研究循环及双轨人工验证。"It has been observed to produce dozens of viable concepts within minutes rather than days.". *第一手：是；可信度：高。*
- [Hedgeweek / Bloomberg, Man Group deploys agentic AI for quant signal discovery](https://hedgeweek.com/news/man-group-deploys-agentic-ai-for-quant-signal-discovery) (2025-07-11)。资深基金经理称 AI 生成的信号经检查点后获批实盘。"AlphaGPT has already produced several dozen investment signals that have been approved for live trading". *第一手：访谈；可信度：高。*
- [Man Group, Building signals that trade themselves](https://www.youtube.com/watch?v=EOg4gY0Yln0) (2026-05-21)。由 AI 提出、回测并投入生产的信号现已交易真实资金；人工审阅全部产出。"we now have 750 of them using Claude Code". *第一手：是；可信度：中。*
