# 事件驱动的模型更新

**工具变体：** `claude-excel`（Claude for Excel 自 2025 年 10 月起公测 [[23]](#sources)） · `hebbia` · `alphasense` · `rogo`

## 背景

跟踪上市公司的分析师会为它建一个电子表格模型，建立在一组称为驱动项的假设之上。公司发布季度业绩、申报文件或财报电话会记录后，分析师要找出新数字，与模型以及市场预期对比，改掉不再成立的驱动项，再写一份简短的研究笔记。业绩集中发布的季节里，这件事靠手工很慢，而且一个数字出错（把月度数字当成季度数字、把小计当成总数），就可能流进客户据以行动的笔记。在这里，智能体提取每个数字并附上引用，更新模型的驱动项并给每处改动加批注，再起草笔记。分析师对照来源检查每一个改动的单元格，笔记在外发之前还要由机构的合规人员批准，因为公开发布的研究受到监管，分析师要对它负责。

**术语：**
- **一致预期（consensus）**：其他分析师对某个数字的预测平均值，用作市场预期。
- **业绩指引（guidance）**：公司自己对即将公布的业绩所作的预测。
- **KPI**：关键绩效指标，公司报告的经营性指标，例如同店销售额。
- **驱动项（driver）**：模型中的输入假设，例如增长率或利润率，其他数字都由它算出。
- **财报、申报文件、电话会记录**：公司的业绩公告、向监管机构提交的正式报告，以及管理层讨论业绩的电话会的文字记录。
- **研究笔记**：分析师发给客户的简短更新。
- **合规**：负责检查笔记是否符合机构和监管机构规定、然后才能分发的人员。
- **业务分部、口径、GAAP 与调整后**：分部是单独报告的一块业务；口径是数字的加总方式（合并，或按持股比例）；GAAP 数字遵循正式会计准则，调整后数字则剔除公司自行选定的项目。
- **REIT**：持有物业、并把大部分收入分给股东的公司。
- **Extended Thinking**：让模型在回答之前思考更久的一种设置。

## 用智能体搭建

**形态：** `skill`。一位分析师一次处理一家公司的一个事件，并且全程在对话中，所以一个装有流程和行业规则的 skill 就够了。

**需要：** 对一致预期和业绩指引数据的读取权限（连接到数据供应商的连接器，或导出的文件）；文字形式的财报、申报文件或电话会记录；Excel 文件形式的模型，以及修改单元格并添加单元格批注的手段，例如处理电子表格的 skill 或放在 skill 旁边的脚本；放在 skill 旁边的、作为参考文件的行业 KPI 清单和消歧规则；机构的笔记模板。不要接入发布或邮件工具。

| 步骤 | 搭建方式 |
|---|---|
| 加载一致预期和指引 | 连接到机构数据供应商的连接器（MCP 服务器），或分析师放进来的文件；skill 先读取它们。 |
| 新的财报、申报文件或电话会记录 | 由分析师把文件交给 skill，由 skill 读取。 |
| 每个 KPI：带引用提取 | KPI 多时，由内置子智能体各负责一组 KPI，返回一张表：KPI、数值、引用的来源原文。行业规则文件规定用哪个业务分部、期间和口径。 |
| 与模型对比 | 在主对话中，把每个实际值和任何业绩指引变化与模型及一致预期对比，列出差异。 |
| 更新 Excel 驱动项并加单元格批注 | 由脚本或电子表格 skill 把新数值写进模型的副本，绝不改原件，每个改动的驱动项配一条批注，写明来源和原因。 |
| 电话会主题 → 笔记 | skill 从记录中提炼主题，并填入机构的笔记模板。 |
| 🛑 review → 🛑 sign-off (合规) → 发布 | 见“检查点”。 |

**检查点：** `review`：skill 最后列出每个改动的单元格和每个被引用的 KPI 及其来源原文，先列各次提取结果不一致的数值，然后停下；由分析师对照来源文件检查。`sign-off`：合规在智能体之外批准笔记，智能体没有发布或邮件工具，所以由人来分发笔记。

**与来源相比：** 来源出自 2025-07 至 2026-06；Claude 文档中关于金融服务插件的页面未注明日期。VentureBeat 的文章无法打开，所以它所报道的内容取自条目本身的文字和 Anthropic 2025-10-27 的官方公告；公告确实介绍了当时处于公测研究预览阶段的 Claude for Excel 会跟踪并解释自己的改动。同一篇文档页面现在列出了一套开源的金融服务插件，提供数据连接器和 `/earnings` 命令，所以 skill 不必从零写起。唯一的公开实例是一项针对 60 份财报的 KPI 提取基准测试，不是模型更新，所以没有来源展示整个流程被跑通。笔记和签发这两步没有引用来源。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 在事件发生前，智能体通过数据连接器加载一致预期和业绩指引：LSEG 分析师预测、S&P Capital IQ、Daloopa、FactSet，以及 financial-analysis 插件中的其他来源 [[23]](#sources) [[25]](#sources)。
2. 财报、申报文件或电话会记录发布后，智能体将其拉取进来；Aiera 提供实时的财报电话会记录 [[23]](#sources)。
3. 对每个 KPI，智能体使用带提取规则的行业分类体系提取数值并附上来源文档的引用。团队编写适用于整个行业的消歧规则，涵盖业务分部、期间（月度还是季度）、口径（合并还是按比例）、监管框架，以及 GAAP 还是调整后口径 [[24]](#sources)。
4. 智能体把每个实际值和任何业绩指引变化与模型及一致预期对比；earnings-analysis 技能涵盖“metrics, guidance changes” [[23]](#sources)。
5. 智能体直接在原 Excel 中更新驱动项。Claude for Excel 会保留公式依赖关系，“tracks and explains its changes”，并链接到它引用的单元格 [[23]](#sources)。每个被改动的驱动项都加一条单元格批注，写明来源和原因。
6. 智能体从电话会记录中提炼主题并起草笔记；`/earnings [company] [quarter]` 可生成财报后更新报告 [[25]](#sources)。
7. 🛑 **审阅**：分析师对照来源检查每个改动的单元格和每个被引用的 KPI。先看模型或规则结果不一致的数值，因为一致预期只是确定优先级的信号，不是证据 [[24]](#sources)。即使提取准确率达到 99.3%，原始的模型输出也不应直接发布 [[24]](#sources)，AI 生成的分析“should always be reviewed by a qualified professional” [[25]](#sources)。
8. 🛑 **签发（合规）**：合规部门在分发前批准笔记。
9. 发布笔记并保存更新后的模型。

**产出：** 一份更新后的模型，每个改动的驱动项都带有来源和原因；以及一份研究笔记，经合规签发后即可分发。
**失败模式 → 防护：** 多业务分部公司选错分部、把月度数字当成季度数字、REIT 取到小计或用错口径、银行比率套用错误的监管框架 → 全行业统一的消歧规则和 Extended Thinking [[24]](#sources)。部分行业（保险、工业、REIT、零售）准确率较低 → 在这些行业加强复核 [[24]](#sources)。悄悄的改动破坏模型 → 变更跟踪以及到引用单元格的链接 [[23]](#sources)。
