# 全量控制测试

**工具变体：** `kaption` · `kpmg-clara`

## 背景

公司有内部控制：嵌在业务流程里的检查，用来发现财务数字里的差错和舞弊，例如“超过一定金额的付款必须有第二个人批准”。内部审计师，以及对账目出具意见的外部审计师，要测试每个控制是否真的起了作用。由于不可能测试每一个实例，他们只测一个样本，并假定其余的与样本一致。每一次测试还意味着索要文件、阅读文件、写出结果。在这里，智能体为每个控制收集证据，对全部样本而不是抽样来测试，并为每项结论引用其依据的来源文件。每一项结论和每一个例外仍由审计师复核，因为审计意见由审计师签署，职业责任也由审计师承担。

**术语：**
- **控制**：流程中防止或发现差错和舞弊的一个环节。
- **ICFR（财务报告内部控制）**：围绕财务报表如何编制而设的一整套控制。管理层必须对其做出评估。
- **全量与抽样**：一个控制所适用的全部实例，与挑出来测试的少数几个。全量测试检查每一个实例。
- **底稿**：审计师针对一项测试建立的档案：测了什么、证据、结论和例外。
- **例外**：控制没有起作用，或证据不支持它的实例。
- **凭证核对（vouching）**：把已入账的项目（如一笔费用）与证明它的文件对照检查。
- **未入账负债**：公司欠下、却没有记进账簿的债务。审计师要去查找。
- **实质性程序**：针对数字本身的审计测试，区别于对控制的测试。
- **漏报**：测试把控制失效报告为通过。
- **四大**：规模最大的四家会计师事务所。
- **KPI**：事先约定的目标指标。这里指测试必须达到的约定标准。

## 用智能体搭建

**形态：** `project`。一个 skill 可以描述单个控制的测试，但这项工作要在两个检查点之间对几十到几百个控制并行展开，每个工作单元应在看不到其他单元的情况下返回证据和带引用的结论，而且有一条规则必须每次都成立：没有引用就不得下结论，客户的证据只读不改。这些需要自定义子智能体和钩子。

**需要：** 一份待测控制的清单，每项写明说明、测试步骤和什么算通过；通过 MCP 连接器或导出文件，对证据（总账导出、审批日志、文件）的读取权限；一份 `CLAUDE.md`，写明底稿格式和“每项结论都引用来源”的规则；底稿的存放位置。只使用事务所或客户批准可处理保密客户数据的环境，并且不要给智能体对其所读系统的写权限。

| 步骤 | 搭建方式 |
|---|---|
| 配置控制项 + 证据格式 + 复核流程，约定 KPI → 🛑 plan | 一个 skill 为每个控制放一份参考文件，并带底稿模板。它把测试计划（控制项、每项的证据、KPI）写成文件，然后停下。 |
| 每个控制项：收集证据 → 处理数据 → 测试 | 每个控制一个自定义子智能体，只带只读工具，按参考文件里的测试步骤执行。控制很多时，用动态工作流为每个控制运行一个子智能体，并对结果交叉核对。 |
| 得出附来源引用的结论 | 每个子智能体返回结果、结论，以及每项证据所在的文件和位置。`Stop` 钩子或脚本会拒绝结论没有引用的底稿。 |
| 🛑 review | 见“检查点”。 |

**检查点：** `plan`：skill 写完测试计划就结束，在审计负责人把该文件标记为已批准之前，不启动工作单元。`review`：智能体没有定稿底稿或把它归入审计档案的工具；它只保存草稿，由审计师打开每个被引用的来源，接受或否定每项结论，并决定如何处理每个例外。

**与来源相比：** 来源出自 2025-04 至 2026，另有一个未注明日期。最新的来源 4（KPMG 的 2025 年审计质量报告，2026）是一份 PDF，其文字在这里无法读取，所以没有拿它与本条目核对。来源 1 是一份厂商的试点案例；来源 2 和 3 是对 KPMG 平台的公告和访谈，步骤很少。这些来源描述的是厂商平台（`kaption`、`kpmg-clara`），它们有自己的证据连接器和审阅界面；上面的搭建方式使用通用的智能体工具和你自己的连接器，并不取代这些平台。来源 1 的试点数字是该厂商就其产品给出的，不适用于这套搭建方式。客户证据属于保密甚至受特权保护的材料，所以在连接任何东西之前，先与客户确定可以在哪里处理。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 审计团队按组织自身的控制项、证据格式和复核流程配置工具 [[1]](#sources)。
2. 🛑 **计划**：审计负责人在首次运行前约定好 KPI [[1]](#sources)。
3. 智能体收集证据、处理数据并测试每个控制项，每项结论都引用到其来源 [[1]](#sources)。在一家四大会计师事务所，智能体执行费用凭证核对、查找未入账负债等实质性程序 [[2]](#sources)。
4. 🛑 **审阅**：审计团队复核每项带引用的结论和例外 [[1]](#sources)。该事务所称自己保留了“人在回路中”（'a human-in-the-loop'）[[2]](#sources)。

**产出：** 已测试控制项的底稿，含带引用的结论和例外，经审计师复核，用于 ICFR 评估或审计档案。
**失败模式 → 防护：** 漏报（试点中低于 10%）→ 审计师复核，并在推广前约定 KPI [[1]](#sources)。

**与相近工作流的区别：** AWF-0005 告警富化与裁决（Alert enrich and adjudicate，SECOPS）裁决的是安全告警。本工作流则对照证据测试财务控制，并产出审计底稿。
**近期实践（2026）：**
- 计划环节：在 KPMG，审计师通过“选择合适的数据要素、组合最佳的方法步骤”来设置运行，之后由智能体挑出需要测试的费用、读取文档、提取日期和金额，并写出底稿（CFO.com 2025-05-16）。[[3]](#sources)

## 公开实例

覆盖度（截至 2026-11-06）：**部分**：有第一手实例，但只覆盖流程的一部分，或检查点设在别处。收集与复核见 [New workflows for empty categories](../../../../../research/2026-11-new-workflows.md)。更多实例见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [Kaption, Celsa Group pilot](https://www.kaption.io/case-studies/celsa) (n.d.)。智能体测试了 60 个 ICFR 控制项，结论带引用，交内部审计复核。"Agent reasoning aligned with the auditors' own judgement in 85% of cases"。*第一手：厂商；可信度：中。*
- [KPMG, Clara AI agents](https://kpmg.com/us/en/media/news/kpmg-clara-smart-audit-platform.html) (2025-04-23)。全所范围的智能体用于凭证核对和未入账负债查找；工作流细节很少。"more than 95,000 auditors globally"。*第一手：是（公告，并非实测运行）；可信度：低。*
- [CFO.com, How KPMG is using AI to revamp their audit practice](https://www.cfo.com/news/how-kpmg-thomas-mackenzie-is-using-clara-ai-to-revamp-their-audit-practice-/748316/) (2025-05-16)。KPMG 审计负责人介绍了 Clara 费用验证智能体的步骤，以及审计师的引导和复核角色。"If we can do 100% testing, it's like placing a filter across the river."。*第一手：访谈；可信度：中。*
