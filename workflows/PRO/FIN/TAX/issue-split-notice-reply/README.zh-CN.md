# 按问题拆分的税务通知回复

**与相近工作流的区别：** AWF-0041 可审阅的 1040 准备：那是根据客户原始文件准备并提交申报表，带字段校验和二次审阅。本工作流的交付物是对税务机关通知的回复，逐个问题起草并附法律引用，由顾问一次性批准。交付物不同，检查点只有一个。
**工具变体：** `shorthills-copilot`

## 步骤

1. 把政府税务通知以 PDF 上传。LLM 识别税务机关提出的每个问题，并将其结构化，以便分别研究和起草 [[1]](#sources)。
2. 对每个问题：检索客户的申报资料、以往回复、内部的法律/法案/通告、判例和模板，使每个论点都有引用的证据支撑 [[1]](#sources)。
3. 按固定的 13 点模板起草回复，由模板组织论点和引用 [[1]](#sources)。
4. 🛑 **审阅**：顾问在发出前审阅、修改并批准草稿；所有操作都作为审计记录留痕 [[1]](#sources)。
5. 审阅人的反馈用于改进系统，使其跟上规则变化 [[1]](#sources)。

**产出：** 一份经批准的、给税务机关的回复，带客户记录和法律的引用，并附在项目的审计记录中归档。
**失败模式 → 防护：** 多问题通知且证据量大，容易漏掉一点 → 先拆分为问题，再按问题套用模板。法律会变 → 基于持续维护的内部知识库检索。引用错误 → 发送前由顾问批准。

## 公开实例

覆盖度（截至 2026-11-13）：**薄弱**：只有匿名、与厂商相关或记者转述的说法。收集与复核见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [Shorthills AI, Reply to Notice](https://www.shorthills.ai/replytonotice) (n.d.)。未具名的全球专业服务公司；逐问题起草，顾问批准。"cut first-draft creation to 10–15 minutes with ~90% initial accuracy"。*第一手：厂商；可信度：中。*
