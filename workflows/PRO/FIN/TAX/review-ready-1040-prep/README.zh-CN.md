# 可供复核的 1040 报税准备

**工具变体：** `juno` · `filed`

## 背景

会计师事务所每年都要为客户准备所得税申报表。1040 是美国的个人所得税申报表。经办人收集客户的原始资料（工资单、利息和投资报告、合伙企业报表），把数字录入报税软件，建立一份记录每个数字出处的底稿，再交给高级复核人检查、签字并报送。录入和交叉核对占去经办人的大部分时间，业务高峰时，读错的数字或漏掉的表单很容易被忽略。在这里，智能体读取文件，给每个字段打置信度分数，生成底稿，再重新审视申报表草稿，找出缺失的表单和与上年相比的大幅变化。置信度低的字段仍由人核验，每个标记项仍由人处理，由高级复核人签字并报送，因为注册会计师（CPA）或其他签字的经办人要对这份申报表承担法律责任。

**术语：**
- **W-2、1099、K-1**：美国的税表，分别报告工资（W-2）、利息或投资出售等其他收入（1099），以及合伙企业或 S 型公司收入中的个人份额（K-1）。
- **原始资料**：客户自己提供的、申报表据以编制的文件。
- **经办人 / 高级复核人**：准备申报表的工作人员，以及负责复核、签字并报送的更资深的人（通常是 CPA）。
- **底稿**：把申报表上每个数字与其原始文件对应起来的工作文件。
- **科目表映射**：对企业申报表，把客户账簿中的每个科目对应到申报表上相应的类别。
- **同比（YoY）**：与上年申报表上同一数字比较。
- **诊断检查**：报税软件自带的、检查错误和缺失数据的功能。
- **报税软件**：用来计算并电子报送申报表的专业程序。

## 用智能体搭建

**形态：** `project`。skill 可以完成提取和底稿，但二次复核必须由没有见过数据是怎么录入的审阅者来做，而且事务所自己的检查必须对每份申报表都执行，所以需要自定义子智能体和常设的项目文件。是否真的需要比 `skill` 更大的形态，取决于事务所对这两点的依赖程度。

**需要：** 文件形式的客户原始资料；上年的申报表；事务所自己的检查清单（各州的特殊规定、选择事项，以及每个季度都要看的其他项目），作为参考文件；如果报税软件接受导入文件，则需要能生成该文件或导出格式的手段；一套经事务所批准、可以处理纳税人身份号码和财务记录（均属保密）的环境。不要给智能体任何签字、报送或传输申报表的工具。

| 步骤 | 搭建方式 |
|---|---|
| 客户上传原始资料 | 客户使用事务所的门户；工作人员把文件放进这份申报表的文件夹。 |
| 提取字段并给出置信度 | skill 读取每份文件，写出一张表：字段、数值、来源页、置信度（高、中或低）及理由。 |
| 🛑 review (经办人核验低置信度字段和科目映射) | 见“检查点”。 |
| 生成底稿并导入报税软件 | skill 根据核验后的表生成底稿，每个数字一行并附来源。把数字载入报税软件取决于软件提供什么：智能体可以写入的导入文件或接口，否则由经办人根据底稿录入。 |
| AI 二次复核（缺失表单、同比、事务所自定检查） | 一个自定义的只读子智能体，接收申报表草稿、上年申报表和事务所的检查清单，返回一份标出各项的复核计划。`PreToolUse` 钩子可以阻止它修改它所读取的文件。 |
| 🛑 review (经办人处理标记项) | 见“检查点”。 |
| 🛑 sign-off (高级复核人签字并报送) | 见“检查点”。 |

**检查点：** `review`（字段）：skill 在提取表之后停下，先列出置信度低的字段；经办人对照来源页核对，并确认映射。`review`（标记项）：复核计划以清单形式给出，经办人逐项处理之后，申报表才继续往下走。`sign-off`：智能体没有报送或传输申报表的工具，并且有一条权限规则拒绝任何会这样做的命令，所以由高级复核人在报税软件里签字并报送。

**与来源相比：** 来源出自 2026 年至 2026-03。两者都是厂商的说法：一篇是 Juno 创始人介绍自己的产品，一篇是 Filed 发布的案例。两者都没有展示这些步骤在内部是怎样搭建的，而且都依赖能读取文件并连接指名的报税程序的产品。通用智能体可以完成读取、底稿和二次复核；把数据载入报税软件则取决于各个程序提供什么，本条目没有核实。来源中有关准确率和节省时间的数字，并不是对这套搭建方式的说法。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 客户把 W-2、1099、K-1 和券商对账单上传到事务所的门户 [[1]](#sources)。
2. AI 提取字段，并为每个字段给出置信度分数 [[1]](#sources)。
3. 🛑 **审阅**：经办人对照源 PDF 核对提取的值，先看低置信度字段。对于企业申报表，经办人还要确认科目表映射 [[1]](#sources)。
4. 系统生成底稿，并把数据导入报税软件。数据录入和诊断检查由 AI 完成 [[1]](#sources)[[2]](#sources)。
5. 申报表草稿回到 AI 复核环节，由它把缺失表单、同比波动和事务所自定检查标记出来，形成复核计划 [[1]](#sources)。
6. 🛑 **审阅**：经办人逐项处理并解决这些标记项 [[1]](#sources)。
7. 🛑 **签发**：高级复核人或 CPA 全面复核、修正、签字并报送 [[1]](#sources)[[2]](#sources)。

**产出：** 一份经 CPA 签字并电子报送的申报表，附有证据可追溯的底稿和已处理完毕的复核清单。
**失败模式 → 防护：** 源字段读错 → 置信度分数加人工核验 [[1]](#sources)。漏掉表单 → 与上年对比检查 [[1]](#sources)。把 AI 当作初级经办人看待：所有内容都要复核 [[2]](#sources)。
**与相近工作流的区别：** AWF-0022 发票提取—匹配—路由（Invoice extract-match-route，AP）提取发票用于付款。本工作流准备的是受监管的申报文件，需要经办人和注册会计师（CPA）签字。
