# 先评后改的基金申请书

**工具变体：** `claude`

## 背景

基金申请书是向资助方申请经费、开展一个研究项目的文件。由首席研究员（PI，即领导实验室的科学家）撰写；资助方做决定之前，由一组其他科学家阅读并打分。写出第一稿要花数周时间，而这些时间本可以用来做研究；而且会使申请书落选的弱点，例如某个研究目标没有早期证据支撑，或某篇被引用的论文实际上支持的是对立的解释，作者自己很容易漏掉。在这里，智能体把实验室自己的材料整理成草稿，扮演评审组，列出最严重的顾虑但不改写任何内容，然后只做 PI 接受的修改，并核查引文。哪些顾虑成立由 PI 决定，也只有 PI 能为科学内容担保，申请书是以 PI 的名义提交的。

**术语：**
- **PI（principal investigator，首席研究员）**：领导实验室的科学家，对申请书和研究负责。
- **NIH**：美国国立卫生研究院，生物医学研究的大型资助方。
- **研究目标（aim）**：申请书承诺要开展的研究目标之一。
- **初步证据**：实验室已有的早期结果，说明某个目标可行。
- **评审组（study section）**：为资助方审阅并给申请书打分的科学家小组。
- **PubMed**：生物医学论文的公开索引，用来核查每篇被引论文确实存在，并且说的与申请书所称一致。
- **修改日志**：列出每一处修改以及它回应的顾虑。

## 用智能体搭建

**形态：** `skill`。一位 PI 一次处理一份申请书，并在对话中对每条顾虑做决定，所以一个装有流程的 skill 就够了。

**需要：** 实验室的论文、研究问题、前期工作和资助方对申请书的指南，都以文件形式提供；能在 PubMed 中查到每篇被引论文的办法（连接器或脚本）；一套经所在机构批准、可处理未发表数据和尚未获得资助的想法的环境。智能体不持有任何提交账号。

| 步骤 | 搭建方式 |
|---|---|
| PI 提供论文、研究目标、前期工作 → 起草 v1 | skill 读取这些文件，按资助方的章节格式写出 `draft-v1.md`。 |
| 模拟评审组的评议（不改写） | 一个只看草稿和指南的评审子智能体，返回最关键的顾虑，每条标明涉及哪个研究目标。skill 禁止在这一步改写。 |
| 🛑 review (PI 逐条接受或驳回) | 见“检查点”。 |
| 整合获批的修改 + 修改日志 | skill 在草稿的副本上修改，只改标为接受的顾虑，并把每处修改及其对应顾虑追加到 `changes.md`。 |
| 引文核查 | skill 在 PubMed 中查每条引文，列出摘要不支持所附句子的引文。 |
| (评议 ⟲ 修订) | 评议和修订重复进行，新出现的顾虑由 PI 再次决定。 |
| 🛑 sign-off (PI 科学性审计) | 见“检查点”。 |

**检查点：** `review`：skill 把顾虑写成带编号的清单，每条留出接受或驳回的位置，然后停下；PI 没有标为接受的内容，它一概不整合。`sign-off`：skill 以草稿、修改日志和引文报告收尾，然后停下；由 PI 编辑并审计，再通过所在机构提交，因为智能体没有提交工具。

**与来源相比：** 唯一的来源出自 2026-10。它是一家办研究员项目的公司发布的案例，讲的是一位研究者用 Claude 起草并审计一份申请书。它描述的是研究者在对话中与模型协作，不是智能体来运转这些步骤，所以这套搭建方式是把同一个循环设计成可重复使用的流程。来源提到这位研究者打算把这套做法打包成可复用的 skill。它还报告说，研究者之后又花了许多小时做人工编辑和审计，这是搭建方式替代不了的。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. PI 把实验室的论文、研究问题、前期工作和历史资料交给模型，模型将其整理成 v1 草稿 [[1]](#sources)。
2. 模型只指出最关键的评审顾虑，不做任何改写，例如某个研究目标缺少初步证据 [[1]](#sources)。
3. 🛑 **审阅**：PI 逐条接受或驳回这些顾虑。模型只整合获批的修改，并记录修改日志 [[1]](#sources)。
4. 模型运行模拟评审组和 PubMed 引文核查，找出结构性缺口和引用不当的支撑文献 [[1]](#sources)。
5. 🛑 **签发**：PI 做人工编辑和科学性审计，得到引文经过核实、可以提交的版本 [[1]](#sources)。

**产出：** 一份经 PI 审计、符合指南要求、引文已核实的申请书草稿，可供机构提交。
**失败模式 → 防护：** 引用的论文实际支持的是竞争性机制 → 对照 PubMed 做引文核查 [[1]](#sources)。有力的结果被埋在补充材料里 → 由模拟评审把它们挖出来 [[1]](#sources)。
**与相近工作流的区别：** AWF-0010 审稿意见回复修订（Reviewer-response revision，WRITE）是在收到真实评审意见后修订稿件。本工作流在提交前，对照模拟评审人起草一份新的申请书。

## 公开实例

覆盖度（截至 2026-11-06）：**薄弱**：只有匿名、与厂商相关或由记者转述的说法。收集与复核见 [New workflows for empty categories](../../../../../research/2026-11-new-workflows.md)。

- [Reactorfield, Northwell's Brian Kim NIH grant](https://reactorfield.com/blog/northwell-health) (2026-10-20)。有名有姓的研究者用先评后改的循环起草并审计了一份 14 页的 NIH 申请书。"One hour of active work produced 12 pages."。*第一手：厂商；可信度：中。*
