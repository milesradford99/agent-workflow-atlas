# 先评后改的基金申请书

**与相近工作流的区别：** AWF-0010 审稿意见回复修订（Reviewer-response revision，WRITE）是在收到真实评审意见后修订稿件。本工作流在提交前，对照模拟评审人起草一份新的申请书。
**工具变体：** `claude`

## 步骤

1. PI 把实验室的论文、研究问题、前期工作和历史资料交给模型，模型将其整理成 v1 草稿 [[1]](#sources)。
2. 模型只指出最关键的评审顾虑，不做任何改写，例如某个研究目标缺少初步证据 [[1]](#sources)。
3. 🛑 **审阅**：PI 逐条接受或驳回这些顾虑。模型只整合获批的修改，并记录修改日志 [[1]](#sources)。
4. 模拟评审组和 PubMed 引文核查，找出结构性缺口和引用不当的支撑文献 [[1]](#sources)。
5. 🛑 **签发**：PI 做人工编辑和科学性审计，得到引文经过核实、可以提交的版本 [[1]](#sources)。

**产出：** 一份经 PI 审计、符合指南要求、引文已核实的申请书草稿，可供机构提交。
**失败模式 → 防护：** 引用的论文实际支持的是竞争性机制 → 对照 PubMed 做引文核查 [[1]](#sources)。有力的结果被埋在补充材料里 → 由模拟评审把它们挖出来 [[1]](#sources)。

## 公开实例

覆盖度（截至 2026-11-06）：**薄弱**：只有匿名、与厂商相关或由记者转述的说法。收集与复核见 [New workflows for empty categories](../../../../../research/2026-11-new-workflows.md)。

- [Reactorfield, Northwell's Brian Kim NIH grant](https://reactorfield.com/blog/northwell-health) (2026-10-20)。有名有姓的研究者用先评后改的循环起草并审计了一份 14 页的 NIH 申请书。"One hour of active work produced 12 pages."。*第一手：厂商；可信度：中。*
