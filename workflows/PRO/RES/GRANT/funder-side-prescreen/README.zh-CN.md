# 资助方一侧的申请预筛选

**工具变体：** `biolinkbert-bioelectra-ensemble`

## 背景

资助科研的基金会会发布项目征集，每份通过初步检查的申请书都要由专家同行评审阅读并打分，而评审人的时间有限。在这一步之前，工作人员可以剔除明显尚未成熟的申请，但为此通读几百份完整的申请书很慢，而一次误剔会让一个好项目永远被挡在这次征集之外。在这里，三个语言模型分类器用基金会自己往年的申请书及其同行评审分数训练，各自独立判断一份新申请是否属于得分最低的类别。只有三个模型都把它判入该类别，申请才会被标记，然后由两名人工资格审查员审看。剔除决定必须由人来做，因为它影响申请人获得资助的机会，资助方也必须能说明理由；审查员只要有合理疑问，就会把申请放回。

**术语：**
- **同行评审**：由领域内独立的专家评估一份申请书并给出分数。
- **分类器**：训练出来的模型，把每个输入归入固定的几个类别之一，这里是分数类别。
- **末位类别**：往年申请中得分最低的那一组；被判入此类，说明它与同行评审评分最低的那些申请相似。
- **资格审查员**：基金会的工作人员，决定一份被标记的申请是否在同行评审之前剔除。
- **放回（rescue）**：把被标记的申请退回正常的同行评审。
- **隐藏的平行试验**：在一次征集中运行这个筛选但不据此行动，以便把它的标记与实际结果对照。
- **NLP**：自然语言处理，让计算机读文本的方法。

## 用智能体搭建

**形态：** `platform`。三个分类器是训练出来的模型，每年用基金会自己的申请书和分数重新拟合，通用智能体替代不了。围绕它们的所有工作，通用智能体可以按 `service` 的形态来做。

**需要：** 训练好的分类器，以及基金会往年的申请书和同行评审分数，放在智能体只能运行评分脚本、别无他用的地方；以文件形式提供的新申请书；一个审查队列，两名指定的工作人员对每份被标记的申请各自记录一个决定；一份记录哪些申请被剔除、哪些被放回的清单。申请书是保密的：只用所在机构批准处理它们的环境，不要发送给任何外部服务。

| 步骤 | 搭建方式 |
|---|---|
| 每年用往年申请 + 评审分数重新训练 3 个模型 | 平台：用基金会的数据训练模型，在智能体之外运行。智能体可以运行训练脚本并记录输出。 |
| 每份申请：3 个独立分类器 | 平台：一个评分脚本，让每份申请分别经过三个模型，为每份申请把三个类别标签写入一个文件。 |
| 三者都判末位类别：标记 \| 否则：同行评审 | 由一个 skill 或它调用的脚本比较三个标签。只有三个都判末位类别才标记；其余都写入同行评审清单。 |
| 🛑 review (每份被标记的申请由 2 名资格审查员审查；有合理疑问即放回) | 见“检查点”。 |
| 确认：剔除 \| 放回：同行评审 | 由人记录每个结果。被放回的申请加入同行评审清单，确认剔除的进入可审计的清单。 |

**检查点：** `review`：每份被标记的申请连同三个标签和申请书正文进入审查队列，两名审查员各自记录“维持标记”或“放回”。运行可以排成云端定时任务或 `claude -p` 任务，在发出队列后结束；下一次运行读取已记录的决定。智能体没有任何把申请从流程中剔除或通知申请人的工具；两名审查员都答复之后才记录结果，任何疑问都算放回。

**与来源相比：** 唯一的来源出自 2024-10，报告的是首个正式运行的征集 HR23。更新的报道显示这种做法争议很大。2026-09，[Times Higher Education](https://www.timeshighereducation.com/news/grant-proposals-rejected-ai-triage-be-reassessed) 报道，英国一个网络安全研究网络 CRANE 对 179 份申请做了 AI 分诊，导致近一半申请在无人阅读的情况下被拒，该网络在被批评不够透明之后承诺重新评审全部申请。2026-11 的搜索还找到一份 2025 年的会议摘要和一份 2026-02 的预印本，都是关于自动化申请筛选的，未打开阅读。这套搭建方式沿用来源的设计，即每一次剔除都由人确认；是否向申请人说明这一步，由资助方决定。可以让通用智能体自己给申请书打分，但来源没有报告这样做，所以这套搭建方式不提议这样做。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 基金会每年用往年申请书的全文及其同行评审分数类别作为标签，重新训练三个生物医学 NLP 分类器（BioLinkBERT、BioELECTRA、BioLinkBERT+Adapter） [[1]](#sources)。
2. 系统让每份新申请书分别经过这三个模型。只有三个模型都把它判入末位类别时才会被标记 [[1]](#sources)。
3. 系统把未被标记的申请送入正常的同行评审 [[1]](#sources)。
4. 🛑 **审阅**：两名人工资格审查员检查每份被标记的申请。只要其中一人有合理疑问，该申请就被放回，重新进入同行评审 [[1]](#sources)。
5. 确认剔除的申请退出流程。第一年以隐藏的平行试验（HR22）运行，随后在 HR23 正式上线 [[1]](#sources)。

**产出：** 缩小后的申请池送交专家同行评审，并附一份可审计的清单，列明由 AI 标记、人工确认的剔除项。
**失败模式 → 防护：** 漏判会让好的科研被永久排除：在 HR22 试验中，有两份被误标记的申请在传统通道中获得了资助 → 要求三个模型一致，有疑问时由两名审查员放回，并在上线前做隐藏的平行试验 [[1]](#sources)。
**与相近工作流的区别：** 最接近的是 AWF-0045 先批评后成稿的基金申请（GRANT），它帮助申请人 PI 撰写申请书。本工作流运行在资助方一侧，对收到的申请做分诊。自主程度为抽检：人只审查被标记的那部分。产出、操作方和检查点都不同。
