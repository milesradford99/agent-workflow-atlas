# 分步把关的复现实验

**工具变体：** `claude-code` · `llm-orchestrator-versioned-rules`

## 背景

研究论文会报告一些数字，通常放在回归表里：估计值（系数），说明某个被测量的量与另一个量的关联有多强。许多期刊现在要求作者提交复现包，也就是产生这些数字的数据和代码。复现一篇论文，就是重建代码所需的软件环境、运行代码，并核对它输出的估计值是否与论文一致。靠人工做既慢又脆弱，因为每个复现包的搭建方式都不同，而且运行没报错也可能得出不同的数字。智能体获取复现包、运行它、把输出与报告的估计值比对，并在有限次数内尝试修复。研究者仍要确定什么算目标、批准计划，并判断每一处差异，因为只有研究者能说清：不一致是代码问题、数据受限，还是论文本身有缺陷。

**术语：**
- **复现包（replication package）**：作者提交的数据、代码和说明文档，供他人重现论文结果。
- **估计值 / 系数**：统计模型给出的数字，例如一个变量对另一个变量的影响，即论文表格里印出的数。
- **可复现**：用提交的代码跑提交的数据，得到论文报告的数字。
- **IV 诊断**：对工具变量（IV）模型的标准检验；工具变量是一种在直接比较会产生误导时估计因果效应的方法。论文的代码和数据跑通之后即可进行这些检验。
- **受版本控制的代码**：保存在 git 之类系统中的脚本，系统记录每次改动，所以每个数字都能追溯到产生它的代码。
- **LLM 编排器**：由语言模型分派任务、并在失败后挑选下一步尝试，而计算由普通代码完成。

## 用智能体搭建

**形态：** `skill`。一位研究者一次复现一篇论文，并且全程在对话中批准计划、查看差异，所以一个装有流程的 skill 就够了。

**需要：** 一份目标文件，列出每个模型以及论文报告的估计值，并注明论文印出的小数位数；复现包，已下载或可通过网址获取；一个隔离的环境（容器或单独的机器），装有代码所需的语言和软件包，因为智能体要运行不是它自己写的代码；一个智能体可以写入的文件夹。数据受限时，由研究者在环境内提供，不要发送给任何外部服务。

| 步骤 | 搭建方式 |
|---|---|
| 研究者指定目标 → 🛑 plan | skill 先索取目标文件，然后写出 `plan.md`（复现包位置、如何重建环境、要运行哪些模型）并停下。 |
| 获取复现包 → 重建环境 → 执行代码 | 在隔离环境里执行 shell 命令；研究者批准计划之前，用权限规则让每条命令都先询问。skill 把每条命令记入运行日志。 |
| 提取系数 → 与论文比对 | skill 旁边的脚本把每个系数按论文的精度取整，并与目标文件比较，所以匹配结果由代码算出，而不是由智能体判断。 |
| (有限修复 ⟲ 重新验证) | 主对话以 diff 的形式提出修复，应用到复现包的副本上，再重新运行脚本。skill 写明最多尝试的次数。用 `PreToolUse` 钩子拦住对目标文件的修改。 |
| 给出结论 | 脚本的输出写进报告：每个模型分为相符、不相符或无法运行，数据缺失或受限的记为不可复现。 |
| 🛑 review (研究者检查进展和差异) | 见“检查点”。 |

**检查点：** `plan`：skill 写出计划文件后停下，直到研究者批准；也可以用计划模式，因为它不能运行或编辑任何东西。`review`：skill 以报告收尾，列出每个不相符的模型、试过什么以及记录下的命令，然后停下，由研究者引导或接受。研究者之后可以批准把从失败中总结的规则加入 skill 的参考文件；不会自动添加任何内容。

**与来源相比：** 来源出自 2026-03 至 2026-07。来源 1 用固定的流水线处理数百篇论文，并用带版本的规则保留以往运行的经验。这套搭建方式一次只处理一篇论文，规则文件只由研究者修改；要在两个检查点之间处理许多篇论文，需要用 dynamic workflow。来源 2 描述的是基于 Claude Code 构建的智能体，用子智能体负责生成代码、测试和质量检查，skill 也可以这样用。这套搭建方式不包含来源中的规模，也不包含它们的评估。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 🛑 **计划**：研究者指定实证目标，即模型设定和要复现的报告量 [[1]](#sources)。
2. 由 LLM 编排器（负责分派任务并挑选恢复步骤的语言模型）指挥运行。所有数值计算都以受版本控制的代码运行 [[1]](#sources)。
3. 智能体获取复现包，重建计算环境，并运行代码 [[1]](#sources)。
4. 智能体随后在单独设卡的阶段做验证：把代码得出的系数按论文的精度取整，与报告值匹配，并给出结论。失败的进入有限次数的修复循环 [[1]](#sources)。
5. 🛑 **审阅**：在既定检查点，研究者审阅进展、给出反馈并引导分析，同时由子智能体生成、测试代码并做质量检查 [[2]](#sources)。
6. 系统把反复出现的失败模式编码为带版本的规则，供下一次运行使用 [[1]](#sources)。

**产出：** 每篇论文一份可复现性结论，含匹配的估计值和审计轨迹。它可以支撑系统性的再分析，例如工具变量（IV）诊断。
**失败模式 → 防护：** 代码跑通不等于复现了结果 → 设置单独的、有关卡的验证阶段 [[1]](#sources)。数据缺失或受限 → 记为不可复现，而不是代码失败 [[1]](#sources)。
**与相近工作流的区别：** AWF-0006 受管控的查询（Governed query，ANALYTICS）回答业务数据问题。AWF-0009 筛选文献。本工作流重新执行已发表的分析，并对照论文报告的数字进行验证。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [New workflows for empty categories](../../../../../research/2026-11-new-workflows.md)。

- [Xu & Yang, Scaling Reproducibility](https://arxiv.org/html/2602.16733v2) (2026-03-24)。该工作流复现了 384 篇政治学论文中的 3,382 个模型。"94.4% of papers are fully reproducible (237/251)"。*第一手：是；可信度：高。*
- [Birk et al., SHARP](https://arxiv.org/html/2604.18752) (2026-07-01)。人与智能体分段把关，复现一项粒子物理喷注分类。"within 0.1 percentage points in accuracy"。*第一手：是；可信度：中。*
