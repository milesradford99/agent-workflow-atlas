# 实验室闭环发现

**与相近工作流的区别：** AWF-0044 受控复现运行是重新执行已有论文的代码，以验证其报告的估计值。本工作流中智能体分析的是人在各轮之间产生的新实验数据，并选择下一个实验。交付物不同，且带有反复出现的湿实验接手检查点。（也比 AWF-0104 假设锦标赛更接近：后者止步于提出供实验室验证的方案，不分析返回的数据。）
**工具变体：** `futurehouse-robin`

## 步骤

1. 给系统指定一种疾病。文献检索代理（Crow 负责简明摘要，Falcon 负责深度摘要，均基于 PaperQA2）生成问题，识别候选机制和体外检测方法，并提出具体的候选药物。Claude 3.7 Sonnet 以锦标赛方式对候选药物排序 [[1]](#sources)[[3]](#sources)。
2. 🛑 **接手**：人类科学家审阅清单，并对排名靠前的候选药物做实物实验。第一轮他们测试了十个分子 [[2]](#sources)[[3]](#sources)。
3. 上传原始或半加工的数据（.FCS 流式细胞文件、RNA-seq 基因计数），并提示分析类型。数据分析代理（Finch）运行八条独立轨迹，每条都在 Jupyter notebook 中执行代码。随后由元分析把它们合并成共识结论 [[1]](#sources)。
4. 用结果生成下一批假设和实验：先是 RNA-seq 机制研究，再是第二轮十个候选药物。循环一直持续「直到有人认为某个候选药物令人满意」 [[2]](#sources)[[3]](#sources)。
5. 🛑 **审阅**：人用自己的分析核对关键结果（Finch 报告 ripasudil 提高 1.89 倍；人工分析为 1.75 倍），并做剂量反应和原代细胞验证 [[1]](#sources)。
6. Robin 产出了全部假设、实验选择、分析和正文图表。物理实验由人完成，解释的责任也由人承担 [[2]](#sources)[[4]](#sources)。

**产出：** 经临床前验证的治疗候选药物及机制假设，写成论文（发表于 Nature），以智能体的 notebook 作为分析记录。
**失败模式 → 防护：** 每次运行的分析结果不同（门控选择、RNA-seq 过滤、LLM 随机性） → 八条并行轨迹加共识元分析 [1]。体外命中是假阳性 → 人工重新分析、剂量反应和重复实验；结果仍停留在临床前阶段 [4]。
