# 实验室闭环发现

**工具变体：** `futurehouse-robin`

## 背景

为一种疾病找到治疗思路，要先读海量文献，推测涉及哪种生物机制，再选定一项实验室检测（检测方法）和要尝试的候选药物。接着科学家做实验、分析测量结果，并决定下一步测什么。靠人工做，读文献没有尽头，分析又会随分析者的选择而变。在这里，智能体读文献、提出假设和候选药物并排序、分析实验返回的数据，并建议下一轮。物理实验仍然全部由科学家来做，因为只有实验才能产生证据；关键结果也要由科学家用自己的分析核对，因为数据意味着什么，要由人来负责。得到的是一个临床前假设，不是一种治疗方法。

**术语：**
- **湿实验**：用设备对细胞或样本动手做的实验，与电脑上的分析相对。
- **检测方法（体外）**：在培养皿里的细胞上做的实验室检测，用来测量候选分子的某一种效果。
- **锦标赛**：把候选对象两两比较来排序，每一对由语言模型评判。
- **流式细胞术（.FCS 文件）和 RNA-seq**：两种实验室测量。前者对单个细胞计数并刻画特征；后者统计每个基因的活跃程度。
- **notebook**：把代码、输出和笔记放在一起的文档，每次分析都可以重读、重跑。
- **轨迹与元分析**：分析智能体的一次独立运行，以及把多次运行合并成一个结论的步骤。
- **临床前**：已在细胞或动物身上测试，但尚未在人身上测试。
- **剂量反应与原代细胞**：检验效果是否随药量增加而增强，以及在直接取自组织的细胞（而不是实验室细胞系）上检验。
- **dAMD**：干性年龄相关性黄斑变性，一种导致视力丧失的眼病。

## 用智能体搭建

**形态：** `project`。流程可以由 skill 承载，但分析需要自定义的并行工作者（八条独立轨迹），还有一条必须每次都成立的规则（原始数据绝不修改），而且循环的状态要跨轮保存，每一轮的长短取决于实验。

**需要：** 一个项目文件夹，里面有疾病简介、假设文件、存放每轮上传数据的 `data/raw/`，以及每轮一个放 notebook 的文件夹；文献检索连接器或其他阅读论文的途径；用于分析的 notebook 或 Python 环境；一份 `CLAUDE.md`，写明各文件的作用，并写明智能体绝不写入 `data/raw/`。智能体不需要接触实验室设备或订购系统，实验由科学家负责。

| 步骤 | 搭建方式 |
|---|---|
| 科学家指定疾病 | 科学家把简介写进项目文件夹。 |
| 文献代理提出机制 + 检测方法 + 排序的候选分子（锦标赛） | skill 并行运行文献子智能体，每个问题一个，各自返回带引用的机制、检测方法和候选分子。另一个子智能体把候选分子两两比较，写出 `ranking.md`。 |
| 🛑 handoff (科学家做湿实验) | 见“检查点”。 |
| 上传原始数据 + 指明分析类型 | 科学家把文件放进 `data/raw/`，并向 skill 说明分析类型。 |
| 每个轨迹（共 8 条）：分析代理运行 notebook | 一个自定义子智能体的八个副本，各有自己的 notebook，看不到其他副本的工作。用 `PreToolUse` 钩子拦住对 `data/raw/` 的任何写入。 |
| 元分析得出共识 | 主对话读取八份 notebook，列表对比一致和不一致之处，并写出一个结论。 |
| 更新假设 + 下一个实验 → (🛑 handoff ⟲ 分析) | skill 更新假设文件并提出下一轮，然后再次停下。 |
| 🛑 review (人工重新分析 + 验证) → 论文图表 | 科学家用自己的工具重新分析并验证。skill 可以根据验证过的表格起草绘图代码。 |

**检查点：** `handoff`：排序完成后以及每轮分析结束后，skill 说明要做哪个实验、需要哪些读数，然后停下。科学家补充数据后再继续。`review`：skill 把共识与每条轨迹的关键结果及分歧并排给出，然后停下；科学家没有说明验证了哪些结果之前，它不起草图表。

**与来源相比：** 来源出自 2026-05 至 2026-11。它们报告的是 FutureHouse 自己的系统 Robin，用的是它自己的文献代理（Crow、Falcon）和数据分析代理（Finch）；来源 2 中链接了它的代码。这套搭建方式让通用智能体承担同样的工作，没有与该系统比较过。其中的假设锦标赛是另一个条目：[AWF-0104](../../LITREV/hypothesis-tournament/)。skill 与 project 之间的选择很接近：一次只做一轮、没有并行轨迹的团队，用 skill 也够。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 科学家给系统指定一种疾病。文献检索代理（Crow 负责简明摘要，Falcon 负责深度摘要，均基于 PaperQA2）生成问题，识别候选机制和体外检测方法，并提出具体的候选药物。Claude 3.7 Sonnet 以锦标赛方式对候选药物排序 [[1]](#sources)[[3]](#sources)。
2. 🛑 **接手**：人类科学家审阅清单，并对排名靠前的候选药物做实物实验。第一轮他们测试了十个分子 [[2]](#sources)[[3]](#sources)。
3. 科学家上传原始或半加工的数据（.FCS 流式细胞文件、RNA-seq 基因计数），并说明分析类型。数据分析代理（Finch）运行八条独立轨迹，每条都在 Jupyter notebook 中执行代码。随后由元分析把它们合并成共识结论 [[1]](#sources)。
4. 系统用结果生成下一批假设和实验：先是 RNA-seq 机制研究，再是第二轮十个候选药物。循环一直持续「直到有人认为某个候选药物令人满意」 [[2]](#sources)[[3]](#sources)。
5. 🛑 **审阅**：人用自己的分析核对关键结果（Finch 报告 ripasudil 提高 1.89 倍；人工分析为 1.75 倍），并做剂量反应和原代细胞验证 [[1]](#sources)。
6. Robin 产出了全部假设、实验选择、分析和正文图表。物理实验由人完成，解释的责任也由人承担 [[2]](#sources)[[4]](#sources)。

**产出：** 经临床前验证的治疗候选药物及机制假设，写成论文（发表于 Nature），以智能体的 notebook 作为分析记录。
**失败模式 → 防护：** 每次运行的分析结果不同（门控选择、RNA-seq 过滤、LLM 随机性） → 八条并行轨迹加共识元分析 [1]。体外命中是假阳性 → 人工重新分析、剂量反应和重复实验；结果仍停留在临床前阶段 [4]。
**与相近工作流的区别：** AWF-0044 受控复现运行是重新执行已有论文的代码，以验证其报告的估计值。本工作流中智能体分析的是人在各轮之间产生的新实验数据，并选择下一个实验。交付物不同，且带有反复出现的湿实验接手检查点。（也比 AWF-0104 假设锦标赛更接近：后者止步于提出供实验室验证的方案，不分析返回的数据。）
