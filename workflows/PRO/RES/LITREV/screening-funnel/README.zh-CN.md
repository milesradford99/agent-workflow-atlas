# 文献筛选漏斗

## 背景

系统综述回答一个健康问题的办法，是找出所有与它相关的研究，并用事先写好的方法合并它们的结果。问题按 PICO 来表述：研究的患者（人群）、治疗措施（干预）、拿什么作对照，以及测量的结局。研究者用检索式在多个文献数据库中检索，去掉重复记录，再筛选数以千计的标题和摘要，每条记录由两个人独立判断。然后阅读全文、提取数字、合并，并写成论文。靠人工做要花几个月，而漏掉一项本该纳入的研究，会使结果产生偏倚。在这里，智能体负责检索，做两次独立筛选，提取数据并为每个数值附上原文引语和页码，还核查参考文献。人负责批准计划，用自己筛选的样本核对筛选结果，核实进入分析的数字，并签发，因为综述由作者负责，期刊也要求他们披露 AI 的使用。

**术语：**
- **PICO**：临床问题的四个部分：人群、干预、对照、结局。
- **检索式（布尔、MeSH）**：用 AND、OR、NOT 把关键词组合起来的数据库查询；MeSH 是为医学论文建立索引所用的标准主题词。
- **研究方案注册（PROSPERO、OSF）**：在开始之前公开综述的计划，使方法之后不能被悄悄改动。
- **PRISMA 流程图**：标准图表，显示每个阶段找到、剔除和保留了多少条记录。
- **敏感度**：真正符合条件的研究中，被筛选器保留的比例。**Cohen's κ** 衡量两个筛选器的一致程度中超出偶然的部分。
- **荟萃分析（meta-analysis）**：对多项研究的结果做统计合并。**偏倚风险表**评估每项研究方法的可靠程度。
- **schema**：从每篇论文中提取的字段的固定清单。
- **ICMJE**：国际医学期刊编辑委员会，许多医学期刊遵循它的规定。

## 用智能体搭建

**形态：** `project`。综述团队要在数周内处理数以千计的记录，所以一个 skill 不够：两个筛选器不能看到对方的决定，样本核对通过之前不能开始大规模筛选，每个提取的数值都必须附有引语。这些需要自定义子智能体和强制执行规则的脚本，状态保存在文件中。

**需要：** 对研究方案所列文献数据库的访问（来源通过 API 使用 PubMed、Scopus、OpenAlex 和 Semantic Scholar）；团队有权使用的全文 PDF 文件夹；一个 PDF 转文本脚本；用来校准的、人工筛选过的记录样本；固定的提取 schema；解析 DOI 的办法（来源使用 Crossref）。智能体没有任何提交或注册账号。

| 步骤 | 搭建方式 |
|---|---|
| PICO 问题 → 检索式 → 🛑 plan | skill 起草布尔检索式和 MeSH 检索式以及 `protocol.md`，然后停下。图书馆员或课题负责人批准并注册研究方案。 |
| 每个数据库：检索 → 去重 | 每个数据库一个脚本，把记录写入一张表；去重脚本合并它们，并写出 PRISMA 流程图所需的数量。 |
| 每个记录：两个独立筛选器 → 分歧与纳入项 | 用 dynamic workflow 把每条记录交给两个指令不同的子智能体，互相看不到对方。各自返回纳入或排除及理由，并被告知拿不准时纳入。由脚本列出分歧，交人解决。 |
| 🛑 sample | 见“检查点”。 |
| 每个论文：提取并附引文 + 页码 | 一个子智能体为每篇论文填写 schema。由脚本或对提取文件写入的钩子，拒绝任何没有引语或页码的数值行。 |
| 🛑 review | 见“检查点”。 |
| 综合 | 由脚本生成偏倚风险表和荟萃分析；主对话据此起草叙述部分。 |
| 核对引用 | 由脚本按 DOI 解析每一条参考文献；skill 标记没有参考文献支持的论断。 |
| 🛑 sign-off | 见“检查点”。 |

**检查点：** `plan`：skill 写完研究方案后停下。`sample`：skill 筛选完一个样本后停下，并报告相对于人工筛选集的敏感度和 Cohen's κ；除非存在只有人才能创建的 `calibration-approved` 文件，工作流脚本拒绝筛选其余记录。`review`：skill 给出提取表以及每个数值的引语后停下，人在综合开始之前核对进入荟萃分析的每一个数字。`sign-off`：智能体没有提交或注册任何东西的工具，由作者承担责任并披露 AI 的使用。

**与来源相比：** 来源出自 2024 年至 2026-06；ICMJE 指南未注明日期。medRxiv 预印本（来源 9 和两个公开实例）以及 JMIR 论文在本次会话中无法打开，所以步骤和公开实例中的数字沿用条目原有记录，没有重新阅读。来源点名了具体的筛选和提取工具（Elicit、ASReview、Rayyan AI、GROBID、Zotero）；这套搭建方式用子智能体和脚本完成这些工作，这些工具中的任何一个都可以接手某一步。公开实例报告的是锁定的模型集成和经人核验的提取，不是这样的一套搭建。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 智能体起草布尔检索式和 MeSH 检索式。🛑 **计划**：图书馆员或课题负责人（PI）批准，然后注册研究方案（PROSPERO、OSF）。
2. 智能体检索、去重，并记录各环节数量，用于 PRISMA 流程图。
3. 两个独立的 LLM 筛选器各自筛选每条记录，每个决定都给出理由。**以敏感度而非准确率为调优目标。** 漏掉符合条件的研究会使结果产生偏倚，而已发表的敏感度差异很大：一项荟萃分析的合并值为 0.73，近期预印本中双模型集成约为 96% [[9]](#sources)。🛑 **抽检**：在大规模信任筛选器之前，先用人工筛选过的集合校准（敏感度、Cohen's κ）。所有分歧由人解决。
4. 智能体按同样的模式筛选全文，人工介入更紧密。
5. 智能体做提取，每个字段都引用原文片段和页码。🛑 **审阅**：人工核对进入荟萃分析的全部数字，比例为 100%。
6. 智能体做综合与成稿：偏倚风险表、荟萃分析脚本、叙述性文字。
7. 智能体解析每一条参考文献，并标记缺乏依据的论断。
8. 🛑 **签发**：作者承担责任并披露 AI 的使用。按 ICMJE 的规定，聊天机器人不能作为作者，使用情况必须披露 [[8]](#sources)。

**产出：** PRISMA 流程图、提取数据集、稿件草稿，以及 AI 决策的审计日志。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。来自 [Where are the real runs?](../../../../../research/2026-11-real-runs.md)；每个数字都已对照原页面复核。

- [Fagerberg et al., Socialstyrelsen, medRxiv](https://www.medrxiv.org/content/10.64898/2026.06.02.26354724v1.full) (2026-06)。锁定的 LLM 集成为 24 项指南综述做筛选；两位盲法方法学专家审计预先设定的样本。"screened 74,679 records"；"415 to 34 person-days"；在 600 条被审计的排除项中，"none was confirmed as a final false negative"。*第一手：是；可信度：高。*
- [Gartlehner et al., RTI and partners, medRxiv](https://www.medrxiv.org/node/963738) (2025-03-21)。在 6 项进行中的综述里由 LLM 先做提取、人工核验，并与纯人工提取对比。"9,341 data elements, extracted from 63 studies"；"precision of 98.9%"；"41 minutes per study"。*第一手：是；可信度：高。*
