# 附加 AI 评审

**与相近工作流的区别：** AWF-0046 评审的评审反馈是就人类审稿人写的评审，向其私下提供反馈。AWF-0106 投稿受理筛查是在同行评审前做诚信检查。本工作流中 AI 写出一份完整的评审，作者和决策者都能看到。交付物是针对论文本身的评审，检查点包括规模化时的抽样和发布前后的检查。
**工具变体：** `aaai-26-review-system`

## 背景

同行评审缺审稿人，而且越来越缺，短缺最严重地落在没人愿意读的那些稿子上：增量很小的结果、写得糟糕的投稿、已经等了四个月才等到第一份意见的作者。AI 评审替代不了审稿人的判断，但它能保证每篇论文在人来决定之前，至少被完整读过一遍，并按固定格式写下来。这就是本工作流的设计，而它的约束条件才是它可被接受的原因：AI 评审清楚标注、不给分数也不给建议、与至少两份人工评审并列而不是取代其中一份。作者可以反驳，决定权留给资深程序委员会与领域主席。工程部分是流水线——转 PDF、读图、分阶段评审、自我批评、再自评质量；治理部分则是在"一份听起来合理的评审可能造成伤害"的那些点位上的检查：在扩到全量之前，以及在草稿触及伦理、泄露作者身份、或断言论文并未说过的内容之时。

**术语：**
- **SPC / AC**：资深程序委员会与领域主席，决定录用的人。
- **完整评审（full review）**：通过初审、已分配审稿人进入评审的论文。
- **OCR**：光学字符识别，把图片与扫描文字转成模型可读的文本。
- **自我批评（self-critique）**：模型在审稿人看到之前攻击自己草稿的那一步。
- **质量评判（quality critic）**：给评审本身质量打分的步骤，用于筛选，不用于决定。
- **标注（labelled）**：明确标出由 AI 生成，使读者不会误认作人工评审。
- **反驳（rebuttal）**：作者对评审的书面回应。
- **身份泄露（identity leak）**：AI 评审暴露作者姓名，破坏双盲。

## 用智能体搭建

**形态：** `service`。它覆盖一个会议的全部投稿——数万篇——没有人逐次启动，按一个必须在审稿人之前跑完的时间表运行，人只出现在抽样与检查两道关口。这就是服务：无人值守的批量工作，量级上没有任何人能逐条监督。

**需要：** 每份投稿的机器可读版本，这意味着对图多的 PDF 要做 OCR，并对会让转换失败的格式做检查；固定的评审模板，因为分节各异的评审既无法比较也无法反驳；论文自身的正文作为检索上下文，好让评审被约束在"论文说了什么"而不是"文献里有什么"；在扩量之前设置首批关口，并且真的有人去读输出而不是确认输出存在；发布前对伦理、身份泄露、结构缺失做检查；以及会议对"AI 评审可以说与不可以说"的政策——不打分、不建议、标注、可反驳——把它编码进流水线而不是交给提示词措辞。智能体不能打分，不能给建议，也不能发布任何未经人检查的内容。

| 步骤 | 搭建方式 |
|---|---|
| 每个论文：PDF → 重采样图像 + OCR 转 markdown | 一个确定性的转换阶段，记录失败而不是跳过，因为转换糟糕的论文会产出对错误对象的评审。 |
| 5 个阶段（故事、呈现、评估、正确性、重要性） | 五遍独立处理、各自输出，再合成一份固定格式的评审，于是薄弱的一节可见而不是被平均掉。 |
| 初步评审 → 自我批评 → 修订 → 质量评判 | 草稿先被批评一遍、再修订、再给自身质量打分；分数用来筛出需要人看的评审，不决定任何事。 |
| 首批 30%：🛑 sample（人工检查输出） | 全量开跑之前由人检查首批，这是在系统性错误还便宜的时候发现它的唯一办法。 |
| 🛑 review（人工检查关键判断：伦理、身份泄露、结构缺失） | 人在发布前读每份评审关于伦理、匿名与结构的判断；转换失败的论文人工重新处理。 |
| 发布标注为 AI 的评审，不打分，与 ≥2 份人工评审并列 | 评审带标注发布，不给分数不给建议，绝不取代一份人工评审——流水线没有任何通往决定的路径。 |
| 作者可以反驳 → 🛑 sign-off（SPC/AC 决定） | 作者可以回应，决定由同时读了两边的人作出；AI 评审只是多一项输入，不是一票。 |

**检查点：** `sample`：首批 30% 在扩量之前由人读，因为在 22,977 篇之后才发现流水线错误，代价是撤回这些评审而不是修一个 bug。`review`：逐份检查伦理、身份与结构，这是"一份流畅的评审"变成保密问题或匿名破坏的地方。`sign-off`：录用权留在 SPC 与 AC 手里，而搭建里根本没有打分或建议字段，所以它不会漂移成投票。

**与来源相比：** 来源出自 2026-01 与 2026-04：试点报告与后续论文。两篇在收集条目时读过，本轮没有重新打开。此后有这些变化：这个领域分成了三种设计，而本条目现在是其中一种，不再是显而易见的下一步。NeurIPS 2026 正在跑相反的一套——一项自愿、经伦理审查的实验：作者选择加入的论文，其审稿人被随机分到"不用 LLM""开放式辅助""结构化辅助"三组，通过 OpenReview 提供的界面使用，领域主席对分组不知情，且不留存数据；辅助给的是审稿人，对作者什么都不发布。执法一侧也在动：ICML 2026 向投稿中注入隐藏指令，并[因违反 LLM 评审政策直接拒掉近 500 篇，约占投稿量的 2%](https://www.thetransmitter.org/publishing/scientists-decry-conferences-use-of-hidden-prompts-to-snare-ai-peer-reviews)，过程中识别出数百名审稿人；NeurIPS 的立场论文赛道用检测工具直接拒掉 178 篇，占其收稿的 18.4%，另要求 12.7% 提供人工撰写的证据。对这套搭建有两点后果。第一，同意问题现在被明确提出来了：一份 AI 评审发布在保密投稿上、作者可见，是作者并未选择的披露；2026 年转向的会议要么征得选择加入，要么让辅助完全不接触作者——这是本条目应当点明的设计选择，而不是留着不说。第二，执法数字给出了替代方案的成本：如果一个会场的问题是"人类评审由 AI 代写"，加一份标注的 AI 评审并不是解法，条目如实说明这一点更好。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 每篇进入完整评审的投稿：把所有图像重采样到 250 DPI，并用 olmOCR 把 PDF 转成 markdown。后续阶段同时拿到 PDF 与 markdown [[1]](#sources)。
2. 五个核心评审阶段分别评估故事、呈现、评估、正确性与重要性。它们的发现被编成一份固定格式的初步评审 [[1]](#sources)。
3. 自我批评阶段检查无依据的主张、缺失的细节以及与论文不一致之处。最后一个阶段据此修订评审 [[1]](#sources)。
4. 一个质量检查的评判者给最终评审打分。🛑 **抽检**：首批 30% 的论文先跑核心阶段，输出经人工检查后才处理其余部分 [[1]](#sources)。
5. 🛑 **审阅**：人工检查关键判断，看是否有伦理问题、暴露作者身份或缺失结构性要素。少数论文在人工转换 PDF 后重新处理。每个阶段的日志与检查点都留存以备审计 [[1]](#sources)。
6. 第一阶段发布一份清楚标注、不带分数或建议的 AI 评审，与至少两份人工评审并列。不取代任何人类审稿人 [[1]](#sources)。
7. 🛑 **签发**：SPC 与 AC 在决定是否进入第二阶段时同时读 AI 评审与人工评审。作者可以反驳 AI 评审，最终决定仍由人作出 [[1]](#sources)。

**产出：** 每篇论文一份标注的 AI 评审，发布在评审系统中供作者、审稿人、SPC 与 AC 查看，并作为人工决定的额外输入。
**失败模式 → 防护：** 误读公式与表格、过度强调次要问题、篇幅过长 → 自我批评阶段加人类决策者。调查：受访者认为 AI 评审"更可能过度强调次要问题" [1]。特殊图形格式导致转换失败 → 人工转换 PDF 并重新处理 [1]。身份或伦理泄露 → 发布前人工检查 [1]。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [Biswas et al., AAAI-26 AI Review Pilot](https://arxiv.org/html/2604.13940) (2026-04-15)。AAAI-26 主赛道每篇进入完整评审的论文都得到一份 AI 评审；5,834 份问卷回复。"generate reviews for all 22,977 full-review papers in less than a day"。*第一手：是；可信度：高。*
