# 端到端 AI 论文

**与相近工作流的区别：** AWF-0010 审稿意见回复修订：由人负责论文，并批准计划和每次修订。本工作流中智能体根据一个宽泛的主题写出整篇论文，人只在设定主题和挑选提交哪些产出时介入（抽检）。交付物是一篇新论文稿，而不是修订。
**工具变体：** `ai-scientist-v2`

## 背景

机器学习论文的大部分工作是可以被描述出来的：选一个方向、查有没有人做过、写代码、跑实验、画图、按会议要求写出来。无法被描述的是"这件事值不值得做"的判断，而在本工作流里，人保留的正是这一部分。系统拿到一个主题文件——标题、关键词、一段关于该领域的摘要——据此提出想法、对着文献过滤、在实验树上搜索，并写出带图表与引用的完整 LaTeX 稿。它会跑很多次，人读这些产出，并把通过自己内部评审的少数几篇投出去。这个设计有两点容易被忽略。第一，有意思的数字不是它产出的最好那篇论文，而是分布：一个生出一百篇稿子、其中一篇能过评审的系统，证明的是产量，不是科学。第二，运行过程要执行模型写的代码，所以沙箱不是实现细节，而是能不能跑的前提。

**术语：**
- **主题文件（topic file）**：种子文档——标题、关键词、TL;DR、摘要——界定系统可以做哪些工作。
- **构思（ideation）**：生成候选研究想法，再剔除已经发表过的。
- **新颖性检查（novelty check）**：在推进一个想法之前，对学术索引做文献检索。
- **智能体树搜索（agentic tree search）**：并行探索若干实验分支，保留有希望的、剪掉其余。
- **沙箱（sandbox）**：运行生成代码的隔离容器，使坏脚本伤不到主机。
- **LaTeX 论文稿**：含图表与参考文献的完整论文源文件。
- **自动审稿人（automated reviewer）**：给生成论文打分的模型，用于在量上初筛，从不作为会议的决定。
- **公开声明的试验（disclosed experiment）**：组织者知道其由 AI 生成、且预先约定撤稿的投稿。

## 用智能体搭建

**形态：** `project`。这套装置要在一次长时间无人值守的运行中、并且跨许多篇论文保持状态：主题文件、想法树、实验分支、生成的代码、图表、LaTeX 源与评审分数都在一个仓库里，重跑要能从这里接着走。这是一个 project，不是研究者跑一次的 skill，也不是按需应答的服务。

**需要：** 一个运行生成代码的容器，无外网出口、无凭据，因为代码是模型写的，失败模式不是崩溃；一个窄到可核查的主题文件，因为宽泛的主题只会产出关于"没人问过的那个问题"的貌似合理的成果；一个用于新颖性检查的文献索引，以及一条规则——查不出近邻的想法就丢掉，而不是假定它新；一个带会议章节结构的固定模板，因为系统是照着格式写的；每个想法的算力预算，否则树搜索会一直展开到自己停下；以及一个由真读论文而不仅看分数的人来做的评审环节。智能体不能联系会议、不能投稿、也不能自行判定某篇足够新颖可以送出：披露协议是运行之前由人达成的安排。

| 步骤 | 搭建方式 |
|---|---|
| 🛑 plan（研究者撰写宽泛的主题文件） | 主题文件就是这次运行的全部范围，由研究者撰写；下游一切都继承它的窄或它的含糊，所以这是第一个检查点。 |
| 构思 + 新颖性检查（Semantic Scholar） | 先生成候选想法，再逐个对学术索引检索；检索不到最近邻的想法被丢掉，而不是假定它是新的。 |
| 每个想法：对实验做智能体树搜索（编写代码 ⟲ 运行） | 并行工作者探索分支，各自写代码、在沙箱里运行，只有运行完成且指标改善的结果才被保留。 |
| 分析 + 绘图 | 图表由运行产物生成，而不是由对产物的描述生成，于是图不可能与实验日志矛盾。 |
| 撰写完整 LaTeX 论文 + 引用 | 论文按模板生成，引用取自检索到的文献；每条引用都要能解析，解析不了的就删掉而不是编一个。 |
| 生成大量论文 | 一次运行产出的是一批而不是一篇；仓库保留全部稿件及其分数，这才让挑选这一步有意义。 |
| 🛑 review（研究者内部评审并挑出少数最佳） | 研究者读这一批，用自己的标准打分并挑选；自动审稿人的分数只用于初筛，来源也明确说投出的稿子没有一篇达到主会标准。 |
| 提交到会议同行评审（公开声明，预先约定撤稿） | 投稿是人在事先与组织者达成协议之后采取的行动，撤稿承诺在发表前预先作出。 |

**检查点：** `plan`：主题文件是人唯一约束科学内容的地方，而一个含糊的主题只会产出一百篇关于什么的稿件。`review`：由研究者阅读与挑选，而来源说得直白——这些产出过的是一条工作坊的标准而不是主会的标准，这个检查点的作用正是阻止一批稿件变成一条投稿流水线。

**与来源相比：** 来源出自 2025-03 与一份 2025 年的 GitHub README，公开实例是 ICLR 2025 工作坊的那次投稿。系统本身的论文此后在《Nature》上发表（Lu 等，2026），本月已打开；更早的博客与 README 本轮没有重新打开。此后有这些变化：经同行评议的版本比当年的公告更谨慎，而且出现了一项给该主张划出边界的受控测试。在《Nature》版本中，作者报告了同样的工作坊结果——投出三篇、一篇被接收，评分为 6、7、6——并说明自动审稿人达到约 69% 的平衡准确率，而人类审稿人彼此之间约为 65% 到 70%。他们也坦率列出失败：编造的引用、跨章节重复使用的图、不成熟的想法、以及在难例上跑不通的代码，并收回了早先的措辞，承认仍需要人工监督来筛选与打磨产出。划边界的那项测试是 2026 年由多所大学与政府实验室完成的研究，[于 8 月被报道](https://www.news.cn/liangzi/20260825/0a21ffa0182b484eb3e2d2cb01fe2238/c.html)：给前沿智能体完整互联网访问、专用算力与约 3,000 美元的模型额度，让它们对两篇未发表论文自主工作六天；两篇产出都被拒，评分分别为 2/6 与 1/6，审稿人形容实验设计奇怪、结论是事后才决定的。两个结果合起来从相反方向说明同一件事：这条流水线能以每篇约 15 美元产出一篇过得去的工作坊论文，而它目前还做不了开放式研究。这也是本条目检查点留在原地的原因——由人对着**一批**挑选，披露协议事先谈好。会议侧的形势也收紧了：主会现在已经禁止纯 AI 撰写的投稿并要求披露，ICLR 2026 的工作坊主席被引述说 AI 写的论文只会让评审负担更重，而检测工具还不足以执行这些规则。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 🛑 **计划**：研究者撰写一份主题描述文件（标题、关键词、TL;DR、摘要），界定范围，例如某个工作坊主题 [[1]](#sources)[[2]](#sources)。
2. 构思脚本根据主题头脑风暴并打磨研究想法，并对 Semantic Scholar 做新颖性检查 [[2]](#sources)。
3. 每个想法：一个实验管理智能体执行渐进式树搜索。它编写并改进代码、运行实验、分析数据并生成图表。因为要运行 LLM 写的代码，必须有沙箱（例如 Docker）[[2]](#sources)。
4. 写出论文的每一个字，从标题到最后一条参考文献，包括图表与排版，没有人工编辑 [[1]](#sources)。
5. 🛑 **审阅**：研究者阅读生成的论文，做自己的详细内部评审，并在权衡多样性与质量后挑出最好的投出去。在 ICLR 2025 那次运行中他们投了 3 篇 [[1]](#sources)。
6. 只有在会议组织者同意、通过伦理审查并向审稿人披露的前提下，才提交双盲同行评审，并按事先约定在发表前撤稿 [[1]](#sources)。

**产出：** 一份完整论文稿（代码、图表、LaTeX），作为公开声明的试验提交同行评审，而不是作为正常研究发表。
**失败模式 → 防护：** 开放式主题成功率低（v2"采取更宽泛、更探索性的路线，成功率更低"）→ 大量生成，由人挑选少数 [2]。只到工作坊水准：3 篇中没有任何一篇达到作者自己对主会的内部标准 [1]。危险的代码执行 → 沙箱容器 [2]。污染文献 → 组织者同意、伦理审查与预先承诺撤稿 [1]。
