# 端到端 AI 论文

**与相近工作流的区别：** AWF-0010 审稿意见回复修订：由人负责论文，并批准计划和每次修订。本工作流中智能体根据一个宽泛的主题写出整篇论文，人只在设定主题和挑选提交哪些产出时介入（抽检）。交付物是一篇新论文稿，而不是修订。
**工具变体：** `ai-scientist-v2`

## 步骤

1. 🛑 **计划**：研究者撰写主题描述文件（Title、Keywords、TL;DR、Abstract）来限定范围，例如某个研讨会的主题 [[1]](#sources)[[2]](#sources)。
2. 构思脚本围绕主题头脑风暴并完善研究想法，并用 Semantic Scholar 检查新颖性 [[2]](#sources)。
3. 对每个想法：实验管理代理运行渐进式的智能体树搜索。它编写并改进代码、运行实验、分析数据并生成图表。LLM 写出的代码会被运行，因此需要沙箱（例如 Docker） [[2]](#sources)。
4. 论文稿从标题到最后一条参考文献，包括图表和排版，每个字都由代理撰写，无人工修改 [[1]](#sources)。
5. 🛑 **审阅**：研究者阅读生成的论文，做自己的详细内部评审，并在兼顾多样性和质量的前提下挑出最佳的提交。在 ICLR 2025 的这次运行中，他们提交了 3 篇 [[1]](#sources)。
6. 只有在会议组织者同意、通过 IRB 批准并向审稿人公开声明的前提下，才提交双盲同行评审，并按预先约定在发表前撤稿 [[1]](#sources)。

**产出：** 一篇完整的论文稿（代码、图表、LaTeX），作为公开声明的实验提交同行评审，而不是当作正常研究发表。
**失败模式 → 防护：** 开放式主题的成功率低（v2「采用更宽泛、更具探索性的方法，成功率也更低」） → 大量生成，由人挑选少数 [2]。只达到研讨会的水准：3 篇都没有达到作者对主会议的内部标准 [1]。危险的代码执行 → 沙箱容器 [2]。污染学术文献 → 组织者同意、IRB 批准和预先承诺的撤稿 [1]。
