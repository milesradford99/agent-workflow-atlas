# 分类路由的患者消息回复草稿

**工具变体：** `epic-in-basket-gpt4`

## 背景

患者通过在线门户给诊所发消息：问检查结果、问用药、要填表、说症状。医生、护士和药师在诊所病历系统里的收件箱中回复这些消息，常常是在两次看诊之间或下班以后，而且消息数量很大。一条好的回复需要患者的基本信息和最近一次门诊记录，所以哪怕答案很短，也要先去查。在这里，系统按类型给每条消息分类，并根据消息、患者基本数据和最近一次门诊记录起草回复，草稿放在临床医生的收件箱里等着。要不要从草稿开始由临床医生决定，修改和发送也由他们来做，因为这条回复是一位具名临床医生给患者的医疗建议，关于检查结果或用药的错误回答可能伤害患者。

**术语：**
- **患者门户**：患者给诊所发消息、查看自己病历的网站或应用。
- **EHR（电子病历）**：保存每位患者病历的系统；临床医生在它的收件箱里接收门户消息。
- **代理人**：代表患者发消息的人，例如父母或照护者。
- **结构化患者数据**：病历中的固定字段，例如姓名、年龄、科室和过敏史，区别于自由文本记录。
- **APP（高级执业医疗人员）**：可以接诊患者的执业护士或医师助理。
- **临床药师**：在诊疗团队中工作、管理患者用药的药师。
- **GI（消化内科）**：负责消化系统的专科。
- **审计日志**：EHR 对用户每个操作及其时间的记录。
- **使用率**：临床医生从草稿开始写回复所占的比例。

## 用智能体搭建

**形态：** `service`。每份草稿在消息到达时生成，任何临床医生打开之前就已备好；临床医生只看到消息旁边的草稿。

**需要：** 新门户消息的数据来源，以及把草稿保存在消息旁边的途径，可以通过 EHR 面向外部程序的接口，或机构批准的 MCP 服务器；对结构化字段和最近一次门诊记录的只读访问；作为参考文件放在 skill 旁边的四类提示词；一套经机构批准、可以处理患者记录的环境（在美国，即受业务伙伴协议覆盖的环境）。不要给智能体任何向患者发消息的工具。

| 步骤 | 搭建方式 |
|---|---|
| 收到患者消息 → 排除检查 (非英文、带附件、代理人发送) | 由一个 Agent SDK 程序从数据来源或队列读取新消息。在调用任何模型之前，先由脚本执行排除规则，被排除的消息不生成草稿。 |
| 分类 (一般 \| 检查结果 \| 用药 \| 文书) | skill 的第一步：选定一个类别，或者一个都不选，这同样意味着不生成草稿。 |
| 分类提示词 + 结构化患者数据 + 最近一次门诊记录 | skill 打开该类别的参考文件，并通过连接器读取患者字段和最近一次记录。 |
| 草稿显示在 EHR 收件箱 | 程序通过连接器把草稿保存在消息旁边。 |
| 🛑 review (医生从草稿或空白开始，修改) → 🛑 action (医生发送回复) | 见“检查点”。 |

**检查点：** `review`：草稿只以草稿的形式存在于消息旁边；临床医生选择从草稿还是从空白回复开始，并在 EHR 中修改。`action`：发送会直接到达患者，所以不给智能体任何发送工具，程序的 `canUseTool` 只允许读取消息和患者数据、保存草稿，其余调用一律拒绝。只有临床医生在 EHR 中点击发送，回复才会送出。

**与来源相比：** 来源和公开实例都出自 2024-03。哥伦比亚大学欧文医学中心在 JAMA Network Open 上发表了一项针对同一 EHR 功能的较新研究，发现使用草稿时回复更快，但下班后的收件箱工作并没有减少（[TechTarget, 2026-11-02](https://www.techtarget.com/searchhealthit/news/366653298/AI-drafted-patient-portal-messages-do-little-for-provider-burnout)）。来源描述的是 EHR 内置的功能，提示词由医疗系统编写：是一串固定的模型调用，不是智能体。上面的搭建方式取决于 EHR 是否允许外部程序读取消息并保存草稿；如果不允许，起草仍由 EHR 厂商完成，本条目就属于 `platform` 的情形。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. EHR 把部分收到的患者门户消息交给起草工具。非英文消息、带附件的消息以及由代理人发送的消息不生成草稿 [[1]](#sources)。
2. GPT-3.5 Turbo 把每条消息归入四类之一：一般、检查结果、用药或文书 [[1]](#sources)。
3. 起草工具为每个类别使用各自的提示词。提示词包含患者消息、选定的结构化数据（姓名、年龄、科室、过敏史）以及最近一次门诊记录。由 GPT-4 写出草稿 [[1]](#sources)。
4. EHR 把草稿显示在临床医生的收件箱中，旁边有“从草稿开始”和“从空白回复开始”两个选项 [[1]](#sources)。
5. 🛑 **审阅**：临床医生（医师、APP、护士或临床药师）决定是否使用草稿并加以修改 [[1]](#sources)。
6. 🛑 **操作**：临床医生发送回复。没有人点击发送，就不会有任何内容到达患者 [[1]](#sources)。
7. 研究团队从 EHR 审计日志中统计按角色划分的草稿使用频率，以及阅读、撰写和回复操作的耗时，并开展前后对照的职业倦怠问卷调查 [[1]](#sources)。

**产出：** 由临床医生发出的患者门户消息回复，归入 EHR 的对话记录。
**失败模式 → 防护：** 临床医生可能很少使用草稿（平均 20%），节省的时间也可能体现不出来 → 按角色衡量，药师和护士使用草稿更多。部分消息不在适用范围内（25% 没有生成草稿）→ 设排除规则，并保留“从空白开始”的路径。
**与相近工作流的区别：** AWF-0026 环境记录员（Ambient scribe）是最接近的一个，它的产出是根据经同意的录音生成、并签入病历的就诊记录。本工作流写的是面向患者的书面回复，按消息类型分流，没有录音或同意环节，并且对每条消息都设有发送操作的检查点。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Second collection pass](../../../../../research/2026-11-second-pass.md)。

- [Garcia et al., Stanford Health Care, JAMA Netw Open](https://jamanetwork.com/journals/jamanetworkopen/fullarticle/2816494) (2024-03-20)。为期 5 周的试点，162 名初级保健和消化内科临床医生；共 12,844 条回复，其中 75% 生成了草稿。"The overall mean utilization rate per clinician was 20%"。*第一手：是；可信度：高。*
