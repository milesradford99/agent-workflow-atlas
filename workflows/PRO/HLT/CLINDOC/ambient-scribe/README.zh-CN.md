# 诊室环境语音病历助手

**工具变体：** `abridge-epic` [[26]](#sources) · `dragon-copilot`（2025 年 3 月发布；把 Dragon Medical One 听写与 DAX 环境录音结合 [[25]](#sources)） · `nabla` · `ambience`

## 背景

每次就诊之后，医生都要写一份病历：患者说了什么、查了什么、决定了什么。医生还要为这次就诊选定编码，往往还要给患者写一份通俗的小结。手工完成这些很费时间，医生只好一边听患者说话一边打字，或者晚上再把病历补完。环境语音病历助手在患者同意后录下整段对话，把它转成能看出谁说了哪句话的转写稿，再起草病历、编码和患者小结，并把每句话链接到它所依据的那段对话。草稿仍由医生阅读、修改并签署，因为签署后的病历是具有法律效力的医疗记录，医生是它的作者，其中的遗漏或凭空编出的内容可能伤害患者。

**术语：**
- **环境录音（ambient capture）**：用诊室里的设备或手机在后台录下就诊过程，而不是由医生口述。
- **区分说话人的转写稿（diarized transcript）**：标明每一句由哪位说话人说出的转写稿。
- **电子病历（EHR）**：医院或诊所保存每位患者病历的系统；Epic 是其中一款产品。
- **编码**：附在这次就诊上的标准诊断和计费编码。
- **专科模板**：某个专科的病历分节格式。
- **Linked Evidence**：Abridge 对“把病历中的每个短语链接到其来源录音或转写稿”这一功能的叫法。
- **Epic Haiku、Hyperdrive**：Epic 面向医生的移动应用，以及它的桌面端应用。
- **HIPAA、BAA**：美国保护患者健康信息的法律，以及厂商在处理这类信息之前必须签署的业务伙伴协议。
- **幻觉（hallucination）**：草稿里出现了对话中没说过、病历里也没有的内容。

## 用智能体搭建

**形态：** `platform`。录下诊室里的声音、把语音转成能区分说话人的转写稿，需要语音模型；病历也必须归档进电子病历系统。这两样通用智能体都替代不了。有了转写稿之后，起草这几个阶段适合做成一个 `skill`：一位医生、一次就诊，医生在场审阅。

**需要：** 一款经所在机构批准的环境录音与语音转文字产品；带时间戳和说话人标签的就诊转写稿文件；作为参考文件放在 skill 旁边的专科模板和编码表；患者的病历上下文，可以通过机构提供的只读 MCP 服务器获取，也可以由医生提供摘录；一套在 HIPAA 业务伙伴协议覆盖之下的环境，因为转写稿和病历都是患者记录。不要给智能体任何写入电子病历的工具。

| 步骤 | 搭建方式 |
|---|---|
| 🛑 plan (患者同意) | 录音开始前，由医生在录音产品中完成。skill 的第一条指令是请医生确认已记录患者同意，没有确认就停下。 |
| 录制就诊 → 区分说话人的转写稿 | 录音与语音转文字平台。 |
| 加载电子病历上下文 | 电子病历的只读 MCP 服务器，或医生提供的摘录。 |
| 病历 + 编码 + 患者小结 | skill，旁边放着专科模板和编码表。 |
| 每句话链接到转写稿 | skill 中的规则：每句话都附上它所依据的转写稿行的时间戳，没有来源的句子单独列给医生。可以用内置子智能体逐句对照所引的行再核一遍。 |
| 🛑 review → 🛑 sign-off → 归档到电子病历 | 见“检查点”。 |

**检查点：** `plan`：患者同意由医生在录音产品中取得；智能体从不启动录音，没有确认同意时 skill 就停下。`review`：skill 停下，给出带链接的草稿，并把没有来源的句子排在最前面；由医生修改。`sign-off`：智能体没有写入电子病历的工具，所以由医生作为法律意义上的作者签署病历并归档到电子病历。

**与来源相比：** 来源出自 2024-02 至 2025-10；公开实例是 2024-07 至 2024-08 的试点，于 2026 年发表。2026-02，Epic 在电子病历系统内发布了自己的环境录音起草病历功能 AI Charting（[HIT Consultant, 2026-02-05](https://hitconsultant.net/2026/02/05/epic-releases-ai-charting-ambient-ai-market-implications/)），所以除了 `variants` 中列出的产品，电子病历厂商本身现在也提供这些步骤。`dragon-copilot` 仍沿用这个产品名。这些来源是厂商公告，以及一家医疗系统对某厂商病历助手所做的质量研究；没有一个来源报告由通用智能体来运行这些步骤，因此上面的搭建方式只是针对起草阶段的方案，前提是专业产品已经生成了转写稿。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 🛑 **计划**：医生取得患者对录音的同意。
2. 病历助手产品在诊室或用手机进行环境录音。
3. 产品生成区分说话人的转写稿，然后按专科模板生成结构化病历。
4. 产品把病历中的每个短语链接到其来源录音或转写稿。Abridge 把这称为“Linked Evidence”，位于 Epic Haiku → Hyperdrive 之内 [[26]](#sources)。
5. 🛑 **审阅**：医生修改病历。
6. 🛑 **签发**：医生签署，并作为法律意义上的作者。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。来自 [Where are the real runs?](../../../../../research/2026-11-real-runs.md)；每个数字都已对照原页面复核。

- [Taylor … Adams, UC Davis Health, JMIR Med Inform 2026;14:e86474](https://escholarship.org/content/qt9r89g3sp/qt9r89g3sp.pdf) (pilot Jul–Aug 2024)。31 位医生，7,545 份病历；其中 356 份被评估有无遗漏和幻觉；每份病历都由医生批准。"94.7% (337/356) free from significant errors"；"hallucinations (n=41, 11.5%)"。*第一手：是；可信度：高。*
