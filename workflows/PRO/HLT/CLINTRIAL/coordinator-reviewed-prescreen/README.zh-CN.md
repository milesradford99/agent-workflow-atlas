# 协调员复核的试验预筛选

**工具变体：** `rag-gpt-ehr-pipeline` · `neurosymbolic-abstraction`

## 背景

临床试验在符合一系列入组标准的患者身上测试新疗法，标准包括诊断、疾病分期、既往治疗、检查结果，以及许多排除条件。在任何人去接触患者之前，研究人员要先做预筛选：读每位候选人的病历，判断每条标准是否满足。证据散落在多年的记录里，所以这件事很慢，读累了的人会漏掉本来符合条件的患者。在这里，语言模型读取每位患者的病历，为每条标准给出标注、理由以及所依据的记录，并按患者看起来满足多少条标准来排序。每条标准仍由研究协调员裁定，接触哪些患者、取得知情同意也仍由试验团队负责。这些决定是研究团队在经伦理委员会批准的方案下应尽的职责，一个错误的标注可能让不符合条件的患者接受试验性治疗。

**术语：**
- **PI（主要研究者）**：在一个研究中心负责开展试验的医生。
- **IRB（伦理审查委员会）、方案**：研究必须经其批准的伦理委员会；以及经批准的方案文件，规定研究怎样开展、谁可以作为研究人员参与。
- **标准、预筛选**：一条入组条件；在接触患者之前对照标准核查病历。
- **协调员**：临床研究协调员，负责预筛选、管理患者在试验中各环节进展的工作人员。
- **电子病历（EHR）**：医院保存每位患者病历的系统，既有结构化字段，也有自由文本记录。
- **LLM、检索增强**：大语言模型；检索增强指模型先在病历中检索，只读取检索到的段落。
- **特异度、假阳性**：实际不满足的标准中，被模型标为不满足的比例；特异度低会产生假阳性，即把不满足的标准标成满足。
- **分歧、裁决**：AI 与协调员意见不一致；由更资深的审阅人对此作出决定。
- **自动化偏见**：人们不加核对就接受机器答案的倾向。
- **摘录**：阅读病历，记录研究所需的数据。
- **接触、知情同意、入组**：向患者介绍试验；患者在知情的前提下同意参加；正式把患者纳入试验。

## 用智能体搭建

**形态：** `service`。预筛选在每个试验的成千上万名患者上运行，现场没有人；协调员只看到排好序的工作清单。

**需要：** 通过医院批准的连接器或数据导出，对结构化电子病历数据和记录的只读访问；经研究团队签发的试验标准文件，作为参考文件放在 skill 旁边；一个工作清单存储（数据库表或看板），供协调员记录裁定和理由；把运行这套系统的人员列为研究人员的 IRB 批准；一套经批准、可以处理患者记录的环境。不要给智能体任何更改患者试验状态或联系患者的途径。

| 步骤 | 搭建方式 |
|---|---|
| 试验接入 (主要研究者修订伦理审批、选定标准) → 🛑 plan | 由主要研究者和研究团队完成。智能体可以根据方案起草标准文件和每条标准的提示词，供他们修改。 |
| 每位患者：逐条标注标准 + 依据 + 出处病历 | 由一个 Agent SDK 程序，或由医院调度器启动的 `claude -p`，把患者分给运行该 skill 的子智能体。每个子智能体按每条标准返回一行：标注、理由、置信度、记录编号和日期。 |
| 按满足比例排序 | 由脚本按标为满足或可能满足的标准所占比例给患者排序，把超过研究团队所定阈值的患者写进工作清单。 |
| 🛑 review (协调员逐条裁定) | 由协调员在工作清单中完成。一个定时运行的任务会对超过约定天数仍未复核的患者发出提醒。 |
| (更新标准提示词 ⟲ 与协调员一致) | 之后的一次运行读取协调员有异议的标准，以修改标准文件的方式提出对这些提示词的改动。研究团队批准后，下一次运行才使用。 |
| 🛑 handoff (试验团队接触患者 + 知情同意) | 由研究团队在智能体之外完成。 |

**检查点：** `plan`：标准文件没有研究团队的签发，调用程序就拒绝启动运行。`review`：工作清单是这次运行唯一的输出，协调员在其中逐条裁定。`handoff`：智能体没有任何设置患者状态或联系患者的工具，所以由研究团队设定状态，并负责接触患者和知情同意。

**与来源相比：** 来源和公开实例出自 2026-02 至 2026-03。UT Southwestern 团队搭建了一条带协调员看板的检索增强流水线，其提示词根据协调员反馈自动更新；上面的搭建方式改为经由研究团队来做这些改动，因为研究团队签发的正是标准配置。来源 2 是用一家厂商的模型（`neurosymbolic-abstraction`）在既往病历上做的随机对照比较，不是已部署的工作流，通用智能体也复现不了那个模型。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 接入：主要研究者（PI）修订试验已获伦理委员会（IRB）批准的方案，把 AI 团队成员加为研究人员。研究团队选出要自动化的标准，分为两个层级。接触患者、知情同意和入组的决定仍由试验团队负责 [[1]](#sources)。
2. 🛑 **计划**：预筛选开始前，研究团队签发标准的配置 [[1]](#sources)。
3. 检索增强的 LLM 读取结构化电子病历数据和自由文本记录。它把每条标准标注为满足、可能满足、可能不满足、不满足、不确定或未找到记录，并附上依据、置信度以及证据所在记录的编号和日期 [[1]](#sources)。
4. 流水线把满足或可能满足的标准占比超过阈值的患者，送进按序排列的协调员看板。协调员起初必须复核满足 ≥50% 标准的患者，随着表现提升收紧到 ≥75%。如果患者在四天内未被复核，系统会发出提醒 [[1]](#sources)。
5. 🛑 **审阅**：协调员把每条标准标为满足、不满足或数据不足，不同意 AI 时需说明理由。出现分歧时，由初级到高级的重新评估，或由高级人员单人裁决 [[1]](#sources)。
6. 流水线根据协调员的反馈更新标准提示词。漏掉的患者会触发对工作流或 AI 逻辑的修正 [[1]](#sources)。
7. 🛑 **接手**：研究团队设定每位患者的状态（预筛选成功/失败、筛选中、已入组），并负责接触和知情同意 [[1]](#sources)。

**产出：** 每个试验一份排好序的预筛选工作清单，附逐条标准的证据。经确认的候选人交给试验团队去接触并取得知情同意。
**失败模式 → 防护：** 特异度较低（0.81）会产生假阳性 → 协调员确认每一条标准 [[1]](#sources)。在一项随机试验中，自动化偏见限制了某些标准领域的准确率 → 保留人工摘录和裁决步骤 [[2]](#sources)。速度提升可能并不出现：每份病历的耗时为 37.4 对 37.8 分钟 [[2]](#sources)。
**与相近工作流的区别：** AWF-0009 筛选漏斗（Screening funnel，LITREV）为综述筛选论文。本工作流则依据实时的试验标准筛选患者，由协调员逐条确认，并交接给入组环节。

## 公开实例

覆盖度（截至 2026-11-06）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [New workflows for empty categories](../../../../../research/2026-11-new-workflows.md)。

- [Dohopolski et al., UTSW human-in-the-loop prescreening](https://doi.org/10.64898/2026.03.20.26348890) (2026-03-27)。在 26 项在研试验中前瞻性部署，由协调员复核，并依据反馈更新提示词。"39,182 patients were prescreened by our LLM-workflow across 26 (21 oncology and 5 non-oncology) studies"。*第一手：是；可信度：高。*
- [Parikh et al., Human-AI prescreening RCT](https://www.nature.com/articles/s41467-026-68873-8) (2026-02-03)。在 355 份病历上对比有无 AI 标注的协调员，采用随机分组。"Human-alone (76.5% vs. 71.1%)"。*第一手：研究（随机，基于既往记录；由 AI 厂商 Mendel.ai 资助）；可信度：高。*
