# 撰写人复核的临床研究报告初稿

**工具变体：** `claude-bedrock-novoscribe` · `merck-internal-genai-platform` · `merck-quantumblack`

## 背景

公司在患者身上完成一种药物的试验后，必须撰写临床研究报告（CSR）：一份篇幅很长、按固定监管结构写成的文件，说明试验是怎样进行的、结果如何。监管机构在决定是否批准药物时会阅读它。医学撰写人要根据数千页的结果数据表来写：化解互相矛盾的数字，逐项核对结果，并用精确的监管措辞表述结论，这很耗时。智能体接手初稿：整理数据表、撰写正文、检查初稿里的疏漏。具资质的医学撰写人仍要审阅整份初稿，因为公司要对提交材料中的每一句话向监管机构负责，一个错误的数字或没有依据的说法都可能拖延批准。

**术语：**
- **临床研究报告（CSR）**：向监管机构报告一项临床试验的设计、执行和结果的文件。
- **临床数据表**：试验的统计输出，以结果表格的形式呈现，一项研究往往多达数千页。
- **医学撰写人**：撰写并核对临床试验相关监管文件的专业人员。
- **初稿**：报告的第一个完整版本，之后才进入常规的文件审阅和提交环节。
- **数据表映射**：把每张结果表对应到报告中讨论它的章节。

## 用智能体搭建

**形态：** `skill`。一位医学撰写人一次处理一项研究的报告，并且全程在对话中；流程、报告结构和检查都可以放进一个 skill，旁边配上脚本。

**需要：** 作为文件提供的该研究结果数据表；放在 skill 旁边的报告模板，以及公司认可的措辞和术语参考文件；一个脚本，把初稿引用的每个数字与它所出自的数据表核对；一套经所在机构批准、可以处理未公开试验数据的环境。不要给智能体任何能向团队之外提交、归档或发送内容的工具。

| 步骤 | 搭建方式 |
|---|---|
| 临床数据表 → 数据表预处理 (映射、提取、样式、验证) | skill 旁边的脚本读取数据表，把每张表映射到报告章节，把数值提取到结构化文件，并检查数据表有无缺漏和不一致。 |
| 生成 CSR 初稿 | skill 根据提取的数值和认可的措辞逐章起草。报告很长时，由内置子智能体各负责一组章节，返回正文以及每句话所依据的数据表。 |
| 初稿自动检查 | 脚本把初稿中的每个数字与提取的数值比对；再在主对话中对引用、术语和章节之间的一致性过一遍。 |
| 🛑 review (具资质的医学撰写人全面审阅初稿) → 经人工审阅的初稿 | 见“检查点”。 |

**检查点：** `review`：skill 最后呈现初稿，附上每项检查结果和每处无法对应到数据表的陈述，然后停下。由医学撰写人修改初稿；智能体没有把它送往下一环节的工具，只有撰写人把它交走，才会进入文件审阅。

**与来源相比：** 来源出自 2025-06 至 2026-04；Novo Nordisk 那一页未注明日期。这些来源描述的是公司自己的平台，没有给出逐步细节：Merck 的是把数据表预处理和语言模型起草结合起来的内部平台，另外两份记述只报告了结果，很少谈方法。因此上面的搭建方式是为通用智能体做的设计，并非复现其中任何一家。Merck 的记述说的是专为数据表打造的平台；来源并没有说明通用智能体加脚本能否处理那种规模的数据表。来源报告了耗时和错误率的数字；本搭建方式不作这类声明。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 研究团队收集该研究的临床数据表（多达数千页），用于撰写临床研究报告（CSR） [[1]](#sources)。
2. 平台预处理数据表：映射、提取数据、套用样式并验证 [[1]](#sources)。
3. 大语言模型撰写 CSR 初稿，最快只需五分钟 [[1]](#sources)。
4. 平台验证数据表，并检查初稿在数据、表述、引用、术语和排版方面的错误 [[1]](#sources)。
5. 🛑 **审阅**：具资质的医学撰写人在初稿进入下一环节之前，审阅整份初稿 [[1]](#sources)。

**产出：** 经人工全面审阅的 CSR 初稿，交给常规的文件审阅和提交流程。
**失败模式 → 防护：** 数据、引用或术语出错 → 数据表验证加上医学撰写人的审阅（公司称这几类错误减少了 50%）。各来源的数据不一致 → 起草前先做预处理。
**与相近工作流的区别：** AWF-0033 协调员复核的预筛选（Coordinator-reviewed prescreen）是最接近的一个，但它是逐条标准地筛查患者是否符合入组资格。本工作流则是根据试验产出撰写监管文件，只有一个检查点，由撰写人审阅整份文件。
