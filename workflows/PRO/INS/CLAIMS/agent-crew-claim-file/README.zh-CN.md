# 多智能体理赔档案


## 背景

住宅遭遇风暴后，住户可以就家庭财产险下受损的物品提出理赔，例如长时间停电导致冰箱里的食物变质。保险公司的理赔员要核对保单是否涵盖这项损失、天气事件是否真实发生、有没有欺诈迹象，然后决定赔多少。大风暴过后，成千上万的小额理赔同时涌来，每一件都要做同样的几项核查，结果简单的理赔排在复杂的后面。这里由一组专职智能体完成各项核查并提出赔付金额，把每项核查的汇总一并交上去。是否付款仍由理赔专业人员决定，因为赔付是保险公司对客户的财务和法律承诺。

**术语：**
- **理赔（claim）**：客户依据保单就一项损失要求保险公司赔付。
- **保障范围（coverage）**：保单是否真的涵盖这种情形下的这类损失。
- **食品变质理赔**：因停电致冰箱或冷冻柜停止工作、食物变质而提出的理赔。
- **赔付（payout）**：保险公司对获批理赔支付的金额。
- **审计摘要**：对每项核查的发现和决定的书面汇总，让审批人一眼看到整份档案。

## 用智能体搭建

**形态：** `service`。理赔在线提交时没有人守在键盘前，人只看到附有审计摘要的成品档案。

**需要：** 通过 MCP 连接器或各一个小脚本，读取保单记录和天气事件数据；客户提交的理赔内容；一个放置可供决策档案的队列、工单系统或理赔界面。不要给智能体任何付款工具，也不要让它接触付款系统。个人数据只保留理赔所需的部分，并记录每次运行读取过的每条记录。

| 步骤 | 搭建方式 |
|---|---|
| 客户在线提交理赔 | 理赔系统发出的事件启动一次运行：由 API 调用触发的云端定时任务，或者你自己的程序启动 `claude -p` 或 Agent SDK 程序。 |
| 规划智能体启动流程 (网络安全智能体监督数据安全) | 一个 skill 保存流程并调用三项核查。数据安全靠权限规则（把运行限定在指定连接器内）和一个记录每次读取的 `PreToolUse` 钩子来保证。 |
| 保障智能体 \| 天气智能体 \| 欺诈智能体 | 三个内置子智能体并行运行，各带一份参考文件（保障规则、天气查询、欺诈迹象），各自返回一条附证据的简短结论。 |
| 赔付智能体提出金额 | skill 根据保单条款和保障结论算出建议金额，并写明算法。 |
| 审计智能体汇总所有智能体的决定 | 最后一个子智能体只看各项结论和建议金额，写出审计摘要。 |
| 🛑 sign-off (理赔专业人员作出付款决定) → 付款 | 见“检查点”。 |

**检查点：** `sign-off`：运行结束时把理赔档案和审计摘要发到理赔队列。智能体没有任何能付款、批准或拒绝理赔的工具，所以由理赔专业人员在理赔系统里作出决定并付款。真正起约束作用的是不给付款工具，而不是 skill 里的文字。

**与来源相比：** 来源和公开实例都出自 2025-11。安联（Allianz）报道的是自家平台上的七个智能体；这套搭建方式用一个 skill 加三个并行子智能体完成同样的核查，没有单独的网络安全智能体，只有权限规则和日志钩子。来源报道的范围是严重天气停电后 500 澳元以下的食品变质理赔；范围更大需要另配保障和欺诈规则，来源没有描述这些。来源没有给出各智能体的提示词、模型或规则细节，所以这个设计出自本目录，不是安联的做法。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 保险公司把范围限定为严重天气导致停电后的食品变质理赔，金额在 500 澳元以下 [[1]](#sources)。
2. 规划智能体启动流程并协调各专职智能体；网络安全智能体全程监督数据安全 [[1]](#sources)。
3. 保障智能体核查保单是否涵盖该损失，天气智能体确认确有相符的天气事件，欺诈智能体检查是否有欺诈迹象 [[1]](#sources)。
4. 赔付智能体确定金额并报告给规划智能体 [[1]](#sources)。
5. 审计智能体复核整个过程，汇总每个智能体的决定，并把档案交给人 [[1]](#sources)。
6. 🛑 **签发**：由人类理赔专业人员作出付款决定。按安联（Allianz）的说法，“赔付决定从不自动化”[[1]](#sources)。

**产出：** 可供决策的理赔档案，附审计摘要；只有经人工签发后才会放款。
**失败模式 → 防护：** 智能体可能错误赔付或被欺诈 → 没有任何智能体能付款，审计智能体为人类审批人汇总每个智能体的决定。
**与相近工作流的区别：** AWF-0022 发票提取-匹配-分派（Invoice extract-match-route，应付账款）会自动支付已匹配的发票，只把例外情况交给人。这里每一项理赔都要经人工签发付款，产出的是理赔决定而非应付款项，并且由专职智能体（保障、天气、欺诈）取代三单匹配。
