# 理赔员确认的发票处理建议

**工具变体：** `uipath-action-center`

## 背景

宠物和马匹保险依据兽医开具的发票赔付。针对某一疾病或伤情的首次理赔开立之后，同一病症的后续发票会陆续寄来，理赔员要逐行阅读每张发票，判断保单哪些赔、哪些不赔。这类工作重复性强，本该除外的一行可能漏过去而被多付。这里由智能体读取每张收到的发票，逐行建议赔付还是除外。每张发票仍由理赔员负责：接受建议、修改建议，或把发票转入人工处理，因为保险公司的付款授权和质量检查都是围绕由人作决定设计的。智能体所掌握知识的变动（例如一种新药）也要先经资深人员批准。

**术语：**
- **理赔员（claims handler）**：保险公司里决定一项理赔赔付多少的员工。
- **后续赔付（continuation payment）**：对已有未结理赔的同一病症，就后续发票所作的赔付。
- **除外（exclude）**：不赔付某一行，例如保单不保的治疗项目。
- **多付漏损（overpayment leakage）**：因漏看某一行而付出的、保单本不要求支付的钱。
- **背景数据（context data）**：智能体读取的参考知识，例如有哪些药品和治疗，以及保单如何对待它们。
- **付款授权与 QA**：钱付出之前，保险公司现有的审批和质量保证步骤。
- **审计轨迹**：每一步由谁或什么作出决定的记录。

## 用智能体搭建

**形态：** `service`。发票进入队列，理赔员打开案件时建议已经在那里；曾与 `skill` 比较过，因为理赔员要过目每一项，但运行并非由人启动。

**需要：** 对保单条款和理赔记录的读取权限；发票文件或提取出的文字；作为智能体只能读、不能改的参考文件存放的背景数据；一个案件界面或队列，让理赔员把每条建议和发票放在一起看；另有一个文件或工单队列，用来收集对背景数据的补充建议。不要给智能体任何付款授权工具。

| 步骤 | 搭建方式 |
|---|---|
| 收到宠物医疗发票 | 队列或事件为每张发票启动一次运行：由 API 调用触发的云端定时任务，或者你自己的程序启动 `claude -p` 或 Agent SDK 程序。 |
| 智能体逐行建议赔付 / 除外 | 一个 skill 读取发票、保单条款和背景数据，写出一张表：发票行、赔付或除外、理由。 |
| 🛑 action (理赔员接受、修改或转人工) → 现有的付款授权 + QA | 见“检查点”。现有的授权和 QA 保持原样。 |
| 理赔员标记缺失的背景信息 → 🛑 review (资深人员核实后才更新背景数据) | 理赔员的标记作为待补充建议保存。见“检查点”。 |

**检查点：** `action`：运行结束时把建议表写入理赔员的队列。智能体没有授权或发出付款的工具，所以只有经理赔员接受、修改或转人工，发票才能进入现有的授权步骤。`review`：背景数据对智能体是只读的（权限规则禁止修改这些文件），智能体只能往待补充建议文件里追加内容；由资深团队成员逐项核实后修改背景数据，所以不会自动更新。

**与来源相比：** 来源和公开实例出自 2026-03。NFU Mutual 基于 UiPath 智能体和它的 Action Center 界面搭建，来源还演示了一个有多个智能体的 UiPath 编排层；这套搭建方式只覆盖建议这一步，并用理赔员已在使用的案件队列代替那个界面。来源没有报道提示词、模型或规则，所以上面的表格是本目录的设计。试点的准确性和发现的多付见“公开实例”，不是对这套搭建方式的说明。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. NFU Mutual 把范围限定为宠物和马匹理赔，基于 UiPath 智能体构建 [[1]](#sources)。
2. 智能体审阅每张收到的发票，并建议哪些赔付、哪些除外 [[1]](#sources)。
3. 🛑 **操作**：建议在 Action Center 中呈现给理赔员；理赔员接受、修改，或转入人工处理 [[1]](#sources)。
4. 现有的付款授权、质量保证和审计轨迹保持不变 [[1]](#sources)。
5. 理赔员标记智能体背景信息中缺少的内容（例如一种新药）。🛑 **审阅**：资深团队成员核实每一项补充，之后才更新背景信息；不会自动更新 [[1]](#sources)。

**产出：** 经理赔员接受的逐张发票赔付/除外建议，随后进入正常的付款流程。
**失败模式 → 防护：** 理赔员漏掉的多付漏损 → 在试点中，智能体发现了理赔员漏掉的一处除外项。药品/治疗知识过时 → 理赔员标记出来，由资深人员把关更新。
**与相近工作流的区别：** AWF-0085 按政策审核报销（Policy-checked expense audit）会自动通过合规的条目，只把违规项交给专员。这里理赔员要确认每一条建议（辅助级），并且知识库的更新另有一道资深人员的审阅关口。
