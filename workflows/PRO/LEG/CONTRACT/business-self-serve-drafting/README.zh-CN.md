# 业务自助合同起草

**工具变体：** `gemini-gems`

## 背景

公司每天要签不少简短的例行协议：终止供应商合同的函件、采购补充协议、保密协议。这类文件通常从业务同事给律师发的一封邮件开始，律师套用模板填好再发回，于是法务团队把时间花在很少需要真正法律判断的文件上，业务方则要等上好几天。在这个工作流中，法务团队一次性写好经批准的模板和使用规则，业务同事回答一份引导表单，就能拿到以公司文本格式出具的初稿。智能体只负责填写已批准的模板，并拒绝模板之外的请求。凡是模板覆盖不了的请求，以及业务方希望再核一遍的草稿，仍然需要律师，因为公司要受所签内容的法律约束，模板之外的条款只有律师才能判断。

**术语：**
- **模板**：由法务团队编写并批准的合同文件，其中为会变动的细节留有空白。
- **审查手册（playbook）**：法务团队为模板写下的规则，例如允许使用哪些措辞、什么情况下必须交给律师。
- **有据可依的提示词（grounded prompt）**：把智能体限定在所提供的模板和数据之内的指令，使它不会自己编造条款。
- **NDA**：保密协议，各方承诺对所共享的信息保密的合同。
- **SOW 变更单**：对工作说明书中约定的范围、价格或进度所做的、经签署的变更。
- **解约函**：正式终止合同的函件。

## 用智能体搭建

**形态：** `skill`。每位业务人员一次准备一份文件，并且全程在对话中，所以一个装有表单、模板和规则的 skill 就够了。由法务写一次，每个业务人员都用它。

**需要：** 经批准的模板，每种文件类型一份文件；作为参考文件放在 skill 旁边的审查手册，其中包括必须交给法务的请求清单；把引导表单写成 skill 依次提出的问题；一套经所在机构批准、可以处理保密合同信息的环境。不要给智能体邮件或电子签章工具，也不要给它已批准模板以外的任何模板。

| 步骤 | 搭建方式 |
|---|---|
| 选定一种高频、低风险的文件类型 | 由法务团队在搭建之前做出的决定：每种文件类型一个 skill。 |
| 法务编写模板 + 审查手册 + 有据可依的提示词 | 法务编写模板文件、`playbook.md` 和 skill 的指令：只使用所提供的文件，其余一律拒绝。 |
| 🛑 plan (先在一个重度使用团队中试点) | 见“检查点”。 |
| 业务人员逐步填写引导表单 | skill 一次问一个问题并检查每个答案，例如解约日期是否晚于合同日期。 |
| 智能体填入已批准的模板 (拒绝超出范围的请求) | skill 复制模板、填好空白，其余内容一概不改。请求一旦落入手册的排除项，就停下来说明。 |
| 业务方使用草稿 \| 🛑 handoff (法务加急审核) | skill 保存草稿，并询问用户是否要交法务审核。要的话，就给法务写一份简短说明，列出已给出的答案。 |
| 复制到下一种文件类型 | 复制这个 skill，换上新的模板和审查手册文件。 |

**检查点：** `plan`：法务团队在共享之前先让一个团队使用这个 skill，阅读生成的草稿，并修改模板和审查手册。skill 里没有任何机制强制这一点；这是一项推广决定。`handoff`：请求落在审查手册之外，或用户要求审核时，skill 停下来，说明哪些它无法判断以及原因。智能体没有发送工具，所以草稿只有在用户转发后才会到法务手中。

**与来源相比：** 唯一的来源出自 2026-01。撰写本节时无法打开它（该站点拒绝了请求），所以这套搭建方式依据的是本条目所写的步骤。来源归在工具 `gemini-gems` 之下，那是某厂商聊天产品里经过配置的助手。带参考文件的 skill 在任何能加载 skill 的应用中都能完成同样的工作。来源报告的是一家公司自己推广其工具的做法，不是智能体无人值守地运行整个流程：每份草稿都由业务人员推动。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 法务团队找出量最大、重复性最高的起草需求，先从其中一种做起，例如解约函 [[1]](#sources)。
2. 法务编写模板、逻辑和有据可依的提示词。工具只能使用提供的模板和数据，并且必须拒绝范围之外的请求 [[1]](#sources)。
3. 🛑 **计划**：法务团队先在一个重度使用团队（采购与寻源）中试点该工具并加以完善，再推广到所有业务单元 [[1]](#sources)。
4. 业务人员（采购、人力资源或销售）填写引导表单，例如对方当事人、合同日期、解约日期和原因 [[1]](#sources)。
5. 智能体把已批准的模板和审查手册转换成合规的初稿，可以是解约函、采购补充协议、NDA、修订协议或 SOW 变更单 [[1]](#sources)。
6. 🛑 **接手**：业务人员直接使用该草稿，或把它交给法务做最终的加急审核 [[1]](#sources)。
7. 法务团队把这个模式复制到下一种文件类型。每个新工具需要几周时间来构建 [[1]](#sources)。

**产出：** 基于已批准模板、以公司文本格式出具的初稿，由业务方使用，或交法务加急审核。
**失败模式 → 防护：** 工具可能编造条款 → 它只以模板为依据，并拒绝超出范围的请求。用户仍然给律师发邮件 → 培训、操作指南，以及“签约提速”的宣传。
**与相近工作流的区别：** AWF-0024 依据审查手册的合同审阅（Playbook contract review）是最接近的一个，其中律师逐条款修订对方的文本，并签发每一份合同。这里是业务人员基于公司模板自己写初稿，律师只审阅送到他们手上的草稿。
