# 数据室红旗风险审查

**工具变体：** `harvey` · `deeligence`

## 背景

公司被收购，或收购另一家企业时，买方的律师要在交易完成之前审查目标公司的文件，这叫尽职调查。目标公司把合同、许可证、贷款协议、诉讼文件和公司记录上传到一个共享的线上文件夹，叫数据室，常常有几百份文件，而且整理得很乱。律师逐份阅读，寻找红旗风险，也就是可能改变价格或条款、甚至让交易告吹的发现，比如公司一旦被出售合同就终止的条款。这件事很慢，漏掉一个条款可能让客户损失金钱。智能体为数据室建立索引，发现缺少的文件，对照律所的检查清单阅读每份文件，并引用每个风险所依据的原文。律师仍要核实并分类每一个风险，并签发报告，因为客户依赖他们的意见，错标或漏标都是律所的职业责任。

**术语：**
- **数据室（data room）**：卖方放置文件、供买方顾问审阅的共享线上文件夹。
- **红旗风险（red flag）**：文件中可能影响价格、条款或交易能否进行的发现。
- **审查手册（playbook）**：律师的检查清单，写明每类文件要看什么、什么情况算问题。
- **目标公司（target）**：被收购或被投资的公司。
- **控制权变更条款（change of control）**：公司被出售时，允许对方终止或变更合同的条款。
- **债务融资安排（debt facilities）**：公司已取得的贷款和授信额度，常附带出售时触发的条件。
- **DD**：尽职调查（due diligence）。

## 用智能体搭建

**形态：** `skill`。一个交易团队一次审一个数据室，并且全程在对话中，所以一个装有审查手册和流程的 skill 就够了，再用内置子智能体并行读文件。

**需要：** 下载成文件的数据室文档，或卖方的数据室允许使用的连接器；作为参考文件的审查手册，每种文件类型一份；交易信息（规模、辖区、债务）；一套所在机构和本交易保密协议都允许用来处理目标公司文件的环境。在把任何文件交给 AI 工具之前，先查保密协议，因为它可能限制谁可以接收这些文件。不要给智能体邮件工具：给目标公司的请求只起草，不发送。

| 步骤 | 搭建方式 |
|---|---|
| 交易背景提示词 (规模、辖区、债务) | skill 的第一步：询问交易信息，存入一个文件，之后每一步都读它。 |
| 为数据室建立索引 + 缺失文件检查 | 智能体列出并归类每个文件，再对照审查手册针对这些交易信息所要求的文件清单。 |
| 索要缺失文件 | 智能体起草一份索要清单，由律师发给目标公司。 |
| 每份文件：对照审查手册带引用审阅 + 外部检索 | 内置子智能体各领一批文件，每份文件返回一行：手册要点、发现、附页码的原文引用和评级。用网络或数据库检索覆盖公开来源，结果标明为外部来源。 |
| 🛑 review (律师核实并分类风险) | 见“检查点”。 |
| 红旗风险摘要 + 尽职调查报告 | skill 按报告模板，根据律师已接受的风险起草这两份文件。 |

**检查点：** `review`：文件审阅完成后，skill 停下来，列出各项风险及其引用的原文。律师对每项确认、驳回并分类，报告只根据确认后的清单起草。skill 里没有发送步骤，智能体也没有邮件工具，所以报告和给目标公司的请求都由律师从自己的系统发出。

**与来源相比：** 来源出自 2025-09 至未注明日期，两者都是厂商案例。2026-11 的检索没有找到对这种做法的独立记述。找到的是 Harvey 自己关于数据室审阅的说明文章，日期为 2026-09（[链接](https://www.harvey.ai/blog/data-room-due-diligence)），以及一篇比较文章，称律所现在提醒，把数据室文件上传到第三方 AI 工具可能违反保密协议（[链接](https://www.peony.ink/blog/ai-due-diligence-tools)，引述 2026-08 的一篇报道）。这就是这套搭建方式把保密协议检查列在“需要”里的原因。来源在两款厂商产品（`harvey`、`deeligence`）里完成这些步骤，包括平台对数据室变更的跟踪；这套搭建方式没有变更跟踪，所以交易中途数据室有变化时，需要对新文件重新审阅。来源报告的是由律所主导、律师核实的试用，不是智能体无人值守地运行整个流程。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 审阅之前，交易团队先设置包含交易背景的系统提示词：公司规模、辖区和债务融资安排。这会触发相应的合规检查 [[1]](#sources)。
2. 带条件的 AI 检查找出缺失或归错类的文件，并起草向目标公司索要文件的请求 [[1]](#sources)。
3. 数据室中的每份文件都由提示词驱动做带引用的审阅，并检索法规数据库和公开来源以发现外部风险 [[1]](#sources)。
4. 🛑 **审阅**：律师对照引用核实、迭代并分类被标出的风险 [[1]](#sources)。律师助理把 AI 的审阅结果与原文并排核对 [[2]](#sources)。
5. 智能体依据经核实的红旗风险生成红旗风险摘要和尽职调查报告 [[1]](#sources)。

**产出：** 一份经律师核实的红旗风险摘要和尽职调查报告，交付给交易团队和客户。
**失败模式 → 防护：** 过度依赖 AI 标出的风险 → 让律师核实并参与流程 [[1]](#sources)。数据室在交易中途发生变化 → 在平台中跟踪变更 [[2]](#sources)。
**与相近工作流的区别：** AWF-0024 依手册审阅合同（Playbook contract review，CONTRACT）对单份合同出修订稿。本工作流并行覆盖整个数据室，索要缺失文件，并交付交易层面的红旗风险报告。

## 公开实例

覆盖度（截至 2026-11-06）：**薄弱**：只有匿名的、与厂商相关的或由记者转述的说法。收集与复核见 [New workflows for empty categories](../../../../../research/2026-11-new-workflows.md)。

- [Harvey, GSK Stockmann due diligence](https://www.harvey.ai/customers/gsk-stockmann) (2025-09-26)。为公司和房地产交易共同设计的尽职调查工作流，由律师核实所标出的风险。"up to 75% when applied to unstructured data rooms"。*第一手：厂商；可信度：中。*
- [Deeligence, Mayne Wetherell](https://www.deeligence.com/resources/mayne-wetherell-market-leading-due-diligence-practice-adopts-deeligence) (n.d.)。在一项大型交易中做 AI 重大合同审阅，并由律师助理复核。"75+ hours of lawyer time saved on a recent deal"。*第一手：厂商；可信度：中。*
