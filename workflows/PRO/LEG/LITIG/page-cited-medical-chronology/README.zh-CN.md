# 逐页引注的病历时间线

**工具变体：** `squary` · `supio`

## 背景

有人受伤并索赔时，他的律师需要准确了解他在医疗上经历了什么、发生在何时：每次就诊、诊断、检查和治疗，按顺序排列。这些事实分散在成百上千页病历和证词笔录里（证词是在宣誓后进行、被记录下来的问答）。律师助理或律师把它们全部读一遍，写出一份病历时间线，也就是带日期的事件清单，每一项都指向所在的页码。同样的工作还产出证词摘要和庭审备忘录。这很慢，一个日期写错或一条没有依据的陈述，都可能削弱索赔函，甚至被对方拿来对付律所。在这里，智能体提取事件，起草时间线，每一条都附页码。律师助理或律师对照所引页码逐条核对，用法由律师决定，因为索赔函由律师签发，律师要向客户和法院负责。

**术语：**
- **病历时间线（medical chronology）**：按日期排列的一个人的医疗事件清单，每项都对应显示它的病历页码。
- **证词（deposition）**：开庭前取得并记录下来的宣誓证言；**证词摘要**按主题和页码对它加以浓缩。
- **索赔函（demand letter）**：陈述伤情，并向对方的保险公司提出一笔确定金额的函件。
- **PI**：人身伤害（personal injury），处理对人身造成损害的索赔的法律领域。
- **页码引注（page cite）**：指向某句陈述所在页码（笔录则含行号）的引用。
- **案件（matter）**：律所为一位客户的案子建立的档案。
- **案件管理系统**：律所用来管理每个案件的文件、任务和期限的软件。

## 用智能体搭建

**形态：** `skill`。律师助理或律师一次处理一个案件，并且全程在对话中，所以一个装有时间线格式和引注规则的 skill 就够了。

**需要：** 以文件形式存放的病历和证词笔录，页码可供引用（可检索文字的 PDF，或先转成文字的扫描页）；放在 skill 旁边的律所自己的时间线或摘要模板；案件类型，它决定要查找什么；一套经批准可处理患者健康信息的环境（这些是受保护的健康记录）。不要接入邮件工具。

| 步骤 | 搭建方式 |
|---|---|
| 把病历和证词上传到案件（案件管理系统链接） | 把文件放进该案件的文件夹；律所有 MCP 服务器连接器的话，可以通过它访问案件管理系统。 |
| 设定案件背景（案件类型、律所摘要格式） | skill 的第一步：询问案件类型，并读取律所的模板。 |
| 对病历分类并提取带页码引注的带日期事件 | 智能体读取每个病历文件，返回一张表：日期、事件、来源文件、页码。每个文件可交给一个子智能体。没有文件和页码的条目不保留。 |
| 起草时间线/证词摘要 | skill 按律所模板，根据这张表逐行填写，每行一条。 |
| 🛑 review (律师助理或律师对照所引页码核对每一条) | 见“检查点”。 |
| 🛑 sign-off (律师用于索赔函、证词准备或庭前备忘录) | 见“检查点”。 |

**检查点：** `review`：skill 最后展示时间线，每条附上所引页码的链接，然后停下；律师助理或律师逐条打开该页，更正或删除。一个会拒绝缺少文件和页码的条目的脚本可以起辅助作用，但不能代替人工核对。`sign-off`：skill 不起草索赔函，智能体也没有邮件工具，所以由律师在自己的系统里，把核实过的时间线用于索赔函、证词准备或庭审备忘录。

**与来源相比：** 来源出自 2025-11 至 2026-09，两者都是厂商案例。2026-11 读取第一个来源的页面时，几乎没有返回文字，所以其中的细节取自本条目。来源在两款法律产品（`squary`、`supio`）里完成这些步骤，这些产品与律所的案件管理系统相连；这套搭建方式读取的是文件，把案件系统留给律所。两个来源都没有展示产品如何提取和引注；本搭建方式中“日期、事件、文件、页码”的表是设计上的选择，并不是对任何一款产品的描述。来源报告的是律所使用产品、由律师助理和律师核对输出，不是智能体无人值守地运行整个流程。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 律所把病历、证词和案件文件上传到案件工作区，并连接案件管理系统（例如 Filevine） [[1]](#sources)。
2. 用户选择任务（病历时间线、证词摘要、庭前备忘录）；律所可以提供自己的摘要格式，使输出符合合伙人的写法 [[1]](#sources)[[2]](#sources)。
3. 智能体提取带日期的临床事件和证词，起草结构化的时间线或摘要，每一项论断都带页码级引注 [[1]](#sources)[[2]](#sources)。
4. 🛑 **审阅**：律师和律师助理点击进入所引的行或页，确认上下文；「如果无法把一句陈述追溯到记录，它就不能用」 [[1]](#sources)。
5. 🛑 **签发**：律师把核实过的时间线用于索赔函、证词准备或庭审 [[1]](#sources)[[2]](#sources)。

**产出：** 案件档案中带原文链接的病历时间线或证词摘要，供索赔函起草和证词准备使用。
**失败模式 → 防护：** 事实无依据或日期有误 → 每条都带页码引注，并对照原文核对。与律所风格不符 → 上传律所自己的摘要模板。
**与相近工作流的区别：** AWF-0035 和 AWF-0093 是对大批文档分类或登记以供提交。本工作流的交付物是律所自己备案用的单案事实时间线，并对照所引页码逐条审阅；交付物和检查点都不同。

## 公开实例

覆盖度（截至 2026-11-13）：**薄弱**：只有匿名、与厂商相关或记者转述的说法。收集与复核见 [Third collection pass](../../../../../research/2026-11-third-pass.md)。

- [Squary, Quatrini Law Group](https://www.squary.ai/blog/how-quatrini-law-group-modernized-legal-workflows-with-squary-ai) (2025-11-10)。人身伤害/残疾案律所：带页码引注的病历摘要和证词准备；引述了创始合伙人的话。注：该律所合伙人在厂商董事会任职。"up to 70% faster document reviews and 10-15 hours saved per case"。*第一手：厂商；可信度：中。*
- [Supio, GLP Attorneys](https://www.supio.com/customers/how-glp-personal-injury-attorneys-levels-the-playing-field-with-supio) (2026-09-02)。律师助理生成时间线和索赔函草稿；合伙人上传自己的摘要格式。"Catastrophic-injury medical record review, compressed from 40 hours"。*第一手：厂商；可信度：中。*
