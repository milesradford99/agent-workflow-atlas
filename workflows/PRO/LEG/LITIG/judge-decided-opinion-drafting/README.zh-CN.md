# 法官定案后的裁判文书起草

**工具变体：** `shenzhen-intelligent-adjudication-system` · `modelbest-judicial-llm`

## 背景

法院案件始于当事人提出诉讼请求，终于法官签发判决：一份书面裁判文书，写明查明的事实、法律上的理由和裁判结果。在这两个节点之间，法院工作人员要检查立案材料是否齐全，并把证据整理成案卷；法官阅卷、开庭，并对每个争议焦点作出裁断。然后法官撰写判决书，这很耗时，因为理由必须依据证据和法律逐步展开。在这个工作流中，智能体整理案卷、列出争议焦点、为庭审建议问题，并且只在法官对每个焦点作出裁断之后才起草裁判理由。法官确认每一步，因为判决是法院的公开行为，案件只能由法官裁判。智能体的设计是：先由人裁断，再由智能体撰写理由。

**术语：**
- **裁判文书**：法院的书面裁判，写明查明的事实、裁判理由和结果。
- **立案标准**：材料在法院受理案件之前必须通过的检查，例如有明确的被告和诉讼请求。
- **争议焦点**：当事人意见不一、需要法官裁断的问题。
- **疑点**：证据中的缺口或不合常理之处，法官可能想在庭审中询问。
- **类案**：事实相近的以往裁判，法官可以用作参考。
- **审计轨迹（audit trail）**：对案件中每一项操作的记录，以便事后监督整个过程。

## 用智能体搭建

**形态：** `platform`。来源是法院自己的办案系统，它与电子立案、案卷记录和一个为司法工作训练的法律大模型连在一起，通用智能体无法取代。通用智能体可以承担中间部分：从导出的案卷到争议焦点清单、庭审问题和裁判理由草稿，作为由法官在对话中运行的 `skill`。

**需要：** 以文档形式导出的案卷，放在法院批准处理案件材料的环境里（这些材料是保密的，有时还是封存的）；法院的受理标准（如果受理检查在范围之内）；法院所用法条和指引的参考文件；判决书模板。不要让智能体连接法院的案件管理或立案系统，也不要给它任何签发或公布的途径。

| 步骤 | 搭建方式 |
|---|---|
| 电子立案 → 智能体对照 35 项受理标准检查立案材料 + 提示当事人补充缺失材料 | 法院的立案平台。skill 可以对照标准文件检查导出的立案材料，并起草给当事人的补充请求，由法院发出。 |
| 智能体整理案卷 + 标出数据不一致 | 一个 skill，列出文件，并标出日期、姓名和数字相互矛盾之处，注明各自的页码。 |
| 智能体辅助阅卷：争议焦点清单 + 供合议庭关注的疑点 | 同一个 skill 起草争议焦点清单和疑点，每项都对应到具体页码。 |
| 开庭，使用智能体生成的问题 | skill 写出一份问题清单，供法官取用或舍弃。庭审记录由法院自己的系统负责。 |
| 🛑 action (法官确认事实模块、选定/修改争议焦点、对每项作出裁断) | 见“检查点”。 |
| 智能体推送匹配的法条、问答条目和类案 | skill 在参考文件中检索法条和指引。类案来自法院的裁判文书库，这是平台功能。 |
| 智能体生成裁判理由 + 完整判决书草稿 | skill 只依据法官的裁断和已查明的事实起草裁判理由和判决书。 |
| 🛑 review (法官修改裁判理由；每个节点都有勾选确认关卡) | 见“检查点”。 |
| 🛑 sign-off (法官签发判决) | 见“检查点”。 |
| 案件级审计轨迹 | 法院的平台。用通用智能体时，可用钩子把每次工具调用记录到文件；它不能代替法院自己的记录。 |

**检查点：** `action`：在法官把对每个争议焦点的裁断录入裁断文件之前，skill 拒绝起草任何裁判理由，草稿中的结果只取自该文件。法官裁断之前，skill 展示事实和焦点清单后停下。`review`：草稿完成后，skill 停下来，展示草稿以及每一段在裁断文件或案卷中的出处；法官修改，每一节标为已确认之后才展示下一节。`sign-off`：智能体没有签发或公布判决的工具，所以由法官在法院自己的系统中签发。

**与来源相比：** 来源出自 2024-08 至 2025-01。来源 1（同行评审的研究）在撰写本节时无法打开，该站点拒绝了请求。2026-11 找到的较新报道：一篇日期为 2026-06-16 的财经媒体文章称，深圳的系统已用于超过 600,000 件案件，并已被最高人民法院纳入全国统一办案平台，先在 23 家法院试运行，再全面推广（[第一财经](https://www.yicai.com/news/103232904.html)）。我没有找到关于“法官先裁断”这一设计本身有何变化的更新说明。来源描述的是法院自己的平台和经过训练的司法模型；这套搭建方式只覆盖导出文件上的文字步骤，受理检查、庭审记录和法院的审计记录仍留在法院的系统里。步骤里的失败模式（草稿强化了法官最初的看法）同样适用于这套搭建方式，它并不能消除这一点。法院能否以及如何在起草中使用 AI，由该法院自己的规定决定；在试用这个设计之前先查清这些规定。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 案件以电子方式立案。受理模块对照 35 项立案标准检查材料，自动分类并校准案件数据，提示当事人补充缺失的材料。上线后的第一个阶段，该模块辅助了超过 310,000 件立案，发出了 9,000 多次一次性补充材料的要求 [[2]](#sources)。
2. 智能体整理电子卷宗，更正数据中的不一致（日期、年份、姓名、数字），并为法官生成争议焦点清单和“疑点”——例如在夫妻债务纠纷中分析夫妻之间的资金往来，并生成庭审中要问的问题 [[2]](#sources)。
3. 法官开庭，向各方当事人提出生成的问题；系统辅助庭审记录 [[2]](#sources)。
4. 🛑 **操作**：法官查明并记录事实（依据证据和庭审，补充系统起草的“本院查明”部分），审阅并修改系统给出的争议焦点清单，对每项焦点作出裁断——原告的每项诉讼请求是被支持还是被驳回 [[1]](#sources)。
5. 智能体从裁判指引语料库推送适用的法条、权威问答条目和类案；法官权衡合同条款和案件相似度，作出法律定性 [[2]](#sources)。
6. 智能体根据法官的裁断和已查明的事实生成裁判理由和完整的判决书草稿。一位法官称，在她核准信息、给出指令、确认结论之后，几秒钟就生成了草稿，完成度超过 90% [[2]](#sources)。
7. 🛑 **审阅**：法官修改 AI 生成的裁判理由，形成最终判决。系统中每个节点都带有审阅 / 确认 / 裁断的选项和提示，法官必须逐项勾选，这才最终决定案件结果——据称既防止了“机器裁判”，又保留了法官的裁量权 [[1]](#sources)[[2]](#sources)。
8. 🛑 **签发**：法官签发判决。整个过程留痕，以便监督和追责，系统还会监控案件进度并实时预警 [[2]](#sources)。

**产出：** 归入法院卷宗、由法官签发的判决书；汇总的案件数据还会用于司法建议报告和调解指引。
**失败模式 → 防护：** 智能体会为法官录入的任何结论写出结构完整的理由，可能强化最初的错误或偏见——同行评审的研究称之为“偏见的回声”，并在 139 名法官身上得到了好坏参半的实验证据 → 法官必须独立查明事实并修改理由，系统不得自行选择结果。文书中日期、姓名和数字有误 → 自动校准加 35 项标准的受理检查。过度依赖生成的草稿 → 逐节点的勾选确认关卡和完整的审计轨迹。
**与相近工作流的区别：** 同类中最接近的是 AWF-0161 带页码引用的医疗时间线（同为辅助，同样是基于案卷生成文件），但那里的交付物是诉讼律师的时间线或证词摘要，逐条对照引用页码核查，智能体从不触及结果。本工作流的交付物是法院自己的判决，检查点的安排也是倒过来的：先由人裁断，智能体事后撰写理由，并设置逐节点确认关卡。它与 AWF-0035、AWF-0093 同样相去甚远，后两者是面向整体人群的审阅产品，靠抽样验证。注意：这是法院一侧的裁判工作，而不是律所的诉讼业务，如果再出现第二个、第三个裁判类工作流，或许应当新设 PRO/LEG/ADJUDICATION 类。

## 公开实例

覆盖度（截至 2026-11-13）：**充分**：有详细的第一手实例，与流程的大部分环节一致。收集与复核见 [Fourth collection pass](../../../../../research/2026-11-fourth-pass.md)。

- [Liu & Li, How do judges use large language models? Evidence from Shenzhen, Journal of Legal Analysis](https://academic.oup.com/jla/article/16/1/235/7941565) (2025-01-02)。经同行评审，记述了“法官先裁断、AI 后写理由”的交互模式。"An experiment with real judges" — a vignette experiment "with 139 judges from China", average sixteen years' judicial experience. *第一手：研究；可信度：高。*
- [人民法院报, 在深圳，智赋未来 (Supreme People's Court)](https://www.court.gov.cn/zixun/xiangqing/441351.html) (2024-08-29)。来自法院自身的生产数据和逐节点确认关卡的说明。"系统全面上线36个工作日，智能辅助阅卷57052件，辅助庭审23701次，辅助生成裁判文书52554份". *第一手：访谈；可信度：高。*
- [人民法院报, 在深圳，智赋未来 (Supreme People's Court)](https://www.court.gov.cn/zixun/xiangqing/441351.html) (2024-08-29)。一位署名法官讲述了她确认之后草稿的完成度。"只用了几秒，一份由法官核准信息、给出指令、认定结论之后的裁判文书初稿就生成了，完成度超九成". *第一手：访谈；可信度：中。*
