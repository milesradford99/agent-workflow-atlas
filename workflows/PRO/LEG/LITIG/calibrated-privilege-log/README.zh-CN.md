# 校准后的特权日志

**工具变体：** `lighthouse-genai-privilege`

## 背景

在诉讼或监管调查中，各方都要交出自己的相关文件。受特权保护的文件，例如律师给客户的意见，可以扣留不交，但扣留的一方必须随后送达一份特权日志：一张清单，把每份扣留文件描述到足以让对方和法院判断这一主张是否成立，又不泄露受保护的内容。大案可能有几十万条记录，靠人工逐条撰写既慢，又容易前后不一致。在这里，智能体先在样本上起草每条描述，供律师修改措辞，再对全部文件运行。对案件负责的律师仍要决定措辞规则并批准提示词，因为日志是以他们的名义送达对方的，描述一旦泄露受保护的内容，就等于放弃了这项保护。

**术语：**
- **特权（privilege）**：让一方可以把保密沟通，例如律师给它的意见，排除在交出的材料之外的法律保护。
- **特权日志（privilege log）**：送达对方的清单，描述每份作为特权文件扣留的文件。
- **特权文件全集**：已经认定属于特权、要扣留的文件。
- **外部律师（outside counsel）**：在案件中代表客户的律师事务所。
- **提交（production）**：把相关的、非特权的文件交给对方。
- **提示词（prompt）**：模型起草每条描述时所遵循的书面指令。

## 用智能体搭建

**形态：** `project`。只用一个 skill 不够：全量运行要并行处理数量极大的文件，而且每条描述在进入日志之前，都必须由脚本检查是否含有受保护的内容。这项检查必须每次都执行，钩子能做到 skill 的文字做不到的强制。

**需要：** 以文件形式存放的特权文件，放在经所在机构和本案保护令都允许处理特权材料的环境里，且不连接该环境之外的任何系统；案件要求的日志格式；一份指令文件，写明案件的名称、术语，以及律师定下的措辞规则（描述可以写什么、绝不能写什么）；一个存放样本输出及律师批注的地方。不要给智能体任何送达或提交的工具。

| 步骤 | 搭建方式 |
|---|---|
| 特权文件全集 → 抽取样本集 | 由脚本从特权文件清单中随机抽取样本，并记录抽到了哪些文件。 |
| 针对案件用语定制提示词 | 一个 skill，装有提示词、案件的名称和术语，以及措辞规则。 |
| (在样本上生成日志描述 ⟲ 🛑 review (外部律师反馈)) | skill 为样本起草描述，写入文件交给律师。律师的批注用来修改提示词，样本重新运行，直到律师批准。见“检查点”。 |
| 在全部特权文件上运行调整后的提示词 | 用动态工作流，或每批文件一个子智能体，套用已批准的提示词，每份文件返回一条描述。钩子或脚本会拒绝含有律师“绝不能写”清单中词语的描述。 |
| 定稿日志 | 由脚本把描述合并成案件要求的日志格式。 |

**检查点：** `review`：每次样本运行之后，skill 都停下来，把起草的描述列给外部律师；只有律师批准了当前的提示词，才开始全量运行，批准情况记录在提示词文件里。动态工作流在运行中途不能接收输入，所以这一停设在它之前。来源没有提到对全量运行的审阅，所以在日志定稿之前，应补上律师对全量输出的抽样通读。智能体没有送达日志或向外发送的工具，由律师从自己的系统送达。

**与来源相比：** 唯一的来源出自 2025-08。2026-11 的检索没有找到对这一做法更新的第一手记述。找到的有：该厂商自己的产品页面，现在介绍一个特权日志生成功能，生成可供二审使用的可编辑条目（[IQ Priv](https://lighthouseglobal.com/iq-priv)）；以及一篇 2026-03 对 Legalweek 研讨会的报道，称由 AI 起草日志描述是风险较低的切入点，由律师审阅并调整每条记录，并对流程做验证和抽样（[ComplexDiscovery](https://complexdiscovery.com/defensible-by-design-what-legal-teams-must-get-right-about-ai-privilege-workflows/)）。同一场研讨会提到，2026-02-10 有两家联邦法院就使用 AI 产生的材料是否属于特权或工作成果，作出了不同的裁判，所以团队在开始之前应先查清本案法院对使用 AI 的态度。来源描述的是厂商顾问借助一个平台完成的一次工作；这套搭建方式用文件、脚本和动态工作流完成同样的步骤，来源并没有报告有人这样运行过。这套搭建方式还增加了描述检查和抽样通读，来源没有描述这两项。

*以上是依据本条目的步骤和截至 2026-11 的工具文档做出的设计，不是已报道的实例。*

## 步骤

*以下按来源所述。*

1. 团队从已认定为特权的文件出发，从中抽取样本集 [[1]](#sources)。
2. 厂商顾问针对该数据集编写提示词，使各条描述既不重复又保持一致，并使用案件自身的用语和语境 [[1]](#sources)。
3. 智能体为样本生成日志描述，团队把它发给外部律师 [[1]](#sources)。
4. 🛑 **审阅**：外部律师的反馈推动提示词反复修改，直到他们对调整后的提示词有信心 [[1]](#sources)。
5. 智能体在全部特权文件上运行调整后的提示词，结果送入日志定稿流程 [[1]](#sources)。

**产出：** 一份载有文件描述的特权日志，可供律师送达。
**失败模式 → 防护：** 描述流于笼统或重复 → 提示词按案件语境调整，并在全量运行之前由律师在样本上检查。来源中没有提到对全量运行做正式的质检抽样，所以在送达日志前要自行补上一道。
**与相近工作流的区别：** AWF-0035 经验证的 GenAI 初筛（Validated GenAI first-pass）是最接近的一个，它标注文件是否相关，并用统计方法验证召回率和漏检率。本工作流则是撰写要送达对方的日志描述，检查点是律师在样本上校准措辞，而不是对召回率的签发。
