# 校准后的特权日志

**与相近工作流的区别：** AWF-0035 经验证的 GenAI 初筛（Validated GenAI first-pass）是最接近的一个，它标注文件是否相关，并用统计方法验证召回率和漏检率。本工作流则是撰写要送达对方的日志描述，检查点是律师在样本上校准措辞，而不是对召回率的签发。
**工具变体：** `lighthouse-genai-privilege`

## 步骤

1. 从已认定为特权的文件出发，从中抽取样本集 [[1]](#sources)。
2. 针对该数据集编写提示词，使各条描述既不重复又保持一致，并使用案件自身的用语和语境 [[1]](#sources)。
3. 为样本生成日志描述，并发给外部律师 [[1]](#sources)。
4. 🛑 **审阅**：外部律师的反馈推动提示词反复修改，直到他们对调整后的提示词有信心 [[1]](#sources)。
5. 在全部特权文件上运行调整后的提示词，并把结果送入日志定稿流程 [[1]](#sources)。

**产出：** 一份载有文件描述的特权日志，可供律师送达。
**失败模式 → 防护：** 描述流于笼统或重复 → 提示词按案件语境调整，并在全量运行之前由律师在样本上检查。来源中没有提到对全量运行做正式的质检抽样，所以在送达日志前要自行补上一道。

## 公开实例

覆盖度（截至 2026-11-06）：**薄弱**：只有匿名、与厂商相关或由记者转述的说法。收集与复核见 [Second collection pass](../../../../../research/2026-11-second-pass.md)。

- [Boone/Lighthouse, 200,000-line privilege log](https://www.lighthouseglobal.com/blog/privilege-log-gen-ai) (2025-08-04)。厂商顾问介绍先用样本校准提示词、再全量运行的做法；律师没有手写任何描述。"more than 200,000 entries"。*第一手：厂商；可信度：中。*
